# Stockfishの未採用PRの調査（週次）

[共通の約束](README.md)を先に読む。コードは変えない。案をIssueにするだけである。

探索の発明は難しいので、情報源を広げる（ROADMAPの候補）。参照実装は
Stockfishに追従しており、採用済みの変更はその追従で拾ってきた。ここで見るのは、
まだ採用されていないPRである。

## 手順

1. 直近1週間に動いたPRを読む

   ```
   gh pr list --repo official-stockfish/Stockfish --state open --limit 30 \
     --json number,title,updatedAt,url
   ```

2. 探索の挙動を変えるPRだけを見る。NNUEの構造、UCI、ビルド、チェス固有の
   規則（キャスリング、アンパッサン、終盤表）は飛ばす
3. 1件ずつ、CLAUDE.mdの「SPRTゲート」にある3点を確かめる。係数のスケールが
   本エンジンで成り立つか、想定する発動率が同じか、その値が前提にしている別の
   仕組みがないか。`crates/engine/src/search.rs` の該当箇所を読んで書く
4. **本エンジンで成り立つ理由を自分の言葉で書けるものだけ**をIssueにする。
   「参照にあるから正しい」は根拠にならない（[ADR-0141](../../docs/adr/0141-singular-rate-calibration.md)）。
   fishtestの結果が良いことも、それだけでは理由にならない
5. Issueには、元のPRのURL、変更の要旨、本エンジンで成り立つ理由、該当する
   コードの場所、測り方の案を書く。ラベルは付けない（実験の候補であり、
   `micro` ではない）

1回で切るのは2件までにする。書けるものが無ければ、何もせず終わる。それが
普通である。
