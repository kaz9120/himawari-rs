# 0029: 詰み探索（mate1ply）

- Status: proposed
- Date: 2026-07-19
- 関連ADR: [0024](0024-search-v1.md), [0027](0027-sprt-framework.md), [0028](0028-pruning-extensions.md)

## Context

通常探索は王手の応酬を深く読まないと詰みを見つけられない。
1手詰めだけでも専用判定があれば、探索の末端で詰みを即座に
確定でき、終盤力と時間効率が上がる。このADRで決めるのは
1手詰め判定の実装方式と呼び出し箇所。df-pnによる長手数の
詰み探索はP3では扱わない（バックログに残す）。

## 選択肢と比較

### 実装方式

案Aは生成ベース: 王手になる手を列挙し、各手について相手の
応手が尽きるかをis_legal＋回避生成で確かめる。実装が単純で
正しさを検証しやすいが、1回あたりのコストが大きい。

案Bは利きテーブル駆動（やねうら王のmate1ply系）: 玉の周囲の
利きと持ち駒から候補マスを絞り、盤面走査を最小化する。
高速だが実装が複雑で、バグの検出も難しい。

案Aから始める。SPRTで効果を確認した後、案Bへの置き換えを
「等価変更＋高速化」として非劣性SPRTで行う。案Aが正解器として
残るため、案Bとの一致テスト（ランダム局面で全数比較）が書ける。

## Decision

- `mate_1ply(pos) -> Option<Move>` をengineに実装する（案A）。
  王手になる手（駒打ち含む）を列挙し、相手の合法応手が
  0になる手を返す
- 呼び出し箇所: 本探索の静的評価の後（王手中を除く）。
  見つかれば `mate_in(ply+1)` を返す。qsearchでは
  stand-patのβカット後に呼ぶ
- 深さ条件は設けず全ノードで呼ぶことから始め、コストが
  見合わなければ条件付けを1調整=1SPRTで直す
- 検証: 詰将棋スモークセットに1手詰めの網羅ケースを足す。
  ランダムプレイアウト局面で「mate_1plyが返す手は実際に詰み」
  「返さない局面に1手詰めはない」を全数探索と照合する
- df-pn（長手数詰み・詰めろ探索）はP3ではスコープ外

## Consequences

- 終盤の読み抜け（ADR-0024が持ち越した静止探索の王手なし問題）の
  一部がここで解消する。残りはQuietChecks（ADR-0028の項目7）が受け持つ
- 案Aのコストが高い場合、SPRTがそれを弾く。その場合は案Bを
  先に作ってから再挑戦する
- 打ち歩詰めの除外（禁じ手）はis_legal側で既に検査されるため、
  mate_1plyが打ち歩詰めを詰みと誤認することはない
