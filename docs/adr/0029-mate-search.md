# 0029: 詰み探索（mate1ply）

- Status: accepted
- Date: 2026-07-19
- 関連ADR: [0024](0024-search-v1.md), [0027](0027-sprt-framework.md), [0028](0028-pruning-extensions.md)

## Context

通常探索は王手の応酬を深く読まないと詰みを見つけられない。
1手詰めだけでも専用判定があれば、探索の末端で詰みを即座に
確定でき、終盤力と時間効率が上がる。このADRで決めるのは
1手詰め判定の実装方式と呼び出し箇所。df-pnによる長手数の
詰み探索はP3では扱わない（バックログに残す）。

## 選択肢と比較

### 実装方式

案Aは生成ベース: 王手になる手を列挙し、各手について相手の
応手が尽きるかをis_legal＋回避生成で確かめる。実装が単純で
正しさを検証しやすいが、1回あたりのコストが大きい。
全ノードで呼ぶとコストが利得を食い、短い持ち時間のSPRTでは
棄却される公算が高い。

案Bは候補マス駆動（Bonanza・やねうら王のmate1ply系）:
敵玉の8近傍＋桂の候補マスに限定し、利き情報とテーブルで
「打って詰むか・動かして詰むか」を直接判定する。全数の
王手生成をしないため速い。実装は複雑でバグの検出が難しい。

案Bを本命とし、ゲートに掛けるのは案Bだけにする。案Aは
テスト用の正解器（オラクル）として実装し、ランダム局面での
全数一致テストで案Bの正しさを担保する。

## Decision

- `mate_1ply(pos) -> Option<Move>` を案B（候補マス駆動）で
  engineに実装する。敵玉近傍への駒打ち詰みと移動詰みを、
  利き・支えの有無・玉の逃げ道マスクで直接判定する
- 案Aは `#[cfg(test)]` 相当のオラクルとして実装し、
  ランダムプレイアウト局面で「案Bが返す手は実際に詰み」
  「案Bが見逃す1手詰めはない」を案Aと全数照合する
- 呼び出し箇所: 本探索の静的評価の後（王手中を除く）と、
  qsearchのstand-patのβカット後。見つかれば `mate_in(ply+1)`
- 深さ・頻度の条件付けはSPRTの結果を見て1調整=1SPRTで行う
- 後段としてBonanza式の限定mate3ply（王手の限定列挙→応手→
  mate1ply）を別ゲートで検討する。df-pnはP3ではスコープ外

## Consequences

- 終盤の読み抜け（ADR-0024が持ち越した静止探索の王手なし問題）の
  一部がここで解消する。残りはQuietChecks（ADR-0028の項目7）が受け持つ
- 案Bの実装コストは高いが、オラクル照合テストがあるため
  リファクタ耐性は高い。詰将棋スモークにも1手詰め網羅ケースを足す
- 打ち歩詰めの除外（禁じ手）を案B内で明示的に検査する必要がある
  （案Aはis_legal経由で自動的に除外される。この差もオラクル照合で
  検出できる）
