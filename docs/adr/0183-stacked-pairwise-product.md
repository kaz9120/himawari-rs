# 0183: FT積を2段にして4駒の相互作用を入れる

- Status: proposed
- Date: 2026-08-22
- 関連ADR: [0127](0127-net-shape-bench.md), [0134](0134-head-capacity.md), [0158](0158-mirror-factorizer.md), [0168](0168-ft-dim-reorder.md), [0171](0171-ft-pairwise-product.md), [0172](0172-multihot-input.md)

## Context

[ADR-0171](0171-ft-pairwise-product.md)は片視点のFT出力を512+512に割って
要素ごとに掛け、駒対（2駒）の相互作用を低ランクで入れた。+65.4 Eloで
採択し、利得の本体は評価の質だった。

この機構は1段で止まっている。積の出力512をさらに対で掛ければ、
駒対どうしの積＝**4駒の相互作用**が入る。

```
y_j = (Σ_i W_ji x_i)(Σ_m W'_jm x_m)          … 2駒（0171）
z_k = y_k · y_{k+256}                          … 4駒（本ADR）
```

zの展開は4つの表の係数の積 `W·W'·W''·W'''` を持ち、（玉, 駒）×4の
相互作用の低ランク近似になる。KPPPやPPPPを表で持つと組合せ爆発するが、
要素積なら**1パスのO(n)で表現の次数が倍になる**。

コストの見込みは実測から立つ。yの要素ゼロ率は0.8794
（[ADR-0171](0171-ft-pairwise-product.md)）で、積は片側ゼロなら結果も
ゼロなので、zのゼロ率は独立仮定で1−0.12²≒0.986になる。第1層は
非ゼロチャンクだけ回る（[ADR-0168](0168-ft-dim-reorder.md)）ため、
zを足しても第1層の追加仕事はほぼゼロである。

## 選択肢と比較

### 案A: yをzで置き換える（幅を増やさない）

第1層の入力は増えないが、2駒の項が消える。0171の利得を捨てる形で、
取れない。

### 案B: yにzを追記する（[y512, z256] の768/視点）

CONCATは1024から1536になるが、zの非ゼロは独立仮定で256中約4次元。
チャンク単位でも追加はわずかで、要素積のコストは視点あたり256回の
乗算だけになる。2駒の項を保ったまま4駒を足せる。

### 案C: ゲート型（z = y·σ(y')）

積の代わりにGLU型のゲートを掛ける。コストは案Bと同等で、表現は
「4駒の積」ではなく「2駒項の変調」になる。案Bの対照実験として
測る価値はあるが、まず積で仮説（高次相互作用の価値）を確かめる。

### 案D: 3段（8駒）まで積む

2段の結果を見てから決める。段ごとにゼロ率が上がるので、3段目は
非ゼロのほぼ消えた状態になり、学習信号は立たない可能性が高い。

## Decision

**案Bを採る**。実装と検証は0171の手順を踏襲する。

### 実装

対の組み方は `z_k = y_k · y_{k+256}`（k = 0..256）。量子化は0171と同じ
手口で、yはu8（0〜127）、`z = (y_k * y_{k+256}) >> 7` とし、学習側の
zへ127/128を掛けて値域を揃える。後段の量子化係数は変えない。

| 場所 | 中身 |
|---|---|
| `engine/nnue.rs` | `CONCAT` を1536へ。視点あたりの幅 `HALF = 768` |
| `engine/nnue_simd.rs` | 活性構築へ第2段の積を1パス追加。`find_nnz` の走査幅を768/視点へ |
| `engine/nnue_acc.rs` | 変更なし（積はaccumulatorの後。0171と同じ） |
| `engine/nnue_io.rs` | 版を分ける。`w2` の長さが1536×16へ変わるため |
| `training/model.py` | 第2段の積と127/128の係数 |

**[ADR-0168](0168-ft-dim-reorder.md)の並べ替えと干渉する**。第2段の対
（k, k+256）があるため、活性次元を自由に並べ替えると掛かる相手が変わり、
評価値が変わってしまう。並べ替えの単位を「第2段の対」（256スロット）に
し、`hmwr net reorder` へ制約を足す。第1段の対（FT側のj, j+512）は
0171と同じくmakenetが追従する。

### 検証（0171と同じ5段）

1. 機能検証。スカラーとSIMDの一致、Python側とRust側の評価値の一致
2. 3億局面（`train_300M_q1`）で学習する。現行と同条件で、違いは第2段だけ
3. NPS計測。ノード数固定・交互（[ADR-0127](0127-net-shape-bench.md)）
4. 3億ネット同士の直接対局。ノード数固定と時間制の両方
5. 通れば29.9億で本学習し、SPRT既定条件にかける

**valid lossで足切りしない**（[ADR-0158](0158-mirror-factorizer.md)）。
`CONCAT` が変わると後段の初期値の乱数消費がずれるためで、0171と同じ。

**撤退ライン**。3億の時間制で負けたら棄却する。zの非ゼロが想定より
多くて速度で潰れる場合と、疎すぎて学習信号が立たない場合の両方が
ありうる。学習後にzのゼロ率と、zに繋がる `w2` の重みの大きさを測り、
どちらに倒れたかを記録する。

## Consequences

- ネットのファイルに互換がなくなる。版を分けるので誤読はしない
- 並べ替え（ADR-0168）の自由度が半分になる。第2段の対を壊せないため、
  全ゼロチャンク率の上限は現行よりわずかに下がる可能性がある
- 案C（ゲート型）と案D（3段目）が、この測定台の上の後続実験として残る
- 死んだ次元（候補表）の影響が2乗で効く。yの死んだ対はzも道連れに
  するので、死んだ次元の回収はこのADRの後でさらに価値が上がる
