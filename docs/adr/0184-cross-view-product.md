# 0184: 視点をまたぐ対の積で両玉の相互作用を入れる

- Status: rejected（ノード数固定で−9.2のH0。下の「測定」）
- Date: 2026-08-23
- 関連ADR: [0127](0127-net-shape-bench.md), [0158](0158-mirror-factorizer.md), [0168](0168-ft-dim-reorder.md), [0171](0171-ft-pairwise-product.md), [0183](0183-stacked-pairwise-product.md)

## Context

[ADR-0171](0171-ft-pairwise-product.md)の積は視点の中で閉じている。
自視点の活性は（自玉, 駒）×（自玉, 駒）の対だけを持ち、係数の中に
**両方の玉が同時に絡む項は存在しない**。KKP・KKPPが別表で持っていた「両玉と
駒の関係」は、いまは後段の16次元MLPが1024次元の要約から復元するしか
ない。

自視点と相手視点の活性を掛ければ、この項が同じ低ランク機構で入る。

```
y_j = (Σ_i W_ji x^own_i)(Σ_m W'_jm x^opp_m)
    = Σ_{i,m} W_ji W'_jm x^own_i x^opp_m    … (自玉, 駒) × (敵玉, 駒)
```

[ADR-0183](0183-stacked-pairwise-product.md)の棄却から制約を引き継ぐ。
**CONCATを広げない**。活性幅を1024から1536へ広げた0183は、非ゼロ
チャンク列挙の固定費だけでNPS−2.94%になり、質の増分ゼロと合わせて
−9.8で沈んだ。本ADRは掛け合わせの組だけを変え、活性幅・演算量・
メモリアクセスを現行と同一に保つ。

もうひとつの根拠は死んだ次元の観測である。現行の視点内512対のうち
51%はゼロ率0.95以上で、**視点内の枠は使い切られていない**。枠の半分を
視点間へ振り替えても、失う視点内の容量は見かけより小さい。

## 選択肢と比較

### 案A: 全部を視点間の積にする

1024対すべてを own×opp にする。仮説は最も純粋に測れるが、0171で
+65.4を実証した視点内（KPP相当）の項を全部捨てる。負けたときに
「視点間に価値がない」のか「視点内を失った」のか切り分けられない。

### 案B: 半々の折衷（採用）

視点内の対を256ずつ、視点間の対を512にする。accumulator 2048次元の
使用回数は各1回のままで、活性は現行と同じ1024次元。視点内の項を
半分残したまま、視点間の項の増分を測る。

### 案C: 視点間の対を追記して幅を広げる

0183の棄却理由（列挙の固定費）がそのまま当たる。取らない。

## Decision

**案Bを採る**。対の組み方は次のとおり（`S = FT_OUT / 2 = 512`、
`Q = S / 2 = 256`）。

| 活性 | 積 | 意味 |
|---|---|---|
| `concat[0..Q]` | `own[j] × own[j+S]`（j=0..Q） | 視点内（自）。KPP相当 |
| `concat[Q..2Q]` | `opp[j] × opp[j+S]`（j=0..Q） | 視点内（敵）。KPP相当 |
| `concat[2Q..3Q]` | `own[j+Q] × opp[j+S+Q]`（j=0..Q） | 視点間。KKPP相当 |
| `concat[3Q..4Q]` | `opp[j+Q] × own[j+S+Q]`（j=0..Q） | 視点間（逆向き） |

accumulatorと差分計算は変わらない。掛け合わせの相手が変わるだけで、
乗算の回数も活性の幅も現行と同一である。量子化は0171と同じ
（`(clip(a)*clip(b)+64) >> 7`、学習側に127/128）。

活性の並びが視点で分かれなくなるので、`clip_to_u8` は両視点のaccを
同時に受けて `CONCAT` 全体を書く形へ変える。手番視点が先という現行の
規約は保つ（own=手番）。

ファイル形式は版を分ける（版15〜18）。**w2の寸法は現行と同じ**なので、
版を分けないと視点内ネットを視点間ビルドが黙って読み、壊れた評価で
対局してしまう。寸法検査では防げない誤用を版で止める。

[ADR-0168](0168-ft-dim-reorder.md)の並べ替えは、視点内ブロックと
視点間ブロックの中でだけ動かせる。置換の単位はブロック内の対スロット
（各Q個）になる。makenetの検査で境界をまたぐ置換を弾く。

### 検証（0171・0183と同じ5段）

1. 機能検証。スカラーとSIMDの一致、Python側とRust側の評価値の一致
2. 3億局面（`train_300M_q1`）で学習する。現行と同条件で、違いは対の組だけ
3. NPS計測。ノード数固定・交互。**中立が見込みで、−1%を超えたら原因を調べる**
4. 3億ネット同士の直接対局。ノード数固定と時間制の両方
5. 通れば29.9億で本学習し、SPRT既定条件にかける

**valid lossで足切りしない**（[ADR-0158](0158-mirror-factorizer.md)）。

**撤退ライン**。3億の時間制で負けたら棄却する。ノード数固定が正で
時間制が負なら速度要因なので、原因（キャッシュの当たり方）を調べてから
判断する。棄却時は視点間ブロックへ繋がる `w2` 列のRMSを測り、
「使われなかった」のか「使われたが増分がない」のかを0183と同じ形で
記録する。

## Consequences

- ネットのファイルは版で分かれる。現行ネットはこのビルドで読めない
- 並べ替えの自由度がブロック内に制限される。全ゼロチャンク率の上限は
  わずかに下がりうる
- 案A（全視点間）は、案Bで視点間ブロックの重みが立ったときの後続実験
  として残る
- 手番の意味づけが変わる。視点間の積は「手番側から見た自玉×敵玉」の
  項なので、手番反転で値の変わる非対称性は視点内より強く出る可能性が
  ある。学習が吸収するかは測定で見る

## 測定（2026-08-23、3億の測定台）

0171と同条件（`train_300M_q1`、同一ハイパラ・seed 0）で学習し、
視点内1段の `pairprod_300M_q1` と突き合わせた。

| 段階 | 結果 |
|---|---|
| 学習 | valid loss 0.49249（視点内1段は0.49240。判断には使わない） |
| NPS（ノード数固定300万・8周・交互） | **+0.40%**（設計どおり中立） |
| 対局・ノード数固定30万 | 5,824局 **−9.2 [−18.0, −0.4]**、LLR −2.90で**H0** |
| 対局・時間制 10+0.1 | 6,000局 −6.9 [−15.6, +1.8]、LLR −2.40、上限で判定に至らず |

**棄却する。** 速度は狙いどおり中立だったが、ノード数固定で有意に
負けた。評価の質そのものが下がっている。

- **視点間の項は使われたが、増分を生まなかった**。視点間ブロックへ
  繋がる `w2` 列のRMSは視点内ブロックの0.86倍で、重みは立っている。
  0183と同じ「使われたが効かない」型である
- **視点内の対を半分失った損のほうが大きかった**。ゼロ率0.95以上の
  次元が51%という観測から「視点内の枠は使い切られていない」と読んだが、
  枠の半減は−9前後の実害になった。**ゼロ率の高い次元にも、まれに発火して
  効く項が残っている**と解釈する。死んだ次元の観測を容量削減の根拠に
  使うときは、この結果を思い出すこと

### 0183と合わせた結論

掛け算の組を変える2案（次数を上げる0183、範囲を広げる0184）はどちらも
「ネットは新しい項を使うが、対局の利得に変換されない」で沈んだ。
**視点内1段の対（0171の形）は、この機構の中では最適に近い**。積の線は
ここで一巡とし、構造の残りの手は活性の枠を変えないもの（死んだ次元の
回収・残差付きヘッド・出力バケット）へ移る。
