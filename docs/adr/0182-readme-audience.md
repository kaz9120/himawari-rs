# 0182: READMEの読み手を2つに固定し、変わり続ける事実を置かない

- Status: accepted
- Date: 2026-08-20
- 関連ADR: [0037](0037-nnue-file-format.md), [0053](0053-docs-structure.md), [0080](0080-net-release.md), [0180](0180-hmwr-cli-in-python.md), [0181](0181-agent-surface.md)

## Context

README.mdが実装から離れていた。2026-08-20に全文をコードとReleasesへ
突き合わせ、6件のずれを見つけた。

1件目は冒頭の要約である。「評価関数は29.9億局面で学習した純粋HalfKP
256x2-32-32」と書いてあるが、現行構成はFT1024・後段L1=16・FT出力の対の積で
ある。同じREADMEの下の節が既定を `1024x16x32` と書いており、1つの文書が
自分と矛盾していた。

2件目は取得コマンドである。`gh release download net-v4` を案内していたが、
配布中の最新は `net-v7` だった。世代が3つ離れており、形式の版も違う。

3件目は「使う」節の入口である。ソースからのビルドを指示していたが、
Windows・Linux・macOS向けに5種のPGOビルドをReleaseで配っている。対局に使う
だけの読み手へ、要らない工程を1つ課していた。

4件目は起動時の挙動である。「`EvalFile` を設定しないと起動時にエラーで
終了する」と書いてあるが、実測では駒割で起動して指す。終了するのはパスが
読めないときだけで、理由の出力先も標準エラーではなくUSIの `info string` で
ある。

5件目は教師データの所要容量で、116GBと120GBはDATASETS.mdの112GBと111GBに
合っていない。6件目はfloodgateのレート・ネットのファイル名・FT幅のEloで、
ROADMAP.mdとADRが持つ数値の写しだった。

**古びたのは、他に正のある事実だけである**。USIオプションの既定値・
workspace構成・ツール一覧・ライセンスはコードと一致していた。これらは
READMEが唯一の置き場か、変化が実装と同時に目に入る情報である。写しは、
元が動いても写した側が動かない。

## 選択肢と比較

### 案A: 記述を実態へ直す

6件を書き換えて終える。安い。ただし写しである構造は残るので、次にネットを
配った日に3件目以降が同じ形で古びる。ADR-0053がREADMEの持ち物を
「概要・ビルド・学習・対局の手順」と決めているだけで、置かない情報を
決めていないことが原因である。

### 案B: 読み手を固定し、変わり続ける事実を置かない

読み手を「対局に使う人」と「開発する人」の2つに固定する。棋力・ネットの
世代・Elo・既定の構成値のように変わり続ける事実は書かず、正の場所を指す。
リリースの番号は書かず、最新を選ぶ手順を書く。

写しが減るぶん、読み手はROADMAP.mdやReleasesへ1回移動する。

### 案C: CIでREADMEの数値を検査する

ネットの最新タグや `DEFAULT_ARCH` をREADMEと突き合わせるジョブを足す。
検査対象を機械で読める形に整える手間がかかり、文言の自由度も落ちる。
古びる事実を書かなければ検査するものがないので、案Bの下位互換になる。

## Decision

案Bを採る。READMEの規律を3つ置く。

### 読み手は2つ

冒頭で読み手を分岐させる。対局に使う人はReleasesの取得からGUIの設定までで
完結し、ビルドの節を読まなくてよい。開発する人は環境構築・ビルド・`hmwr`・
検査の順に読む。

### 変わり続ける事実は正の場所を指す

| 情報 | 正の場所 |
|---|---|
| 棋力（実戦レート） | floodgateの対局者ページ。URLは `hmwr/tools/floodgate.py` |
| 現行のネットと定跡 | `hmwr/config.py` の `EVAL_FILE`・`data/book/main.db` |
| 配布物の版 | Releases（番号ではなく「最新」を指す） |
| 既定のネットワーク次元 | `crates/engine/build.rs` の `DEFAULT_ARCH` |
| 測定値・判断の根拠 | docs/adr/ |
| 教師データの内訳 | docs/DATASETS.md |

2026-08-22追記: 当初は棋力と現行構成の正をROADMAP.mdに置いたが、
ROADMAP側も数値の写しを持たない方針にした。上の表はその後の正を示す。
ROADMAP.mdの「現在地」がこの表と同じポインタを持つ。

### ADRの番号を書かない

READMEの読み手はADRの番号で行動を変えない。対局に使う人には読む対象では
なく、開発する人はCLAUDE.mdとdocs/adr/README.mdから入る。15か所あった参照を
外し、動線は文書表の1行に集約した。判断の根拠を追う導線はこれで足りる。

範囲そのものはREADMEの先頭へHTMLコメントで残す。読み手には見えず、次に
書き換える者だけが読む。

## Consequences

古びる面が減る。今回直した6件のうち5件は、規律を守る限り再発しない。
残る1件（USIオプションの既定値）はコードと同時に目に入る情報で、写しでは
ない。

対局に使う読み手の工程が減った。ビルドの節を飛ばし、zipを解いて `EvalFile`
を設定すれば動く。ADR-0080が配布物へ与えた「これを使えば現行の棋力が出る」
という約束が、READMEの導線に載った。

棋力の数値がREADMEから消えた。初見の読み手はROADMAP.mdへ1回移動する。
リポジトリの顔として数値を見せる利点より、古いレートを掲げ続ける害を採った。

**別件を1つ見つけた**。`EvalFile` が未設定のとき、エンジンは駒割評価で起動
する。ADR-0037は「気づかず弱いまま対局する事故を防ぐ」ためにフォールバック
を禁じており、読み込み失敗の経路はそのとおり終了する。未設定の経路だけが
意図から外れている。READMEは実態を書いたうえで、修正をROADMAPの候補へ置いた。

見直すトリガーは2つある。配布物の構成が変わったとき（対象環境の増減、
ネットの同梱）と、開発の入口が `hmwr` から変わったときである。
