# 0170: 後段のL1を16へ半減する

- Status: accepted
- Date: 2026-08-16
- 関連ADR: [0127](0127-net-shape-bench.md), [0131](0131-frozen-ft-light-head.md), [0134](0134-head-capacity.md), [0159](0159-ft-width-1024.md), [0168](0168-ft-dim-reorder.md), [0169](0169-clip-nnz-fusion.md)

## Context

FT1024は時間制で互角（−0.1 [−8.7, +8.4]、6,000局）のまま採択した
（[ADR-0159](0159-ft-width-1024.md)）。**採択したが、勝ててはいない。**
H1（elo1=5）を超えるにはあと5 Elo要る。

速度側で残っているのは第1層である。プロファイルでは並べ替え後もなお
14.69%を占める。小細工の線は閉じており、活性の構築と非ゼロチャンクの
列挙を1パスにまとめる案は−0.25%だった（[ADR-0169](0169-clip-nnz-fusion.md)）。
**命令数やメモリ往復を削る改善は4件連続で外れている。** 残るのは
演算そのものを減らす方向になる。

`1024x16x32` は第1層の演算を半分にする。
[ADR-0131](0131-frozen-ft-light-head.md)がL1を32→16にしてもvalid lossは
0.0006しか動かないと実証しており、[ADR-0134](0134-head-capacity.md)も
「後段を太らせても精度は返らない」と結論している。

**2026-08-13のオーナー判断で保留していた。** Stockfishで実績のある後段の
形を保ちたい、速度は別の手で取り返す、という理由である。その別の手を
2つ測り、並べ替えが+13.19%（[ADR-0168](0168-ft-dim-reorder.md)）、融合が
0%だった。**残る取り先がここしかないため、2026-08-15のオーナー判断で
着手する。**

## 選択肢と比較

### 案A: L1を16へ半減する（`1024x16x32`）

第1層は `CONCAT × L1_OUT` の積和で、L1_OUTに比例する。半分にすれば
演算も半分になる。精度の中立は[ADR-0131](0131-frozen-ft-light-head.md)が
実証済みだが、FT256での結果なのでFT1024でも成り立つかは測って確かめる。

### 案B: 容量側で稼ぐ（死んだ次元を活かす）

[ADR-0168](0168-ft-dim-reorder.md)がFT1024の147次元（14.4%）は完全にゼロ、
513次元がゼロ率0.95以上と測っている。有効次元を増やせばノード効率で
採択ラインを超えられ、後段の形も保てる。ただし正則化・初期化・lrの
どれが効くかは読めず、1回の学習に13時間かかる試行錯誤になる。

### 案C: 現状維持

FT1024を互角のまま使い、教師データの増量を待つ。容量の効きはデータで
伸びる（3億で+58.1、29.9億で+70.6）ので、次の増量で自然に勝ち越す
可能性はある。ただし公開教師は使い切っており、増量は自前生成待ちである
（[ADR-0144](0144-selfplay-teacher-loop.md)）。

## Decision

**案Aを採る。** 見込みが数字で出せるのが決め手である。探索木を揃えた
比較（同じネットを16→32へ広げて評価値を一致させる）でL1半減は+3.9%
だった。[ADR-0159](0159-ft-width-1024.md)が更新した換算率3.12 Elo/%を
当てると**+12.2 Elo相当**で、互角の−0.1に乗ればH1に届く。

案Bは当たりが読めず、案Cは待ちになる。どちらも案Aの後に回せる。

**SPRTは既定条件で測る**（elo0=0、elo1=5）。精度が中立なら速度がそのまま
棋力になるので、棋力向上を主張する変更にあたる（[ADR-0163](0163-sprt-hypothesis-choice.md)）。

## 測定（2026-08-16）

### 精度は落ちなかった

29.9億局面で学習した（182,593ステップ、46,886秒）。教師も検証集合も
条件もすべて `ft1024_2990M_q1` と同じで、違うのはL1の幅だけである。

| step | `1024x32x32` | `1024x16x32` | 差 |
|---|---|---|---|
| 36000 | 0.49611 | 0.49560 | −0.00051 |
| 38000 | 0.49547 | 0.49508 | −0.00039 |
| 40000 | 0.49532 | 0.49505 | −0.00027 |
| **best** | **0.48915** | **0.48938** | **+0.00023** |

**差は初期値のばらつき（0.00136）より小さい。**
[ADR-0131](0131-frozen-ft-light-head.md)がFT256で得た0.0006と同じ水準で、
FT1024でも後段の幅は精度に効かないことを確かめた。

### 活性はさらに疎になった

[ADR-0168](0168-ft-dim-reorder.md)の手順で並べ替える（深さ25の探索から
12,500サンプル）。

| | `1024x32x32` | `1024x16x32` |
|---|---|---|
| 要素のゼロ率 | 0.7833 | **0.7990** |
| 独立仮定の全ゼロチャンク率 | 0.3765 | 0.4075 |
| 実測の全ゼロチャンク率 | 0.3716 | **0.4472** |
| 並べ替え後 | 0.6880 | **0.7129** |
| 第1層が回るチャンク | 159.7 / 512 | **147.0 / 512** |
| 完全にゼロの次元 | 147 | **218** |

**後段を狭めるとFTの出力はさらに死ぬ。** 完全にゼロの次元は147から218
（21.3%）へ増えた。並べ替え前の実測が独立仮定を上回る（0.4472 > 0.4075）
のも `1024x32x32` と違う点で、ゼロが同時に起きる方向へ相関が出ている。

**第1層のコストは2つの効果で下がる。** 回るチャンクが159.7→147.0
（−8.0%）で、1チャンクあたりの演算がL1_OUTに比例して半分になる。
合わせて0.46倍である。

### NPSは+2.46%だった

ノード数固定200万・6周・交互で測る。どちらも並べ替え済みのネットを使う。

| バイナリ | NPS（6周の平均） | 差 |
|---|---|---|
| `1024x32x32`（現行） | 1,601,172 | — |
| **`1024x16x32`** | **1,640,483** | **+2.46%** |

**着手前の見積もり（+3.9%）に届かない。** 見積もりは同じネットを16→32へ
広げて評価値を揃えた比較から出したもので、探索木が完全に一致する条件
だった。今回は別々に学習したネット同士なので、評価値が違えば探索木の
形も変わる。**第1層の演算を0.46倍にしても、NPSは2.5%しか動かない。**
[ADR-0169](0169-clip-nnz-fusion.md)と同じ構図で、削った演算の多くが
メモリ待ちに隠れている。

換算率3.12 Elo/%を当てると**+7.7 Elo相当**になる。互角（−0.1）に乗れば
H1（elo1=5）に届くが、余裕はない。

### SPRTはH1採択。見積もりの倍近く出た

| 項目 | 値 |
|---|---|
| 条件 | `--tc 10+0.1 --concurrency 8 --adjudicate 2000,8`、elo0=0、elo1=5 |
| 対局数 | 6,160（3,080ペア） |
| W-D-L | +3126 =146 -2888 |
| Elo [95%CI] | **+13.4 [+4.9, +21.9]** |
| LLR | +2.91 → **H1採択** |

3,000ペアの上限では LLR +2.80 で判定に至らなかった。条件を変えず
`--resume` で積み（[ADR-0087](0087-sprt-resume.md)）、80ペア足したところで
閾値を超えた。

**NPSからの見積もり（+7.7 Elo）を5.7上回っている。** 速度だけでは説明が
つかない。考えられるのは2つで、換算率3.12 Elo/%がまだ控えめであること、
後段を狭めたこと自体に速度以外の効きがあることである。**どちらかは
この測定では切り分けられない。** ノード数固定で測れば分かるが、
採択の判断には要らないので測っていない。

## Consequences

- **FT1024は初めて明確なプラスに立った。** [ADR-0159](0159-ft-width-1024.md)の
  採択時点では現行ネットと互角（−0.1）で、そこへ+13.4が乗る
- **後段の形はStockfishと違うものになった。** 2026-08-13に「実績のある形を
  保ちたい」として保留した判断を、測定で覆したことになる。参照実装の
  設計点が本エンジンで最適とは限らない例がまた1つ増えた
  （[ADR-0141](0141-singular-rate-calibration.md)・[ADR-0155](0155-reference-walkthrough.md)と同じ型）
- **削った演算の割に速度が伸びない傾向は続いている。** 第1層の演算を
  0.46倍にしてNPSは+2.46%だった。[ADR-0169](0169-clip-nnz-fusion.md)と
  合わせて、NNUE推論の律速がメモリ待ちであることの傍証になる
- **後段を狭めるとFT出力の死んだ次元が増える。** 147から218（21.3%）へ
  増えた。容量側の余地はむしろ広がっており、次の的になる
- ネットは128.4MBで `1024x32x32` とほぼ同じ。後段の重みは全体の
  0.05%に満たないので、L1を半減してもファイルサイズは変わらない
- **`1024x8x32` へさらに削る線が残る。** ただしL1_ACCSが2本になり、
  vdotの依存チェーンが詰まる。同じ比率で効くとは限らない
