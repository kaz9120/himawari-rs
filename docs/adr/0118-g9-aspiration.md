# 0118: 反復深化とaspirationを参照実装へ揃える（G9）

- Status: accepted
- Date: 2026-07-31
- 関連ADR: [0109](0109-reference-parity.md), [0059](0059-easy-move-scaling.md), [0062](0062-root-move-nodes.md), [0031](0031-lazy-smp.md), [0117](0117-g8-ponder.md), [0074](0074-feature-verification.md)

## Context

[ADR-0109](0109-reference-parity.md)の追従キャンペーンの第10群。反復深化と
aspirationを参照実装（やねうら王）へ揃える。

**この群にはMEMORY.mdが「次の本命」と記録していた問題が入る。** 初期窓が
`delta = 20` 固定で、評価値2800では±0.7%しかない。窓外れが1周で6.35回まで
増える（当時のRESULTS.md）。参照実装は評価値に応じて窓を広げる。

思考時間の伸縮も対象になる。現行は3係数（[ADR-0059](0059-easy-move-scaling.md)で
+69.3）だが、参照実装は5係数でgoをまたぐ記憶を使う。

## Decision

aspirationの窓・思考時間の伸縮・increaseDepthをまとめて入れる。

### 依存の棚卸し

実装の前に洗い出した。指示書が挙げた4点はすべて不足し、加えて1件が見つかった。

| 不足 | 対応 |
|---|---|
| `averageScore` / `meanSquaredScore` | `RootMove` へ追加 |
| goをまたぐ記憶4つ | `MainMemory` を新設。スレッドループがhistoryと同じ形で持ち回る |
| スレッド横断の `bestMoveChanges` | `Shared` の `AtomicU64` |
| `increaseDepth` | `Shared` の `AtomicBool` |
| **root探索ごとの安定ソート**（指示書外） | 参照実装はroot探索1回ごとに `stable_sort` する（S:1717） |

最後の1件は後述する。**指示書の範囲外だったが、この群で入れる係数の入力を
守る仕組みだった。**

### 入れたもの

| 項目 | 原典 | 変更点 |
|---|---|---|
| 初期窓 `5 + threadIdx%8 + \|二乗平均\|/9000` | S:1670-1673 | `delta = 20` 固定を廃止 |
| 窓の中心をaverageScoreへ | S:1671 | 前深さの生スコアから移動平均へ |
| fail lowで `beta = alpha` | S:1777-1784 | `(alpha+beta)/2` から |
| fail highで `alpha = max(beta−delta, alpha)` | S:1786-1790 | 新規 |
| 幅の伸びを4/3倍へ | S:1795 | 3/2倍から |
| failedHighCntで実効深さを削る | S:1705-1706 | 新規 |
| 思考時間5係数 | S:1958-1996 | [ADR-0059](0059-easy-move-scaling.md)の3係数を置換 |
| 合法手1手の502ms上限 | S:1995-1996 | 新規 |
| `effort` をgo全体の累計へ | search.h:129 | [ADR-0062](0062-root-move-nodes.md)は1周ごとに0へ戻していた |
| increaseDepth / searchAgainCounter | S:1600-1606, 2049-2051 | 新規 |
| root探索ごとの安定ソート | S:1717, 4113-4165 | 新規 |

`threadIdx%8` はLazy SMPの多様化で、参照実装が持つ唯一の明示的な多様化である
（[ADR-0031](0031-lazy-smp.md)は多様化しない案Bを選んでいた）。

### 番兵をそのまま移すのが正解だった

`meanSquaredScore` の初期値は `−VALUE_INFINITE²` である。これを窓幅の式へ
入れると `|mss|/9000` が118091になり、窓が全開になる。**深さ1でaspirationを
無効にする仕掛けである。**

0で初期化すると深さ1が幅5の窓になり、無駄な再探索が1回入る。現行が持っていた
「深さ5未満は窓を全開にする」というガードは、この番兵が同じ効果を出すので
撤去した。

### 指示書外で1件直した

**bestMoveInstabilityは、root探索1回ごとの安定ソートに守られていた。**

並べ替えがないと、窓を外した再探索のたびに同じ「入れ替わり」を数え直し、係数が
膨らむ。実測で平均2.46だった。並べ替えを入れると2.11に下がり、1手の消費時間が
306msから263msへ、実効深さが16.9から17.1へ動いた。

[ADR-0116](0116-g7-timeman.md)で「その値が何に守られているかを見る」と書いた
教訓が、そのまま当てはまった例である。

## 測定

### 窓外れ回数（この群の主目的）

固定深さ15、評価値の帯ごとに12局面ずつ計60局面。確定した反復1周あたりの
`lowerbound` / `upperbound` の出力回数である。

| 評価値の帯 | G8完了時点 | G9 | ノード数（12局面計） |
|---|---|---|---|
| \|score\|<300 | 2.46 | 5.39 | +4% |
| 300-800 | 2.71 | 4.54 | -21% |
| 800-1500 | 4.01 | **1.80** | -59% |
| 1500-2500 | 3.91 | **0.97** | -60% |
| 2500以上 | 4.09 | **0.40** | **-96%** |
| 合計 | 3.29 | 3.00 | **-88%** |

**MEMORY.mdの問題は解けた。** G8完了時点では評価値が大きいほど窓外れが単調に
増える（2.46→4.09）。G9では逆転して単調に減る（5.39→0.40）。

**2500以上の帯がノード全体の86%を食っていた。** そこが1/27になる。合計の
92,063,813から10,803,780への減少はほぼこの帯による。

低い帯では窓外れが増える。初期窓が20から5へ狭まるためである。ただしノード数は
増えていない。1回あたりの再探索が安くなるので相殺する。

### 思考時間の5係数

自己対局での平均は fallingEval 0.73、reduction 1.40、bestMoveInstability 2.24、
highBestMoveEffort 0.96 である。

深さ8未満とMultiPV>1で係数を適用しない条件（[ADR-0059](0059-easy-move-scaling.md)）は
捨てた。参照実装は深さで場合分けしない。

### increaseDepth

10+0.1相当の自己対局で、**反復の10.1%** で `increaseDepth` が下りた。

一度下りるとそのgo内では上がらない。経過時間は増える一方だからである。
結果として `searchAgainCounter` が終盤の反復で増え続け、**名目深さ19.93に対し
実効深さは17.11**（差2.83ply）になる。infoの `depth` は名目値なので、GUI表示の
深さが実際より深く出る。参照実装も同じである。

### 自己対局での対比

| | 手数 | 1手の平均時間 | 実効深さ | 時間切れ |
|---|---|---|---|---|
| G8完了時点 | 746 | 249ms | 14.22 | 0 |
| G9 | 752 | 263ms | **17.11** | 0 |

時間を5.6%多く使い、実効深さが2.9ply深くなる。

### 機能検証（ADR-0074）

深さ13、4局面。

| 局面 | G8 | G9 | 変化 |
|---|---|---|---|
| 1 | 17,436 | 23,407 | +34% |
| 2 | 61,457 | 51,978 | -15% |
| 3 | 113,459 | 175,168 | +54% |
| 4 | 26,657 | 19,248 | -28% |

4局面では増減が混ざる。名目深さ13の内訳が変わるためである。**窓が広がる方向と
窓外れが減る方向の差し引きは、60局面の合計（-88%）のほうが実態を表す。**

## SPRT

```
H1採択 | 1154局 | +614 =109 -431 | Elo +55.6 [+36.6,+74.8] | LLR +2.92
```

**+55.6 Eloで採択した。** 探索の群ではG2（+124.0）・G3（+95.2）・G1（+88.5）に
次ぐ。MEMORY.mdが「次の本命」と記録していた見立てが当たった。

### 条件

床を外す（`MinimumThinkingTime=1`・`RoundUpToFullSecond=false`）。既定の
2000は10+0.1で成立しない（[ADR-0116](0116-g7-timeman.md)）。[ADR-0117](0117-g8-ponder.md)が
300を選んだのは `set_search_end` の `t2` 項を残すためで、この群はponderを
使わないので `t2` は効かない。

`Threads` は既定の1で回す。`threadIdx%8` はThreads=1では常に0で多様化が効かない
が、この群の主効果（窓幅を評価値に比例させる、5係数、increaseDepth）はすべて
単スレッドで効く。多様化だけを測るなら採択後に `Threads=4` で追試する。

## Consequences

**MEMORY.mdの見立てが当たった。** 2026-07-29に「aspirationの窓外れ（評価値が
大きいほど再探索が増える）が次の本命」と記録していた。+55.6はその見立てを
裏づける。

**効いたのは評価値の大きい局面である。** 2500以上の帯でノードが1/27になる。
序盤の互角な局面ではむしろ窓外れが増えるが（2.46→5.39）、ノード数は増えない。
勝敗が決まる終盤で深く読めるようになったことが効いたと読める。

思考時間の5係数化で実効深さが2.9ply深くなった（14.22→17.11）。時間を5.6%多く
使うが、それ以上に深く読む。

**`increaseDepth` でinfoのdepthが名目値になった。** 名目19.93に対し実効17.11で、
GUI表示の深さが実際より深く出る。参照実装も同じ挙動なので揃えたが、floodgateの
棋譜を読むときはこの差を念頭に置く。

[ADR-0059](0059-easy-move-scaling.md)の3係数は置き換えた。+69.3を得た機能だが、
参照実装の5係数がそれを含む形で上回った。[ADR-0062](0062-root-move-nodes.md)の
`effort` も1周ごとの集計からgo全体の累計へ変えた。**追従が過去の採択を
上書きする2例目である**（1例目は[ADR-0115](0115-g6-qsearch.md)が
[ADR-0100](0100-movepick-argmax-simd.md)をsupersededにした件）。

`threadIdx%8` の多様化はThreads=1では効かない。既定が1なので、この群の+55.6に
多様化の寄与は含まれない。**多様化だけを測るなら `Threads=4` で追試する。**
[ADR-0031](0031-lazy-smp.md)が「多様化しない案B」を選んだ判断を見直す材料に
なる。
