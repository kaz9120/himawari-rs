# 0093: 1手詰め判定を探索へ組み込む

- Status: rejected
- Date: 2026-07-29
- 関連ADR: [0029](0029-mate-search.md), [0089](0089-improvement-criteria.md), [0074](0074-feature-verification.md)

## Context

[ADR-0029](0029-mate-search.md)で `mate_1ply` を実装した。テスト用の
オラクル（`mate_1ply_oracle`）まで揃っている。しかし探索から一度も
呼ばれていない。`crates/engine/src/mate.rs` に関数があるだけで、
`search.rs` からの参照がゼロである。

[IDEAS.md](../IDEAS.md)には「P3で+1.1（968局、駒割時代）で見送り」と
記録がある。当時は駒割評価で、探索も枝刈りがほとんど入っていなかった。
[ADR-0050](0050-singular-extension-retry.md)のsingular extensionが
P3の-16.0からP8で+12.6に反転した先例があり、NNUE後の再測定に意味がある。

[ADR-0089](0089-improvement-criteria.md)の軸3（終盤の正確さ）に乗る。
詰みの判定は評価関数を介さず勝敗が確定する。終盤は評価関数の精度が
落ちる領域で、探索で補う必要がある。

## 発動率の実測（2026-07-29）

着手の前に発動率を測った（[ADR-0074](0074-feature-verification.md)）。
実戦の棋譜から局面を取り、固定深さ13で「TTミスかつ非王手かつ非rootの
ノードで `mate_1ply` を呼び、詰みが見つかった割合」を数えた。

| 局面 | 呼び出し率 | ヒット率（呼び出し比） |
|---|---|---|
| 初期局面 | 68.6% | 0.0000% |
| 24手目（中盤） | 72.5% | 0.0396% |
| 60手目 | 67.8% | 0.3318% |
| 90手目 | 66.8% | 3.7853% |
| 110手目 | 72.1% | 13.9119% |

序盤・中盤ではほぼ発動しない。ADR-0074の基準（0.1%）を下回る。
一方で終盤は劇的に上がり、110手目では呼んだ7回に1回が詰みである。

**対局全体でならすと基準を上回る。** floodgateの負け11局はすべて
105手以上の長手数で（RESULTS.md）、終盤の局面数は無視できない。

呼び出し率が約70%と高い点が課題になる。TTミスのノードすべてで呼ぶため、
ヒットしない大多数のノードでもコストを払う。

## 選択肢と比較

### 案A: やねうら王と同じ条件（TTミス時のみ）で呼ぶ

```
非root・TTミス・非王手のノードで mate_1ply を呼ぶ。
詰みが見つかれば mate_in(ply + 1) を返し、TTへ下界として保存する。
```

TTミスに限るのは、詰みが見つかる局面は再訪されやすく、2度目以降は
TTから返せるためである。出典の条件をそのまま使う。

### 案B: 全ノードで呼ぶ

TTヒットしたノードでも呼ぶ。発見の機会は増えるが、TTに答えがある
ノードで重い判定を繰り返すことになる。

### 案C: 条件を絞ってコストを下げる

「持ち駒がある」「相手玉の周囲に自分の利きがある」「depthが小さい」
などを足し、呼び出し率を下げる。

条件の設計に根拠がない。やねうら王にもStockfishにもない条件を発明する
ことになり、[ADR-0074](0074-feature-verification.md)の「出典のスケール
前提を確かめる」から外れる。まず案Aで測り、NPSの損が効果を上回るなら
条件の追加を検討する。

## Decision

案Aを採る。

```
非root・TTミス・非王手のノードで mate_1ply を呼ぶ。
詰みが見つかれば mate_in(ply + 1) を返し、TTへ下界として保存する。
```

## 機能検証（2026-07-29）

### 序盤・中盤（`scripts/verify-feature.sh`、固定深さ13）

| 局面 | 変更前 | 変更後 | 変化 | 評価値 |
|---|---|---|---|---|
| 1 | 217,866 | 217,866 | +0% | 16 |
| 2 | 233,546 | 233,546 | +0% | -50 |
| 3 | 1,533,617 | 1,231,224 | -20% | 754 → 552 |
| 4 | 196,122 | 196,122 | +0% | -174 |

3局面が完全一致である。序盤・中盤では詰みが見つからず、探索が変わらない。
コストだけを払う区間になる。

### コスト（NPS、`go movetime 5000`）

呼び出しだけを行い詰みを返さない計測版で、純粋なコストの上限を測った。

| 局面 | 変更前 | 変更後 | 変化 |
|---|---|---|---|
| 初期局面 | 1,185,389 | 1,089,746 | -8.1% |
| 90手目 | 963,128 | 681,508 | -29.2% |

### 終盤（固定深さ13、実戦の棋譜から）

| 局面 | ノード数 | 時間 |
|---|---|---|
| 60手目 | 507,528 → 762,303（+50%） | 517ms → 939ms（**+82%**） |
| 90手目 | 535,125 → 344,980（-36%） | 528ms → 467ms（-12%） |
| 110手目 | 2,539,965 → 1,991,512（-22%） | 2,553ms → 2,716ms（+6%） |

ノード数は90手目以降で減る。ただし1ノードあたりのコストが上がるため、
深さ13へ到達する時間では3局面中2つが悪化した。60手目は+82%である。

**コストが効果を上回っている可能性が高い。** それでも発動率は基準を
満たすため、SPRTで測る。実測なしに棄却すると、
[ADR-0050](0050-singular-extension-retry.md)のような反転を見逃す。

## SPRT結果（2026-07-29、打ち切り）

494局（247ペア）で **-57.5 Elo [-90.1, -25.8]**、LLR -1.17。
W-D-L は +196 =21 -277（勝率41.4%）。判定に至る前に打ち切った。

打ち切りはオーナー判断である。CI上限が-25.8で0から離れており、H0側へ
倒れるのを待つ意味が薄かった。機能検証で見えていたコストがそのまま
出た形である。

## Decision（改訂）

**案Aを棄却する。** やねうら王と同じ条件（TTミス・非王手・非root）で
呼ぶと、コストが効果を上回る。

発動率そのものは終盤で13.9%に達し、[ADR-0074](0074-feature-verification.md)の
基準を大きく超えていた。効かなかったのは呼び出しコストである。探索1ノードが
約0.83us（NPS 1.2M）なのに対し、`mate_1ply` は1回1.5usかかる。TTミスの
約70%のノードで呼ぶ設計では、探索コストが倍増する。

やねうら王で同じ条件が成立するのは、あちらの `mate_1ply` が駒を動かさず
利きの計算だけで判定するためと見ている。本エンジンの実装は
[ADR-0029](0029-mate-search.md)で「候補手を実際に指して検証する」設計を
選んだ。誤検出がない代わりに1回のコストが高い。

再挑戦するなら、条件を絞るのではなく `mate_1ply` 自体を速くするところ
から始める。[ADR-0094](0094-mate1ply-speedup.md)で16%削ったが、
桁を変えるには指さずに判定する方式への書き換えが要る。

## Consequences

`mate_1ply` は探索から呼ばれないままになる。`mate.rs` の実装は
`tsume` ツールとテストからのみ使われる。

発動率が高くても効くとは限らない、という事例が残った。
[ADR-0074](0074-feature-verification.md)の発動率チェックは「動いて
いない機能をSPRTにかけない」ためのもので、「動いていれば効く」ことは
保証しない。コスト側の計測（NPSと到達時間）を併せて見る必要がある。

以下は棄却前に書いた見込みである。記録として残す。

`mate_1ply` が探索から使われるようになる。実装済みで未使用だった資産が
活きる。

終盤で詰みを1手早く見つける。反復深化の浅い周で詰みが確定すれば、
[ADR-0088](0088-mate-early-stop.md)の打ち切りが働いて残りの時間を
節約できる。両者は補完しあう。

序盤・中盤ではコストだけを払う。呼び出し率70%に対しヒット率0.04%以下で
ある。ここでNPSがどれだけ落ちるかが採否を分ける。
