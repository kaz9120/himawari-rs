# 0113: improvingの再定義とevalベース枝刈りを参照実装へ揃える（G4）

- Status: accepted
- Date: 2026-07-30
- 関連ADR: [0109](0109-reference-parity.md), [0112](0112-g3-pruning.md), [0111](0111-g2-lmr.md), [0096](0096-rfp-margin.md), [0075](0075-razoring-margin.md), [0052](0052-nmp-dynamic.md), [0074](0074-feature-verification.md)

## Context

[ADR-0109](0109-reference-parity.md)の追従キャンペーンの第5群。ムーブループへ
入る前の枝刈りと、その判断材料であるimprovingを揃える。

**improvingは5か所が同時に読む共有の判断材料である。** RFP・NMP・ProbCut・
LMP・`reduction()` である。定義を変えると5か所の挙動が同時に動くため、1か所
ずつ測れない。

本エンジンの定義は「王手中はfalse固定」だった。将棋は王手が続くので、連続王手の
後でimprovingが長くfalseに張り付き、枝刈りが一律に甘くなる。参照実装は王手中に
2手前の静的評価を写して連鎖を切らない。

この領域は過去に3件触って3件とも通っていない。[ADR-0075](0075-razoring-margin.md)は
razoringの深さ制限撤廃でマージンの向きを取り違えて棄却、
[ADR-0096](0096-rfp-margin.md)はRFPのマージン緩和で-139.4、
[ADR-0052](0052-nmp-dynamic.md)はNMPのR拡大が判定未了で保留のままだった。
いずれもimprovingの定義を触らずに数値だけ寄せている。

## Decision

improvingの定義と、それを読む枝刈りを一括で揃える。

### improvingの再定義

王手中は評価関数を呼ばず、2手前の静的評価を写す。improving自体は王手中false
のままだが、写した値が次の非王手ノードへ渡るので連鎖が切れない。非王手では
2手前との素の比較にする。NMPの後に `improving |= 静的評価 >= beta` で
再計算する。

improvingが真の割合は37.66%から50.51%へ上がった。王手中のノードは全体の
20.1%を占める。

opponentWorseningを足した。`静的評価 > -(1手前の静的評価)` で、RFPの
マージンに入る。

### 入れた枝刈り

| 項目 | 変更点 |
|---|---|
| razoring | 深さ上限3・マージン300固定から、上限なし・`alpha − 502 − 306×depth²` へ |
| RFP | 上限6から15未満へ。マージンをimproving・opponentWorsening・ttHit・correction値で動かす。返り値を `(2β+eval)/3` へ。`!ttPv` と「TT手なしまたはTT手が取る手」を追加 |
| NMP | cutNode限定、閾値 `β − 16×depth − 53×improving + 378`、R=`7+depth/3`、検証探索とnmpMinPly |
| IIR | `depth>=4 かつ TT手なし` から、followPV除外・allNode除外・`depth>=6`・1手前のreductionが3以下へ |
| ProbCut | 閾値 `β + 224 − 61×improving`、`depth>=3`、MovePickerのProbCut系統、返り値からマージンを戻す |
| 深さの事後補正 | 新規。1手前のreductionを子が読んで消す |
| alpha更新後の深さ短縮 | 新規。深さが2超14未満で決着スコアでないとき depth−2 |

`reduction` フィールドはG2で足してあり、読む側がこの群にあたる。読む側が
値を消す順序も参照実装のとおりで、これによりLMR後の再探索は補正を受けない。

ProbCutはMovePickerのProbCut系統を新設した。閾値以上のSEEを持つ取る手だけを
返す形で、capture historyがオーダリングに入る。G1でMovePickerを作り直した
ときにこの系統は入れていなかった。

### 原典の読み取りで判断した5件

**cutNodeの深さ引き下げは実装しない。** ADR-0109の付録はS:3341を挙げていたが、
このブロックは `#if OLD_CODE` の中にあり、`OLD_CODE` はリポジトリ内で一度も
定義されていない。無効化されたコードである。式も付録の「depth−2」ではなく
`depth −= 1 + !ttMove` だった。再現が目標なので入れていない。

**NMPの検証探索は同じ深さではなく `depth − R` である。** 原典の日本語コメントが
「同じ深さで探索しなおして」と書いているが、コードは `depth − R` を渡す。
コードに従った。

**razoringとRFPが読むのは `eval` で、静的評価そのものではない。** `eval` は
TTの値がより良い見積りなら置き換わる（S:3084-3087）。ADR-0109の付録にこの
項目がなく、G6の「stand patのTT値上書き」だけを載せていた。条件式を値ごと
移すには必須なのでこの群で入れた。

**RFPには `!ttPv` と「TT手なしまたはTT手が取る手」の2条件がある。**
[ADR-0096](0096-rfp-margin.md)は「やねうら王の76×depthは `!ttPv` という安全弁と
組で成立している」と書いていたが、条件はもう1つあった。`!is_pv` は原典にない
（ttPvがPVノードで真になるため不要）。

**razoring・RFP・ProbCutの除外手ガードは原典にない。** NMPだけが持つ。
外した。

## 機能検証（ADR-0074）

深さ13、4局面。基準はG3完了時点である。

| 局面 | G3 | G4 | 変化 |
|---|---|---|---|
| 1 | 59,635 | 25,459 | -57% |
| 2 | 149,740 | 141,293 | -6% |
| 3 | 169,246 | 118,942 | -30% |
| 4 | 83,122 | 68,114 | -18% |

4局面すべてで減った。深さ19では4,983,347から2,846,975へ減り（-43%）、
到達時間は3,262msから2,051msへ縮んだ（-37%）。

### 発動率

| 枝刈り | 判定 | 発動 | 発動率 |
|---|---|---|---|
| razoring | 240,845 | 5,377 | 2.23% |
| RFP | 235,468 | 137,902 | 58.6% |
| NMPのnull探索 | 97,566 | 4,426 | 4.54% |
| NMPカット | 4,426 | 1,896 | 判定比1.94% |
| **NMPの検証探索** | 1,896 | **0** | **0%** |
| 深さ事後補正（+1） | 240,845 | 8,750 | 3.63% |
| 深さ事後補正（−1） | 240,845 | 26,260 | 10.90% |
| IIR | 95,670 | 6,503 | 6.80% |
| ProbCutカット | 25,188 | 12,631 | 50.1% |
| alpha更新後のdepth−2 | 888 | 511 | 全ノード比0.17% |

RFPの58.6%は高いが原典どおりである。improvingが真だとマージンが浅い深さで
負になり、`eval >= beta` だけで刈る式になる。

**基準の0.1%を下回るのはNMPの検証探索だけである。** 深さ16以上が条件なので
深さ13では一度も届かない。深さ19で74回（NMPヒットの4.2%、全ノードの0.025%）、
深さ22で608回（5.2%）と、深さを上げると発動する。群として入れる方針に従い、
これを理由に外していない。

### G3の制限が解けた

[ADR-0112](0112-g3-pruning.md)で入れた取る手のfutilityは、王手中に静的評価が
`VALUE_NONE` だと発動しなかった。王手中に値を写したことで、判定1,119回のうち
116回（10.4%）発動するようになった。

### NPS

同一実行での比較で1,528,875から1,388,090へ落ちた（-9.2%）。到達時間は縮んで
いるため、ノード効率の改善が速度低下を上回っている。

[ADR-0112](0112-g3-pruning.md)に記録した1,646,581は別セッションの値で、同じ
機体でも数%動く。**NPSの比較は同一実行内で行う。**

## SPRT

既定条件（10+0.1、elo0=0、elo1=5、α=β=0.05）でG3完了時点のバイナリと比べた。

```
H1採択 | 1672局 | +876 =117 -679 | Elo +41.1 [+25.2,+57.3] | LLR +2.95
```

**+41.1 Eloで採択した。** 追従の4群では最も小さく、判定に1,672局を要した。
G1が762局、G2が508局、G3が718局だったのに対し2倍以上である。効果量が小さい
ほど必要な局数は増える。

**過去に3件通らなかった領域が、improvingの定義ごと揃えると通った。**
[ADR-0075](0075-razoring-margin.md)・[ADR-0096](0096-rfp-margin.md)・
[ADR-0052](0052-nmp-dynamic.md)はいずれもimprovingを触らずに数値だけを
寄せていた。

ただし効果量は他の群より小さい。RFPの発動率58.6%が刈りすぎに寄っている
可能性は残る。切り分けは行っていない。採択された変更を分解して測る価値が
あるかは、追従が一巡してから判断する。

## Consequences

improvingが将棋の性質に合った定義になった。王手中に連鎖が切れないため、
連続王手の後でも枝刈りの強度が保たれる。**チェス由来の実装をそのまま持ってきた
ときに差が出やすい箇所だった。**

過去に3件通らなかった領域（razoring・RFP・NMP）を、improvingの定義ごと揃えた
状態で測ることになる。個別の数値だけを寄せた過去の試みと違い、条件式も判断材料も
同時に移している。

RFPの発動率が58.6%と高い。参照実装どおりだが、本エンジンの評価関数の分布が
参照実装と違えば刈りすぎになりうる。**この群が不採択なら、まずRFPを切り分けて
測る。**

`#if OLD_CODE` で無効化されたコードをADR-0109の付録に載せていた。付録は
2026-07-30の棚卸しで作ったもので、有効・無効の区別をしていない。**残りの群でも
同じ取り違えがありうる。** 実装のたびに原典で確かめる。
