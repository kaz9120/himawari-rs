# 0171: FT出力の対を掛けて駒対の相互作用を入れる

- Status: proposed
- Date: 2026-08-16
- 関連ADR: [0034](0034-nnue-architecture.md), [0036](0036-nnue-quantization-simd.md), [0066](0066-halfkp-factorizer.md), [0127](0127-net-shape-bench.md), [0138](0138-ft-i8-quantization.md), [0157](0157-king-mirror-buckets.md), [0158](0158-mirror-factorizer.md), [0168](0168-ft-dim-reorder.md), [0170](0170-l1-half.md)

## Context

**HalfKPは駒と駒の相互作用を持たない。** 特徴は(玉, 駒)の対までで、盤上の
2駒がどう関係するかはFTに入らない。KPP時代に別項で持っていた情報である。

現行ネットのFT重みを分解すると、表の構造が見える（出力128次元、盤上の
玉81 × 駒-升1458 の直交分解）。

| 成分 | 説明する割合 |
|---|---|
| 駒単独 P | 90.77% |
| 玉単独 K | 0.41% |
| 交互作用 KP | 8.82% |

**125,388行の表の91%は1,548行の表である。**残る8.82%を持つために81倍の
行数を払っている。同じやり方で駒対を持とうとすると、表は 81 × 1548 × 1548 に
なり、`FT_OUT=1024` のi8で約200GBになる。**入力側の直積では駒対を持てない。**

掛け算をする場所を入力から出力へ移すと、この壁を回避できる。片視点のFT出力を
2つに割って要素ごとに掛けると、展開はこうなる。

```
y_j = (Σ_i W_ji x_i)(Σ_m W'_jm x_m) = Σ_{i,m} W_ji W'_jm x_i x_m
```

**係数 W_ji·W'_jm が駒対の表の低ランク分解になっている。**KPPの表を明示的に
持たずに、内積で近似する形である。Stockfishが2022年のSFNNv5で入れた
`pairwise multiplication` と同じ構造になる。

### 差分計算は壊れない

積を取る場所はaccumulatorの後である。`clip_to_u8` がi16のaccumulatorを
u8の活性へ落としている1手順を置き換えるだけで、**accumulatorの差分更新は
1行も変わらない。**

per-nodeのコストはむしろ減る。`CONCAT` が2048から1024になるので、第1層の
重みも `find_nnz` の走査も半分になる。今の `clip_to_u8` が2048レーンを
舐めているのに対し、積は1024回の乗算で済む。

## 選択肢と比較

### 案A: 現状維持

駒対は後段のMLPに任せる。ただし後段は `CONCAT → 16 → 32 → 1` で、
[ADR-0170](0170-l1-half.md)で第1層を16へ半減したばかりである。**1024次元の
要約から駒対を復元する余地は最も小さい。**

### 案B: 入力をKPPの直積にする

表が200GBになる。玉を落としたPP対だけでも1.2GBで、活性の対が703本
（38枚から2枚を選ぶ組合せ）あるので、差分1手で148行を叩く。現行は
2〜4行×1KBの連続読みなので、桁で重くなる。**メモリ待ちが律速という観測が
4件続いている以上、この方向は取れない。**

### 案C: 出力側で対の積を取る

`FT_OUT` は1024のまま、片視点の活性を512+512に割って掛ける。片視点の出力は
512次元になり、`CONCAT` は1024になる。

- accumulatorと差分計算は変わらない
- 第1層の入力が半分になり、速度は上がる方向に働く
- 駒対だけでなく玉と駒の相互作用も低ランクで入る
- 表のサイズは128MBのまま変わらない

### 案D: 入力を81+1548のマルチホットにして積を取る

玉と駒を直積にせず、1,629次元のマルチホットにする。表は 1629 × 1024 で
1.7MBになり、L2に全部載る。**メモリ待ちが律速という前提が消える。**

ただしパラメータが128Mから1.7Mへ、75分の1になる。ランクが足りることと
表現力が足りることは別で、賭けの幅が大きい。

## Decision

**案Cを採る。**

決め手は、accumulatorを1行も変えずに測れることである。案Dは同じ積の機構を
使うが、表を75分の1にする賭けが同時に乗る。案Cで積の効果を先に確かめれば、
案Dは「表を小さくして速度を取る」だけの実験に分解できる。**同時に2つ動かすと、
勝っても負けても原因が分からない。**

### 実装

対の組み方は j と j + `FT_OUT`/2 にする（Stockfishと同じ）。

積の値域を合わせる。学習側の活性は0〜1、推論側は0〜127である。
`(A * B) >> 7` の最大は 127×127/128 = 126.0 で、127にならない。**この
127/128を学習側の積へ掛けておく。**そうすれば量子化の係数（活性127、
隠れ層64）を1つも変えずに済む。後段のスケールへ波及させない。

`CONCAT` の定義を `FT_OUT * 2` から `FT_OUT` へ変える。片視点あたりの
連結幅を `HALF = CONCAT / 2` として、視点でスライスしていた箇所を置き換える。

| 場所 | 中身 |
|---|---|
| `engine/nnue.rs` | `CONCAT`・`HALF` の定義、`evaluate_scalar` の活性構築 |
| `engine/nnue_simd.rs` | `clip_to_u8` を積の形へ。`FT_OUT` レーンを読んで `FT_OUT`/2 個書く |
| `engine/nnue_acc.rs` | 視点のスライスを `HALF` 基準へ |
| `engine/nnue_io.rs` | ファイル版を分ける。`w2` の長さが変わるため |
| `training/model.py` | `CONCAT`、`transform_both` の積 |

**ビルド時フラグは作らない。**[ADR-0157](0157-king-mirror-buckets.md)と同じく、
このブランチを積ありの唯一の実装にする。積なしとの比較は、mainのビルドと
ブランチのビルドを並べて行う（[ADR-0127](0127-net-shape-bench.md)の手順）。

ファイル形式は寸法が同じまま `w2` の長さだけ変わるので、版を分ける。分けないと
既存ネットを読んだときのエラーが「末尾に余分なバイトがある」になり、原因が
読めない。

### 検証

**valid lossで足切りしない**（[ADR-0158](0158-mirror-factorizer.md)）。`CONCAT` が
変わると `l2.weight` の形が変わり、乱数の消費順序がずれる。以降の層の初期値が
すべて違うので、0.001〜0.002規模の差は初期値のばらつきと区別がつかない。

1. 機能検証。スカラーとSIMDの一致、Python側とRust側の評価値の一致
2. 3億局面（`train_300M_q1`）で学習する。mainと同条件で、違いは積だけにする
3. NPS計測。ノード数固定300万・8周・交互（[ADR-0157](0157-king-mirror-buckets.md)と同じ手順）
4. 3億ネット同士の直接対局。**時間制とノード数固定の両方を測る。**時間制で
   効果を、ノード数固定で評価の質を切り分ける
5. 通れば29.9億で本学習し、あらためてSPRT既定条件にかける

**撤退ライン。**3億の時間制で負けたら棄却する。ノード数固定で勝って時間制で
負けた場合は、速度の代償ではなく評価の質が足りていないことになる
（積は速度を上げる方向なので、[ADR-0127](0127-net-shape-bench.md)の
「精度は上がるが速度で潰れる」構図にはならない）。

### 積の導入と第1層の入力半減は同時に起きる

案Cは `CONCAT` を2048から1024へ半減させる。効果の切り分けはできない。

**切り分けないことを選ぶ。**分けるには `FT_OUT` を2048にして活性1024を
保つしかないが、表が256MBになり差分計算のバイト数が倍になる。速度で潰れる
見込みが高く、測る価値がない。**「積を入れて第1層の入力が半分になった構成が、
今より強いか」が実務上の問いである。**

## Consequences

- ネットのファイルに互換がなくなる。既存ネットはこのビルドで読めない
- [ADR-0168](0168-ft-dim-reorder.md)の並べ替えは、対を壊さない単位で行う必要が
  ある。次元jを動かすときはj + `FT_OUT`/2 も一緒に動かす
- 死んだ次元の意味が変わる。**片側がゼロなら積もゼロになる。**現行で218次元が
  死んでいるので、対の相手を道連れにする分だけ有効次元が減りうる。学習し直すので
  同じ配置にはならないが、学習後に死んだ対の数を数える
- 積の疎さは第1層の空回りを減らす方向にも働く。ゼロ率0.95以上が583次元ある
  現状の傾向が続けば、[ADR-0168](0168-ft-dim-reorder.md)の経路がさらに効く
- 案D（入力を1,629次元のマルチホットにする）が測れる形で残る。案Cが通れば、
  次は表を75分の1にする実験になる
