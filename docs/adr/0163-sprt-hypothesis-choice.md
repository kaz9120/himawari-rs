# 0163: 変更の性質でSPRTの対立仮説を着手時に決める

- Status: accepted
- Date: 2026-08-15
- 関連ADR: [0028](0028-pruning-extensions.md), [0068](0068-sprt-driven-versioning.md), [0087](0087-sprt-resume.md), [0109](0109-reference-parity.md), [0116](0116-g7-timeman.md), [0154](0154-sprt-ops.md), [0162](0162-parallel-group.md)

## Context

既定の検定条件は `elo0=0, elo1=5` で、「5 Elo以上の改善があるか」を問う。
この条件は**真の効果がelo0とelo1の間にあると判定を出さない**。SPRTの性質で
あって、局数を積めば解決する話ではない。

[ADR-0162](0162-parallel-group.md)で実測した。

| ペア | Elo | LLR |
|---|---|---|
| 400 | +30.9 | +1.04 |
| 1200 | +15.1 | +1.36 |
| 2000 | +8.9 | +1.14 |
| 2197 | +8.9 [−0.9, +18.8] | +1.27 |

点推定は+8.9で正側だが、LLRは1200ペア以降ほぼ動かない。既定条件のまま
判定（+2.94）へ届かせるには5000ペア規模、`Threads=4` の測定速度（190ペア/時）で
15時間かかる。

**同じ棋譜を非劣性（`elo0=-5, elo1=0`）で評価し直すとLLRは+2.26だった**。
追加対局はゼロである。残り約660ペア、3.5時間で判定が出る位置にある。

### 条件を後から変えている

問題は条件の選び方ではなく、選ぶ時期にある。

- [ADR-0116](0116-g7-timeman.md)のG7は3回測り、3回目に非劣性へ落とした
- [ADR-0162](0162-parallel-group.md)は既定で2197ペア回したあと、判定が出ないと
  分かってから非劣性で評価し直した

**同じ棋譜に対して、後から有利な対立仮説を選ぶのは検定の水準を保証しない**。
α=0.05は「1つの仮説を1回検定する」前提の値である。走らせてから仮説を選べば、
実際の第一種過誤はそれより大きくなる。

いまは前例が2件で、どちらも「効果が小さいと分かってから緩めた」形である。
この運用が既定になると、H0で終わるべき変更が非劣性で通り続ける。

## 選択肢と比較

### 案A: 着手時に検定条件を決め、走行後に変えない

変更の性質から条件を選び、ADRへ書いてから回す。判定が出なければ、その条件の
ままの結果として記録する。

### 案B: 既定を非劣性へ寄せる

`elo0=-5, elo1=0` を既定にすると判定は速く出る。ただし「悪化していない」しか
言えない変更が積み上がる。5 Elo刻みで前進しているかを追えなくなる。

### 案C: 現状のまま、必要に応じてその場で判断する

前例2件と同じ運用を続ける。判断のたびに根拠を書く手間が残り、上に書いた
水準の問題も残る。

## Decision

**案Aを採る。着手時に検定条件を決め、ADRへ書いてから回す**。

| 変更の性質 | elo0 | elo1 | 例 |
|---|---|---|---|
| 棋力向上を主張する | 0 | 5 | 新しい枝刈り、評価関数の入れ替え、探索定数の変更 |
| 参照追従・構造整列で「害がなければ入れたい」 | −5 | 0 | [ADR-0116](0116-g7-timeman.md)のG7、[ADR-0162](0162-parallel-group.md) |
| 既定条件では機能しない | 条件を変え、なぜ既定で測れないかをADRへ書く（既存の規約） | | 並列専用、時間管理 |

**2行目を選ぶ条件を明示する**。次の3つをすべて満たすときに限る。

1. 参照実装に対応物があり、構造を揃えること自体に価値がある
2. 棋力の向上をコミットメッセージでもCHANGELOGでも主張しない
3. 無害性をSPRT以外の実測でも裏づけている（機能検証、発動率、コストの計測）

3つ目は[ADR-0116](0116-g7-timeman.md)がG7で行った裏づけと同じ水準を求める。
SPRTが「悪化していない」しか示さないぶん、別の観点からの実測で補う。

### 走行後に条件を変えたくなったら

**変えてよい。ただし新しい棋譜で測り直す**。既存の棋譜を流用して仮説だけ
差し替えると、上に書いた水準の問題が出る。

例外は、**着手時の判断が誤っていたと分かった場合**である。その場合は誤りの
中身をADRへ書き、条件を選び直して測り直す。「判定が出ないから緩める」は
理由にならない。

### 非劣性で採択した変更の記録

コミットは `feat` とし、**件名にEloを入れない**。
[ADR-0116](0116-g7-timeman.md)のG7が前例で、
`feat: 停止を予約する構造へ移し最小思考時間を入れる（G7、ADR-0116）` である。
棋力向上を主張しないので、CHANGELOGにも数値が載らない。

`SPRT:` トレーラには非劣性であることを書く。

```
SPRT: +8.9 [-0.9,+18.8] 5000games H1（非劣性 elo0=-5 elo1=0）
```

書式は[CLAUDE.md](../../CLAUDE.md)の
`SPRT: <Elo> [<CI下限>,<CI上限>] <対局数>games <H0|H1>` を拡張する形になる。
既定条件の走行では末尾の括弧を付けない。

## Consequences

- **判定までの時間が変わる**。[ADR-0162](0162-parallel-group.md)の例では15時間が
  3.5時間になる。参照追従が主戦場である以上、この差は積み上がる
- 「5 Elo以上あるか」を問わない変更が増える。**前進の測り方が2系統になる**。
  棋力の前進はfloodgateのレートと、既定条件で採択した変更のEloで追う
- 着手時に性質を判断する手間が増える。迷う変更は既定（1行目）へ倒す。
  緩いほうへ倒すと、上に書いた水準の問題がそのまま出る
- **本ADR以前の2件（G7・ADR-0162）は、走行後に条件を変えた形のまま残る**。
  遡って測り直さない。前例として引くときは、条件を後から変えた経緯も
  一緒に読む必要がある
- 判定に至らない走行は、[ADR-0087](0087-sprt-resume.md)の `--resume` で続けられる。
  上限で捨てる必要はない。**条件を変えずに局数を積むのが正しい対処である**。
  [ADR-0175](0175-sprt-until-decision.md)で `sprt-run.sh` が判定まで走るように
  なり、この積み増しは自動になった

## 補足: 収束の速さと点推定の読み方（2026-08-18追記）

対立仮説の選択は判定の基準を決めるだけでなく、**収束の向きと速さも決める**。
GSPRTの正規近似（`sprt.rs:67`）でLLRのドリフトの符号を決めるのは
`2·mean − s0 − s1` で、真のEloが `elo0` と `elo1` の**中点**より上か下かに
なる。中点は既定条件で約+2.5、非劣性で約−2.5である。

[ADR-0173](0173-knight-non-promotion-movegen.md)の実測からペアあたり分散を
逆算すると var ≈ 0.118 で、必要局数はこうなる。

| 真のElo | 既定条件 | 非劣性 |
|---|---|---|
| 0 | H0側へ収束 | 26,879局 |
| +3 | 134,359局 | 12,217局 |
| +5 | 26,879局 | 8,960局 |
| +11.2 | 7,727局 | — |

**真のEloが中点に近いほど遅い**。「非劣性のほうが速い」のではなく、中立な
変更（真のElo=0）が非劣性の中点より上にあるから速く見えるだけである。
真のEloが+11.2なら既定条件のほうが速い。

**SPRTが保証するのは「真のEloが中点より上か下か」だけで、点推定の精度では
ない**。逐次検定は閾値を超えた瞬間に止まるので、上振れしたタイミングで
停止しやすく、**H1採択時の点推定は真値より高めに偏る**。早く決着した走行
ほどCIも広い。ADR-0173の「+11.2」は「+2.5より確実に上で、点推定は+11.2」と
読むのが正しい。

換算率のような精度の要る数値（[ADR-0171](0171-ft-pairwise-product.md)の
「速度1%あたり3.12 Elo」など）は、SPRTではなく局数を固定した測定で求める。
逐次停止しなければこのバイアスは入らない。

## 追記（2026-08-29）: ゲート用途は上限を宣言して打ち切ってよい

世代ループの検収（[ADR-0188](0188-selfplay-rl-loop.md)）のように、
**H1が出たときだけ採択する**走行には、判定を待たない打ち切りを認める。
着手時にペア数の上限を宣言し（`--max-pairs`）、上限で判定が出なければ
「見送り」として記録する。

これが安全なのは採択の向きが片側だからである。打ち切って見送っても
誤採択率αは増えない。失うのは検出力β（本当は良い変更を見逃す確率）
だけで、それは待ち時間と引き換えに払うと決めてよいコストになる。
実例では、真のEloが中点近傍の走行を6,542局まで積んでも判定が出ず、
3,000ペアで見切っても結論は同じだった（ADR-0188の世代2・2b）。

**棋力向上を主張する走行には適用しない**。主張にはH1の判定そのものが
要るので、従来どおり判定まで走らせる（[ADR-0175](0175-sprt-until-decision.md)）。
