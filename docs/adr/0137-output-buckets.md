# 0137: 出力層を盤上駒数バケットで分岐する（output bucket）

- Status: proposed（機構は残すが、分岐の指標を決め直す。下の「指標を決め直す」）
- Date: 2026-08-04
- 関連ADR: [0034](0034-nnue-architecture.md), [0036](0036-nnue-quantization-simd.md), [0037](0037-nnue-file-format.md), [0067](0067-ft-dimension-512.md), [0127](0127-net-shape-bench.md), [0128](0128-round-robin-league.md)

## Context

SF系NNUEは局面フェーズごとに出力層を分岐し（8バケット）、大きな効果を
得ている。序盤の駒得と終盤の駒得は価値が違うのに、単一ヘッドは1つの
写像で両方を近似しなければならない。バケット分岐はこの負担を層の複製で
解消する。

[ADR-0067](0067-ft-dimension-512.md)はこれを案Cとして検討し、
「将棋は取った駒が持ち駒になり総数が減らない」として見送った。
ただし塞がれたのは**指標**であって、機構ではない。SF系の
`(駒数-1)/4` をそのまま使えないだけで、将棋にも進行とともに単調に動く
量はある。

後段の容量を一様に増やす道は[ADR-0134](0134-head-capacity.md)で塞がった
（最良で−0.0007）。バケットは同じパラメータ増でも質が違う。**計算量を
増やさずに、局面に応じて使うパラメータを切り替える**。一様な拡大が
効かなくても、条件分岐が効く余地は残っている。

## 選択肢と比較

分岐の指標を3案比べる。

### 案A: 盤上駒数（持ち駒を除く）

将棋でも盤上の駒は取り合いで持ち駒へ移り、進行とともに減る傾向を持つ。
差分管理が軽く（駒を取った時だけ変わる）、探索中の任意局面で定義できる。
打ち込みで戻る非単調性はあるが、バケットは順序を仮定しないので害はない。

### 案B: 手数（game_ply）

単調だが、探索木の中の局面では「rootの手数+深さ」となり、同一局面が
到達経路で違うバケットに落ちる。置換表・評価キャッシュと相性が悪い。

### 案C: 玉の段（入玉度）や持ち駒枚数

情報としては面白いが、分布が偏る（大半の局面で玉は自陣）。
バケット間の学習データ量が不均衡になる。

## 指標を決め直す（2026-09-03）

**案Aは採らない**。オーナー指摘で、駒の数は将棋において進行度の指標として
弱いと分かった（2026-09-03）。分岐の機構そのものは残すが、何で分けるかを
設計し直す。

### 測ってみると範囲が狭い

`psv stats` へ盤上駒数の分布を足して測った（`train_300M_q1.psv` の先頭
20万局面）。四分位は30枚・33枚・36枚で、4バケットへほぼ均等に割れる。

| 駒数 | 割合 | 累積 |
|---|---|---|
| 〜29枚 | 21.6% | 21.6% |
| 30〜32枚 | 26.6% | 48.2% |
| 33〜35枚 | 25.7% | 73.9% |
| 36〜40枚 | 26.1% | 100.0% |

**均等に割れることと、指標として意味があることは別である**。範囲は実質
20〜40枚で、20枚以下は0.2%しかない。チェスの32枚から2枚までと違い、将棋は
取った駒が持ち駒へ移るので盤上が減りにくい。バケットの境界が3枚刻みになり、
その差が評価の写像を変えるほどの意味を持つとは言えない。

[ADR-0067](0067-ft-dimension-512.md)が「取った駒が持ち駒になり総数が減らない」
として見送った判断は、この分布に裏づけられている。本ADRのContextは「塞がれた
のは指標であって機構ではない」と書いたが、**代わりの指標を用意しないまま
案Aへ進もうとしていた**。

### チェスの先行研究が示す形

チェスでは局面を序盤・中盤・終盤に分けて専用のネットを使い、+122 Eloを
得た報告がある。出典は
[Checkmating One, by Using Many](https://arxiv.org/abs/2401.16852)（2024年、
2026-09-03オーナー共有）。分類はLichessの定義で、ニューラルネットを
使わない簡単な計算になる。

```
終盤: KingとPawn以外の駒の合計が6個以下
中盤: 終盤でなく、次のいずれかを満たす
  1. KingとPawn以外の駒の合計が10個以下
  2. 少なくとも一方のbackrankがスパース
     （1ランクか8ランクで、kingを含めて4未満）
  3. 混合度が150より大きい
     （白と黒の駒がどのくらい近いか。2×2の升ごとに数え、全升で合計）
序盤: それ以外
```

実装は[scalachess](https://github.com/lichess-org/scalachess/blob/master/core/src/main/scala/Divider.scala)にある。

**この定義が示すのは、駒数だけでは足りないということである**。3つの条件の
うち2つは盤面の形（backrankのスパース性、駒の交錯度）を見ている。同報告は
「単に手数で分類するとほぼ強くならないか弱くなる」とも記録しており、本ADRの
案Bを否定する材料にもなる。

### 将棋へ写すときの論点

将棋の進行は、駒の総数ではなく盤面の状況で決まる（2026-09-03オーナー）。

- 序盤は、駒がぶつかって開戦するまで。ただし角換わりや横歩取りは早い段階で
  駒がぶつかるので、「本格的に駒がぶつかったタイミング」をどう測るかが難しい
- 中盤は、開戦してから詰むや詰まざるやになるまで
- 終盤は、詰みや入玉を考えるタイミング

Lichessの3条件を将棋へ写すなら、次が候補になる。

1. 混合度はそのまま使える。むしろ将棋のほうが自然で、開戦すると敵味方の
   駒が交錯する。2×2の升ごとに先手・後手の駒を数える形は盤の大きさに依らない
2. backrankのスパース性は自陣（1〜3段）の駒の密度へ写せる。囲いが崩れて
   いるか、玉が薄いかを表す
3. 駒数は、盤上の総数ではなく成駒の枚数や大駒の位置に置き換える余地がある

激指や技巧が進行度を使っていた先例もある（2026-09-03オーナー）。

### 着手は保留する

**指標の設計が本体で、そこに時間をかける価値がある**。分岐の実装（学習器・
推論・ファイル形式の3か所）は指標が決まってからでよい。急いで案Aで測ると、
「バケット機構が効かない」のか「指標が悪い」のかを切り分けられない結果に
なる。

次に着手するときは、まず指標の候補を実データで比べる。同じ局面集合に対して
候補ごとの分類を出し、クラス間で評価の系統誤差が違うかを測る。違いが出ない
指標でネットを分けても、パラメータが薄まるだけになる。

## Decision（保留、2026-08-04の起草時）

案A（盤上駒数）を4バケットで始める。

分岐は最終段だけに入れる。現行の後段はL1(32)→L2(32)→出力1で、
出力段の複製はパラメータ33個×バケット数にしかならない。推論の追加コストは
インデックス計算1回で、NPSへの影響は小さいと見込むが、断定はせず
検証手順で測る（速度と精度は対局で測るまで判断しない、
[ADR-0127](0127-net-shape-bench.md)の教訓）。
量子化・ファイル形式は版を上げて対応する（[ADR-0037](0037-nnue-file-format.md)、
ADR-0127で版3導入済み）。

効果が出たらL2から分岐する形（SF系に近い）へ広げる。最初から広げないのは、
対局比較の解像度が1カード±55 Elo（[ADR-0132](0132-ft-distillation.md)）しか
なく、変更幅を欲張ると原因を切り分けられなくなるためである。

**Elo見込みの根拠は、SF系での実績と、本エンジンの後段が「一様には
増やせないが使い分けは未実装」という状態にあることである**。

検証は4段になる。valid loss（バケットなしと同一データで比較）→
NPS計測 → FT差し替え測定（[ADR-0131](0131-frozen-ft-light-head.md)、
1時間コース）→ SPRT既定条件。

**撤退ライン**。バケット別のvalid lossを見て、全バケットで一様に
悪化していたら指標の設計から戻る。lossが0.001以上動かなければ
対局へ進まず棄却する。

（2026-09-03の追記）この撤退ラインは[ADR-0158](0158-mirror-factorizer.md)
より前に書いたもので、いまの方針と食い違う。検証lossは初期値の系列が違う
だけで0.00136動くので、0.001の足切りは意味を持たない。**採否は対局で
決める**。着手時にこの節を書き直す。

## Consequences

- ネットのファイル形式が変わり、版の分岐が1つ増える
- 学習器はバケットごとの出力ヘッドとインデックス供給が要る。
  `training/model.py` と `dataset.py` の変更で閉じる
- バケット境界（駒数の区切り）がハイパーパラメータとして増える。
  教師データの盤上駒数分布の四分位で初期値を決め、調整は
  [ADR-0143](0143-spsa-tuning.md)の枠組みに乗せられる
- 効いた場合、進行度で条件づける他の案（時間管理・contempt、ROADMAP
  「評価関数と探索を結合する」）の足場になる
