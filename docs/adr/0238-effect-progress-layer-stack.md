# 0238: 利きから出す2軸の進行度で、後段（L1から出力まで）を4組に切り替える

- Status: proposed
- Date: 2026-10-17
- 関連ADR: [0229](0229-roadmap-visible-focus.md), [0137](0137-output-buckets.md), [0198](0198-phase-indicator.md), [0232](0232-effect-table-prototype.md), [0237](0237-effect-count-inputs.md), [0224](0224-selection-bench.md), [0170](0170-l1-half.md), [0158](0158-mirror-factorizer.md)

## Context

[ADR-0229](0229-roadmap-visible-focus.md)の段階3（入力を増やす）のうち、進行度で後段を
切り替える案である。合格の条件は「SPRTで強くなる」と決まっている。

### 第36回の型

第36回（2026年）の選手権では、進行度でLayerStackを切り替える型が複数のチームに現れた
（`research/wcsc_appeals/wcsc36/`）。LayerStackは、FTの後ろの層（L1から出力まで）を
複数組持ち、局面ごとに1組を選ぶ構造である。

| チーム | 切り替えの指標 | 要約にある工夫 |
|---|---|---|
| 六角堂狸 | KP特徴のロジスティック回帰で推定した進行度 | 回帰の重みの量子化、差分計算、シグモイドを表引きで省く |
| 奏乗 | KP絶対（玉位置×BonaPiece、125,388パラメータ）の重みの和にシグモイドを掛けた0〜1の値 | 後手玉は盤を反転して先手視点にそろえる |

進行度を1本の軸で持たない例もある。

<!-- textlint-disable ja-technical-writing/ja-no-successive-word -->

| チーム | 中身 | 要約にある結果 |
|---|---|---|
| 元気もりもりニンニクパワー | 進行をphase（駒交換）・danger（玉の危険）・nyugyoku（入玉）の3軸で数える。通常と入玉で別のモデルにする | 詰み探索を掛ける局面の選別に使う |
| ねね将棋 | 局面の性質（戦型・入玉・手数・評価値の差）からDNNで8つのNNUEの混合重みを出す | 評価の損失は改善した。対局での勝率向上は確認できていない |

<!-- textlint-enable ja-technical-writing/ja-no-successive-word -->

**LayerStackそのものの寄与は、要約に数字がない**。六角堂狸の前年比+85.48は、知識蒸留と
アンサンブルを含めた全体の値である。起動前に原文（`source_urls`）で、LayerStackだけを
測った数字があるかを確かめ、本ADRへ追記する。

### ADR-0137・ADR-0198で何を閉じたか

[ADR-0137](0137-output-buckets.md)は、出力層を盤上の駒数で分岐する案だった。
[ADR-0198](0198-phase-indicator.md)が指標10本を測り、案を閉じた。
測り方は、学習済みのネットを固定し、最終段（L2から出力への33パラメータ）をクラスごとに
当て直すものである。どの指標で4クラスに分けても、誤差は当てはめノイズの3倍以下しか
減らなかった。同ADRの結論は「現行ネットの後段は、どの進行度でも同じ写像で足りる程度に
較正されている」である。

同ADRは、言えないことも書いている。FTから分ける案は範囲外で、チェスの+122 Elo
（[Checkmating One, by Using Many](https://arxiv.org/abs/2401.16852)）はフェーズごとに
ネットを丸ごと学習していた。

## ADR-0137・ADR-0198との違い

本ADRの案は、閉じた案と3点で違う。

| 点 | ADR-0137（ADR-0198で測定） | 本ADR |
|---|---|---|
| 分ける範囲 | 最終段だけ。1組33パラメータ | L1から出力まで。1組約17,000パラメータ（L1が1024×16、L2が16×32、出力が33） |
| 学習 | 学習済みのネットを固定し、後から当て直す | ゼロから学習する。FTと各組が一緒に学ぶので、FTは組ごとに使い分けられる表現を作れる |
| 指標 | 1本の指標を四分位で4クラス | 2本の指標の組で2×2の4クラス（多軸） |

1つ目と2つ目が本質である。ADR-0198の測定は「固定したFTの上で最終段を分けても得がない」
ことを示した。後段全体を分け、FTと一緒に学習したときの効きは測っていない。

一方で、ADR-0198の結果は本ADRに不利な材料でもある。現行ネットの誤差が進行度に偏って
いないなら、後段を分けても取り返す誤差は小さい。**効きは小さい見込みで、1億の規模の
測定幅（±15）に隠れる可能性がある**。それでも測るのは、学習1本0.7時間・対局1本1.9時間で
決着がつき、第36回の主流の型を本エンジンで確かめた記録が残るためである。

## 選択肢と比較

決めることは3つある。指標、分ける範囲、組の数である。

### 指標

#### 案I1: KP特徴から学習した1軸の進行度（六角堂狸・奏乗）

第36回の主流である。進行度を学習する目標が要る。psvは局面の手数を持つが、その対局が
何手で終わったかを持たない。目標の作り方から設計が要る。1軸なので、多軸の問いには答えない。

#### 案I2: 利きから数える2軸（本ADR）

ADR-0198の指標から、利きで数える2本を選ぶ。

- 接触（`contact`）: 相手の駒に利かれている駒の数。両者の合計で、玉を含む。開戦の度合いを表す。
  ADR-0198の第1測定で、主・副の両方の局面集合で上位5本に入った2本のうちの1本である
- 玉の危険（`king_zone`）: 玉の周囲8升への相手の利きの数の合計。両者の大きいほうを取る。
  副の局面集合でノイズ比14.9の首位だった

どちらも先後で対称な集計なので、手番によらず同じ組が選ばれる。ADR-0198の `psv phase` に
計算がある（`crates/tools/src/bin/psv.rs`）。

[ADR-0232](0232-effect-table-prototype.md)の利きの表があれば、どちらも表引きで安く出る。
接触は駒の升ごとに「利いている駒の位置」と相手の駒の論理積を見るだけで、約40回の論理演算になる。
玉の危険は16升のpopcountである。

#### 案I3: DNNで混合重みを出す（Expert Blending）

ResNetの推論を評価のたびに走らせる形で、NNUEの速さと両立しない。採らない。

### 分ける範囲

#### 案S1: 最終段だけ

ADR-0137の案で、ADR-0198の測定で閉じた。

#### 案S2: L1から出力まで（LayerStack）

FTは共有し、L1・L2・出力を組ごとに持つ。評価1回の計算量は変わらない。増えるのは組の
選択と、重みのキャッシュの占有である。

#### 案S3: ネットを丸ごと分ける（チェスの先行研究）

FTの表（128MB）が組の数だけ要る。玉位置ごとのキャッシュ（[ADR-0156](0156-bucket-accumulator-cache.md)）も
組ごとに要る。採らない。

### 組の数

2軸を中央値で2つずつに切り、4組にする。

8組（3軸、または各軸を4分割）にしない理由は2つある。1つはデータで、1億局面を8組に分けると
1組1,250万になる。もう1つはキャッシュである。L1の重みは1組あたり、密の表16KBと列駆動の表16KB
（[ADR-0170](0170-l1-half.md)の16出力）で32KBある。4組で128KBになり、M4 Proの性能コアの
L1データキャッシュと同じ大きさに達する。8組はそれを超える。

入玉の軸（元気もりもりニンニクパワーのnyugyoku）は入れない。入玉局面は少なく、組の間で
教師の量が偏る（ADR-0137の案Cと同じ理由）。入玉は並行する改善（入玉を点数で教える）が扱う。

## Decision

**案I2・案S2で、接触と玉の危険の2軸の中央値で4組に切り替える**。

決め手は、ADR-0198が閉じた範囲の外側を、最小の新しい部品で測れることである。指標の計算は
`psv phase` にすでにある。ADR-0198の順位から、効く見込みのある2本を選べる。案I1は目標の
設計が別に要るので、本ADRの結果を見てから起こす。

### 構成の詳細

- 境界は、学習データの先頭1,000万局面で取った各軸の中央値とする。`hmwr diag phase` が
  書くTSV（`data/profile/phase-<名前>.tsv`）から取り、起動前に本ADRへ書く
- 組の番号は `2×(接触が中央値以上) + (玉の危険が中央値以上)` とする
- 境界と組の数はネットのファイルに持たせる。推論側は、ファイルが持つ選び方の番号に従って組を選ぶ
- 学習側は、PyO3の特徴抽出（`crates/py/src/lib.rs`）が局面ごとの組の番号を返す。`training/model.py` は
  L1・L2・出力をそれぞれ `組の数×出力` の線形層として持ち、番号で取り出す

### Issue #768との順番

**Issue #768（ネットの層の定義とファイル形式を1か所へ寄せる）を前提にする**。

本ADRは後段の層を4組に増やす。いまは層がフィールド名で手書きされ、構造体リテラル5か所・
scalarとSIMDのforward・save/load・pyブリッジ・`quantize.py`・`model.py` に散っている。
組を足すと、そのすべてに手が入る。#768の手順のうち次の3つを先に済ませる。

1. 学習と推論の一致テスト。組を選ぶ処理が学習側と推論側で一致するかを、このテストで確かめる
2. 自己記述のファイル形式。組の数・選び方の番号・境界をヘッダに持たせる
4. 層を列で表す。組は「層の列」を組の数だけ持つ形で書ける

着手の順は、#768の手順1・2・4、本ADR、[ADR-0237](0237-effect-count-inputs.md)とする。本ADRを
先にするのは、accumulatorと差分更新に触れないためである。ADR-0232の結果も待たない。
表が無いうちは `attackers_to` で数え、その代償をNPSの測定に含める。

## 測定の設計

### 仮説

**後段を接触と玉の危険の2軸で4組に切り替えると、同じ1億局面・同じ乱数で学習したネットは、
切り替えないネットより強くなる**。

### 動かす変数

組を選ぶ規則だけを動かす。統制は、同じ4組の構造で、常に0番の組を選ぶネットである。
**構造が同じなので、初期化で乱数を消費する順序も同じになる**（[ADR-0158](0158-mirror-factorizer.md)の
指摘への対処）。統制で学習されるのは0番の組だけで、関数としては切り替えのないネットと同じになる。

| 群 | 組を選ぶ規則 | 名前 |
|---|---|---|
| 統制 | 常に0番 | `ls_ctrl` |
| 処置 | 接触×玉の危険の2×2 | `ls_phase` |
| 参照（条件つき） | 盤面のハッシュの下位2ビット | `ls_rand` |

参照の群は、処置が効いたときだけ走らせる。組を分けること自体が効いたのか、進行度で
分けたことが効いたのかを切り分ける。ハッシュの下位2ビットは各組へ均等に割れ、局面の性質と
関係がない。

### 固定するもの

- データは[ADR-0224](0224-selection-bench.md)の重複除去の1億（`sel_dedup_100M`）
- 学習のレシピは `sel_dedup` と同じ。1周、batch 16384、peak_lr 1e-3、λ0.7、seed 0、
  FTクリップ1.0、兄弟群 `rank_tanuki_210M`、検証 `valid_tanuki_dl430_q1`。ゼロから学習する
- 構成は既定の1024x16x32、組の数は4
- 境界は起動前に決めた中央値で、学習中に動かさない
- 対局は10+0.1、開始局面 `start_sfens_ply24`、hash 64、並列8、裁定2000,8、`hmwr match` の
  既定の最大手数で、各1,000ペアを指し切る。3群とも同じビルドで、ネットだけを差し替える

暗黙に動く変数を点検した。局面数・ステップ数・検証集合は群で同じになる。対局のビルドが
同じなので、速度の差は組を選ぶ計算（統制は計算しない）と、キャッシュの占有だけになる。
これは本番でも払う代償なので、測定に含める。

組ごとの局面の割合は、学習の前に `hmwr diag phase` のTSVで数えて記録する。中央値で切るので
各軸は半々に近いが、2軸の相関で4組の大きさは偏る。いちばん小さい組が全体の10%を下回るときは、
起動前に境界の取り方（各軸の中央値か、4組を均等にする分位か）を本ADRへ書き直してから起動する。

### 解釈の事前登録

Eloの読み方は[ADR-0224](0224-selection-bench.md)と同じにする。「効いた」は点推定が+15以上で、
95%区間の下端が0を超えること。「害」は点推定が−15以下で、上端が0を下回ること。
どちらでもなければ「どちらでもない」とする。

`ls_phase` の対統制をP、`ls_rand` の対統制をRと書く。

| 結果 | 読み | 次の一手 |
|---|---|---|
| Pが効いた、Rがどちらでもないか害 | 進行度で後段を分けることが効く | 本学習（下の「合格の条件」）へ進む。並行して、案I1（学習した1軸）と3軸を同じ統制で測るADRを起こす |
| Pが効いた、Rも効いた | 分けること自体が効き、進行度の意味は効きの説明にならない | 本学習へ進む。選び方は速さで決める（ハッシュは計算がほぼただ）。ADRに「進行度は効きの理由ではない」と記録する |
| Pがどちらでもない | 1億の規模では、後段を分けても効きが測定幅に隠れる。ADR-0198の較正の結果と同じ向きである | 見送り。案I1と3軸には進まない。ADR-0237の結果が出たら、利き数の入力を持つネットの上で1回だけ測り直す |
| Pが害 | 4組に分けると1組あたりの教師が減り、その損が上回る | 本ADRをrejectedにする |

NPSは `hmwr bench --nodes` で、`ls_ctrl` と `ls_phase` を同じビルドで比べる。組の選択の代償を
読む値で、採否の条件には次の節で使う。

### 合格の条件

- Eloの判定: 本学習（現行の評価関数と同じ `pool1` の2周）のネットを、現行とSPRTにかけて既定
  （elo0=0、elo1=5）のH1。棋力の向上を主張する変更なので、非劣性は選ばない
  （[ADR-0163](0163-sprt-hypothesis-choice.md)）
- Elo以外の条件:
  - 正しさ: 組の番号が、学習側（PyO3）と推論側で全局面一致する。#768の一致テストに、4組のネットを加えて通す
  - 速さ: 組の選択によるNPSの低下が3%以内である。超えたら、本学習の前に指標の計算を
    ADR-0232の表引きへ移すか、差分で持つ（六角堂狸の工夫）形へ直す
  - 既定のネットへの影響: 組を持たないネットでは、探索のノード数が変更前と一致する
    （`hmwr verify` で2組の全局面）
- 採否: SPRTのH1と3つの条件をすべて満たしたときだけ、現行の評価関数を切り替える

## Consequences

- ネットのファイルに、組の数・選び方・境界が入る。後段の重みは4倍になるが、1組17,000パラメータ
  なので、ファイル全体（128MB）に比べて無視できる
- 進行度の指標が、評価関数の部品として初めて探索に入る。[ADR-0229](0229-roadmap-visible-focus.md)の
  段階4（分布の広さで思考時間を配る、焦点を見せる）で、局面の性質を示す値として再利用できる
- 統制の構造（同じ形で選び方だけ定数にする）は、後段の構造を変える案の統制として使い回せる
- 見直しのトリガーは2つある。ADR-0237で利き数の入力が採られたとき。入力が利きを持てば、
  後段を利きで分ける効きは変わる。もう1つは、原文の確認で第36回のLayerStackの寄与の数字が
  見つかったときである。その大きさで1億の測定幅との比を見直す
