# 0227: 1億局面を、玉の位置×形勢の区画の配分と区画の中のαで組み立てる

- Status: proposed
- Date: 2026-10-07
- 関連ADR: [0190](0190-selfplay-decided-thinning.md), [0206](0206-entering-king-mix.md), [0215](0215-dl-relabel-pilot.md), [0219](0219-relabel-2b-in-place.md), [0224](0224-selection-bench.md), [0225](0225-dedup-20b.md)

## Context

dlshogiでラベルを付けられるようになり（[ADR-0219](0219-relabel-2b-in-place.md)）、局面と
ラベルを切り離して扱えるようになった。どの局面に学習の予算を使うかを、自分たちで
設計できる。オーナーと議論し、「1億局面で最強のネットを作るなら、このデータセット」
と言えるものを仮説を持って組み立てることにした（2026-10-07）。

2026-10-07の探索的な分析で、教師の局面には次の偏りがあった。

- 手番側の玉が敵陣（1〜3段目）にいる局面は1.8%、4〜6段目は5.5%しかない
- 玉が上がった局面は、9割が勝負のついた局面だった。互角のまま玉が上がった局面は、
  tanukiの局面にはほぼない
- 現行ネットとdlshogiの評価のずれは、互角付近で玉が囲いから出た局面ほど大きい
  （玉が3段目以上なら15〜19%、最下段なら7%）

入玉5億（[ADR-0206](0206-entering-king-mix.md)、floodgateの入玉局面、Suisho5のラベル）は、
玉が敵陣にいる局面が20.9%ある。互角・優勢のまま玉が上がった局面の主な出どころになる。

## 仮説

**区画（手番側の玉の帯×形勢の帯）の配分を決めて組み立てた1億局面は、自然な分布の
1億局面より強いネットを作る。区画の中で、ありふれ度の低い局面をなめらかに厚くすると、
さらに強くなる**。

## 設計

### 区画

2軸で9区画に分ける（オーナー判断）。

- 玉は手番側から見た段で、敵陣（1〜3段）・4〜6段・自陣（7〜9段）の3帯
- 形勢はdlshogiの勝率 `p = σ(score / 430)` で、互角（40〜60%）・優勢（20〜40%・60〜80%）・
  勝勢（0〜20%・80〜100%）の3帯

### 配分（案A）

玉の配分を敵陣15%・4〜6段25%・自陣60%、形勢の配分を互角25%・優勢25%・勝勢50%とし、
区画の目標は両者の積にする。勝勢は自然な分布の約58%から50%へ下げる（オーナー判断）。
決着圏の間引き（[ADR-0224](0224-selection-bench.md)、47%→18%で−65.9）より下げ幅は小さい。

標本から推定した在庫では、敵陣×互角（必要375万・在庫約320万）と4〜6段×互角
（必要625万・在庫約600万）が少し足りない。足りない区画は全部を取り、不足を同じ玉の
帯の優勢へ回す。

### 区画の中の選び方（α）

ありふれ度は、局面でオンになる特徴（自玉のマス×bona piece）の出現頻度の幾何平均と
する。区画の中では、選ぶ確率をありふれ度のα乗に反比例させ、上限を1として目標数に
合わせる。α=0は自然な分布のまま、α=1は同じ形を同じ重みにする。αを上げると、
中心を残したまま裾が連続的に厚くなる。「広さ」と「なめらかさ」を両立させる
選び方としてオーナーと決めた。α=0.5で、下位5%の珍しい局面の取り分は約3倍になる。

### 候補の局面

- tanukiの局面: `dl20u`（重複除去後の17.1億、dlshogiのラベル、1手静止化済み）
- 入玉5億: 手番側の玉が6段目以内で、Suisho5の勝率（評価値を600で割る）が10〜90%の
  局面を取り出す（約2,460万）。重複を除き、1手静止化して、dlshogiで付け直す
  （S=430）。付け直した後の勝率で区画を決め直す

## 測定の設計

### 群

| 群 | データ | ネット |
|---|---|---|
| 統制 | `dl20u` の先頭1億（無作為の1億） | 既存の `sel_dedup` |
| 処置1 | 案Aの配分で選び、区画の中はα=0 | `cell_a0` |
| 処置2 | 案Aの配分で選び、区画の中はα=0.5 | `cell_a05` |

統制のネットは、[ADR-0224](0224-selection-bench.md)の重複除去の群をそのまま使う。
`dl20u` の先頭1億は、`sel_dedup_100M` と同じ局面の並びになるためである。

### 動かす変数と交絡

- 統制→処置1は「区画の配分」を動かす。ただし、配分を満たすために入玉5億の局面が
  入るので、局面の出どころ（floodgateの他のソフトの対局）も一緒に動く。この2つは
  分けられない。足りない区画を埋めるには、入玉5億が要るためである
- 処置1→処置2は「区画の中の選び方（α）」だけを動かす。配分・出どころ・局面数は同じ

### 固定するもの

- 局面数は1億。選んだ後に全体シャッフルし、先頭からちょうど1億を切り出す
- 学習のレシピは `sel_dedup` と同じ。1周、batch 16384、peak_lr 1e-3、λ0.7、seed 0、
  兄弟群 `rank_tanuki_210M`、検証 `valid_tanuki_dl430_q1`。ゼロから学習する
- 選択の乱数種は1。頻度表と在庫の見積もりは500万局面の標本で行う
- 対局は両側 `data/bin/adr0226-himawari`、10+0.1、各1,000ペアを指し切る。
  統制対処置1、統制対処置2、処置1対処置2の3本

検証損失は比べない。検証集合はtanukiの自然な分布なので、配分を変えた群に不利に出る。

### 解釈の事前登録

統制対処置1をQ（配分の効き）、処置1対処置2をS（αの効き）、統制対処置2をT（合計）と書く。
「効いた」は点推定が+15以上で95%区間の下端が0を超えること、「害」は点推定が−15以下で
95%区間の上端が0を下回ることとする（[ADR-0224](0224-selection-bench.md)と同じ基準）。

| 結果 | 読み | 次の一手 |
|---|---|---|
| Qが効いた | 区画の配分（と入玉の出どころ）が効く | 配分を振る次の測定と、20億規模への適用を設計する |
| Qがどちらでもない | 1億では配分の効きは測定幅に隠れる | 配分はTの結果と合わせて判断する |
| Qが害 | 自然な分布から離すと害になる。ADR-0190・0224の決着圏の結果と同じ向き | 配分は自然な分布へ戻す方向で考え直す |
| Sが効いた | 区画の中でなめらかに裾を厚くすると効く | αを振る次の測定を設計する |
| Sがどちらでもない | 1億ではαの効きは測定幅に隠れる | αは0のまま |
| Sが害 | 珍しい局面を厚くすると害になる | αは0のまま。ありふれ度の定義を見直す |

QとSは互いに独立に読む。Tは補助として、Q・Sと矛盾がないかを確かめるのに使う。

## 実行

手順は2つのspecに分ける。データを作った後、学習の前に、選ばれた1億の分布（区画ごとの
実績・ありふれ度・入玉の割合・手数や持ち駒）を分析してオーナーと確かめるためである
（オーナーの方針、2026-10-07）。

前半は `experiments/adr0227-cell-dataset.toml` である。まず入玉5億を全体シャッフルし
（約20GB）、候補を取り出して重複除去・静止化・dlshogiでの付け直し（約3時間）をかける。
続けて選択2本（各約1.5時間）と、シャッフル・切り出しを走らせる。約8時間を見込む。

後半は `experiments/adr0227-cell-train.toml` で、学習2本（各約0.7時間）と対局3本
（各約1.9時間）である。選んだ1億のpsvは、分布の事後分析のために残す。
