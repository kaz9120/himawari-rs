# 0235: 静かな手の並べ替えに、取られる駒を逃がす手と取られる升へ行く手の項を足す

- Status: proposed
- Date: 2026-10-17
- 関連ADR: [0025](0025-move-ordering.md), [0109](0109-reference-parity.md), [0232](0232-effect-table-prototype.md), [0216](0216-defense-oversample.md), [0141](0141-singular-rate-calibration.md), [0155](0155-reference-walkthrough.md), [0074](0074-feature-verification.md), [0159](0159-ft-width-1024.md)

## Context

静かな手の採点は `score_quiets`（`crates/engine/src/movepick.rs:731-756`）にある。
中身は3つある。historyの和（main・pawn・continuation 5本）と、浅いplyのlowPly historyと、
静かな王手へのボーナスである。王手のボーナスは、SEEが−75以上の王手に16384（`CHECK_BONUS`）を足す。
局面の今の状態を見る項は、王手のボーナスだけである。

historyは「この駒をこの升へ動かす手が、過去に良かったか」を覚える。駒が今取られそうかは覚えない。
当たりになった駒を逃がす手は、その局面でだけ良い。historyの上では、同じ駒・同じ升の
平凡な手と区別がつかない。逃げる手が後ろへ回ると、LMRで削られ、move count pruningで生成ごと
打ち切られる（`search.rs:2341-2343`）。

本エンジンでこの穴が効くと考える理由は2つある。

- 評価関数が当たりの扱いに弱い。現行ネットは攻撃的な受け（相手の攻め駒に当てる手）が
  見えておらず、最善手の静的評価の順位が一般より+1.08悪かった
  （[ADR-0216](0216-defense-oversample.md)のContext）。当てられた側の逃げ方も、
  評価関数だけでは拾いにくいと見ている
- 将棋は駒打ちがある。静かな手の多くは駒打ちで、打った駒がそのまま取られる升への打ちも
  候補に並ぶ。今はhistoryが悪くなるまで前に出てくる

チェスのStockfishは、当たりの駒を逃がす手に加点し、取られる升へ行く手を減点する項を
並べ替えに持つ（`movepick.cpp` の `threatenedPieces`）。**これは根拠にしない**。参照の項と定数は、
参照の評価関数と調整環境で最適化されている（[ADR-0141](0141-singular-rate-calibration.md)・
[ADR-0155](0155-reference-walkthrough.md)）。本エンジンでの根拠は、下の事前測定で作る。

### 取られる駒の定義

升 `s` にいる手番側の駒が「取られる」とは、`s` に相手の利きがあり、
手番側の利き（その駒自身を除く）が無いことを言う。ピン・X線・交換の損得は見ない。
利きの表（[ADR-0232](0232-effect-table-prototype.md)）の `attackers(s)` を1回引けば決まる。

## 選択肢と比較

### 案A: 移動の前後で「取られる」が変わる分だけ加点する

1つの量にまとめる。静かな手ごとに次の値を足す。

`hanging_delta = (移動元で取られる − 移動先で取られる) × 駒価値 × 16`

逃げる手は正、取られる升へ行く手は負になる。駒打ちは移動元が無いので、取られる升への打ちだけが負になる。
係数16は、飛（990）が逃げる手を王手のボーナス（16384）と同じ大きさにする尺度である。

### 案B: 逃げる手の加点だけ

減点を持たない。駒打ちの無駄打ちは減らない。

### 案C: SEEで判定する

移動先のSEEを手ごとに引く。精度は上がるが、静かな手は1ノードで数十〜百を超えるので、
採点のたびにSEEを全部の手で引くことになる。表の1回引きに比べて桁で重い。

## Decision

**案Aを採る**。決め手は、逃げる手と取られる升への手を1つの量で扱え、
費用が表の引きに限られることである。係数は16に固定し、調整はH1の後にSPSAへ回す。

### 実装の位置

- `score_quiets`（`movepick.rs:731`）で、ループの前に「手番側の取られる駒の集合」を1回求める
- 各手の移動元が集合に入るか、移動先が取られる升かを見て `hanging_delta` を足す
- 移動先の判定では、動かす駒自身の利きを除く。移動元の升を空けたことで通る相手の飛び利きは見ない
- 王手回避（`score_evasions`）と取る手の採点は変えない

### 事前測定（仮説の根拠を作る）

診断用のビルド（内訳カウンタ、コミットしない）で、βを超えた静かな手を集める。
それが何番目に読まれたかを、逃げる手（移動元が取られる升）とそれ以外に分けて数える。

- 局面: 組み込みの4局面と `openings/profile_late_positions.txt`、深さ16、1スレッド

| 事前測定の結果 | 次の一手 |
|---|---|
| 逃げる手のβ超えの平均の順番が、それ以外の1.5倍以上で、件数が100件以上ある | 並べ替えに穴がある。SPRTへ進む |
| 1.5倍未満か、100件未満 | historyで足りている。SPRTにかけず、本ADRをrejectedにする |

### 仮説と固定するもの（実験の規律の4点）

1. 仮説: **静かな手の採点に `hanging_delta` を足すと強くなる**
2. 動かす変数: `score_quiets` の `hanging_delta` の項の有無だけ
3. 固定するもの: 係数16と、`GOOD_QUIET_THRESHOLD` などほかの採点の定数。
   評価関数（`hmwr/config.py` の `EVAL_FILE`）、比較元（着手時のorigin/main）、
   対局条件（10+0.1、裁定2000,8）も固定する。
   表の有無は着手時のmainに従う。項の値は表の有無で変わらない
4. 事前登録: 上の事前測定の表と、下の「結果の読み方」

### 機能検証

- `hmwr verify` の固定深さのノード数が、3局面以上で変わること
- 発動率: 採点した静かな手のうち、`hanging_delta` が0でない割合。0.1%未満ならSPRTにかけない
  （[ADR-0074](0074-feature-verification.md)）
- 並べ替えの質: β超えが1手目で起きた割合（first move cutoff率）を前後で比べる。
  下がったら、加点が良い手を押し出している。SPRTの前に係数の尺度を見直す

### 合格の条件

- Eloの判定: 既定（elo0=0、elo1=5、α=β=0.05）。棋力の向上を主張する変更である。
  並べ替えの変更は1本あたり数Eloにとどまることが多く、+10以上は見込まない
- Elo以外の条件: 事前測定で根拠が出ていること。機能検証を満たすこと
- 採否: 両方を満たしたときだけ入れる。上限と中点の規則は[ADR-0217](0217-sprt-pass-cap.md)の追記に従う

## 前提条件: ADR-0232が合格しない場合

本ADRは表への依存が4本の中で最も強い。取られる駒の集合を求めるには、手番側の駒（20枚前後）ごとに
両色の利きを見る。表が無いと `attackers_to` を40回前後引くことになる。
静かな手の採点は、TT手と取る手で切れなかったノードでだけ走る。それでも費用は無視できない。

表が無いときは、事前測定で根拠が出た場合に限り、`attackers_to` 版でNPSを先に測る。
低下が0.5%を超えるなら、SPRTの前にADR-0232の後継（案U3・案T2）を待つ。
速度は1%あたり3.5 Eloの実測がある（[ADR-0159](0159-ft-width-1024.md)）。
0.5%の低下は2 Elo弱にあたり、見込む効きと同じ桁になる。

## Consequences

- 静かな手の採点に、historyでない局面の項が王手のボーナスに続いて2つ目として入る
- 段階3（利き数の入力）で評価関数が当たりを学べば、本ADRの項の効きは小さくなるはずである。
  そのとき外せるかを測り直す
- 相手の攻め駒に当てる手（攻撃的な受け）の加点は、本ADRの項と同じ表で書ける。
  ADR-0216が学習側で埋められなかった盲点を、探索側から拾う案になる

## 事前測定の結果（2026-10-21）

起草の後に前提が1つ変わった。探索の盤が配列盤になり（[ADR-0241](0241-mailbox-board-research.md)）、
利きの表（ADR-0232）は入っていない。配列盤は升ごとに手番別の利き数を持つので、
取られる駒は利き数を読むだけで決まる。駒は自分の升へ利かないため、手番側の利き数が
そのまま「その駒自身を除く守り」になる。問い合わせは `SearchBoard` の `hanging_pieces` と
`lands_hanging` に置いた。core-searchの側は `attackers_to` で同じ値を返す。
mailbox-shadowのデバッグビルドで、組み込みの4局面と終盤の12局面を深さ8まで読み、食い違いは出なかった。

測り方は次のとおりである。診断用のビルド（コミットしない）で、本探索のβ超えを数えた。
王手されていないノードの、取る手でない手だけを集める。順番はノードで何番目の合法手だったかで、
TT手と取る手も前に数える。逃げる手は、盤上の駒を動かす手で、移動元がノードの時点で
取られる升だったものである。局面は組み込みの4局面と `openings/profile_late_positions.txt` の
12局面、深さ16、1スレッド、評価関数は `pool1_2ep_f2_reorder` である。局面ごとにプロセスを立て直した。

| 種類 | 件数 | 平均の順番 |
|---|---|---|
| 逃げる手 | 6,576 | 2.19 |
| それ以外 | 525,116 | 1.44 |
| 比 | | 1.53 |

**判定は表の1行目（並べ替えに穴がある）である**。比が1.5以上で、件数が100件以上ある。

ただし閾値の際にある。事前登録の数え方はTT手を除いていない。次の3つの補助の数字は、
どれも1.5を下回るか跨ぐ。判定には使わないが、読み手のために残す。

| 補助の数え方 | 逃げる手の件数 | 比 |
|---|---|---|
| TT手を除く（`score_quiets` が並べた手だけ） | 4,269 | 1.35 |
| 同じ16局面、局面を単位にしたブートストラップの95%区間 | | 1.29〜1.75 |
| `openings/actdump_positions.txt` の200局面、深さ12 | 10,320 | 1.35 |

局面ごとの比は0.84〜2.10に散る。組み込みの4局面だけなら1.41、終盤の12局面だけなら1.53だった。

## 機能検証の結果（2026-10-21）

候補は案Aを書いたとおりに実装した（係数16、コミット `b40295f`）。移動元の項は動かす前の駒、
移動先の項は動かした後の駒の価値で量る。移動先が取られる升かは、相手の利き数が正で、
手番側の利き数から動かす駒の分（駒打ちは0、盤上の駒は1）を引いて0になることで判定する。

| 項目 | 結果 | 条件 |
|---|---|---|
| `hmwr verify` 深さ13のノード数 | 組み込み4局面と終盤12局面の全16局面で変わった | 3局面以上で変わる。満たす |
| 発動率 | 採点した静かな手の26.2%で `hanging_delta` が0でない | 0.1%以上。満たす |
| first move cutoff率 | 下がった（下の表） | 下がらない。満たさない |

発動率の内訳は、移動元が取られる升の手が1.8%、移動先が取られる升の手が25.9%である
（変更前の木、深さ16、16局面）。

first move cutoff率は本探索のβ超えのうち、1手目で起きた割合である。

| 局面と深さ | 変更前 | 変更後 |
|---|---|---|
| 16局面、深さ16（全β超えの合算） | 87.84% | 83.39% |
| 16局面、深さ16（局面ごとの平均） | 86.02% | 83.68% |
| 16局面、深さ13（全β超えの合算） | 87.54% | 86.33% |
| 200局面、深さ12（局面ごとの差の平均） | | −0.93pt ±0.40、下がった局面121・上がった局面56 |

静かな手の並びは小さな変化でも木を大きく動かす（Issue #872）。そこで200局面で、項を分けて測り直した。
差は局面ごとの差の平均と95%区間である（有効な177局面）。

| 変種 | first move cutoff率の差 |
|---|---|
| 案A、係数16（候補） | −0.93pt ±0.40 |
| 案A、係数1 | −0.10pt ±0.39 |
| 逃げる手の加点だけ（案B）、係数16 | −0.03pt ±0.45 |
| 取られる升へ行く手の減点だけ、係数16 | −1.18pt ±0.47 |

下げているのは移動先の減点である。逃げる手の加点だけなら率は動かない。
将棋では、取られる升への手に良い手が多いと読める。叩きの歩や捨て駒のように、取らせる手が筋になる場面がある。

事前登録に従い、**係数16の案AはSPRTにかけない**。first move cutoff率が下がったので、
SPRTの前に係数の尺度を見直す。見直しの材料は上の分解である。減点の項を外した案Bは率を下げない。
案Bへ移るなら動かす変数が変わるので、仮説と合格の条件を書き直してから測る。
NPSは測っていない。配列盤では集合を作るのに81升の利き数を1筋ずつ読むだけで済み、
「前提条件」の節が心配した `attackers_to` 40回前後の費用はかからない。

## 案Bへの切り替えと、SPRTの事前登録（2026-10-21、監督）

上の機能検証の分解を受けて、**SPRTにかける形を案B（逃げる手の加点だけ）に切り替える**。決め手は3つある。

1. 事前測定で穴が見つかったのは逃げる手である。案Bは、その穴だけを埋める
2. 「係数の尺度を見直す」は事前登録の手順で、見直しの材料は上の分解である。減点の項が first move cutoff率を下げ、加点の項は下げない
3. 係数は16のまま変えない。案Bは案Aから項を1つ外した形で、新しい変数を足さない

判定は事前測定の線の際だったことを書き残す。逃げる手の平均の順番は、それ以外の1.53倍だった（線は1.5倍）。
局面を単位にしたブートストラップの95%区間は1.29〜1.75で、TT手を除くと1.35だった。根拠は強くない。

### 仮説と固定するもの

1. 仮説: **静かな手の採点で、取られる駒を逃がす手に `16 × 駒価値` を足すと強くなる**
2. 動かす変数: `score_quiets` の逃げる手の加点の有無だけ
3. 固定するもの: 係数16、ほかの採点の定数、評価関数 `pool1_2ep_f2_reorder`、比較元（着手時のorigin/main）、対局条件（10+0.1、裁定2000,8）
4. 事前登録: 下の「機能検証」と「結果の読み方」

### 機能検証

- `hmwr verify` の組み込み4局面で、ノード数が3局面以上で変わること
- 発動率: 採点した静かな手のうち、移動元が取られる升の手は1.8%だった（上の機能検証の内訳）。0.1%の線を超える
- first move cutoff率: 上の200局面の測定で −0.03pt ±0.45 で、下がっていない

### 合格の条件

Eloは既定（elo0=0、elo1=5）で判定する。上限と中点の規則はADR-0217の追記に従う。

| 結果 | 読み方 | 次の一手 |
|---|---|---|
| H1 | 逃げる手を前に出す項が、historyの穴を埋めた | mainへ入れる。係数16をSPSAの次の群の対象に加える |
| H0 | 穴は小さいか、項の加点が大きすぎる | mainへ入れない。係数を動かした再挑戦はしない |
| 上限で中点より上 | 効きは小さいが正の側にある | ADR-0217に従い延ばす |
| 上限で中点以下 | 効きは±2.5の中にある | 見送りとして記録する。SPSAで係数ごと測る候補に回す |
