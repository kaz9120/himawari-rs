# 0030: 入玉宣言勝ち

- Status: accepted
- Date: 2026-07-19
- 関連ADR: [0019](0019-usi-architecture.md), [0027](0027-sprt-framework.md)

## Context

相入玉になると通常の詰みでは決着せず、宣言勝ちルールがないと
selfplayでは手数上限の引き分けに流れる（ADR-0027の既知の穴）。
GUI・floodgate・選手権のいずれも宣言勝ちを前提とするため、
ルール完全対応（P3出口）に必須。決めるのは採用ルールと
実装の持ち場。

## 選択肢と比較

候補は27点法（CSAルール準拠の宣言勝ち）と24点法（トライ系の
変種）。コンピュータ将棋の対局環境（floodgate、選手権、
主要GUI）はいずれも27点法を採用しており、実質的に選択肢はない。
27点法を採用する。

## Decision

- 27点法の宣言条件をcoreに `Position::can_declare_win()` として
  実装する。条件は次のすべてを満たすこと:
  - 手番側の玉が敵陣三段目以内にある
  - 手番側の敵陣内の駒（玉除く）が10枚以上ある
  - 点数（飛角=5点、その他小駒=1点、玉除く、持ち駒含む）が
    先手28点以上・後手27点以上ある
  - 手番側に王手が掛かっていない
- USI: 条件成立時に `bestmove win` を返す。探索側は
  root入口で判定し、成立なら探索せず宣言する
- 探索中のノードでも判定し、成立局面は `mate_in(ply)` 相当の
  勝ち値を返す（呼び出しコストが問題ならSPRTで条件を絞る）
- selfplayマネージャ: `bestmove win` を受けたら
  can_declare_winで検証し、正当なら勝ち、不当なら反則負けとして
  記録する（ADR-0027の宣言未対応を解消）
- テスト: 宣言条件の境界（点数ちょうど、駒数ちょうど、
  王手が掛かっている場合）を単体テストで網羅する

## Consequences

- selfplayの相入玉が正しく決着し、手数上限引き分けが減る。
  枝刈りゲートのノイズも下がる
- 点数計算は駒種ごとの定数テーブルで済み、性能影響は無視できる。
  全ノード判定のコストだけSPRTで確認する
- 24点法・トライルールの必要な対局環境が現れた場合は
  オプション追加で対応する（現時点では想定しない）
