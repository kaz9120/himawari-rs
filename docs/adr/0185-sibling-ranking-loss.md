# 0185: 兄弟局面のランキング損失を回帰へ足す

- Status: proposed
- Date: 2026-08-23
- 関連ADR: [0038](0038-training-data-format.md), [0089](0089-improvement-criteria.md), [0129](0129-auxiliary-heads.md), [0136](0136-quiet-teacher-positions.md), [0158](0158-mirror-factorizer.md), [0183](0183-stacked-pairwise-product.md), [0184](0184-cross-view-product.md)

## Context

現行の損失は局面1つに数値1つの回帰で、**探索が実際に要求する
「兄弟局面の順序」を見ていない**。探索が評価関数に問うのは「この手と
あの手のどちらが良いか」であり、絶対値の精度ではない。lossが誤差の
範囲でも対局で52 Elo負ける（[ADR-0172](0172-multihot-input.md)）のは、
物差しと要求のこのずれの現れでもある。

教師データには使っていない信号が眠っている。PSVのmoveフィールドは
生成エンジンがdepth 9で選んだ最善手である。ここから「最善手の子は、
他のどの合法手の子よりも親にとって良い」という順序制約が、1局面あたり
合法手の数だけ（平均80本前後）付いてくる。**教師データは1バイトも
増えない**。Bonanza法（比較学習）の目的関数を、NNUEの回帰と
併用する形へ戻す。

[ADR-0129](0129-auxiliary-heads.md)の指し手ヘッド（−300 Elo）とは別物で
ある。あれは指し手を当てる分類ヘッドを足した。本ADRが課すのは評価値の
出力の順序だけで、ヘッドも推論経路も変えない。

構造の2案（[ADR-0183](0183-stacked-pairwise-product.md)・
[ADR-0184](0184-cross-view-product.md)）が連続で棄却され、掛け算の線は
一巡した。損失の側が次の本命である。

## 選択肢と比較

### 案A: 制約を親局面の静的評価に課す

子の評価を使わず実装が軽いが、探索が使うのはqsearch後の値である。
取り合いの途中の子に制約を課すと、静止化（[ADR-0136](0136-quiet-teacher-positions.md)）
で消した不整合を再導入する。

### 案B: 制約をqsearchの葉に課す（採用）

各子 `P·m'` からqsearchのPV葉まで進め、葉の評価に順序を課す。
静止化と同じ規約で、計算の主コストはこの葉歩きになる。

### 案C: 全合法手に制約を課す

情報は最大だが、生成も学習も合法手数倍のコストになる。まず負例2本の
サンプリングで信号の有無を確かめる。

## Decision

**案Bを負例2本で採る**。

### データ生成（`psv rank`）

静止化前の `train_300M.psv` を源とする（moveフィールドが要るため。
静止化後のレコードは葉に置き換わっており、親と最善手の対応が崩れている）。
レコードごとの手順は次のとおり。

1. 局面Pを復元し、教師の最善手mを `move16` から得る。非合法なら捨てる
2. 合法手が3手未満なら捨てる。m以外から負例2手を一様に引く
   （乱数はレコード通し番号から決定論で引く）
3. 3つの子それぞれについて `do_move` と `walk_to_quiet(16)` で葉まで進め、packする
4. 正例・負例・負例の順で40バイト×3＝120バイトの群として書く。
   各レコードの予備バイト（b[39]）に、親からの手数の偶奇を入れる。
   学習側はこの偶奇で葉の評価値を親視点の符号へ戻す

生成は入力を分割して並列に走らせ、結合する。1億群（子のqsearch 3億回）を
第1弾とする。

### 損失

回帰と同じシグモイド空間で、ヒンジを取る。親視点の値を
`u = (−1)^parity · v(葉)` として、次の式で足す。

```
L_rank = mean( relu( δ + σ(u⁻/600) − σ(u⁺/600) ) )    δ = 0.02
L = L_reg + α · L_rank                                  α = 1.0
```

マージンδを小さく取るのは、教師の最善手がdepth 9の判断であり
誤りうるためである。ヒンジなので、順序が既に十分ついている群は勾配を
出さない。αとδは着手時の宣言値で、走行後に動かさない。学習が発散した
場合に限り1回だけ再較正し、そのときは数値と理由をここへ追記する。

ランキングのミニバッチは4,096群（12,288局面）を回帰バッチ16,384へ
併走させる。ステップの計算はおよそ1.75倍になる。

### 検証

エンジンは無変更なので、対局は**同一ビルドのネット差し替え**で測る
（`hmwr sprt net`）。NPS計測は要らない。

1. 機能検証に相当するのは生成データの検査。群の構造・偶奇・葉の静止性を
   サンプリングで確かめる
2. 3億の測定台で学習し、`pairprod_300M_q1` と対局（時間制とノード数固定）
3. 通れば29.9億で本学習し、SPRT既定条件にかける。ランキング群も
   29.9億の源から作り直して増やす

**valid lossで足切りしない**（[ADR-0158](0158-mirror-factorizer.md)）。
回帰lossはランキング項の分だけ上がりうるが、それは物差しの側の問題である。

**撤退ライン**。3億の時間制で負けたら棄却する。棄却時は、ヒンジの
発火率（順序が壊れている群の割合）を学習前後で測り、「順序は改善したが
棋力に繋がらない」のか「順序自体が改善しない」のかを切り分けて記録する。

## Consequences

- 教師データの置き場が1つ増える（`data/train/rank_*.rankpsv`、120B/群）
- 学習時間が1.75倍前後になる。3億の測定台で2.5時間程度
- 生成エンジンの最善手を正解とみなす仮定が入る。教師より強くなった
  領域では制約が足を引っ張りうる。マージンとヒンジで緩和するが、
  効き始めたら負例の選び方（浅い探索で上位の手を外すなど）が次の調整軸になる
- 案C（全合法手）と、λ側との配合調整が後続の実験として残る

## 測定・第1段（2026-08-24、3億の測定台）

| 段階 | 結果 |
|---|---|
| 生成 | 1億レコードから9,594万群（合法手3未満の4%を除く）。4分割並列で10分 |
| 学習 | ヒンジ発火率83%→21.4%。valid loss 0.49179（積1段は0.49240。判断には使わない） |
| 対局・時間制 10+0.1 | 4,176局 **+19.6 [+9.2, +30.0]**、LLR +3.04で**H1** |
| 対局・ノード数固定30万 | 2,754局 **+28.1 [+15.4, +40.8]**、LLR +3.06で**H1** |

対局は同一ビルドのネット差し替え（`pairprod_300M_q1` 対 `pairrank_300M_q1`）。
**両条件H1で、ノード数固定のほうが大きい**。仮説（順序の学習はノード
効率に効く）と整合する。回帰lossもランキング項を併走させたまま悪化して
いない。

生成の実測は候補メモの見積もりを大きく下回った。単スレッド4〜5万局面/秒
で、qsearchの葉歩きは支配的コストにならなかった。

第2段は29.9億で行う。ランキング群は `train_2990M.psv`（静止化前）の
先頭2.1億レコードから約2億群へ増やす。学習後は並べ替え
（[ADR-0168](0168-ft-dim-reorder.md)）を当ててから、現行ネット
`pairprod_2990M_q1_reorder` とSPRT既定条件で検収する。
