# 0259: 配分の分母の起点を48から64へ増やす

- Status: rejected（10+0.33のSPRTでH0、−5.1 [−12.0, +1.9]。48を据え置く）
- Date: 2026-11-05
- 関連ADR: [0021](0021-time-management.md), [0102](0102-move-horizon.md), [0253](0253-short-tc-floors.md), [0256](0256-slowmover-allocation.md), [0257](0257-cut-settled-iteration.md), [0258](0258-maximum-ratio.md)

## Context

floodgateの300+10で、Himawariは序中盤に持ち時間を使い、終盤は加算の10秒前後で指す。
2026-10-01以降の600局の手数帯ごとの集計は次のとおりである。

| 手数 | 平均の消費[秒] | 残り時間の中央値[秒] |
|---|---|---|
| 31〜60 | 15.6 | 198 |
| 61〜90 | 14.1 | 111 |
| 91〜120 | 11.6 | 46 |
| 121〜150 | 9.9 | 23 |

配分は `残り / max(48 − 手数/2, 16) + 加算` で、手数80で分母が下限の16へ着く。

SlowMover（[ADR-0256](0256-slowmover-allocation.md)）、反復の打ち切り（[ADR-0257](0257-cut-settled-iteration.md)）、
上限の倍率（[ADR-0258](0258-maximum-ratio.md)）はどれも利得を出さなかった。分母の起点は
[ADR-0253](0253-short-tc-floors.md)の後の配分では測っていない。

## 選択肢と比較

### 案A: 参照実装のmove horizon方式へ替える（不採用）

[ADR-0102](0102-move-horizon.md)で−107.2だった。ADR-0253より前の配分での測定だが、式の形まで替えると
動かす変数が増える。

### 案B: 起点を48から64へ増やす（採用）

式の形を保ったまま、手数112までの配分を減らす。下限の16は変えない。300+10の開始局面の配分は
16.25秒から14.69秒になる。

## Decision

案Bを採る。

時間管理の中だけの変更なので、固定ノードと固定深さの探索は変わらない。

### 合格の条件

- Eloの判定: 10+0.33のSPRT（elo0=0、elo1=5）。既定の10+0.1は加算の比率が1/100で、
  floodgateの1/30より配分の式の効きが違うので、比率を揃える
- Elo以外の条件: 切れ負けが1%以下
- 採否: 両方を満たしたときだけ入れる

固定深さのノード数は一致する見込みなので、`--no-verify` で起動して別に確かめる。

### 事前登録

- 仮説: 序中盤の時間を手数の遅い局面へ回すと強くなる
- 動かす変数: 分母の起点だけ。評価関数と開始局面集は固定する
- H1なら入れる。300+10そのものでは測っていないので、floodgateの切れ負けとレートを放流後に確かめる
- H0なら棄却し、48を据え置く。ほかの起点は試さない
- 判定が出ないまま10,000ペアに届いたら、ADR-0217の追記に従い点推定で決める

## SPRT

10+0.33、elo0=0、elo1=5で測った。比較元はmainの `f52cb2d` である。固定深さのノード数は変更前と全局面で一致した。

| 対局数 | W-D-L | Elo [95%CI] | LLR | 切れ負け | 判定 |
|---|---|---|---|---|---|
| 8770 | 3921-800-4049 | −5.1 [−12.0, +1.9] | −3.00 | 0 | H0 |

事前登録どおり棄却し、48を据え置く。ほかの起点は試さない。

## Consequences

- コードは変えない。300+10の配分も変わらない
- 配分の定数を動かす案は、SlowMover、maximumの倍率、分母の起点のどれもH1に届かなかった
