# 0017: 指し手生成の分類と成り規約

- Status: accepted
- Date: 2026-07-17
- 関連ADR: [0012](0012-move-encoding.md), [0016](0016-legality-check.md)

## Context

探索は「取る手だけ」「静かな手だけ」のように指し手を段階的に
使うため、生成を種類別に分ける。また将棋には成り・不成の選択が
あり、合法だが実戦的に無意味な不成（歩・香・角・飛など）を
生成するかどうかで、探索の分岐数とperftの意味が変わる。
perftの公開値は全合法手を数える定義なので、探索用の生成と
検証用の生成を両立させる必要がある。

## 選択肢と比較

### 生成の網羅性

#### 案A: 常に全合法手を生成し、探索側でフィルタ

生成器は1系統で済むが、無意味な不成が毎ノードでバッファに
積まれ、オーダリングとフィルタのコストがかかる。

#### 案B: 生成モードを2系統持つ（やねうら王のGenerateAllLegalMoves相当）

探索用（Normal）は無意味な不成を生成せず、検証・詰将棋用（All）は
全合法手を生成する。生成器はジェネリクスのモード引数で分岐し、
実行時コストはない。perft・property testはAllを使い、探索はNormalを使う。

### 不成の扱い（Normalモード）

無意味さの判断は駒種で異なる。歩・角・飛は成りが移動能力を
完全に包含するため不成に価値がない（打ち歩詰め回避などの例外は
Allモードで扱える）。香の中段不成・桂の不成は稀に意味があるが、
探索v1では価値に対してコストが見合わない。銀は成り・不成の
両方に実戦価値があるため両方生成する。

**桂についてはこの判断が誤りだった（[ADR-0173](0173-knight-non-promotion-movegen.md)）。**
成桂は金の動きなので、桂の王手とは利きが違う。「成ると王手にならないが、
不成なら王手になる」形があり、落とすと相手の詰め手順ごと探索木から消える。
floodgateの実戦で敗着11局がこの型だった。参照実装（やねうら王・Apery）も
桂の不成だけは全生成フラグで条件付けていない。

## Decision

案B（2モード）を採用する。生成分類と合わせて次のとおり定める。

### 生成分類

```
Captures     取る手＋歩の成り（qsearchの主対象）
Quiets       取らない手（Capturesの補集合）
Evasions     王手回避（ADR-0016の専用生成）
NonEvasions  Captures ∪ Quiets（非王手時の全生成）
QuietChecks  取らない王手（P2の静止探索・P3のmate1plyで使用。枠だけ定義）
```

歩の成りは駒得に準じる価値があるためCapturesに含める
（やねうら王のCAPTURES_PRO_PLUSと同じ判断）。

### 成り規約（Normalモード）

| 駒 | 生成する手 |
|---|---|
| 歩・角・飛 | 成れるときは成りのみ。不成は生成しない |
| 香 | 2段目への不成は生成する（3段目以遠の成れる不成は生成しない）、1段目は成りのみ |
| 桂 | 3段目への不成も生成する（[ADR-0173](0173-knight-non-promotion-movegen.md)で訂正）。1・2段目の不成は行き所がなく元々非合法 |
| 銀 | 成り・不成の両方を生成する |
| 金類・玉 | 成りなし |

Allモードは上記に加え、合法な不成をすべて生成する。

### 行き所のない駒・二歩（両モード共通で除外）

- 歩・香の1段目、桂の1・2段目への移動・打ちは生成しない
  （移動先マスクをテーブルで持ち、分岐レスに除外）
- 二歩: 自歩のある筋への歩打ちを除外する。歩のbitboardから
  「歩のある筋の全マスク」を作り（筋は9bit連続なので、筋ごとの
  占有判定はマスクとの積で書ける）、歩打ち候補から引く

### MoveList

固定長配列（608要素）のスタック確保。生成関数は
`fn generate<const KIND: ...>(pos: &Position, list: &mut MoveList)` の
形でモードと分類をコンパイル時に分岐する。

## Consequences

- perft・property test（All）と探索（Normal）で同じ生成器を
  モード違いで共有でき、検証が探索経路と同じコードを通る
- Normalの成り規約は探索の枝を減らすが、香2段不成のような
  境界判断は将来SPRTで見直してよい（規約変更はこのADRの更新で行う）
- 打ち歩詰め回避のための大駒不成のような極稀な手はNormalでは
  指せない。実戦での影響は無視できると判断するが、詰将棋対応
  （P3のdf-pn以降）ではAllモードを使う
- 分類の追加（ProbCut用など）はP2以降、必要になった時点で
  このADRを更新して行う
