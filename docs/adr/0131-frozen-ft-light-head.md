# 0131: 良いFTを凍結して軽量ヘッドを載せる作り方を、本番規模で確かめる

- Status: proposed
- Date: 2026-08-03
- 関連ADR: [0034](0034-nnue-architecture.md), [0066](0066-feature-factorizer.md), [0089](0089-improvement-criteria.md), [0127](0127-net-shape-bench.md), [0128](0128-round-robin-league.md), [0129](0129-auxiliary-heads.md), [0130](0130-freeze-ft.md)

## Context

[ADR-0127](0127-net-shape-bench.md)の最後で、後段を `256x16`（2層）へ削ると **+56.0 Elo**
になった。1600局・10+0.1の測定である。FTを太らせる8構成がどれも基準に届かなかったのに対し、
唯一の勝ち筋になった。

**ただしこの数字は、そのままmainへ入れられる形で測っていない。** [ADR-0130](0130-freeze-ft.md)が
定めたとおり、FTを固定した測定は足切りにしか使えない。

### 何がまだ確かめられていないか

誤解しやすいので先に書く。**あの測定で凍結したFTは、すでに19.9億局面で学習したものである**
（`halfkp_1900M_fact`）。FTの規模は本番と同じで、そこは確かめ直す必要がない。小規模だったのは
後段の学習と、比較の取り方である。穴は3つある。

| 穴 | 中身 |
|---|---|
| 基準 | 比べた `256x32x32` は、同じ手順（FT凍結・3億局面）で後段を学習し直したものだった。**現行ネットそのものとは比べていない** |
| 後段の学習量 | 3億局面で止めた。19.9億へ増やすと差が動くかを見ていない |
| 作り方 | まるごと学習した `256x16` と比べていない。**FTを凍結したことに意味があったのか**を分離できていない |

3つ目が本題である。オーナーの見立ては「良いFTを学習し、そこから軽量なヘッドで学習する」形が
効いており、凍結が破滅的忘却を防いだというものである（2026-08-03オーナー指摘）。
[ADR-0129](0129-auxiliary-heads.md)も同じ方向を示唆する。**偏ったFTでも評価値方向へ学習し直せば
戻せる**（案D'が−1.8で生き残った）という結果は、裏返せば「学習し直すとFTが元の性質を失う」
ことでもある。

この見立てが正しいなら、今後の関心は「どんなFTを、どう作るか」へ移る。**だからここで、形の
効果と作り方の効果を分けておく必要がある。**

## 選択肢と比較

### 案A: 256x16をまるごと学習し、現行とSPRTだけ回す

[ADR-0127](0127-net-shape-bench.md)のDecisionが求めている最小の形である。学習1回・SPRT1回で
済み、いちばん安い（学習2.5時間）。

ただし**通っても落ちても、なぜそうなったかが分からない。** 落ちたときに「形が悪いのか、
まるごと学習したのが悪いのか」を切り分けられず、次の一手が決まらない。

### 案B: 2×2で4通りを比べる

後段の形（`32x32` か `16`）と作り方（まるごと学習かFT凍結）を直交させる。

| | 後段 32x32 | 後段 16 |
|---|---|---|
| **まるごと学習** | 現行ネット（学習済み） | 条件B |
| **FT凍結+後段のみ** | 条件C | 条件A |

左上は現行の `halfkp_1900M_fact` そのもので、**新たに学習する必要がない。** 追加の学習は3本、
合計およそ4.5時間で足りる。FT凍結の2本は後段だけを更新するので1本1時間、まるごと学習は
1本2.5時間である。

主効果を2つとも読める。行を比べれば作り方の効果が、列を比べれば形の効果が出る。

## Decision

案Bを採る。**3条件を19.9億局面で学習し、現行を加えた4者でリーグ戦を回し、勝った構成を
現行とSPRTで決着させる。**

**決め手は、追加費用が案Aの2倍しかないことである。** 案Aは学習2.5時間、案Bは4.5時間で、差は
2時間にすぎない。リーグ戦とSPRTは案Aでも要る。**2時間で「なぜ効いたか」が読めるなら払う価値が
ある。** ADR-0127が+56.0の理由を読み違えた前科もある（事前見積もりを76 Elo外した）。

### 測る条件

学習条件は[ADR-0127](0127-net-shape-bench.md)と揃える。`--batch-loader --dense-ft --factorized`、
batch 16384、peak_lr 0.001、λ0.7、1エポック、seed 0。

| 条件 | 構成 | 初期値 | FT | 出力 |
|---|---|---|---|---|
| A | `256x16` | `halfkp_1900M_fact` | 凍結 | `frz1900-256x16-s0` |
| C | `256x32x32` | `halfkp_1900M_fact` | 凍結 | `frz1900-256x32x32-s0` |
| B | `256x16` | 乱数 | 学習する | `full1900-256x16-s0` |

条件Cは後段の形が現行と同じなので、`--init-net` が後段まで読む。**現行ネットの続きを、FTだけ
止めて学習する形になる。** 条件Aの後段は形が違うので乱数から始まる。この非対称は残るが、
19.9億局面はどちらの後段にも十分すぎる量なので、初期値の差は収束までに消えると見る。

### デバイスをmpsへ揃える

[ADR-0127](0127-net-shape-bench.md)の3億局面の測定はCPUで回した。**本番規模で現行ネットと
比べるなら、現行ネットと同じmpsへ揃える。** `halfkp_1900M_fact` はmpsで学習している。
FT凍結の実測は595k samples/sで、19.9億が1時間を切る。

`scripts/train-shapes.sh` に `SHAPE_DEVICE` と `SHAPE_TAG` を足した。札は出力名と実験名の頭に
付き、[ADR-0127](0127-net-shape-bench.md)の3億局面の結果を上書きせずに済む。

### 本番規模ではmmapが要る

最初の実行はOOM（`Killed: 9`）で落ちた。`train_1900M.psv` は79.7GBで、このマシンのRAM 48GBに
載らない。3億局面（12GB）までは載っていたので、`scripts/train-shapes.sh` は `--mmap` を
渡していなかった。`SHAPE_MMAP` を足して渡すようにした。

**現行ネットもこの経路で学習している**ので、条件は揃う。mmap時のシャッフルはチャンク単位に
なるが（`dataset.py` の `PsvBatchLoader`）、比べる4者がすべて同じ扱いを受ける。
実測は470k〜560k samples/sで、19.9億が約1時間で終わる。

### 判断の順序

1. **リーグ戦**（[ADR-0128](0128-round-robin-league.md)）で4者を総当たりし、順位を出す。
   持ち時間10+0.1。速度の差がそのまま効く条件でないと、後段を削る価値を測れない
2. 1位が現行なら、そこで終わる。**+56.0は足切りの中でだけ成り立つ数字だったと記録して棄却する**
3. 1位が現行以外なら、その構成を現行と**SPRT**にかける（既定条件、elo0=0、elo1=5）

リーグ戦を挟むのは、SPRTを3回回すより安いからである。総当たりは候補同士の直接対決を含むので、
上位の判別が個別のガントレットより効く。

### valid lossは判断に使わない

[ADR-0127](0127-net-shape-bench.md)でlossとEloが逆相関した。0.001を下回る差は初期値のばらつきに
埋もれる。**記録はするが、順位づけには使わない。**

## Consequences

- 学習が4.5時間かかる。内訳は条件A・Cが各1時間、条件Bが2.5時間である
- リーグ戦は4者6カードなので、[ADR-0127](0127-net-shape-bench.md)の28カードより軽い
- **エンジンバイナリと評価ファイルは対で扱う。** `256x16` は `HIMAWARI_ARCH=256x16` でビルドした
  バイナリでしか読めない。`scripts/build-shapes.sh` が対で作る
- `SHAPE_TAG` の既定を `train` にしたので、レジストリの実験名が `shape_*` から `train_*` へ
  変わる。過去の行はそのまま残る
- **どちらの主効果が出ても次の一手が決まる。** 作り方が効いていれば、関心は「どうFTを作るか」へ
  移り、[ADR-0129](0129-auxiliary-heads.md)の補助ヘッドや事前学習が本線になる。形だけが効いて
  いれば、output bucketなど後段の設計が本線になる
- 条件Bが勝った場合、FT凍結は足切りの道具に戻る。[ADR-0130](0130-freeze-ft.md)の位置づけは
  変わらない
