# 0142: df-pnの詰み探索をrootへ並走させる

- Status: proposed
- Date: 2026-08-04
- 関連ADR: [0020](0020-search-threading.md), [0029](0029-mate-search.md), [0030](0030-nyugyoku-declaration.md), [0088](0088-mate-early-stop.md), [0089](0089-improvement-criteria.md)

## Context

詰み探索は1手詰め（mate_1ply）しかない。長手数の詰みは
[ADR-0029](0029-mate-search.md)がスコープ外としてバックログへ残したまま
である。

floodgateの初参戦（30局、レート3186）で、負けはすべて相手3121以上・
長手数で時間枯渇だった。終盤で読み切れずに時間を使い切る負け方である。
[ADR-0089](0089-improvement-criteria.md)の3軸のうち「終盤の正確さ」へ
いちばん直接に効くのが詰み探索になる。詰みを読み切れば、探索は評価値の
比較をやめて手を確定でき、時間も残る。将棋の詰み探索はdf-pnが
標準で、実装の蓄積も厚い（脊尾の原論文、やねうら王のtanuki-詰め等）。

## 選択肢と比較

### 案A: rootで専用スレッドを並走させる

本探索と独立に、root局面（と相手玉）へdf-pnを走らせる。詰みが見つかれば
本探索の結果を上書きする。探索本体と疎結合で、NPSを落とさない
（コアを1つ使う。`Threads` の配分は要設計）。やねうら王の詰みルーチンの
使い方に相当する。

### 案B: 探索ノード内で浅いdf-pnを呼ぶ

終盤の内部ノードでも詰みが拾えるが、呼び出しコストの管理が難しい。
mate_1plyの通常探索組み込み（[ADR-0139](0139-mate1ply-in-search-retry.md)）
と役割が重なる。案Aで基盤を作ってから検討する後段とする。

### 案C: 詰将棋エンジンとして独立させ、対局では使わない

検証は楽だが棋力に寄与しない。

## Decision

案Aを採る。工程が長いので3段に切り、各段が単独で価値を持つ形にする。

1. **単体ソルバ**。df-pn本体（証明数・反証数、置換表、優越関係、
   千日手・無限ループ対策）を独立モジュールとして実装し、詰将棋集で
   解答率と速度を測る。USIの `go mate` にもつなぐ。ここまでは
   棋力に触れない「その他」のPRで入れられる
2. **root並走**。専用スレッド1本で自玉・相手玉の詰みを常時探索し、
   見つけたら本探索へ通知する。時間管理との接続（詰み発見時の即指し）は
   [ADR-0088](0088-mate-early-stop.md)（proposed）と同じ論点なので、
   あちらの決定と整合させる
3. **SPRT**。既定条件で測る。10+0.1は終盤が長いfloodgate条件より
   詰み探索に不利な短時間だが、まず既定で測り、H0なら300+10相当の
   条件でも測って条件依存を記録する

**Elo見込みの根拠は、実戦の負け筋（長手数終盤の時間枯渇）に直接
対応することと、詰み探索を持つエンジンと持たないエンジンの終盤力の差が
将棋では定説であることである**。

**撤退ライン**。詰将棋集で実用的な解答率（5手詰め99%・9手詰め9割以上を
目安）に達しない実装は対局へ進めない。SPRTで両条件H0なら、宣言勝ち
（[ADR-0030](0030-nyugyoku-declaration.md)）周りの限定用途だけ残して閉じる。

## Consequences

- 実装量が大きい。独立モジュールの新規実装なので、1〜2週間の工程を見込む
- スレッド配分が変わる（`Threads=N` のうち1本を詰み専用へ）。
  Threads=1の既定では並走できないので、本探索の合間に呼ぶ縮退動作か、
  既定でオフのオプションにするかを工程2で決める
- 詰み証明の置換表メモリが別枠で要る（USIオプション化する）
- 単体ソルバは教師データ生成（[ADR-0144](0144-selfplay-teacher-loop.md)の
  詰み局面ラベル）や定跡の終盤検証にも流用できる
