# 0090: lmrDepth基準を導入しSEEベースの枝刈りを入れる

- Status: accepted
- Date: 2026-07-28
- 関連ADR: [0089](0089-improvement-criteria.md), [0076](0076-lmr-fixed-point-ttpv.md), [0074](0074-feature-verification.md), [0028](0028-pruning-extensions.md)

## Context

[ADR-0089](0089-improvement-criteria.md)で枝刈りを危険度で並べたところ、
**危険度の低いSEEベースの枝刈りが未実装のまま、危険度の高いものが
すべて入っている**状態だと分かった。RFP・futility・LMP・NMP・ProbCutは
実装済みで、SEEベースの2件（静かな手・取る手）だけが残っている。

SEEは移動先での駒の取り合いを静的に解く。読み抜けのリスクが小さい。
「大きく駒損することが静的に確定している手」を読まずに捨てるのは、
評価値の推定で捨てるRFPやfutilityより安全である。

この候補は[ADR-0089](0089-improvement-criteria.md)の軸2（ノード効率）に
乗る。同じPVへ到達するノード数を減らし、その分だけ深く読める。

前提が1つある。やねうら王の閾値は `lmrDepth` を尺度にしている。

```cpp
// 静かな手
if (!pos.see_ge(move, -25 * lmrDepth * lmrDepth)) continue;
// 取る手
if (!pos.see_ge(move, -std::max(167 * depth + captHist * 34 / 1024, 0))) continue;
```

`lmrDepth` は「LMRで削ったあとに実際に読む深さ」で、生の `depth` 以下に
なる。本エンジンはこの量を持たず、枝刈りはすべて生の `depth` で判断
している。生の深さで閾値を決めると、深いノードほど許容する駒損が
大きくなりすぎる。実際に浅く読む手を、深く読む手と同じ基準で扱うことに
なるためである。

## 選択肢と比較

### 案A: lmrDepthを導入し、SEE枝刈り2件をまとめて入れる

延長（`new_depth`）とLMRのリダクション量をムーブループの枝刈りより前で
決め、`lmr_depth = new_depth - reduction` を算出する。この値を尺度に
SEE枝刈りを入れる。

リダクション量は枝刈りの尺度と実際の浅い探索で同じ値を使う。二重に
計算しない。

3つをまとめて1つのSPRTで測る。[ADR-0084](0084-lmr-cutnode.md)で
「1つずつ積む」方針が否定された経緯に沿う。lmrDepthの導入は単独では
探索を変えない（機能検証で確認済み）ため、単独でSPRTにかける意味がない。

### 案B: 生のdepthを尺度にSEE枝刈りだけ入れる

lmrDepthの導入を避け、`-25 * depth^2` とする。

深いノードで閾値が過大になる。depth=10なら -2500（歩27枚分）で、
事実上ほとんどの手が通る。浅いノードでは逆に厳しくなる。出典の意図
（実際に読む深さで測る）から外れ、[ADR-0075](0075-razoring-margin.md)と
同じ「スケールを取り違える」失敗になりかねない。

### 案C: 静かな手だけ入れる

取る手のSEE枝刈りはcapture historyを前提にしている（`captHist * 34/1024`
の項）。本エンジンにcapture historyはない。

captHist項を落とせば `-167 * depth` で成立する。この項は閾値を上下に
振るだけで、枝刈りの骨格ではない。落として入れる。

## Decision

案Aを採る。

```
lmr_depth = max(new_depth - max(reduction/1024, 0), 0)

非PVノード・非王手中・2手目以降・詰まされ筋でない、で判定する:
  取る手   : see_ge(m, -167 * depth)
  静かな手 : see_ge(m, -25 * lmr_depth^2)
を満たさない手は読まずに捨てる。
```

`SEE_QUIET_COEF = 25`、`SEE_CAPTURE_COEF = 167`。出典はやねうら王で、
SEEの駒価値は歩=90で本エンジンと同系列である（[ADR-0074](0074-feature-verification.md)で
確認済み）。閾値をそのまま使える。

閾値が負なので「多少の駒損は許し、大きな損だけ刈る」判定になる。
`lmr_depth` が大きい（＝深く読む）手ほど許容が広がり、浅くしか読まない
手ほど厳しく刈る。

延長の計算をムーブループの前半へ移した。これは等価変換で、`new_depth` の
値も使われ方も変わらない。

### 打つ手の扱い

本エンジンの `see_ge` は打つ手に対して常に0を返す（`Position::see_ge`）。
打った駒がその場で取られる筋を見ていない。したがって打つ手はこの枝刈りを
すり抜ける。

将棋は打つ手の比率が高く、取り逃しは小さくない。ただし打ちのSEEを正しく
解くのは `see_ge` 自体の変更で、本ADRの範囲を超える。別途扱う。
すり抜けは「刈らない」方向の誤りなので、読み抜けは起こさない。

## 機能検証（2026-07-28）

lmrDepthの導入だけを入れた時点で、固定深さ11の4局面がすべてノード数
完全一致だった。等価変換であることを確認できている。

SEE枝刈りを載せた状態での比較は次のとおり。

| 局面 | 変更前 | 変更後 | 変化 | 評価値 | 最善手 |
|---|---|---|---|---|---|
| 1 | 93,667 | 91,902 | -2% | 47 → 40 | 6i7h → 2g2f |
| 2 | 68,201 | 97,310 | +43% | -127 → -70 | 同じ |
| 3 | 738,171 | 331,951 | -55% | 503 → 960 | 同じ |
| 4 | 118,822 | 98,552 | -17% | -138 → -163 | 7b7c → 8c8d |

4局面中3局面で減り、局面3で55%減った。枝刈りとして機能している。
局面2で増えたのは、刈った結果として読み筋が変わり、別の分岐を深く
読んだためと見ている。

局面3の評価値が503から960へ動いた。駒損する手を切ったことで、
本筋の評価が上がった形である。最善手は変わらない。

## SPRT結果（2026-07-29）

**H1採択**。782ペア（1564局）で **+45.6 Elo [+28.8, +62.6]**、LLR +2.98。
W-D-L は +859 =50 -655。

判定に1564局しか要していない。効果が大きいためである。
[ADR-0085](0085-correction-history-multi.md)の+17.7が4410局、
[ADR-0078](0078-tt-probcut.md)の+15.6が5404局を要したのと対照的で、
1局あたりの情報量が多い。

[ADR-0089](0089-improvement-criteria.md)の「危険度の低い枝刈りを
実装しきってはいない」という見立てが正しかった。危険度の高い枝刈りが
すべて揃った状態でも、SEEという安全な判定を足す余地が残っていた。

## Consequences

`lmr_depth` という尺度が入る。他の枝刈り（LMP・futility）も生の `depth`
で判断しているが、本ADRでは変えない。尺度の付け替えは1件ずつ測る。

SEEの呼び出しがムーブループに入るぶん、1手あたりのコストが増える。
`see_ge` は移動先の取り合いを解くだけで、探索を伴わない。刈れる手が
多ければ差し引きで得になる。NPSへの影響はSPRTの前後で確認する。

打つ手をすり抜ける制約が残る。`see_ge` が打ちを扱えるようになれば、
この枝刈りの効きが上がる。IDEAS.mdへ候補として残す。
