# 0039: 学習器v1（教師あり）

- Status: superseded（[ADR-0040](0040-training-infra-v2.md)がPyTorchへ移行し、2026-08-01に実装を削除）
- Date: 2026-07-20
- 関連ADR: [0034](0034-nnue-architecture.md), [0036](0036-nnue-quantization-simd.md), [0037](0037-nnue-file-format.md), [0038](0038-training-data-format.md)

## Context

P5の出口条件は「自前学習ネットが駒割にSPRT有意勝ち」。
v1の学習基盤・目的関数・量子化の対応を決める。
RL・世代ループ・多ヘッド化は後続ADRに送る。

## Decision

### 基盤: 依存ゼロの自前Rust学習器

- toolsに `train` バイナリを実装する。外部MLフレームワークは
  使わない。f32重み、Adam、ミニバッチSGD、スレッドの
  データ並列（バッチ分割で勾配を集計）
- 学習対象は既存アーキテクチャ全体（FT 256×2、利き塔800→32、
  隠れ32-32-1。ADR-0034）。ネットワーク構造の変更はしない
- データ供給はPSVのストリーミング読み（ADR-0038）。複数
  スレッドでデコードと特徴抽出を行う。シャッフルは前処理済み
  を前提とする

### float意味論と量子化の一対一対応

- 活性は clamp(x, 0, 1)。整数推論のClippedReLU(0..127)と
  スケール127で対応する
- 量子化スケール: FT系=127、隠れ層=64（ADR-0036の>>6と対応）、
  出力はシグモイドスケール600とFV_SCALE=16から導出する
- 学習中から重みを量子化可能域（i16/i8の表現範囲）にクリップし、
  書き出し時の丸め劣化を抑える
- 書き出しは学習来歴（データ識別・λ・lr・ステップ数）付きの
  独自形式（ADR-0037）。量子化前後の評価値相関をheld-out局面で
  検査する

### 損失と初期化

- 教師score→sigmoid(cp/600)の勝率と、game_resultの勝敗
  （0/0.5/1）をλでblendした値への交差エントロピー。λは
  CLIパラメータ、既定0.7
- 初期化は乱数から。公開ネットのウォームスタート（nn.bin→
  第1塔流用、ADR-0037）は対照実験とし、配布ネットのライセンスに
  依存しないネットを本線とする

### 外部フレームワークへの移行条件

自前実装が前提だが、次のいずれかで PyTorch 等の導入を別ADRで
再検討する（2026-07-20のオーナーレビューで合意）。

- 学習スループットが不足する（目安: 総合で10万局面/秒を大きく
  下回り、学習計画が日単位で破綻する）
- 多ヘッド化・特徴変種など、構造をいじる実験段階に入り、
  自動微分の恩恵が大きくなる
- CUDA環境を導入する

移行してもPSV入力（ADR-0038）と独自形式出力（ADR-0037）は
不変とし、学習器は差し替え可能な部品にする。自前実装は移行後も
勾配・量子化の参照実装として残す。

### 検証

- 勾配の数値微分一致（縮小ネットでCI）
- 過学習スモーク（小データで損失がほぼ0まで下がる）
- P5出口SPRT: 学習ネット vs 駒割（10+0.1秒、elo[0,5]）。
  参考記録として vs 公開ネットの相対Eloも測る

## Consequences

- フレームワーク非依存で再現性と移植性が高い。学習の再現条件は
  来歴文字列で追跡できる（ADR-0007の残課題に接続）
- GPUを使わないため大規模学習は時間がかかる。まず数千万局面
  規模で出口条件を満たし、性能不足が実測されたらMetal等の
  利用を別ADRで再検討する
- 学習器と推論器で同じ特徴抽出コード（engineのnnueモジュール）を
  共有するため、特徴のバグは外部照合済みの推論側で抑えられている

## 2026-08-01: 実装を削除した

[ADR-0040](0040-training-infra-v2.md)はPyTorchへ移すにあたり、Rust学習器を
「勾配・量子化の参照実装」として残すと決めた。**その役割は果たされなかった。**

- 生成されたネットは0個である。`data/nets/` の全ネットが `train-v2-pytorch` 由来
- PyTorch実装と突き合わせる仕組みが作られなかった。`crates/tools/src/bin/train/` の
  テスト3件はいずれもRust実装の内部整合（数値微分との勾配一致、小データへの過学習、
  量子化とfloatの一致）で、Python側とは比べていない
- `training/test_forward.py` はdocコメントに「Rust参照実装との順伝播一致テスト」と
  書いてあるが、実装はPythonのfloatと量子化模倣の比較で、Rustを呼んでいない
- 参照は `crates/tools/Cargo.toml` の `[[bin]]` だけで、docs・scripts・CIからゼロ

1212行を消した。**参照実装は、突き合わせて初めて参照実装になる。** 突き合わせる
仕組みがないまま置いておくと、実装が古びても誰も気づかない。必要になれば履歴から
戻せる（2026-08-01オーナー判断）。
