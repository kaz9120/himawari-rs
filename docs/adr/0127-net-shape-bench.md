# 0127: ネットワーク構造の探索は、学習前のNPS計測から始める

- Status: proposed
- Date: 2026-08-01
- 関連ADR: [0034](0034-nnue-architecture.md), [0045](0045-remove-effect-tower.md), [0067](0067-ft-dimension-512.md), [0089](0089-improvement-criteria.md), [0124](0124-hot-path-allocs.md)

## Context

追従が一巡し（[ADR-0109](0109-reference-parity.md)〜[0119](0119-g10-book.md)）、探索は参照実装と
同じ構造になった。**先へ行くには評価関数を伸ばすしかない**（[ADR-0120](0120-after-parity.md)）。

ネットワーク構造には3つの伸びしろがある。FTを太らせる、隠れ層の形を変える、output bucketを
増やす。どれも学習してみないと精度は分からないが、**速度は学習前に分かる。**

### 過去2回、速度で負けている

| ADR | 変更 | valid loss | NPS | 結果 |
|---|---|---|---|---|
| [0045](0045-remove-effect-tower.md) | 利き塔（+32次元） | −0.005（良い） | 0.6倍 | **棋力 −70〜100 Elo。除去** |
| [0067](0067-ft-dimension-512.md) | FT 256→512 | −0.00139（最良） | 0.65倍 | **不採択** |

**精度が上がってもNPSが落ちれば負ける。** これがこのエンジンの支配的な制約である。

### 前回の測定から状況が変わっている

[ADR-0067](0067-ft-dimension-512.md)のFT512測定は2026-07-26である。その後に次が入った。

- 追従11群（[ADR-0109](0109-reference-parity.md)〜[0119](0119-g10-book.md)）。単純加算で+525.5 Elo
- 挙動を変えない高速化（[ADR-0124](0124-hot-path-allocs.md)）。NPS +2.71%
- 探索本体の分割（[ADR-0125](0125-search-decomposition.md)）

深さ25のプロファイル（2026-08-01、26050サンプル、1スレッド）は次のとおり。

| 箇所 | self時間 |
|---|---|
| FT更新（`nnue_acc.rs` の `ensure`） | 25.2% |
| 隠れ層（`forward_hidden`） | 9.5% |
| `attackers_to` | 7.2% |
| `attacks::attacks` | 6.9% |
| `partial_insertion_sort` | 5.6% |

**ボトルネックが動いている可能性がある。** FT512の0.65倍という数字を前提に判断を続けるのは
危うい。測り直す。

### 隠れ層は「どこを厚くするか」で費用が桁違い

現行は `CONCAT(512) → 32 → 32 → 1` で、積和は 512×32 + 32×32 + 32×1 = **17,440回**。
このうちL1（16,384）が94%を占める。

| 変更 | 追加の積和 | 隠れ層の増加 | 全体への影響（隠れ層9.5%として） |
|---|---|---|---|
| 層を1つ足す（32→32） | +1,024 | +5.9% | +0.6% |
| L2を32→64 | +3,040 | +17% | +1.6% |
| L1を32→64 | +17,408 | +100% | +9.5% |
| FT 256→512（L1入力が倍） | +16,384 | +94% | +8.9%（FT更新の増加は別） |

**後ろの層を厚くするのは安く、前を厚くするのは高い。** FT512が0.65倍になったのは、FTの
差分計算が重くなっただけでなく、L1の入力が1024次元になったためでもある。

参考として、Stockfishは FT 256→1024〜1536 と太らせる一方で **L1を32→16前後へ削り**、
output bucketを8へ増やしている（`(pos.count<ALL_PIECES>() - 1) / 4` で駒数を8分割）。
**前を太らせたぶんを後ろで返す**構造になっている。

## 選択肢と比較

### 案A: 構造ごとに学習して比べる

精度と速度を同時に測れる。ただし1条件あたり本番規模で2.5時間、3億局面でも20分かかる。
FT・L1・層数の組み合わせは容易に10通りを超え、**速度で落ちると分かっている構成にも
学習時間を払う**ことになる。

### 案B: 学習の前に、ランダムネットでNPSを測る

`makenet` が乱数ネットを生成できる（[ADR-0037](0037-nnue-file-format.md)）。構造だけ変えて
ビルドし、NPSとプロファイルを取る。**学習を1回も回さずに、構造ごとの速度が分かる。**

NPSは「1ノードあたりの時間」なので、重みの値に依存しない。ランダムネットでも測れる。

## Decision

案Bを採る。**速度で足切りしてから、残った構成だけ学習にかける。**

学習は3億局面で20分、本番で2.5時間かかる。速度で落ちる構成にその時間を払う理由がない。
過去2回（利き塔・FT512）とも速度で落ちており、**この足切りは実際に効く。**

### 測る構成

| 名前 | FT | L1出力 | L2出力 | 層数 | 狙い |
|---|---|---|---|---|---|
| base | 256 | 32 | 32 | 3 | 基準 |
| ft512 | 512 | 32 | 32 | 3 | ADR-0067の再測定 |
| ft512-h16 | 512 | 16 | 32 | 3 | L1を削ってFT増を相殺できるか |
| ft768-h16 | 768 | 16 | 32 | 3 | さらに太らせられるか |
| wide-l2 | 256 | 32 | 64 | 3 | 後ろを厚くする（安い側） |
| deep | 256 | 32 | 32 | 4 | 層を1つ足す（最も安い） |

前半4つはFTと L1 のトレードオフ、後半2つは「安い側を厚くする」案である。

### 手順

1. `crates/engine/src/nnue.rs` の `FT_OUT` と `HIDDEN` をfeatureで切り替えられるようにする。
   現状 `ft512` があるので、`ft768` と `hidden16` を足す。L2の幅と層数は構造変更なので、
   前半4構成を先に測る
2. 構成ごとに `RUSTFLAGS="-C target-cpu=native" cargo build --release --features ...` でビルド
3. `makenet --seed 1 --out data/nets/shape_<名前>.hmwr` で乱数ネットを作る。
   **同じfeatureでビルドした `makenet` を使うこと。** 次元が合わないと読めない
4. `bench` でNPSを測る。**定跡生成や学習を止めてから測る**（[ADR-0123](0123-stop-and-resume.md)の
   停止ファイル）。振れが±1.5%あるので5周以上
5. `profile --depth 25` でボトルネックの移動を見る。FT更新と隠れ層の比率がどう動くか

### 足切りの基準

**NPSが現行の0.9倍を下回る構成は、valid lossが0.001以上改善しないと採算が合わない。**

根拠は過去2回の実測である。[ADR-0067](0067-ft-dimension-512.md)のFT512はNPS 0.65倍・
loss −0.00139で不採択、[ADR-0045](0045-remove-effect-tower.md)の利き塔はNPS 0.6倍・
loss −0.005で −70〜100 Elo だった。**loss −0.005 でもNPS 0.6倍を覆せない。**

0.9倍を下回った構成は、学習にかける前にこの基準で判断する。落とすとは限らないが、
「どれだけloss が下がれば見合うか」を先に決めてから学習する。

## Consequences

- 学習時間を、速度で通った構成にだけ使える。**過去2回は落ちると分かる測定を後に回していた**
- ボトルネックの地図ができる。FT更新25.2%・隠れ層9.5%という比率が構成ごとにどう動くかが
  分かれば、次にどこを削るべきかも見える（[ADR-0124](0124-hot-path-allocs.md)の残り候補の
  優先順位づけに使える）
- ランダムネットでは**ノード数を比較できない。** 評価値がでたらめなので枝刈りの効き方が変わる。
  比較できるのはNPS（1ノードあたりの時間）だけである。精度の判断には使えない
- featureの組み合わせが増える。`ft512`・`ft768`・`hidden16` で4通りになり、CIで全部を
  検証するのは現実的でない。**計測が終わったら、採用しなかったfeatureは消す**
- L2の幅と層数の変更は、`nnue.rs`・`nnue_simd.rs`・`nnue_io.rs`（.hmwr形式）・
  `training/model.py`・`training/quantize.py` に及ぶ。前半4構成（FTとL1のみ）とは
  作業量が違う。**前半で地図を作ってから、後半に着手するか決める**
