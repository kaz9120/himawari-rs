# 0087: 中断したSPRTを棋譜から再開できるようにする

- Status: proposed
- Date: 2026-07-28
- 関連ADR: [0027](0027-sprt-framework.md), [0028](0028-pruning-extensions.md)

## Context

[ADR-0085](0085-correction-history-multi.md)のSPRTが、1391ペア（2782局）
まで進んだところで外部から停止された。LLRは +2.00 で、H1の閾値 +2.94 へ
向かう途中だった。

`selfplay` はpentanomialをメモリ上にしか持たない。プロセスが落ちると
2782局分の結果が判定に使えなくなる。棋譜自体は `--out` のjsonlへ
1局1行で追記されており、情報は残っている。使う手段がなかった。

既定条件（10+0.1、8並列）で3000ペアまで回すと数時間かかる。この長さで
中断耐性がないのは、対局リソースの使い方として無駄が大きい。ADR-0078の
判定には5404局を要しており、長時間のSPRTは例外ではない。

## 選択肢と比較

### 案A: 棋譜jsonlから集計を復元して続きを回す

`--resume <jsonl>` を足す。起動時にjsonlを読み、ペアごとの2局を突き合わせて
pentanomialとW-D-Lを再構築する。ペア番号も引き継ぎ、`counter` の初期値を
「最大ペア番号+1」にする。

開始局面は `openings[pair % len]` で決まるため、ペア番号を引き継げば
局面の割り当ても続きから始まる。同じ局面を二度使わない。

2局そろっていないペアは捨てる。中断時に飛行中だった対局が片方だけ
記録されている場合がある。ペア単位のpentanomialに片側だけ入れると
統計が歪む。

jsonlの書式は `selfplay` 自身が生成する固定形式で、フィールドは
`pair` `game` `opening` `candidate` `winner` `reason` `plies` `moves` の
8つである。完全なJSONパーサは要らない。

### 案B: 状態をチェックポイントファイルへ書く

pentanomialとペア番号を別ファイルへ定期保存する。

保存タイミングの設計が要る。棋譜と状態ファイルがずれると、どちらが
正しいか分からなくなる。棋譜は既に全情報を持っており、二重に持つ理由が薄い。

### 案C: 再開しない

中断したら最初から回す。

3000ペアの上限まで回すと数時間かかる。中断のたびにそれを捨てるのは
対局リソースの浪費である。SPRTは逐次検定で、途中経過に意味がある。

## Decision

案Aを採る。

```
selfplay --baseline B --candidate C --resume data/sprt/name.jsonl \
         --out data/sprt/name.jsonl ...
```

`--out` と `--resume` に同じパスを渡せば、復元した続きを同じファイルへ
追記できる。`--out` は既に追記モードで開いている。

`--max-pairs` は通算のペア数として働く。`counter` が復元後の値から
始まるため、3000を指定すれば「既存分を含めて3000ペアまで」になる。

判定の逐次性は保たれる。復元した時点のLLRは、中断前に最後に表示された
値と一致する。SPRTは観測の順序に依存しないpentanomial度数だけを使うため、
再開しても検定の性質は変わらない。

**再開時は同じバイナリと同じ条件を使うこと。** 別のビルドや別の持ち時間で
再開すると、統計が混ざる。この確認は運用側の責任とし、ツールでは検査
しない。棋譜にバイナリのハッシュを持たせる案は、必要になったら足す。

### 2026-07-29追記: 再開を自動化する

[ADR-0097](0097-capture-history.md)のSPRTが**1回の測定で3回止まった**。
そのたびに手で `--resume` を打つのは自動化として不完全なため、
`scripts/sprt-run.sh` で繰り返す。

```
scripts/sprt-run.sh data/bin/base-adrNNNN data/bin/cand-adrNNNN name
```

既存の棋譜があれば最初から `--resume` で始め、判定前に異常終了したら
再開する。判定（H1・H0）か上限到達で終わる。

**効く範囲を誤解しないこと。** selfplayプロセスだけが落ちた場合は
このループが拾い直す。スクリプト自体が止められた場合（セッションの
終了、マシンの再起動）はループごと消える。

後者でも棋譜は残る。次に実行すれば続きを回す。**「止まらない」では
なく「止まっても失わない」のが本質である。**

## Consequences

長時間のSPRTが中断されても、対局結果を捨てずに済む。

jsonlの書式に依存する。`jsonl_line` の出力形式を変えるときは
`restore_from_jsonl` も併せて直す必要がある。フィールドの追加は
影響しない（読むのは4つだけ）。

同じ棋譜ファイルを二重に `--resume` すると、集計が二重に入る。運用で
避ける。ツール側では検査しない。
