# 0120: 追従一巡後の方向を評価関数と探索の結合へ置く

- Status: proposed
- Date: 2026-08-01
- 関連ADR: [0109](0109-reference-parity.md), [0089](0089-improvement-criteria.md), [0066](0066-halfkp-factorizer.md), [0067](0067-ft-dimension-512.md), [0068](0068-sprt-driven-versioning.md)

## Context

参照実装（やねうら王）への追従が一巡した（[ADR-0109](0109-reference-parity.md)）。
11群のうち10群が完了し、単純加算で+517.5 Eloを積んだ。

**探索部は参照実装と同じ構造になった。** ノード種別の3値化、Stack、historyの
面と更新、LMRの12項、ムーブループとevalベースの枝刈り、singular、qsearch、
時間管理、ponder、aspirationまで移してある。残るのは保留2件（singularの多段
延長、時間配分の分母）と、既定条件で測れなかった3件（定跡のponder手、best
thread voting、Lazy SMPの窓幅多様化）である。

**ここで問いが変わる。** 追従は「差を埋める」作業で、埋め終われば同等になる。
**同等より先へ行くには別の軸が要る。**

オーナーが2026-08-01に「既存実装の参照は今後も続くとは限らない。どこかで
オリジナリティを出す必要がある」と示した。

## 本エンジンの独自資産は何か

追従で埋まらなかったもの、つまり参照実装が持たないものを数える。

**評価関数を自前で学習している。** 純粋HalfKP 256x2-32-32を19.9億局面で
学習し、factorizerを併せて対halfkp_370Mで+243.8 Eloを得た
（[ADR-0066](0066-halfkp-factorizer.md)）。学習基盤は449,000 samples/sで、
19.9億局面の1エポックが2時間で回る。**参照実装は評価関数を外部（水匠など）に
依存する形をとる。** ここは構造から動かせる。

**測定の基盤がある。** SPRTの中断耐性、機能検証の局面と深さの固定、発動率の
計測、対応のある時間測定まで揃っている。追従の11群で実際に回してきた。

**判断の記録が残っている。** ADR 120本、棄却の理由と再解釈まで含む。
追従キャンペーンでは、過去の棄却5件がなぜ効かなかったかを特定して覆した。

## 選択肢と比較

### 案A: 追従の残りを埋める

保留2件と未測定3件、`mate_1ply` の通常探索への組み込みを片づける。

利点は安いこと。実装は済んでいるか、原典が明確である。欠点は上限が見えて
いること。**すべて埋めても参照実装と同等にしかならない。**

### 案B: 評価関数の構造を変える

output bucket（駒数で層分岐）、PSQT直結パス、玉ライン特徴、FT重みのi8量子化。
[ROADMAPの候補](../ROADMAP.md#候補)のネットワーク構造の節にある。

利点は独自資産の上に積めること。欠点は、探索と切り離すと「評価が良くなった
だけ」で止まること。[ADR-0067](0067-ft-dimension-512.md)のFT512は評価精度で
上回りながらNPSの損で不採択になった。**評価の改善が棋力に繋がるかは探索との
関係で決まる。**

### 案C: 評価関数と探索を結合する

多ヘッド出力（WDL・進行度・安定度）を学習し、探索へ供給する。時間管理の
判断材料、枝刈りの強度、contemptの根拠に使う。

利点は2つある。**参照実装にない。** そして本エンジンの過去の傾向に合う。
2026-07-29の測定で「判定材料の精度を上げると効き、強度を一律に変えると
効かない」という形が出ていた。多ヘッド出力は判定材料そのものを増やす。

欠点は工程が長いこと。学習器の変更、ネットの再学習、探索側の受け口、
3つが揃って初めて測れる。

### 案D: floodgateで実戦を確認する

追従で入れた機能のうち4つが既定条件のSPRTで測れていない。定跡のponder手
（`BookFile` の指定が要る）、best thread voting（`Threads=4`）、Lazy SMPの
多様化（同上）、時間管理の既定値（`MinimumThinkingTime=2000` は300+10向け）
である。

floodgateは300+10で、参照実装の既定値が本来想定する条件に近い。

## Decision

**案Dを先に、案Cを本命に置く。** 案Aは案Dのついでに拾う。案Bは案Cの一部として
行う。

### 順序と理由

**1. floodgateで実戦を確認する（案D）。**

追従で+517.5を積んだ状態がレートでどこに現れるかを見る。2026-07-24〜25の
初参戦は30局でレート3186、実力の境界が3100〜3250にあった。ここが動くかを
測る。

**測れていない4機能はfloodgateでしか確かめられない。** SPRTの既定条件
（10+0.1）は参照実装の前提と桁が違う。実戦が次の測定の場になる。

安く、かつ次の判断材料になる。**ここを飛ばすと案Cの効果も測れない。**

**2. 追従の残りを拾う（案A）。**

`mate_1ply` の通常探索への組み込みは、[ADR-0093](0093-mate1ply-in-search.md)が
棄却した理由（呼び出しコスト）が[ADR-0115](0115-g6-qsearch.md)で消えている。
安く拾える。

保留2件は再訪の条件を満たしたときだけ触る。

**3. 評価関数と探索を結合する（案C）。**

多ヘッド出力を本命にする。理由は3つある。

**参照実装にない。** 追従では得られない。オリジナリティの源泉になる。

**本エンジンの傾向に合う。** 判定材料の精度を上げる変更は効き、強度を一律に
変える変更は効かない、という形が2026-07-29の7件で出ている。追従キャンペーンは
この傾向を「単発なら」という条件付きに書き換えたが、判定材料の価値そのものは
否定していない。

**探索側の受け口が揃った。** 追従で時間管理・枝刈り・LMRの構造が参照実装水準に
なった。多ヘッド出力を供給する先が明確である。以前は「供給先の構造が弱いので
情報を足しても使えない」状態だった。

### 選定基準へ第4の軸を足す

[ADR-0089](0089-improvement-criteria.md)は3軸（速度・ノード効率・終盤の正確さ）
を置いた。**第4の軸として「判断材料の質」を足す。**

探索が読む情報の量と質を増やす変更がここに乗る。多ヘッド出力、correction
historyの系統追加、SEEの精度向上などである。

この軸は他の3軸と性格が違う。速度とノード効率は「同じ判断をより速く／少ない
ノードで」だが、第4の軸は「判断そのものを変える」。効果の測定は探索を通して
しかできない。

## Consequences

**追従は終わりではなく土台になる。** 探索の構造が参照実装水準になったことで、
評価関数側の改善が探索へ届く経路ができた。順序として追従が先だったのは正しい。

**参照実装との差は今後開く。** 多ヘッド出力を入れれば、探索の一部が参照実装に
ない構造になる。以後の追従は「差分を全部埋める」形ではなく、「取り込む価値の
ある機能を選ぶ」形になる。移植で得た教訓は
[ADR-0109](0109-reference-parity.md)から[ADR-0119](0119-g10-book.md)までの
各ADRにある。

**工程が長くなる。** 案Cは学習器・ネット・探索の3つが揃って初めて測れる。
1群1SPRTのような短い周期にならない。中間の測定（valid loss、指し手一致率、
供給した情報の発動率）で進捗を見る必要がある。

**floodgateの結果次第で順序を変える。** 実戦で時間管理の既定値に問題が出れば
そちらが先になる。追従で入れた機能が実戦で効いていなければ、原因の特定が
先になる。

2027年5月の選手権まで9か月ある（[ADR-0068](0068-sprt-driven-versioning.md)）。
実力の壁はfloodgateのレート3100〜3250にある。追従で越えたかを確かめてから、
次の一手を決める。
