# 0222: dlshogiラベルの20億で学習したネットを、手を加えずに現行と比べて昇格させる

- Status: proposed
- Date: 2026-10-04
- 関連ADR: [0195](0195-reorder-on-late-positions.md), [0201](0201-loop-recipe.md), [0217](0217-sprt-pass-cap.md), [0219](0219-relabel-2b-in-place.md)

## Context

[ADR-0219](0219-relabel-2b-in-place.md)で、dlshogiのラベルの20億で学習した
`dl20_7860M` が本学習 `pairrank_7860M_q1` に+67.9 [+47.1, +89.3]で勝った。
事前登録の次の一手は、継続学習（[ADR-0201](0201-loop-recipe.md)）と並べ替え
（[ADR-0195](0195-reorder-on-late-positions.md)）を施してから現行と比べる、だった。

この順序を変え、手を加えない `dl20_7860M` をそのまま現行と比べる。早く
floodgateへ出して実戦の棋力を取るためである（オーナー提案、2026-10-04）。
継続学習と並べ替えは、それぞれ現行へ足した利得が小さい。

- 現行 `rl_e1d8_reorder` は、並べ替え済みの本学習に+20.2 [+9.5, +30.9]
  （[ADR-0201](0201-loop-recipe.md)の昇格）
- 並べ替えの効果は+3.6 Elo の見積もり（[ADR-0195](0195-reorder-on-late-positions.md)）

推移律が成り立つなら、`dl20_7860M` は現行に+40前後で勝つ。2つの処理は
昇格の後で別に当てられ、そこで改めてSPRTにかける。

## 仮説

**手を加えない `dl20_7860M` は、現行 `rl_e1d8_reorder` より強い**。

## 測定の設計

- 動かす変数は評価関数だけ。同一ビルドのネット差し替え（`hmwr sprt net`）で、
  baselineは `data/nets/rl_e1d8_reorder.hmwr`、candidateは
  `data/nets/dl20_7860M.hmwr`（[ADR-0219](0219-relabel-2b-in-place.md)の対局と同じファイル）
- 固定するもの。既定の持ち時間 10+0.1・裁定・開始局面・上限10,000ペア
  （[ADR-0217](0217-sprt-pass-cap.md)）
- 対立仮説は elo0=0、elo1=10。+40前後の見込みは+10を大きく超えるので、
  CLAUDE.mdの「+10以上を見込む変更は elo1=10」に当たる。局数は既定の4分の1で済む

並べ替えの有無が交絡する。現行は並べ替え済みで、`dl20_7860M` は並べ替えて
いない。並べ替えはNPSを上げる処理で、`dl20_7860M` に不利な側へ働く。H1なら
結論は変わらない。

### 解釈の事前登録

| 判定 | 読み | 次の一手 |
|---|---|---|
| H1 | 手を加えなくても現行より強い | `hmwr/config.py` の評価関数を差し替え、ネットをReleaseで配ってfloodgateへ出す。並べ替えと継続学習は昇格の後に別のSPRTで当てる |
| H0 | 推移律が成り立たず、+10に届かない | 差し替えない。事前登録どおり並べ替えと継続学習を施してから測り直す |
| 見送り | 差は0〜+10の間にある | H0と同じ扱い。並べ替えの+3.6で届く可能性があるので、並べ替えてから測る |
