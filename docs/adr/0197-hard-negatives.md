# 0197: ランキング損失の負例に、静的評価で上位の手を混ぜる

- Status: rejected（3億の測定台で−19.2のH0。下の「測定・SPRT」）
- Date: 2026-09-02
- 関連ADR: [0136](0136-quiet-teacher-positions.md), [0158](0158-mirror-factorizer.md), [0163](0163-sprt-hypothesis-choice.md), [0185](0185-sibling-ranking-loss.md), [0196](0196-rank-hinge-diagnosis.md)

## Context

[ADR-0196](0196-rank-hinge-diagnosis.md)で、ランキング損失のヒンジが何に
発火しているかを測った。発火18.7%の内訳は次のとおり。順序の逆転が5.9%、
マージン不足が12.8%になる。**3分の2は順序が正しく付いていて、差がδに届かない
だけである**。

正例と負例の差（親視点の勝率）は中央値で12.4%あった。負例は合法手から
一様に引いているので、多くは明らかに悪い手になる。**平均的な負例は
簡単すぎて、学習が飽和している**。

同ADRの結論は、δを下げる線とαを上げる線を閉じ、負例の選び方へ進むこと
だった。本ADRがそれを引き取る。

## 選択肢と比較

### 案A: 負例を全合法手にする（ADR-0185の案C）

制約は最大になるが、群のサイズが可変になり、データ量が平均40倍へ膨らむ。
1億群で440GBは置けない。

### 案B: 静的評価で上位の手から負例を引く（採用）

各合法手の子を静的評価で並べ、最善手を除いた上位から引く。群の形（正例
1・負例2）は変えないので、データ量も学習側も変わらない。生成の手間だけが
増える。

### 案C: αとδの配合を振る

[ADR-0196](0196-rank-hinge-diagnosis.md)で効きが限定的と分かっている。
αは発火した群の勾配を強くするだけで、その3分の2は既に順序が正しい。

## Decision

**案Bを採る**。`psv rank --hard N` を足し、負例2本のうちN本を上位から引く。

- `--hard 0`（既定）は現行どおり一様に2本。過去の生成と一致する
- `--hard 1` は上位から1本、一様から1本を引く
- `--hard 2` は2本とも上位から引く

**測るのは `--hard 1` である**。簡単な制約と難しい制約を1群に同居させる。
2本とも難しくすると、[ADR-0185](0185-sibling-ranking-loss.md)が懸念した
ラベルノイズ（depth 9の最善手が誤っている場合、上位手を負例にすると
誤った制約になる）を全面的に浴びる。

### 上位の引き方

全合法手について `do_move` してから静的評価を引き、親視点の値で降順に
並べる。最善手を除いた上位25%（最低2手）から一様に1本を引く。**1位を
決め打ちにしない**。決め打ちだと生成が決定的になりすぎ、教師の誤りが
そのまま制約へ写る。

静止化（qsearch）は現行どおり、選んだ3手に対してだけ行う。並べるための
評価は静的なので、合法手が平均80手あっても qsearch 3回より軽い。

## 実験の事前登録

1. **仮説**。一様に引いた負例は簡単すぎる。上位から1本混ぜると、細かい
   順序を学ぶ制約が課され、ノード効率が上がる
2. **動かす変数**。負例2本のうち1本の選び方だけである。群の数・教師・
   学習設定・乱数の種は変えない
3. **固定するもの**。教師（`train_300M_q1.psv`）、群の数（1億）、α=1.0、
   δ=0.02、rank-batch=4096、バッチ16384、ステップ数、seed=0を固定する。
   対照も同じ設定で学習し直す。過去のネットは流用しない
4. **読み方**を先に決める
   - **H1**なら負例の難易度が効く。78.6億の本学習へ進む
   - **H0**ならADR-0185の懸念が現実である。難しい負例はラベルノイズを
     増やすほうへ働く。一様が最適に近いと結論し、負例の選び方の線を閉じる
   - **上限まで判定が出ない**なら効果量は小さい。H0と同じ結論として扱い、
     配合の線も閉じたまま次の構造の案へ移る

### 条件と上限

3億の測定台で、同一ビルドのネット差し替えで測る（`hmwr sprt net`）。
条件は既定（`--tc 10+0.1`、elo0=0、elo1=5）。

**上限を10,000ペア（2万局）で宣言する**。H1のときだけ採択するゲート
用途なので、上限での打ち切りは「見送り」として扱ってよい
（[ADR-0163](0163-sprt-hypothesis-choice.md)の追記）。効果量が+7 Elo
以上なら、この範囲で判定が出る見込みになる。

### 生成の検証

生成した群が実際に難しいかを、学習の前に確かめる。現行ネットで
`hmwr net rank` を掛け、正例と負例の差の分布を現行の群と比べる。

- 差の中央値が下がっていれば、負例が難しくなっている
- ヒンジの発火率が上がっていれば、制約が強くなっている

**下がらなければ学習へ進まない**。生成の意図が実現していないことになる。

## 測定・生成の検証（2026-09-02）

`train_300M.psv` の先頭20万レコードから群を作り、現行ネット
（`pairrank_7860M_q1_reorder`）で `hmwr net rank` を掛けた。

| 指標 | `--hard 0` | `--hard 1` |
|---|---|---|
| 順序が逆 | 6.8% | **11.6%** |
| マージン不足 | 12.4% | 14.3% |
| 余裕あり | 80.8% | 74.1% |
| ヒンジ発火 | 19.2% | **25.9%** |
| 差の中央値 | +0.1350 | **+0.1019** |
| 差のp10 | +0.0008 | **−0.0009** |

**事前登録した検証条件を両方満たした**。差の中央値が下がり、発火率が
上がっている。下位10%は負へ転じており、上位から引いた負例は現行ネットの
評価で正例と拮抗する。狙いどおり難しくなった。

`--hard 0` の生成物は、変更前のバイナリで作ったものとバイト単位で一致
する（同じ評価関数、同じ入力、20万レコード）。既存の経路は動いていない。

生成の速度は42,193局面/秒から10,783局面/秒へ落ちた。合法手ぶんの静的
評価が乗るためで、4倍弱になる。1億レコードなら単スレッドで2.6時間、
4分割並列で約40分の見込みになる。撤退ライン（4分割並列で30分を大きく
超える）の内側に収まる。

### 撤退ライン

生成が現行の3倍（4分割並列で30分）を大きく超えるなら、上位を決めるための
評価を全合法手から標本へ落とす。ADR-0185の実績は1億レコードから
9,594万群を4分割並列で10分だった。

## 測定・SPRT（2026-09-02〜03、3億の測定台）

| 項目 | 値 |
|---|---|
| 比較 | `h0_300M`（一様2本）対 `h1_300M`（上位1本＋一様1本） |
| 条件 | 既定（`--tc 10+0.1`、elo0=0、elo1=5）、上限10,000ペア |
| 対局数 | 3,292（1,646ペア） |
| W-D-L | +1507 =96 -1689 |
| Elo [95%CI] | **−19.2 [−31.1, −7.4]** |
| LLR | −2.99（**H0採択**） |

事前登録の読み方どおり、H0なので棄却する。**難しい負例は害だった**。
上限を待たず、1,646ペアで決着している。

### 学習の推移が原因を指している

両者は同じ教師・同じ設定・同じ乱数で学習した。動いたのは負例の選び方
だけである。

| step | 対照の発火率 | 介入の発火率 |
|---|---|---|
| 100 | 50.0% | 53.4% |
| 3,500 | 22.8% | 28.5% |
| 9,000 | 21.8% | 27.4% |
| 18,300 | 21.2% | **26.6%** |

**介入の発火率は下がりきらない**。最後まで対照より5.4ポイント高い。
難しい制約が学習されずに残っている。

回帰lossは対照0.48721、介入0.48769で介入がわずかに悪い。検証lossは
0.49224と0.49228でほぼ同じだった。**検証lossでは−19.2の差が見えない**
（[ADR-0158](0158-mirror-factorizer.md)の再確認）。

### 学習できない制約は、教師の誤りである

[ADR-0185](0185-sibling-ranking-loss.md)の懸念が現実だった。上位25%から
引いた負例は、depth 9の教師より実際に良い手を含む。それを「正例より
悪い」と教えると、**評価が正しい方向から引き離される**。

発火率が下がりきらないのは、この矛盾した制約が学習不能だからである。
ネットは正解のない要求を押しつけられ、そのぶん回帰の側が歪む。一様に
引いた負例が簡単すぎるのは事実だが、**簡単さはラベルの正しさとの
引き換えで買っていた**。

制約の強さだけを見て負例を難しくすると、教師の質という別の軸を壊す。
[ADR-0196](0196-rank-hinge-diagnosis.md)の診断は「順序は既に付いている」
までは正しく、そこから「もっと難しい制約を課せばよい」へ進んだ推論に
飛躍があった。

### この線を閉じる

負例の選び方でランキング損失を強くする線は閉じる。[ADR-0196](0196-rank-hinge-diagnosis.md)で
δとαの線を閉じているので、**ADR-0185の後続実験は全部閉じたことになる**。
残っていた案C（全合法手）はデータ量が440GBになり、置き場がない。

ランキング損失そのものは+28.9 Eloで採択済みの資産である。閉じるのは
「配合と負例で上積みする」線であって、損失自体ではない。

## Consequences

- **`--hard` の実装はmainへ入れない**（[ADR-0070](0070-pr-based-workflow.md)の
  マージ条件）。棄却の記録はこのADRが持つ。再現するときはPR 457の差分から
  組み直す
- 難しい負例の群（`rank_300M_h1.rankpsv`）と両者のネットは保持期限まで
  残す。同じ源から別の選び方を試すときの比較対象になる
- 3億の測定台での結果が78.6億へ転移するかは別の問題である。
  [ADR-0185](0185-sibling-ranking-loss.md)は3億の+19.6が29.9億で+28.9に
  なったが、教師がhaoからtanukiへ変わっているので前提は同じでない
- **H1でも本学習にすぐは進めない**。ランキング群には静止化前の教師が要る
  （moveフィールドが要るため）。tanuki 2024の静止化前は
  [ADR-0192](0192-tanuki2024-teacher.md)の消費型パイプラインで消えており、
  手元に残っているのは静止化後の293GBだけである。作り直すには生データの
  先頭2.1億レコードぶん（約78GB）を取り直す必要があり、いまの空き
  （約22GB）には入らない。`train_2990M.psv`（111GB、haoの静止化前）は
  tanukiへ移行したので用済みで、これを消せば場所は空く。**H1が出てから
  消す**。順序を逆にすると、H0のときに戻せる資産を失う
