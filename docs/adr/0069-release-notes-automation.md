# 0069: リリースノートをSPRT採択から自動生成する

- Status: superseded
- Date: 2026-07-27
- 関連ADR: [0027](0027-sprt-framework.md), [0037](0037-nnue-file-format.md), [0068](0068-sprt-driven-versioning.md), [0071](0071-release-please.md)（本ADRを置き換え）

## Context

リリースノートが空である。`release.yml` はタグpushで5種類のCPU別バイナリをビルドして添付する。
ノートは `softprops/action-gh-release` の既定動作に任せているため、
その版に何が入ったか、どれだけ強くなったかが読めない。

[ADR-0068](0068-sprt-driven-versioning.md)でSPRT採択1件ごとにMINORを
上げる運用にした。リリース一覧がそのまま棋力向上の履歴になるため、
各版に「何を採択し、何Elo上がったか」が載っている必要がある。
載っていなければ、番号を細かく刻む意味が薄れる。

リリースは頻繁になる。ノートを毎回手で書く運用は続かない。

## 選択肢と比較

### 案A: コミット件名だけを列挙する

`git log` の件名を並べる。実装は最も簡単だが、SPRTの結果が
本文に埋もれる。何Elo上がったかを読み取れない。

### 案B: コミットのトレーラから構造化して抽出する

棋力が変わるコミットに機械可読なトレーラを付ける。
`Co-Authored-By` と同じ位置に書けるため、既存のコミット規律を
崩さない。

```
SPRT: +28.1 [+15.2,+41.1] 2772games H1
```

`git log --pretty=format:"%(trailers:key=SPRT,valueonly)"` で
そのまま取り出せる。

### 案C: RESULTS.mdから抜き出す

計測記録はRESULTS.mdが持つ。ただし散文と表が混在しており、
機械的な抽出には向かない。append-onlyの性質上、どの記述が
どのタグに対応するかも判定できない。

### 案D: 毎回手で書く

自由度は高いが、SPRT採択のたびにリリースするため続かない。

## Decision

案Bを採る。案Aを土台にし、SPRTトレーラを併記する形にする。

タグpush時に、前タグからのコミット件名とSPRTトレーラを集めて
ノートを組み立てる。

```
## 採択したSPRT
- +28.1 [+15.2,+41.1] 2772games H1

## 変更
- 学習時だけ駒単独の仮想特徴を併用する（ADR-0066）
- ...
```

棋力が変わる変更のコミットには `SPRT:` トレーラを付ける規約を
[CLAUDE.md](../../CLAUDE.md)へ追加する。書式は
`SPRT: <Elo> [<CI下限>,<CI上限>] <対局数>games <H0|H1>` とする。

強制はしない。付け忘れれば採択欄が空になるだけで、リリース自体は
成立する。CIで検査する仕組みは置かない。運用の負担を増やしてまで
守らせる価値のある規約ではない。

## 評価関数はリリースに含めない

リリースをバイナリと評価関数の組にする案は退けた。

理由は更新の性質が違うことである。ADR-0068によりバイナリは
SPRT採択のたびに版が上がるが、評価関数はそれよりずっと低い頻度で
差し替わる。同じ64MBのネットを毎リリースへ添付すると、
リリース一覧が実体の重複で膨らむ。

評価関数はリポジトリにも同梱しない（[ADR-0037](0037-nnue-file-format.md)）。
学習の成果物であり、バイナリとは別の系統で管理する方が扱いやすい。
管理方法はADR索引のバックログへ「学習済みネットの管理・配布方法」
として残し、別途起草する。

## Consequences

- リリース一覧が棋力の履歴として読めるようになる。ADR-0068で
  番号を細かく刻む判断が活きる
- `SPRT:` トレーラは棋力が変わるコミットにのみ付ける。
  不採択（H0）の記録にも使えるが、ADR-0068によりバージョンが
  上がらないためノートには載らない
- リリースのバイナリは評価関数を持たない。ダウンロードした状態では
  駒割評価で動く。`EvalFile` の指定方法をリリースノートに1行書いて
  補う
- ノート生成はシェルで完結する。追加の依存を持ち込まない

## 追記（2026-07-27）

[ADR-0071](0071-release-please.md) が本ADRを置き換えた。

リリースノートの生成はrelease-pleaseが担う。CHANGELOGも同時に手に入る
ため、`release.yml` へ書いたシェルによる生成は役目を終えた。同ファイルは
バイナリのビルドと添付に絞っている。

`SPRT:` トレーラの書式は引き続き使う。リリースノートの生成元としてでは
なく、RESULTS.mdへの転記元としてである。SPRTで得たEloは、CHANGELOGに
残すためコミットの件名にも書く。

評価関数をリリースに含めない方針は変わらない。
