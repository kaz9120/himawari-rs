# 0189: 成果物の保持を日数で決め、掃除をhmwr cleanに固定する

- Status: accepted
- Date: 2026-08-27
- 関連ADR: [0053](0053-docs-structure.md), [0154](0154-sprt-ops.md), [0180](0180-hmwr-cli-in-python.md), [0188](0188-selfplay-rl-loop.md)

## Context

成果物がたまり続けている。ネット276個で20GB、SPRT棋譜132件、比較用
バイナリ70本超。2026-08-27にはディスクの空きが14GiBまで落ち、手作業で
330GiBを整理した（hao系の3重持ちが主因）。手作業の掃除は再現せず、
消してよい基準も人の記憶に依存する。ゴミがたまり続ける環境にしない、
という方針をオーナーが示した（2026-08-27）。

これまでの運用は「data/binのバイナリとdata/sprtの棋譜・結果は消さない」
（running-sprtスキル）だった。実験結果の正はADRとコミットのトレーラに
あり、棋譜とバイナリの再現価値は時間とともに下がる。無期限の保持は
根拠を失っている。

## 選択肢と比較

### 案A: 保持を日数で決める（採用）

30日を過ぎた成果物を消す。例外は現行の評価関数の系列と `.result`
（結果の要約、数KB）だけ。規則が1つなので、判断も実装も小さい。

### 案B: 成果物ごとに残す一覧を管理する

何を残すかの列挙を始めると、一覧の手入れ自体が新しいゴミになる。
残す価値のあるものは使われ続けてmtimeが更新されるので、日数の規則が
実質的に同じ集合を守る。

### 案C: 消さずにディスクを増やす

たまる構造が変わらない。手作業の大掃除が再発する。

## Decision

案Aを採り、`hmwr clean` に固定する。

```
hmwr clean            下見（消せるものの一覧と合計を出す）
hmwr clean --apply    消す
hmwr clean --days 14  保持日数を変える（既定30）
```

対象と規則は次のとおり。

| 対象 | 規則 |
|---|---|
| `data/sprt/*.jsonl` | 30日で消す。`.result` は残す（結果の一覧性） |
| `data/bin/` | 30日で消す。バイナリはコミットから再ビルドできる |
| `data/nets/` | 30日で消す。現行の評価関数の系列（並べ替え前後）は残す。配布済みの版はGitHub Releasesにある |
| `training/checkpoints/` | 30日で消す。現行の評価関数の系列は残す |
| `data/logs/` | 30日で消す |
| `data/train/*.stop` | 30日で消す（停止ファイルの消し忘れ） |
| git worktree | 日数では決めない。下の「作業ツリーはgitの状態で決める」 |

### 作業ツリーはgitの状態で決める（2026-09-02の追記）

並列作業のworktreeは成果物ではなく作業場なので、日数では決められない。
古くても作業中なら消せないし、昨日作ったものでも取り込み済みなら要らない。
判断の材料はgitが持つ。

- ブランチがmainへ入っていて、未コミットの変更がなければ消す
- detached HEADは意図が読めないので触らない
- 登録だけ残ってディレクトリが消えたものは `git worktree prune` で片付ける

取り込み済みかの判定にコミットの祖先関係は使えない。**squashマージなので、
取り込まれた後もローカルのコミットはmainの祖先にならない**。上流の追跡
ブランチが消えていれば済むが、`--delete-branch` を使わずマージしたPRでは
残る。最後はGitHubへ聞き、聞けないときは「分からない」を「消さない」へ
倒す。

初回の実行で3件・1.78GBを回収した。どれもマージ済みのブランチだった。

**教師データ（`data/train`）は消さない**。正本（`train_2990M.psv`・
3億測定台・valid群）の整理は個別判断で、世代ループの窓の管理は
[ADR-0188](0188-selfplay-rl-loop.md)が持つ。`data/spsa` と `data/profile`
も対象外とする（小さく、SPSAの状態は走行をまたぐ資産のため）。

結果の正はADRである。棋譜・バイナリを消した実験を再現するときは、
ADRの記録とコミットのトレーラから条件を組み直す。

掃除は月に1回を目安に、大きな生成・学習の節目で回す。cronは置かない。
消す操作を無人で走らせるより、下見つきで人の手で叩くほうを選ぶ。

## Consequences

- running-sprtスキルの「消さない」をこの方針へ差し替える（同じPR）
- 30日より古い実験を再測するときは再ビルドの一手間が要る
- 初回適用（2026-08-27）は68件1.59GBを消した。8月の実験群は保持期間を
  抜け次第、次回以降のcleanが拾う
