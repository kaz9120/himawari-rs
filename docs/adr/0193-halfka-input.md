# 0193: 入力をHalfKAへ拡張し、両玉の関係を1次特徴にする

- Status: proposed
- Date: 2026-08-29
- 関連ADR: [0134](0134-head-capacity.md), [0157](0157-king-mirror-buckets.md), [0184](0184-cross-view-product.md), [0192](0192-tanuki2024-teacher.md)

## Context

HalfKPは（自玉の升×玉以外の駒配置）の線形和で、両玉の同時関係を表す
項を持たない。Bonanza系の評価関数が持っていたKK・KKP相当の項が
抜けている形になる。入玉や相玉の接近戦のように、同じ駒配置でも
相手玉の位置で価値が反転する局面は、1次では原理的に表現できない。

チェス側のStockfishはHalfKP→HalfKA（玉を含む全駒）へ移行した。
本エンジンでの傍証も2つある。活性側から両玉相互作用を入れた
[ADR-0184](0184-cross-view-product.md)は「ネットは項を使うものの
対局に変換されない」で棄却された。一方で、入力の行数を減らす変更は
一貫して悪化した（ミラー45が−16.0、マルチホットが−52.2）。入力側の
拡張が素直に効く可能性は残っている。

蒸留より先に測る（2026-08-29オーナー判断）。78.6億への教師移行
（[ADR-0192](0192-tanuki2024-teacher.md)）の本学習前に入力形式を
確定させれば、5日規模の学習を最終構成で1回だけ走らせられる。

## 仮説と実験設計（起動前に固定）

仮説は「相手玉の位置平面をBonaPieceへ足すと両玉関係の1次項が入り、
3億の測定台の対局で正の利得が出る」である。動かす変数は入力特徴
だけで、FE_END 1548→1629の81升の相手玉平面になる。

固定するものを挙げる。データは `train_300M_q1.psv` と
`valid_385M_q1.psv`、rank群は `train_300M.psv` の先頭から決定論で
再導出する。レシピは対の積＋ランキング損失
（[ADR-0185](0185-sibling-ranking-loss.md)の第1段と同じ）、seed 0、
学習量も揃える。**基準側も同じ起動コマンドで再学習する**。既存ネットの
流用では当時の引数との一致を保証できないためである。

読み方も固定する。時間制のネット差し替えSPRT（既定、elo0=0・elo1=5）で
H1なら採択し、[ADR-0192](0192-tanuki2024-teacher.md)の本学習をHalfKA
構成で行う。H0・見送りならHalfKPのまま進める。NPSが下がる場合は
換算率3.12 Elo/1%で差し引いて読む。検証損失は判断に使わない。

## Decision

案を1つに絞って実装する。

### 特徴の定義

- BonaPieceの末尾に「相手玉の升」81個を足す（FE_END 1548→1629、
  特徴表は81×1629=131,949行、約5%増）
- 視点の正規化は既存の`halfkp_index`と同じ。後手視点は盤を180度回す
- 1局面の発火特徴は視点あたり39個（38＋相手玉1）になる

### 実装の段階

1. `bonapiece.rs`と特徴列挙（engine・学習抽出の両方）へ平面を足す
2. アキュムレータの差分更新は、当面は「どちらかの玉が動いたら
   その視点を全再計算」の保守実装とする。相手玉の移動は1特徴の
   付け替えで済むが、正しさを測定台で確かめるのが先。NPSへの影響を
   実測し、採択時に差分更新へ最適化する
3. 学習器・量子化・ネット形式は次元定数の変更に追従させる。
   FT_INが変わるのでネットの互換は切れる（構成名で区別する）

## Consequences

- 3億の測定台で学習2本（基準の再学習＋HalfKA）とSPRT1本を消費する
- H1なら、ADR-0192の本学習と以後のネットはHalfKA構成になる。
  自己生成ループの継続学習は初期値の互換が切れるため、次の本学習を
  新たな出発点にする
- 氷彗の報告（蒸留データが容量拡張の前提）と合わせ、これが入力側の
  最後の単独変更になる見込み。以後の容量拡張は蒸留後に測る
