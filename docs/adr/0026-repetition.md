# 0026: 千日手まわり

- Status: accepted
- Date: 2026-07-18
- 関連ADR: [0013](0013-hand-packing.md), [0014](0014-position-structure.md), [0015](0015-zobrist-hash.md), [0024](0024-search-v1.md)

## Context

将棋の千日手は「盤面・手駒・手番が同一の局面が4回現れたら
引き分け。ただし一方が王手を掛け続けていた場合は王手側の負け」。
さらに盤面同一で手駒だけ多い（優等）局面は、循環しても手駒を
使えるぶん有利側が打開できるため、探索上は勝ち・負けに準じた
値を返せる。検出の材料（board_key・生値hand_key・連続王手
カウンタ・plies_from_null）はP1のADRで仕込み済みで、ここでは
判定と探索での扱いを決める。

## 選択肢と比較

検出方式は、専用のハッシュ履歴テーブルを別に持つ案と、
StateInfoスタックを遡る案がある。StateInfoには board_key
（bit 0 = 手番込み。ADR-0015）と hand_key（生値。ADR-0013）が
既にあり、スタックの遡りは添字デクリメントで書ける（ADR-0014）。
専用テーブルの追加管理は不要と判断し、遡り方式とする。

ルール上の千日手は「4回目」だが、探索中に同一局面の再訪を
見つけた時点でその先は循環なので、初回検出で千日手値を返す
（実対局の判定はGUI側が行う。エンジン内は探索値の問題）。

## Decision

### 検出

各ノードの冒頭で、StateInfoスタックを現在から2plyごとに
`plies_from_null` を上限に遡り、`board_key` 一致を探す。
一致したら `hand_key` を比較して分類する。

| 手駒の関係 | 分類 | 探索が返す値 |
|---|---|---|
| 一致 | 千日手 | 連続王手でなければ draw値 |
| 一致＋相手が王手し続け | 連続王手の千日手 | `mate_in(ply)`（相手の反則負け） |
| 一致＋自分が王手し続け | 連続王手の千日手 | `mated_in(ply)` |
| 自分の手駒が優等 | 優等局面 | `+VALUE_SUPERIOR`（勝ち未満の大値） |
| 自分の手駒が劣等 | 劣等局面 | `−VALUE_SUPERIOR` |

- 連続王手の判定: StateInfoの `continuous_check`（ADR-0014）を
  使い、「検出区間のply数 ≤ 王手継続カウンタ×2」で判定する
- 優等・劣等は `Hand::is_superior_or_equal`（ADR-0013）で判定。
  hand_keyが生値のため偽陽性はない（ADR-0015）
- `VALUE_SUPERIOR = 28000`（MATEより十分小さく、通常評価より
  十分大きい）。ply補正はしない

### 探索・USIでの扱い

- draw値は 0 を基準とし、厳密には `1 − (nodes & 2)` のような
  ±1の揺らぎを入れて千日手PVへの固着を防ぐ（Stockfish方式）
- 千日手値・優等値は置換表に保存しない（経路依存の値のため）。
  検出したノードで直接返す
- `MaxMovesToDraw`（ADR-0019のオプション）: `game_ply` が上限に
  達したノードでdraw値を返す。0なら無効
- 宣言勝ち（27点法）はここでは扱わない（P3のADR）

## Consequences

- 対局ゲーム木の履歴（`position ... moves ...` で適用した手）も
  StateInfoスタックに載っているため、対局中の千日手が正しく
  検出される
- 経路依存値をTTに入れない規約により、TT由来の千日手誤判定を
  避ける。そのぶん同一局面の再探索が起きるが、千日手絡みの
  局面は少数で影響は小さい
- 遡りは最悪で数十エントリの線形走査になる。board_keyの
  bit 0 = 手番により半分は即座に不一致になり、実測で問題に
  なったら4plyごとの先頭絞り等を検討する
- 検証は「同一手順の往復で千日手値が返る」「連続王手の千日手で
  王手側が負け値になる」「優等局面で大値が返る」の単体テストと、
  対局テスト（P2出口条件）で行う
