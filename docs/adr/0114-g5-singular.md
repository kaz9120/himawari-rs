# 0114: singularの条件とmulti-cut・negative extensionを参照実装へ揃える（G5）

- Status: accepted
- Date: 2026-07-30
- 関連ADR: [0109](0109-reference-parity.md), [0113](0113-g4-eval-pruning.md), [0050](0050-singular-extension-retry.md), [0074](0074-feature-verification.md)

## Context

[ADR-0109](0109-reference-parity.md)の追従キャンペーンの第6群。singularの
検証探索の結果を、返り値の位置で3通りに使い分ける形へ揃える。

本エンジンは延長側（+1のみ）しか持たない（[ADR-0050](0050-singular-extension-retry.md)の
案A）。参照実装は同じ検証探索1回の結果を排他的な3分岐で使う。検証値が
singularBeta未満なら多段延長（最大+3）、beta以上ならmulti-cut、中間なら
negative extension（−3または−2）である。

**1つだけ入れると検証探索のコストを払って残りが「延長0」に落ちる**。参照実装が
本エンジンの半分の係数（`60/55` 対 `2`）を使えているのは、multi-cutと
negative extensionが反対方向に効くからである。

## Decision

4つをまとめて入れる。値は変えない。

### singularの発動条件と検証窓

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 深さの下限 | `depth >= 7` | `depth >= 6 + ttPv` |
| 検証窓 | `ttValue − 2×depth` | `ttValue − (60 + 66×(ttPvかつ非PV))×depth/55` |
| 検証探索の深さ | `depth/2` | `(depth−1)/2` |
| shuffling判定 | なし | 往復手のパターンで除外 |

判定の位置を置換表の下界によるProbCut（[ADR-0078](0078-tt-probcut.md)）の
後ろへ移した。参照実装はムーブループの中で判定するため、ループ手前の枝刈りが
すべて検証探索より先に効く。

shuffling判定は将棋版を採った。原典の `#if STOCKFISH` 側はチェス版で、
`STOCKFISH` は `config.h` でコメントアウトされている。将棋版は50手ルールの
条件を持たず、代わりに駒打ちを除く。

### 多段延長・multi-cut・negative extension

doubleMarginとtripleMarginで最大+3まで延長する。multi-cutは検証値がbeta以上で
決着スコアでないとき検証値を返し、ttMoveHistoryを `max(−424 − 107×depth, −3375)`
で減点する。negative extensionはTT値がbeta以上で−3、cutNodeで−2である。

ttMoveHistoryのmulti-cut更新は[ADR-0110](0110-g1-history.md)（G1）が空けておいた
箇所を埋めた。

`rootDepth` を持っていなかったので `Worker` へ足した。doubleMarginと
tripleMarginが `ply > rootDepth` を読む。

### 付録に載っていなかった2件を入れた

**除外手つき探索で合法手が尽きたら `alpha` を返す**。本エンジンは無条件に
`mated_in(ply)` を返していた。将棋は「逃げ道が1つだけ」の局面が多く、TT手が
唯一の合法手だと検証値が常に最小になり、多段延長が必ず最大まで積む。直すと
4局面中2局面でノード数が2割減った。

**PVノードの再探索前に `newDepth = max(newDepth, 1)` を置く**。負の延長で
newDepthが0以下になったTT手を静止探索へ落とさないための歯止めで、negative
extensionと同じ機構である。

## 機能検証（ADR-0074）

深さ13、4局面。基準はG4完了時点である。

| 局面 | G4 | G5 | 変化 |
|---|---|---|---|
| 1 | 25,459 | 33,867 | +33% |
| 2 | 141,293 | 183,159 | +30% |
| 3 | 118,942 | 856,507 | **+620%** |
| 4 | 68,114 | 78,240 | +15% |

**評価値が大きい局面3（cp 874）だけ7.2倍に膨らむ**。深さ19では240秒で
読み終わらなかった（基準は2,967,852ノード）。30秒で読ませると到達深さは22から
18へ4段落ちる。初期局面を8秒で読ませても29から27へ2段落ちた。

延長量を+1で打ち止めにする切り分けでは、4局面のノード数が
34,090 / 134,102 / 99,595 / 82,564 と基準とほぼ同じになる。**膨張の主因は
triple extensionである**。

### 発動率

深さ13、4局面。探索ノードは1,023,873。

| 項目 | 回数 | 全ノード比 | 判定比 |
|---|---|---|---|
| singular判定に入った | 12,041 | 1.18% | — |
| singular=true | 5,236 | 0.51% | **43.5%** |
| うち +1 | 319 | 0.031% | 2.6% |
| うち +2（double） | 1,122 | 0.11% | 9.3% |
| うち +3（triple） | 3,795 | 0.37% | 31.5% |
| multi-cut | 5,751 | 0.56% | 47.8% |
| negative extension −3 | 104 | 0.010% | 0.86% |
| negative extension −2 | 848 | 0.083% | 7.0% |
| shuffling除外 | 35 | 0.0034% | 0.29% |

0.1%を下回るのは4項目（+1、negative extensionの両方、shuffling除外）である。
群として入れる方針に従い、これを理由に外していない。

**singular=trueの割合が43.5%で、参照実装の「1割がsingularになるよう調整」から
4.4倍外れている**。局面別では23.4%・38.1%・48.1%・41.9%である。

検証窓の係数を2倍・4倍・8倍まで振っても10〜20%までしか下がらない。係数の
問題ではない。**本エンジンの評価値の分布では「TT手以外はマージン分だけ悪い」が
参照実装より強く成り立っている**。

singular率が高いと多段延長の影響が増幅される。非PVでTT手が取る手でないとき
tripleMarginは負（73−218=−145）になり、singularが成立すれば必ず+3まで積む。
参照実装の設計点（1割）では抑えられていたものが抑えられない。

### NPS

初期局面 `go movetime 8000` の同一実行内の比較で、1,445,883から1,381,004へ
落ちた（-4.5%）。

## SPRT

### 第1回: 群全体（H0採択）

既定条件（10+0.1、elo0=0、elo1=5、α=β=0.05）でG4完了時点のバイナリと比べた。

```
H0採択 | 562局 | +180 =46 -336 | Elo -99.0 [-126.9,-72.4] | LLR -3.01
```

**-99.0 Eloで不採択**。機能検証の懸念（到達深さが4段落ちる）がそのまま出た。
追従の群で初めてH0になった。

[ADR-0109](0109-reference-parity.md)の手順に従い、事前に決めた分け方で
二分割する。多段延長を+1で打ち止めにし、multi-cutとnegative extensionだけを
残す。

### 第2回: 多段延長を除いた形（H1採択）

多段延長を+1で打ち止めにし、singularの条件・検証窓・shuffling判定・multi-cut・
negative extension・除外手つき探索の返り値の修正を残した。

```
H1採択 | 1530局 | +806 =129 -595 | Elo +48.2 [+31.0,+65.7] | LLR +3.01
```

**+48.2 Eloで採択した**。群全体の-99.0から147 Elo動いた。**害は多段延長
だけだった**。

機能検証も裏づけになっている。G4比のノード数は
34,090（+34%）/ 71,397（-49%）/ 83,447（-30%）/ 42,510（-38%）で、群全体で
7.2倍に膨らんだ局面3が-30%へ戻った。multi-cutとnegative extensionは木を
縮める側なので、多段延長を外すと縮む側が残る。

## Consequences

**この群は初めて到達深さが落ちる変更である**。G1からG4はいずれもノード数が
減るか、増えても深さを稼いでいた。ここでは30秒で4段、8秒で2段落ちる。

値を変えずに測る方針を守った（[ADR-0109](0109-reference-parity.md)）。singular率の
乖離は移植の誤りではなく、評価値の分布の違いに由来する。**参照実装の値が本
エンジンで成立しない最初の例になりうる**。

不採択なら二分割する。分け方は「多段延長を+1で打ち止めにし、multi-cutと
negative extensionだけを入れる」である。切り分けの測定でノード数が基準へ戻ることは
確認済みなので、依存の閉包は保たれる。multi-cutとnegative extensionは検証探索の
結果を使うだけで、多段延長を前提としない。

### 多段延長は保留する

多段延長（double / triple extension）は入れない。[ADR-0109](0109-reference-parity.md)の
保留の扱いに従い、棄却はしない。再訪の条件を1つ書いておく。

**singular率を参照実装の設計点（1割）へ寄せる方法が見つかったとき**。
現状は43.5%で、検証窓の係数を8倍まで振っても10〜20%までしか下がらない。
係数では届かないため、判定そのものの作り方を変える必要がある。

これは「参照実装の値をそのまま使う」という方針の例外になる。追従が一巡して
から判断する。[ROADMAPの候補](../ROADMAP.md#候補)へ1行で戻した。

**参照実装の値が本エンジンで成立しなかった最初の例である**。
[ADR-0074](0074-feature-verification.md)は「出典のスケール前提が本エンジンで
成り立つかを実測する」と定めている。今回成り立たなかった前提は係数の
スケールではなく、**singular率という発動頻度の設計点**だった。マージンの
絶対値が正しくても、それの掛かる頻度が4倍違えば挙動は別物になる。

付録に載っていない項目が2件見つかった。除外手つき探索の返り値と、PVノードの
再探索前の歯止めである。**付録はムーブループとStep単位で作ったため、返り値の
扱いのような横断的な項目が漏れている**。残りの群でも同じ漏れがありうる。
