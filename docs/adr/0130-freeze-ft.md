# 0130: FTを固定して、後段の実験を一桁速くする

- Status: proposed
- Date: 2026-08-02
- 関連ADR: [0034](0034-nnue-architecture.md), [0064](0064-dense-ft-gradient.md), [0127](0127-net-shape-bench.md), [0128](0128-round-robin-league.md), [0129](0129-auxiliary-heads.md)

## Context

[ADR-0127](0127-net-shape-bench.md)で8構成を比べるのに、**学習だけで7時間かかった**。
1構成あたり3億局面で50〜100分である。本番規模（19.9億局面）なら1構成2.5〜5時間になる。

この時間のほとんどはFTが食っている。FTは3210万パラメータでネット全体の99.94%を占め、
後段の隠れ層は17,440個しかない。**後段の形を比べたいだけなのに、毎回3210万パラメータを
学習し直している。**

比べたい対象は今後も増える。[ADR-0129](0129-auxiliary-heads.md)の補助ヘッドはλを2つ振る
必要があり、output bucketやPSQT直結パスも後段の変更である。1条件1時間では回らない。

## 選択肢と比較

### 案A: 毎回まるごと学習する（現行）

条件ごとにFTから学習し直す。**その構成にとって最適なFTが学ばれる**ので、結果は素直に
解釈できる。ADR-0127の測定はこれで行った。

ただし1条件1時間が動かない。後段だけを10通り試すのに10時間かかる。

### 案B: FTを固定して後段だけ学習する

学習済みネットのFTを読み込んで凍結し、後段だけを更新する。勾配計算も更新も後段だけに
なるので、**1条件が数分で終わる見込み**である。

代わりに、後段の構成にとって最適なFTは学ばれない。FTは元の後段（32×32）に合わせて
学習されたものなので、L1を64にしてもFTはそれを活かす形になっていない。**得られるのは
「同じ表現をどう使うか」の比較であり、「どんな表現を学ぶか」は比べられない。**

## Decision

案Bを足す。**案Aは残す。** 用途が違う。

| 目的 | 使うもの |
|---|---|
| 後段の候補を広く絞り込む | 案B（FT固定、数分） |
| 絞った候補を本評価する | 案A（まるごと、1時間） |
| mainへ入れる判断 | SPRT（[ADR-0028](0028-pruning-extensions.md)） |

**決め手は、案Bで落ちる候補は案Aでも落ちる公算が高いことである。** 固定したFTで使いこなせない
後段が、FTを学習し直したとたんに活きるとは考えにくい。逆は起こりうる（案Bで良く見えた候補が
案Aで伸びない）ので、**案Bは足切りにだけ使い、採用の判断には使わない。**

これは[ADR-0127](0127-net-shape-bench.md)が速度で足切りしてから学習にかけたのと同じ形である。
段を1つ増やして、安い順に落とす。

### 実装

`train.py` に2つ足す。

- `--init-net <path>`: 既存の `.hmwr` を読んでFTの重みを初期値にする
- `--freeze-ft`: FTの `requires_grad` を落とす

`.hmwr` の重みは量子化されている（FTはi16、`f32 × 127` を丸めたもの）。読むときは127で割って
戻す。丸めのぶん元のf32とは一致しないが、**固定して使う以上その差は動かないので影響しない。**

`--init-net` は `--freeze-ft` なしでも使える。**ゼロから学習するより良い初期値から始める**
使い方（継続学習・世代運用）がそのまま乗る。[ADR-0127](0127-net-shape-bench.md)の
`makenet --resize` と組み合わせれば、256で学習したネットを512へ広げてから継続学習できる。
追加次元はゼロから始まるので、**既存の表現を壊さずに容量だけ足す**形になる。

### 何を比べられて、何を比べられないか

FTを固定した比較で意味があるのは、後段の形とハイパーパラメータである。

| 比べられる | 比べられない |
|---|---|
| L1・L2の幅、層数 | FTの幅（FTを学習し直す必要がある） |
| output bucketの分け方 | 特徴設計（HalfKPを変える） |
| 損失の重み（λ） | [ADR-0129](0129-auxiliary-heads.md)の補助ヘッド（FTの表現を変えるのが目的） |

**ADR-0129の補助ヘッドはこの方法で測れない。** 補助ヘッドの狙いはFTの表現を厚くすることなので、
FTを固定したら意味がなくなる。混同しないよう明記しておく。

## Consequences

- 後段の候補を試す回転が一桁速くなる。10通りが10時間から1時間以内になる見込み
- **案Bの結果は案Aと一致しない。** 足切りにだけ使い、採用は案Aとリーグ戦・SPRTで決める。
  この使い分けを守らないと、固定したFTに都合の良い後段を選んでしまう
- 量子化された重みから戻すので、初期値は元のf32と完全には一致しない。`--freeze-ft` なら
  固定なので影響はないが、`--init-net` だけで継続学習するときは丸め誤差が初期値に乗る
- 継続学習の道が開く。`makenet --resize` で構成を広げてから続きを学習できる。
  [ROADMAPの候補](../ROADMAP.md#候補)の「継続学習の世代運用」「公開ネットウォームスタート対照」
  がこの口に乗る
- FT固定の学習はMPS/GPUに載せやすくなる。更新するパラメータが数万に減るので、
  [ADR-0064](0064-dense-ft-gradient.md)で問題になったFT勾配の扱いが関係なくなる
