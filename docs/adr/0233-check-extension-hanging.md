# 0233: 取られるだけの王手を、利きで見分けて王手延長から外す

- Status: proposed
- Date: 2026-10-17
- 関連ADR: [0024](0024-search-v1.md), [0211](0211-check-extension-see.md), [0217](0217-sprt-pass-cap.md), [0232](0232-effect-table-prototype.md), [0074](0074-feature-verification.md), [0163](0163-sprt-hypothesis-choice.md)

## Context

Issue #653で、dl20のネット（`dl20_7860M`）は大差の局面で深さ16の探索が終わらない。
`openings/actdump_positions.txt` の195局面を1局面20秒で打ち切ると、3局面が終わらなかった。
71番目の局面の内訳では、約1,690万ノードのうち王手延長が約850万を占めた。
手数60より深いノードは約1,640万あった。王手延長は無条件で、持ち駒を打つ王手は
同じ局面へ戻らないので千日手でも止まらない。

王手延長は本エンジン独自の機能である（[ADR-0024](0024-search-v1.md)）。
参照実装には無く、単独でSPRTにかけたことはない。
今のコードは `crates/engine/src/search.rs:1889` で `gives_check` を求める。
`search.rs:1897-1905` は `i32::from(gives_check)` をそのまま延長量にしている。

### 前例: ADR-0211

[ADR-0211](0211-check-extension-see.md)は同じ爆発（Issue #471）を相手に、
延長を `see_ge(m, 0)` の王手に限った。診断では爆発が消え、評価値も深く読んだ値を
保った。SPRTは23,483ペアで+2.7 [−0.3, +5.7]、LLR +0.44で判定に至らず、打ち切った。

ADR-0211から引き継ぐ事実は3つある。

- 損な王手は多い。序盤で王手の85%、終盤の大差の局面で23%だった
- 既定の裁定（2000,8）は爆発する域の対局を途中で切る。SPRTの値は実戦の効きの下限に近い
- H0の読みとして「捨て駒の王手から始まる詰み筋を拾っている可能性」が残った

今の規約なら、ADR-0211の+2.7は中点（+2.5）より上なので、上限で延長して続ける
対象になる（[ADR-0217](0217-sprt-pass-cap.md)の追記）。ADR-0211の候補は見送りとして
群で測り直す道が残っている。本ADRはそれと別の変数を測る。

### ADR-0211と何が違うか

利きの表（[ADR-0232](0232-effect-table-prototype.md)の `EffectTable`）があれば、
「王手した駒が、相手に利かれていて自分の利きが無い升にいる」を表引きで判定できる。
これを「取られるだけの王手」と呼ぶ。

| 観点 | ADR-0211（SEE≥0） | 本ADR（取られるだけ） |
|---|---|---|
| 外す王手 | 交換で損をする王手すべて | 王手した駒に自分の利きが1つも無く、相手の利きがある王手だけ |
| 残す王手 | 交換で得か互角の王手 | 損でも自分の駒が支えている王手。例えば支えのある大駒の打ち込み |
| 判定の精度 | 交換の手順まで読む。X線も拾う | 利き数の有無だけを見る。ピンと交換の損得は見ない |
| コスト | 王手ごとにSEEを1回。駒を除くたびに `attackers_to` を引き直す | 進めた後の表で、移動先の升の `attackers` を1回引く |
| 発動率 | 探索した手の1.80%（序盤）、5.38%（終盤） | 未測定。SEE<0の王手の部分集合になる |

コストの差は決め手にならない。王手の多くは、すでにSEEを引かれている。`prune_shallow` の
`see_ge`（`search.rs:2376`）と、静かな王手のオーダリングの `see_ge`（`movepick.rs:747`）である。ADR-0232が通ればSEE自体も表引きになる。

違いは外す集合にある。ADR-0211は「交換で損」を外した。そこには、支えのある駒を
打ち込んで玉の逃げ道を塞ぐ王手も入る。詰将棋の筋で多いのはこの型で、H0の読みが疑った
「捨て駒から始まる詰み筋」に当たる。本ADRは「支えが1つも無い王手」だけを外す。
Issue #653の連鎖で負けている側が続けるのは、玉や守り駒にそのまま取られる駒打ちの王手である。
狙いはそこだけを止めることにある。

外す集合がADR-0211とほぼ同じなら、本ADRはADR-0211の繰り返しになる。
そこで、SPRTの前に集合の重なりを測る（下の「機能検証」）。

## 選択肢と比較

### 案A: 取られるだけの王手を延長から外す

上の定義で外す。表があれば1回の表引き、無くても `attackers_to` を2回で同じ値が出る。

### 案B: 案Aに「玉の逃げ道を減らさない」を足す

取られるだけでも、玉の8近傍の逃げ道を減らす王手は残す。詰み筋をさらに残せる。
条件が2つになり、どちらが効いたか分からなくなる。案Aの結果を見てから考える。

### 案C: 連続王手の回数で延長を止める

`StateInfo` の `continuous_check`（`crates/core/src/position.rs:173`）は、手番側の
連続王手の回数をすでに数えている。N回目以降の王手に延長を付けない案である。
表が要らない。ただし、詰ます側の長い王手の連続も同じように止める。
ADR-0211の診断では、深さの上限（rootの深さの2倍）は爆発を止めなかった。回数の上限も
同じ型の上限なので、見込みは低い。

## Decision

**案Aを採る**。決め手は、ADR-0211のH0の読みが疑った筋（支えのある捨て駒）を残したまま、
Issue #653の連鎖の型を外せることである。

### 実装の位置

`search.rs:1897-1905` の延長量を次のように変える。singularの判定が付いたTT手は、
これまでどおりsingular側の延長を使う。

- 延長は `gives_check && !hanging_check` とする
- `hanging_check` は直接王手に限る。王手駒が動いた駒そのもので、開き王手と両王手は含めない
- 判定は `make_move` の後に、移動先の升 `to` で行う。表の `attackers(to)` で、
  相手の駒がいて自分の駒（`to` の駒自身を除く）がいないなら真にする。
  延長量は `make_move` の後の深さの計算（`search.rs:1940` 以降）で初めて使うので、
  判定を後ろへ動かせる
- 表が無いビルドでは `attackers_to(them, to, occ)` と `attackers_to(us, to, occ)` で同じ値を出す

静止探索の王手の扱いと、枝刈りが見る `gives_check` は変えない。

### 仮説と固定するもの（実験の規律の4点）

1. 仮説: **王手延長から取られるだけの王手を外すと強くなる**
2. 動かす変数: 王手延長の条件だけ。`gives_check` を `gives_check && !hanging_check` にする
3. 固定するもの: 評価関数（`hmwr/config.py` の `EVAL_FILE`）と比較元（着手時のorigin/main）。
   対局条件（10+0.1、裁定2000,8、並列は既定）と開始局面集（既定）も固定する。
   表の有無はビルドに付いてくる。ADR-0232がmainに入っていればその表を使い、
   入っていなければ `attackers_to` 版にする。判定の値は同じなので、木は変わらない
4. 事前登録: 下の「合格の条件」と「結果の読み方」

### 機能検証（SPRTの前に行う）

診断用のビルド（内訳カウンタ、コミットしない）で、2組の局面を測る。
序盤はADR-0211と同じ局面（`start_sfens_ply24` の1397行目、深さ18）である。
終盤は `openings/actdump_positions.txt` の6行目と71行目（深さ19）を使う。

| 測る値 | 足切り |
|---|---|
| 探索した手のうち、取られるだけの王手の割合（発動率） | 0.1%未満ならSPRTにかけない（[ADR-0074](0074-feature-verification.md)） |
| SEE<0の王手のうち、取られるだけの王手の割合（重なり） | 90%以上ならADR-0211と同じ変更とみなし、SPRTにかけない |
| Issue #653の3局面（20秒で終わらなかったもの）が深さ16を終えるか | 1局面も終わらなければ、爆発の型が違う。SPRTの前に原因を調べ直す |
| `hmwr verify` の固定深さのノード数 | 3局面以上で変わること |

重なりが90%以上なら、本ADRはADR-0211をなぞるだけになる。そのときはADR-0211を
[ADR-0217](0217-sprt-pass-cap.md)の延長の規則で測り直す案へ切り替え、本ADRはrejectedにする。

深さ16の完了は、Issue #653と同じく1局面20秒で打ち切って測る。この測定は `hmwr` に入口が無い。
実装のPRで `hmwr diag` に足す（`hmwr bench` は局面ごとの到達深さを出さず、打ち切りで止まる）。

### 合格の条件

- Eloの判定: 既定（elo0=0、elo1=5、α=β=0.05）。棋力の向上を主張する変更である
  （[ADR-0163](0163-sprt-hypothesis-choice.md)）。+10以上は見込まない。ADR-0211の点推定が+2.7で、
  外す集合はそれより狭い
- Elo以外の条件: 上の機能検証の4行を満たす
- 採否: 両方を満たしたときだけ入れる。上限は既定の10,000ペアで、中点の規則は
  ADR-0217の追記に従う

### 結果の読み方（事前登録）

| 結果 | 読み方 | 次の一手 |
|---|---|---|
| H1 | 支えの無い王手の延長はノードの無駄で、支えのある王手の延長は残す価値があった | mainへ入れる。Issue #653を閉じる。ROADMAPの候補「極端な評価値の域での探索」から爆発の記述を消す |
| H0 | 支えの無い捨て駒の王手にも、延長の価値がある | mainへ入れない。王手延長の条件を利きで絞る案は打ち切る。爆発は案C以外の形（深さ指定のときだけ効く形）で別に考える |
| 上限で中点より上 | 効きは小さいが正の側にある | ADR-0217に従い10,000ペアずつ延ばす。30,000ペアを超えるならオーナーに諮る |
| 上限で中点以下 | 効きは±2.5の中にあり、この対立仮説では答えが出ない | 見送りとして記録する。ADR-0211の候補と群にして測り直す材料に回す |


ペアの作成・機能検証・SPRTの3ステップにし、本ADRと同じPRでmainへ入れる。

```
# キューを使わないときは
```

## 機能検証の結果（2026-10-17）

4つの関門をすべて通った。重なりだけは90%の足切りに近く、読みを下に書く。
ADR-0232は不合格で表がmainに無いので、判定は `attackers_to` の2回で実装した。

### 局面の数え方

上の表の「71行目」は、Issue #653の「71番目の局面」を指す。番号はコメント行を
数えない1始まりで、ファイルの74行目に当たる。`hmwr diag reach` もこの数え方で番号を出す。
「6行目」はADR-0211と同じくファイルの6行目である。

### 発動率と重なり

診断用のビルド（コミットしない）で数えた。評価関数は `EVAL_FILE`、1スレッド、置換表256MBである。
数えるのは `make_move` まで進んだ手で、`prune_shallow` で枝刈りした手は含めない。
木は変更前のもの（取られるだけの王手にも延長を付けたまま）である。
終盤の2局面は変更前の木が深さ19を終えないので、60秒で打ち切った値である。

| 局面 | 探索した手 | 王手 | SEE<0の王手 | 取られるだけ（発動率） | 重なり |
|---|---|---|---|---|---|
| 序盤（1397行目、深さ18） | 14.4万 | 8,319 | 7,166 | 6,667（4.64%） | 89.5% |
| 終盤（6行目、深さ19で60秒） | 5,138万 | 2,414万 | 954万 | 850万（16.5%） | 86.0% |
| 終盤（71番目、深さ19で60秒） | 5,256万 | 1,594万 | 429万 | 381万（7.25%） | 80.3% |
| 3局面の合計 | | | 1,384万 | | 84.2% |

重なりは「SEE<0の王手のうち、取られるだけでもある王手」の割合である。
発動率は足切りの0.1%を大きく上回る。重なりは3局面とも90%を下回った。

足切りに近いので、変更後の木でも数えた。序盤は91.5%、6行目は89.6%、71番目は84.0%で、
3局面の合計は84.2%になる。序盤の1局面だけは変更後の木で90%を超える。
事前登録の表は木を指定していない。発動率と同じく、変更前の木の値で読む。
外す集合はADR-0211の集合に近い。それでもSEE<0の王手の1〜2割（支えのある損な王手）は
延長が残り、ADR-0211とは別の変更として測る。取られるだけの王手の96%はSEE<0でもある。

### 深さ16の完了

`hmwr diag reach` で、`dl20_7860M` を使って200局面を深さ16、1局面20秒で打ち切って測った。
1スレッド、置換表256MBである。

| | 変更前 | 変更後 |
|---|---|---|
| 所要の中央値 | 0.40秒 | 0.24秒 |
| 5秒超 | 14件 | 0件 |
| 20秒で打ち切り | 6件（19・51・71・82・122・147番） | 0件 |

変更前の打ち切りはIssue #653の3件より多い。測定中は別のworktreeのビルドが同じ機械で
走っていた。Issueで名前の出た71番と147番は、変更後にどちらも20秒以内に終わった。

### 固定深さのノード数

`hmwr verify --depth 13` で、組み込みの4局面とも、`profile_late_positions.txt` の12局面とも
ノード数が変わった。終盤の12局面では10局面でノードが減り、減り幅は15〜70%である。
8番目の局面の評価値は、変更前の `mate -18` から変更後の `cp -8857` へ変わった。手番側が、
相手の詰みを深さ13で見つけられなくなっている。詰ます側の支えの無い王手にも延長が付かないためで、
H0の読み（支えの無い捨て駒の王手にも延長の価値がある）に関わる。

## 前提条件: ADR-0232が合格しない場合

本ADRは表が無くても成り立つ。判定は `attackers_to` の2回で同じ値になり、探索の木は表の有無で変わらない。
変わるのは判定の費用だけである。王手は探索した手の2〜23%なので、`attackers_to` 版でも
費用は小さいと見込む。SPRTはその費用込みで測る。

ADR-0232が合格したら表引きに置き換える。置き換えは木を変えないので、ノード数の一致で確かめれば足りる。

## Consequences

- H1なら、参照に無い独自の機能を、利きで根拠づけた形に直せる。Issue #653の深さ指定の診断
  （`hmwr net actdump`）も大差の局面で戻る見込みである
- 既定の裁定は爆発の域を切るので、終盤の効きはSPRTに出にくい。floodgateの棋譜で、
  大差の局面の到達深さと切れ負けを、USIログ（`hmwr kifu usilog`）で追う
- 案Bは、H1かつ詰み筋の見落としが残る兆候（floodgateの崩壊局面）が出たときに起こす
- 見直しのトリガーは、評価関数が大差の域で平らに張り付かなくなったときである。
  Issue #653は、dl20が教師を±5941で頭打ちにしたことと重なっている
