# 0178: 日本語文書の書き方をtextlintでCIゲートにする

- Status: accepted
- Date: 2026-08-20
- 関連ADR: [0053](0053-docs-structure.md), [0001](0001-adr-process.md), [0070](0070-pr-based-workflow.md)

## Context

このリポジトリは文書が主要な成果物である。ADR 177本・ROADMAP・DATASETS・
README・CLAUDE.md・スキルで合計182ファイル、1.3MBある。判断の記録が残ることは
オーナーが求める2つのうちの1つで（CLAUDE.mdの冒頭）、読めない文書は
残していないのと同じになる。

**日本語の書き方の規約は既にある**。CLAUDE.mdが一文100字・読点3個まで・
二重否定の禁止・冗長表現の置換・AIっぽさの排除を定めている。守られているかは
人が読んで判断するしかなく、書いた本人が見落とす種類の違反は残り続ける。

実際に測ると520件あった。内訳は次のとおりである。

| ルール | 件数 |
|---|---|
| 一文が100字を超える | 179 |
| 同じ助詞が一文に2回以上 | 233 |
| 誇張・絶対化の表現（`完全に`、`大幅に`） | 33 |
| 漢字が7字以上連続 | 12 |
| 冗長表現（〜を行う、〜することはできない） | 6 |
| その他（弱い表現、二重否定、読点4個以上ほか） | 57 |

規約を書いただけでは守られない。**機械が判定できる規約は、機械に判定させる**。

## 選択肢と比較

### 案A: レビューで見る

PRのたびに人が読む。道具を増やさずに済む。ただしCLAUDE.mdの規約は12項目あり、
1本のADRが300行になることもある。見落としの起きる種類の作業を人が担う形は、
[ADR-0074](0074-feature-verification.md)がSPRT前の機能検証を機械化したのと
同じ理由で続かない。

### 案B: 独自スクリプトを書く

正規表現で冗長表現やAIっぽい語を検出する。CLAUDE.mdの規約と1対1で対応させられる。
ただし一文の長さや助詞の重複は形態素解析が要る。文の分割も、括弧・強調・
箇条書きを踏まえないと誤検出だらけになる。作るものが大きい。

### 案C: textlintを入れる

textlint-ja のプリセットを使う。`preset-ja-technical-writing` が一文の長さ・
読点の数・助詞の重複・二重否定・冗長表現を持ち、`preset-ai-writing` が
誇張表現とAIっぽいリスト書式を持つ。CLAUDE.mdの規約と重なる範囲が広い。
Node依存が増えるが、エンジン本体のビルドには関係しない。

## Decision

案Cを採る。CIで `npm run lint` を回し、指摘が1件でもあれば落とす。

**決め手はCLAUDE.mdの規約が既にプリセットの既定値と一致していたことである**。
一文100字は `sentence-length` の既定100、読点3個までは `max-ten` の既定3、
漢字6字までは `max-kanji-continuous-len` の既定6と同じである。規約を書き換えずに
そのまま機械化できる。

### 無効化したルールと根拠

3つを無効化した。いずれもこのリポジトリの書き方では誤検出になる。

| ルール | 無効化の理由 |
|---|---|
| `max-comma` | 半角カンマ3個で警告する。Eloの信頼区間 `[+9.4, +31.2]` と数値の桁区切りで出る。日本語の読点は `max-ten` が別に見ている |
| `ja-unnatural-alphabet` | 単独のアルファベットを拾う。式の変数名（`r`・`s`・`v`・`p`）が該当する |
| `no-unmatched-pair` | 全角括弧の対応を見る。本文を80桁で折り返すため括弧が行をまたぎ、閉じていても検出される |

`no-doubled-joshi` は並列の助詞（も・でも・にも・とも・ても・や・か）を
許可対象にした。「値も条件も変えない」は日本語の正しい並列表現で、書き換えると
かえって読みにくくなる。CLAUDE.mdの規約にも助詞の重複の項目はない。一方で
「が」「に」「は」「で」の重複は主語と目的語の関係を曖昧にするので残した。

`ja-no-mixed-period` は `allowPeriodMarks` へコロンを足した。CLAUDE.mdが
「名詞ラベル（「例:」「使用方法:」）はそのままで可」と定めているためである。

`max-kanji-continuous-len` は将棋の駒の並び（`歩香桂銀金角飛`）と
`敵陣三段目以内` を許可した。用語として分割できない。

### 強調の中に句点を書かない

導入の過程で、長文179件のうち71件が同じ機械的な原因で出ていると分かった。

textlintが使う文の分割器は `。**` の並びで文を切らない。そのため
`**要点である。** 続きの文` と書くと、強調の閉じ記号より後ろの文まで1文として
数えられる。**この書き方はリポジトリ全体で1,267箇所にあった**。

句点を強調の外へ出す（`**要点である**。続きの文`）と正しく分割される。
見た目は変わらず、強調の範囲が句点1文字ぶん縮むだけである。全1,267箇所を
機械的に変換した。以後は**強調の中に句点を書かない**を規約とする。

### 引用文の扱い

参照実装のコメントなど、原文を変えられない引用は
`<!-- textlint-disable ja-technical-writing/sentence-length -->` で局所的に
外す。[ADR-0153](0153-superior-repetition-root-gate.md)のやねうら王の
コメント引用が該当する。**規約へ合わせて引用を書き換えるほうが害は大きい**。

## Consequences

- 既存の520件をすべて解消した。156ファイルに手を入れている。意味を変えない
  範囲に限り、長い列挙は箇条書きか表へ変えた
- CIにNodeのジョブが1つ増える。`npm ci` と lint で30秒前後になる。
  エンジン本体のビルドと配布物には影響しない
- `package.json` と `package-lock.json` がリポジトリに入る。`node_modules/` は
  gitignoreする
- 新しいADRを書くときは `npm run lint` を通してからPRを出す。CIが落ちてから
  直すより速い
- **プリセットの更新でルールが増えると、既存の文書の落ちる可能性がある**。
  依存はキャレット指定なので、`npm ci` はlockfileに固定した版を使う。更新は
  意図して行い、そのとき出た指摘をまとめて直す
- `完全に一致する` のような技術的に正確な表現も誇張として拾われる。33件は
  「一致する」「すべてゼロ」へ言い換えた。程度のない語へ `完全に` を付けても
  情報は増えないので、CLAUDE.mdの「抽象語より具体を選ぶ」へ沿う結果になった
- 見直しのトリガーは誤検出の増加である。原文を変えたくない箇所で
  `textlint-disable` が5件を超えたら、そのルールの要否をこのADRへ追記して
  判断し直す
