# 0196: ランキング損失のヒンジ発火を分け、後続の方向を決める

- Status: proposed
- Date: 2026-09-02
- 関連ADR: [0158](0158-mirror-factorizer.md), [0185](0185-sibling-ranking-loss.md), [0192](0192-tanuki2024-teacher.md), [0194](0194-dead-dim-measurement.md)

## Context

兄弟局面のランキング損失（[ADR-0185](0185-sibling-ranking-loss.md)）は
+28.9 Eloで採択された。同ADRは後続の実験として「負例の数と選び方」と
「α・δ・rank-batchの配合」を残しており、配合は宣言値のまま一度も
動かしていない。

学習ログを見ると、**ヒンジの発火率は2割弱で下げ止まる**。3億の測定台で
21.4%、29.9億で21%前後、78.6億（[ADR-0192](0192-tanuki2024-teacher.md)）でも
18.7%だった。データを2.6倍にしても動かない。

下げ止まりの中身には3つの見込みがあり、手当てが違う。

1. **順序が逆**。正例より負例のほうが良く見えている。表現力かデータの問題
2. **マージン不足**。順序は正しいが差がδに届かない。δを動かす話になる
3. **教師の誤り**。depth 9の最善手が実際には最善でない。データの上限

**どれがどれだけかを知らずに配合を振っても、当たるかは運になる**。
[ADR-0194](0194-dead-dim-measurement.md)と同じで、実験の前に測る。

## Decision

診断の道具として `hmwr net rank` を足す。学習チェックポイントか書き出し後の
ネットと、`psv rank` が書いた群を受け取り、正例と負例の差の分布を出す。
発火を「順序が逆」と「マージン不足」へ分ける。

```
hmwr net rank training/checkpoints/<名前>/best.ckpt data/train/rank_tanuki_210M.rankpsv
```

分けられるのは1と2で、3は分けられない（正解を知らないため）。それでも
「順序が逆の比較がどれだけ残っているか」が分かれば、αを上げる線とδを
動かす線のどちらに意味があるかを決められる。

## 測定（2026-09-02、`pairrank_7860M_q1`）

10万群（20万比較）を乱数の種を変えて2回測った。δは学習時と同じ0.02。

| 内訳 | f32のチェックポイント | 書き出し後のネット |
|---|---|---|
| 順序が逆 | 5.9% | 6.3% |
| マージン不足 | 12.8% | 13.1% |
| 余裕あり | 81.3% | 80.7% |
| **ヒンジ発火** | **18.7%** | **19.4%** |

学習ログの最終発火率（18.7%）と一致する。量子化を通しても内訳は動かない。

**発火の3分の2はマージン不足である**。12.8/18.7で68%を占め、順序自体は
正しく付いている。順序が逆なのは5.9%しかない。

正例と負例の差（親視点の勝率）の分位点は次のとおり。

```
p1=-0.0529  p10=+0.0019  p25=+0.0368  p50=+0.1243  p75=+0.2937  p90=+0.4494  p99=+0.7986
```

中央値では勝率12.4%の差が付いている。**平均的な負例は簡単すぎる**。
負例は合法手から一様に引いているので、多くは明らかに悪い手になる。
下位10%だけが僅差で、そこにヒンジが集中している。

逆転した比較の深さは平均−0.0308、最小−0.8475だった。大きく逆転している
群も少数ある。

## この測定から言えること

- **δを下げる線は閉じる**。下げれば発火は5.9%へ近づくが、それは
  「勾配を減らす」だけで、順序の学習が進むわけではない
- **αを上げる線の効きは限定的**。αは発火した群の勾配を強くする。
  発火の3分の2は既に順序が正しいので、押し上げても順序の改善にはならない
- **負例の選び方を変える線が残る**。一様に引いた負例は平均的に簡単で、
  中央値で勝率12.4%の差が付く。難しい負例を混ぜれば、細かい順序を学ぶ
  制約を課せる

ただし[ADR-0185](0185-sibling-ranking-loss.md)は逆の懸念を書いている。
「浅い探索の上位を外す」、つまり難しい負例はdepth 9の教師が誤っている
可能性が高いので避ける、という設計意図である。**難しい負例は制約を
強くするが、同時にラベルノイズも増やす**。この綱引きが後続実験の論点になる。

## Consequences

- `hmwr net rank` が増える。学習器のモジュールを読むのでtorchが要る
- 発火率を引用するときは内訳を添える。「2割の発火」だけでは、読み手が
  考える手当てを誤らせる。順序の逆転は6%にとどまる
- 後続の実験は負例の選び方から始める。α・δの配合を振る線は、この測定を
  根拠に優先度を下げる
