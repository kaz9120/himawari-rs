# 0257: 予算を超えた反復を、PVが確定していれば途中で打ち切る

- Status: rejected（既定条件のSPRTでH0、−6.2 [−13.8, +1.3]。mainへ入れない）
- Date: 2026-11-04
- 関連ADR: [0021](0021-time-management.md), [0116](0116-g7-timeman.md), [0253](0253-short-tc-floors.md), [0256](0256-slowmover-allocation.md)

## Context

時間の予算は反復の終わりにしか見ない。予算内で次の反復を始めると、予算を超えても
`maximum`（配分の約3倍）まで読み続ける。そのため1手の消費が大きくばらつく。

floodgateの棋譜4局の160手を順に読むと（20+1、1スレッド）、消費はoptimumの中央値0.72倍に対して
90%点が2.83倍で、15.0%の手が `maximum` まで使っていた。

## 選択肢と比較

### 案A: 次の反復を始める条件を厳しくする

予算の手前で反復を止める比率を動かす案である。完走の見込みを時間から推定するので、
誤ると読めた反復も捨てる。

### 案B: 予算を超えた時点で無条件に打ち切る（不採用）

最善手が崩れかけている反復まで止める。時間を伸ばす係数の狙いと逆になる。

### 案C: PVの手が確定し、最善手が入れ替わっていなければ打ち切る（採用）

条件を満たす反復では、残りの手を読んでも指し手が変わることは少ないと見込む。PVの手が
窓を下回ったときと入れ替わりが起きたときは、従来どおり `maximum` まで読む。

## Decision

案Cを採る。メインスレッドの時間確認で、次のすべてを満たしたら終了時刻を予約する。

- 経過時間が直近の反復の終わりに決めた予算を超えた
- この根の探索で1手目の値がalphaを超えた
- この反復で最善手が入れ替わっていない（全スレッドの計数が0）
- MultiPVが1である

時間確認でしか発動しないので、固定ノードと固定深さの探索は変わらない。

同じ160手で比べると、総消費は406.9秒から371.3秒へ8.7%減り、`maximum` 到達は15.0%から9.4%へ
減った。平均の到達深さは25.69から25.57である。この比較は毎手同じ持ち時間を渡すので、
浮いた時間を後の手へ回す効果は含まない。

### 合格の条件

- Eloの判定: 既定条件のSPRT（10+0.1、elo0=0、elo1=5）。短い持ち時間の棋力向上を主張する
- Elo以外の条件: 切れ負けが1%以下。`hmwr verify` の固定深さのノード数が全局面で一致する
- 採否: 両方を満たしたときだけ入れる

固定深さのノード数は一致する見込みなので、`--no-verify` で起動して別に確かめる。

### 事前登録

- 仮説: 打ち切りで浮いた時間を後の手へ回すと、捨てる読みの価値を上回って強くなる
- 動かす変数: 打ち切りの有無だけ。評価関数と開始局面集はSPRTの既定で固定する
- H1なら入れる
- H0なら棄却する。条件を変えた再試行はしない
- 判定が出ないまま10,000ペアに届いたら、ADR-0217の追記に従い点推定で決める
