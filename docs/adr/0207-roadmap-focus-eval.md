# 0207: ROADMAPを再び棚卸しし、注力を評価関数の学習と構造の1本に絞る

- Status: accepted
- Date: 2026-09-17
- 関連ADR: [0199](0199-roadmap-inventory.md), [0202](0202-smp-loss-diagnosis.md), [0206](0206-entering-king-mix.md), [0126](0126-mate-score-in-training.md), [0120](0120-after-parity.md)

## Context

[ADR-0199](0199-roadmap-inventory.md)の棚卸しから2週間たち、注力の前提が
動いた。オーナーから「やらないことをROADMAPから消し、本当にやりたいことを
整理したい」と要望が出た（2026-09-17）。ROADMAPは経緯を書かない決まりなので、
根拠はここに残す。

動いた前提は3つある。

- 注力1（複数スレッドでの測定と改善）は完了した。8スレッドの並列効率は参照実装の
  0.49に対し本エンジンが0.50で、共有の質は同等だった
  （[ADR-0202](0202-smp-loss-diagnosis.md)）
- 入玉5億の混合は棄却した（[ADR-0206](0206-entering-king-mix.md)）。
  登録外の+37.3だけが次の問いとして残った
- 走っている実験も、開いているPRもない。切り替えに費用がかからない

文書の食い違いも見つかった。ROADMAPの候補に棄却済みの案が残り、千日手の件数が
注力（64局）と候補（38局）で食い違い、CLAUDE.mdはROADMAPを3節と書いていた。

## オーナーの判断（2026-09-17）

- **掘るのは評価関数の構造と学習である**。探索で発明的な発見をするのは
  難しく、それ以外の場所で上位と戦うのは厳しい
- **「探索で戦わない」を極端に解釈しない**。時間管理は有効なはずで、易しい
  局面をすぐ指し、難しい局面に時間を回すだけでレートは上がる。伸び代が
  小さいので後回しにするだけである
- **目標は、いまの放流機でfloodgateのレートが上がることに置く**。選手権は
  AWSの最上位のインスタンスで出る（効果があればクラスター構成も可）。
  ただし、それを当てにした評価関数の構造は取らない。本番は計算資源が
  増えるだけ、と考える
- **PCの新調はしない**。AWSは検討してよいが、資源の投入に厳しい姿勢は
  変わらない。学習1エポック$17〜55の試算（ADR-0199）でも相当に厳しい。
  基本は手元の開発機で進め、本当に当たったレシピの最終実行に限る。
  選手権のリハーサルには使ってよく、優先度は低い
- **応答停止の切り分けは打ち切る**。放流機の問題である
- Stockfishの未採用PRから案を拾う作戦は、あり得る。注力にはしない

## 選択肢と比較

### 案A: 注力2本の形を保ち、完了した項目だけ入れ替える

書き換えは小さい。しかし注力1は完了しており、注力2の7項目のうち4つは
探索・時間管理・放流機の話である。オーナーの判断と合わない項目が注力に
残り、セッションの入口が毎回そこへ引かれる。

### 案B: 注力を評価関数の1本に絞り、探索の案は候補へ下ろす

注力が1本なら、着手の判断に迷いが出ない。探索の案は候補に残るので、
「極端に解釈しない」とも両立する。

### 案C: 探索と時間管理の案をROADMAPから消す

文書はいちばん軽くなる。しかし時間管理や千日手には、実戦の棋譜という
証拠と単独で成り立つ仮説がある。消すと、後で戻る場所がなくなる。

## Decision

**案Bを採る**。決め手は、オーナーの判断が「やらない」ではなく「後回し」
だったことである。

### 消すもの

打ち切った根拠があるものだけを消す。

| 対象 | 根拠 |
|---|---|
| 注力1（複数スレッドでの測定と改善）の節 | 参照実装と同等で完了した（ADR-0202） |
| 応答停止の切り分け、余白の自動較正 | 放流機の問題（オーナー判断） |
| 入玉教師データの混合、入玉局面の評価精度を測る | ADR-0206で棄却した。入玉の指標（開始局面集）は残っている |
| 詰みスコアの扱い | [ADR-0126](0126-mate-score-in-training.md)で素通しの維持と決まっていた。候補への消し忘れである |
| 自己生成の生成条件の精査 | 計算を積む案を打ち切った（ADR-0199の追記）。論点は[ADR-0190](0190-selfplay-decided-thinning.md)が持つ |
| 枝刈り・延長の発動率の計測 | 単独で効く仮説がない。SPSAの対象選定で要るときに起こす |

### 候補へ下ろすもの

Lazy SMPの置換表、極端な評価値での探索の膨れ（Issue #471）、千日手、
時間管理、historyの共有（Issue #430）とfalse sharingは候補に置く。

時間管理の候補は仮説を書き換える。これまでの記述は参照追従の経緯が中心
だった。単独で成り立つ仮説は「易しい局面をすぐ指し、難しい局面に時間を回す」
である。

評価値のクランプとIssue #471は1行にまとめる。どちらも「外挿された極端な
評価値の域で、枝刈りの前提が崩れる」という同じ原因を疑っている。

選手権のリハーサルは候補の基盤へ置く。64スレッド以上で壊れないことの確認で、
historyのメモリ（1スレッド65MiB）、NUMA、置換表の大きさを見る。戦い方では
なく、出場のための点検である。

### 注力

「評価関数の学習と構造」の1本にする。入口は教師系列の混合の統制実験
（ADR-0206の登録外の発見の検証）で変えない。

**何をどの順で掘るかは、本ADRでは決めない**。オーナーと別に議論する。
それまで、評価関数と学習の候補は現状の記述のまま残す。proposedで止まって
いる評価関数系のADR（0132・0134・0140・0147・0194・0196）の扱いも、
その議論で決める。

8月後半の実績は、構造が7連敗、データと損失が当たりだった（ADR-0199）。
この偏りは議論の材料としてROADMAPの注力に書いておく。

### 止まっているproposedの扱い

[ADR-0120](0120-after-parity.md)（追従一巡後の方向）はsupersededにする。
方向の判断はADR-0199と本ADRが上書きした。探索系の3本（0072・0142・0148）は
proposedのまま「保留」と索引に注記する。着手の予定はないが、棄却する測定も
していない。

### 開発プロセスは別のADRで扱う

同じ議論で、`micro` Issueのサイクルが2026-09-04から止まっていたことが
分かった（作成も消化も0件）。原因は開発プロセスが散文で書かれていることに
あり、コマンドの設計と仕事の置き場の両方を見直す。1アイデア1ADRなので、
CLIの設計原則と、ワークフローの層分けは別に起こす。

## Consequences

- ROADMAPの注力・次に着手する・候補を書き換える。千日手の件数は64局
  （ADR-0199の再集計）へ揃える
- CLAUDE.mdの「ROADMAPは3節で構成する」を実態の5節へ直す
- ROADMAPの候補の並び順は、引き続き優先度を表さない。順序付きのキューに
  するかは、ワークフローのADRで決める
- 注力が1本になるので、評価関数の議論が済むまで新しい実験は混合の統制実験
  だけになる。待ち時間は開発プロセスの整備に充てる
- 見直しのトリガーは2つある。評価関数の案が構造・学習とも3件続けて空振り
  したとき。放流機のレートが1か月動かないとき
