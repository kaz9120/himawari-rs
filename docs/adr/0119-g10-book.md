# 0119: 定跡・投票・実務オプションを参照実装へ揃える（G10）

- Status: accepted
- Date: 2026-08-01
- 関連ADR: [0109](0109-reference-parity.md), [0117](0117-g8-ponder.md), [0063](0063-book-loader-and-mini-book.md), [0031](0031-lazy-smp.md), [0026](0026-repetition.md), [0074](0074-feature-verification.md)

## Context

[ADR-0109](0109-reference-parity.md)の追従キャンペーンの第11群。**これで一巡
する。**

3つの独立した機能が入る。互いに依存しない。

**定跡まわりの穴が大きい。** 現行は定跡ヒット時にponder手を返さない。定跡区間
（既定24手）でponderがまるごと死んでいる。[ADR-0117](0117-g8-ponder.md)（G8）で
ponderが+19.3を出したので、その効果が序盤に及んでいない。

**best thread voting**は複数スレッドの結果から投票で最終手を選ぶ。現行は
メインスレッドの結果のみを採る。

**実務オプション**は `ResignValue` と `DrawValueBlack` / `DrawValueWhite` である。

## Decision

3機能をまとめて入れる。

### 定跡

| 項目 | 原典 | 変更点 |
|---|---|---|
| ponder手を返す | book.cpp:58、S:1364-1369 | 新規 |
| ponder欄がないときの補完 | book.cpp:1805-1820 | 1手進めて引き直す |
| ponder中も定跡を引く | S:1115-1117 | 現行は引かなかった |
| 深さと評価値の足切り | book.cpp:1721-1747 | db形式のdepth欄を読む |

指し手の選択は決定的なまま据え置いた。参照実装は足切り後の候補から一様ランダムに
選ぶが、SPRTの再現性を落とす。ランダム化は運用の判断として別に扱う
（[ROADMAPの候補](../ROADMAP.md#候補)の「定跡の掘り下げ」）。

### best thread voting

`votingValue(th) = (score(th) − minScore + 14) × completedDepth(th)` で投票し、
得票数で最終手を選ぶ（S:599-671）。勝ち確定なら短い詰みへ、負け確定なら長く
粘るほうへ、という優先順位が先に立つ。

`completedDepth` をスレッドごとに公開する必要があった。**`Threads=1` では
発動しない。** 既定が1なので、この群の測定には現れない。

### 実務オプション

`ResignValue`（既定99999）は、GUIへ出す評価値が `−ResignValue` 以下なら投了する。
既定では詰みスコアでも届かないので無効である。

`DrawValueBlack` / `DrawValueWhite`（ともに既定−2）は引き分けの評価値を手番別に
持つ。leafではrootと同じ手番なら+、相手番なら−にする。**符号を反転させないと
非対称な探索になる**（原典S:1006のコメント）。千日手を避けやすくするための
負の既定である。

現行は `VALUE_DRAW = 0` に±1の揺らぎを載せるだけだった（[ADR-0026](0026-repetition.md)）。

### 定跡ヒットの保留を2か所で直した

`go infinite` で定跡にヒットしたとき、bestmoveを即座に返していた。参照実装の
待機条件は `ponder || limits.infinite` で、どちらでもstopを待つ（S:1157-1160）。
検討モードでbestmoveを先に返すと、GUIが探索を打ち切ったものとして扱う。

あわせて `usinewgame` で保留を捨てる。前局の保留が残ったまま次局のstopを受けると、
古いbestmoveを返してしまう。

## 機能検証（ADR-0074）

深さ13、4局面。基準はG9完了時点である。

| 局面 | G9 | G10 | 変化 |
|---|---|---|---|
| 1 | 23,407 | 23,407 | +0% |
| 2 | 51,978 | 51,978 | +0% |
| 3 | 175,168 | 189,067 | +8% |
| 4 | 19,248 | 19,248 | +0% |

**3局面が完全一致で、局面3だけ変わる。** 千日手が絡む局面で `DrawValue` が
効いている。定跡（BookFileなし）とbest thread voting（Threads=1）はこの条件で
発動しないので、差は `DrawValue` だけから出ている。

## SPRT

既定条件（10+0.1、床を外して `MinimumThinkingTime=1`・`RoundUpToFullSecond=false`）で
測った。

```
判定に至らず | 6000局 | +2889 =360 -2751 | Elo +8.0 [-0.3,+16.3] | LLR +1.52
```

3000ペアの上限まで回して判定に至らなかった。**測れているのは `DrawValue` の
効果だけである。**

定跡は `BookFile` を両者に指定しないと効かず、best thread votingは `Threads=4` が
要り、定跡ヒットの保留の修正は `go infinite` でしか発動しない。3機能ともこの測定に
現れない。機能検証でも3局面が完全一致で、動いたのは千日手が絡む局面だけだった。

### H1を得ないまま取り込む判断

[ADR-0116](0116-g7-timeman.md)（G7）と同じ扱いにする。根拠は4つ。

**+8.0で正の方向にある。** 下限が-0.3で、6000局を要してこの位置である。効果量が
小さいことは機能検証から予想できていた。

**測れているのは4機能のうち1つだけである。** 残る3つは既定条件で発動しない。
測定の対象になっていない機能を、測定できないことを理由に外すのは筋が違う。

**定跡のponder手は実戦で効く見込みがある。** [ADR-0117](0117-g8-ponder.md)（G8）で
ponderが+19.3を出したが、定跡区間（既定24手）ではその効果がまるごと死んでいた。
floodgateは300+10で定跡を使うので、ここで効く。

**定跡ヒットの保留の修正はバグ修正である。** `go infinite` でbestmoveを即座に
返すと、GUIが探索を打ち切ったものとして扱う。`usinewgame` で前局の保留が残る件も
同じである。

既定値の妥当性はfloodgateでの実戦で確認する。

## Consequences

**これで追従が一巡した。** 11群のうちG10を含む10群が入り、単純加算で+525.5 Elo
（G0は等価変換）。保留はsingularの多段延長と時間配分の分母の2件である。

**既定条件で測れない機能が3つ残った。** 定跡のponder手、best thread voting、
Lazy SMPの窓幅多様化である。いずれも実装は入っているが、SPRTの既定条件
（`BookFile` なし、`Threads=1`）では発動しない。**floodgateが次の測定の場になる**
（[ADR-0120](0120-after-parity.md)）。

定跡の指し手選択は決定的なまま据え置いた。参照実装は一様ランダムに選ぶが、SPRTの
再現性を落とす。同じ相手に同じ負け方を繰り返すなら、実戦の結果を見て判断する。

`DrawValue` を手番別に持てるようになった。既定は−2で千日手を避けやすくしている。
強い相手に引き分けを許容する運用（contempt相当）へ振ることもできる。
