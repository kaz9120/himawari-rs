# 0140: 玉ライン特徴をHalfKPへ追加する

- Status: proposed
- Date: 2026-08-04
- 関連ADR: [0034](0034-nnue-architecture.md), [0035](0035-nnue-accumulator.md), [0044](0044-p7-feature-experiments.md), [0045](0045-remove-effect-tower.md), [0066](0066-halfkp-factorizer.md), [0127](0127-net-shape-bench.md), [0133](0133-effect-pretraining.md)

## Context

容量の3方向が塞がったいま、残る道は特徴設計と教師信号である（ROADMAP）。
教師信号側は利き予測が「初期値の工夫止まり」で終わり
（[ADR-0133](0133-effect-pretraining.md)）、**入力特徴の追加が本命に戻った**。

追加する特徴の候補にはP7期の測定がある。玉ライン特徴
（[ADR-0044](0044-p7-feature-experiments.md)で設計）は、各玉から8方向の
最近接駒を符号化する特徴である。P7期の実測（旧IDEAS.md、git履歴）は
valid lossで 純HalfKP 0.53066 / 玉ライン 0.52832 / 利き塔 0.52565 だった。
**利き塔が稼いだ改善幅の47%を、差分計算可能なまま得ている**。
ただし利き塔側の測定は学習条件（エポック数）が違い、当時ROADMAPに
残っていた「87%」という要約は今回この数字から再構成できなかった。
本ADRでは47%を保守側の実測として使う。

利き塔はNPS 0.6倍で棄却された（[ADR-0045](0045-remove-effect-tower.md)）。
玉ライン特徴の差分計算は平均O(1)・最悪O(9)（ADR-0044）で、桁で軽い。
次元も `玉2 × 方向8 × 駒符号113 = 1,808` である。HalfKPの125,388
（81×1548、`crates/engine/src/nnue.rs` の `FT_IN`）に対して1.4%の
追加にすぎない。ADR-0044は学習実験まで行い、推論側の実装を
「効果確認後に着手」として残したまま、P7の利き塔棄却とともに止まっていた。

利きが表現しづらい理由（遮りの論理積は和で書けない、
[ADR-0133](0133-effect-pretraining.md)）に対して、この特徴は**遮りの答えを
入力に直接与える**。最近接駒はまさに「その方向で最初に遮る駒」であり、
完全復元に数千ユニットが要り256次元には入らない情報（ADR-0133）の
方向別の要約が、1特徴で入る。

## 選択肢と比較

### 案A: HalfKPへ連結してFT入力を拡張する

accumulatorの構造は変えず、特徴インデックス空間を1,808広げる。
学習器はfactorizer（[ADR-0066](0066-halfkp-factorizer.md)）と同居できる。

### 案B: 独立したaccumulatorを持つ

分離はきれいだが、apply_dirtyの経路が2本になりFT更新コストが増える。
FT更新は既に実行時間の25.2%で最大の項目である
（[ADR-0127](0127-net-shape-bench.md)）。

### 案C: 特徴でなく教師信号（合法手集合の予測）で攻める

ROADMAP候補にあるが、利き予測で「的の精度と下流の効きが連動しない」
観測が出た直後であり、同型の的をもう1本張る前に入力側を試すべきである。

## Decision

案Aを採る。工程は4段になる。

1. **差分更新の実装**。駒がAからBへ動いたとき、各玉についてA・Bが属する
   方向（最大4方向）だけ再走査する（ADR-0044の設計）。玉移動時は
   その玉の8方向を全再計算する
2. **学習**。19.9億で現行レシピ。factorizerは玉位置次元を持たないので
   玉ライン特徴には適用せず、素の重みで学習する
3. **NPS計測**。差分再走査のコスト実測。玉移動はHalfKPでも全再計算
   なので、増分は非玉移動時の最大4方向走査に限られる
4. **FT差し替え測定 → SPRT既定条件**

**Elo見込みの根拠は、loss改善のP7期実測（−0.0023、判別限界0.001の2倍超）が
あり、コストが利き塔の桁下であることである**。ただしlossの改善は棋力を
保証しない。同じP7期に、利き塔はlossで勝りながら速度の代償で
+70〜100 Elo負けた（[ADR-0045](0045-remove-effect-tower.md)）。
玉ライン特徴の賭けは「lossの再現」と「速度の軽さ」の2点で、
最終判定はSPRTに置く。

**撤退ライン**。NPSの損が5%を超えたら差分実装を見直し、
それでも残るなら棄却する。loss改善が現行規模の学習で再現しなければ
（0.001未満）、P7期の測定条件（小規模データ・少ステップの学習）との差を
記録して閉じる。

## Consequences

- 特徴インデックスの定義が変わり、ネットのファイル形式の版が上がる
- `Position` 側に8方向最近接駒の管理が入る。do/undoの状態が増える
- 玉ライン特徴が効けば、同型の「安い非加法特徴」（例: 玉周辺の
  利き数の粗い要約）を同じ枠で追加検討できる
- [ADR-0137](0137-output-buckets.md)（output bucket）とは独立に測れるが、
  同時に入れない。1変更1SPRTを守る
