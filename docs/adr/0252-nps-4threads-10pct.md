# 0252: 探索木を変えずに4スレッドのNPSを10%まで上げる

- Status: accepted（4スレッドで+10.68%、1スレッドで+9.81%。比較の起点はb12299c。固定深さのノード数は全局面で一致。SPRTはb12299c比で+39.6 Elo、H1）
- Date: 2026-10-31
- 関連ADR: [0074](0074-feature-verification.md), [0250](0250-nps-4threads.md), [0251](0251-nps-4threads-again.md)

## Context

オーナーの指示（2026-10-30）は、[ADR-0250](0250-nps-4threads.md)の改善を入れたmain（b12299c）から、
探索木を変えずに4スレッドのNPSをさらに10%上げることである。成否はSPRTで判断する。
[ADR-0251](0251-nps-4threads-again.md)の変更で+5〜7%まで来たが、10%に届かなかったので続けた。

測り方はADR-0251と同じである。候補の選別には、1スレッドで1,000万ノードを探索したときの
1ノードあたりのサイクル数を使い、3回交互に測った。採否はNPSのベンチで決めた。

## 選択肢と比較

ADR-0251で命令を減らした部品は、多くが重みの読み込みで律速していた。命令を減らしても
サイクルが減らなかったのはそのためである。今回は、命令の数よりサイクルを縮める変更を探した。
効いたのは2種類だった。1つは、子の局面で引く表の先読みを早く出す変更である。
もう1つは、分岐の予測の外れと演算の依存の連鎖を減らす変更である。

### 採ったもの

| 変更 | サイクル/ノード |
|---|---|
| 静かな手の部分ソートで、閾値以上の手を前へ寄せる走査を分岐なしにする | −20 |
| 対の積の活性は、u8へ飽和縮小してから掛ける | 誤差の範囲（命令−61） |
| 置換表の先読みに使う子のキーを、81升の番号と移動後の駒から求める | −20 |
| 同上をインライン化し、持ち駒を両者の1語のまま足し引きする | −20 |
| 王手の判定を81升の番号で受け、配列盤の添字への往復をなくす | 誤差の範囲（命令−13） |
| 千日手の走査の前に、盤のキーの一致を分岐なしで確かめる | −12 |
| 第1層の疎な積和を、2チャンクずつ別の和に積む | −19 |

各行は1つ前の版との差である。

#### 子のキーと先読み

指し手のループは、合法と分かった時点で子の置換表とeval hashを先読みさせる（ADR-0250）。
そのときの子のキーは、移動元の駒を盤から読み、升を変換してから求めていた。
この読み込みの連鎖が長いと、先読みの出るのが遅れる。手は移動後の駒と81升の番号を持っているので、
盤を読まずに求められる。連鎖を縮めた2つの変更で、合わせて40サイクル減った。

先読みは探索木を変えないが、効き目は大きい。eval hashの先読みを外すと100サイクル遅くなった。
先読みしたキーのうち、実際に進める手は35.6%で、残りは枝刈りされる。それでも
合法と分かった時点で出すほうが速いことは、ADR-0250の測定どおりである。

#### 分岐と依存の連鎖

部分ソートで閾値以上の手を寄せる走査は、静かな手の全部（平均58.8手）を回る。どの手が閾値を
超えるかは手ごとにばらつくので、分岐で書くと予測が外れ続けていた。寄せない手は自分の位置へ
書き戻す形にすると、分岐が消える。

千日手の走査は、遡る手数（最大16手）が局面ごとに違い、ループの出口で予測が外れる。
千日手・優等局面のどれも盤のキーの一致が前提なので、まず7局面ぶんのキーを分岐なしで比べ、
一致が無ければ走査を飛ばす。

第1層の疎な積和は、非ゼロのチャンク（評価1回あたり平均96個）ごとに4本の和へSDOTを足していた。
2チャンクずつ別の和に積むと、依存の連鎖が半分になる。i32の和は正確なので、値は同じである。

利きの段の祖先は平均7.3段たどっていた。たどらない形にした2つの版は、どちらも選ぶ祖先は同じで、
サイクルだけが40増えた。小さな変更でもコードの配置が変わり、サイクルが±2%動くことがある。
そのため、1回の差だけで採らず、3回以上の交互測定と4スレッドのベンチで確かめた。

## Decision

採ったものをすべて入れる。種別は棋力に影響しない変更（`fix`）で、マージの条件はCIが緑であることである。
棋力への効果は、マージの後にSPRTで確かめる。

### 合格の条件

- Eloの判定: マージの後にSPRTで測る。条件は別の節で事前登録する
- Elo以外の条件: 固定深さのノード数・評価値・最善手が、mainと全局面で一致すること。
  4スレッドのNPSがb12299cより10%以上高いこと

## 結果（2026-10-31）

固定深さ13・18・22の組み込み4局面と、深さ16の別の6局面で、ノード数・評価値・最善手がmainと一致した。

NPSは1手500万ノード（1スレッドは300万ノード）×組み込み4局面で、3本を交互に測った。

| スレッド | 周 | b12299c | main（ecd48dc） | この変更 |
|---|---|---|---|---|
| 4 | 10 | 6,938,593 | 7,381,218（+6.38%） | 7,679,831（+10.68%） |
| 1 | 5 | 1,793,603 | 1,903,167（+6.11%） | 1,969,602（+9.81%） |

1ノードあたりの命令はb12299cの9,121から8,155へ、サイクルは2,324から2,103へ減った。
4スレッドのNPSの条件と、ノード数の一致の条件を満たした。

ログは `data/logs/bench-adr0252-nps4.log` と `data/logs/bench-adr0252-nps1.log` にある。

## SPRTの事前登録（2026-10-31）

探索木は変わらないので、棋力の差はNPSの差だけから来る。指示の起点からの改善全体が、
対局で出るかを確かめる。

### 仮説

**NPSが1スレッドで+9.81%上がったmainは、10+0.1の対局で起点のb12299cより強い**。

### 条件

- 比較: baseはb12299c、candはこの変更をマージした後のmain。間にあるのはADR-0251とこの変更で、
  どちらも探索木を変えない
- 持ち時間と並列: 既定（10+0.1、Threads=1）。ADR-0251と同じく、1スレッドでも速さの差があるので、
  4スレッドの条件にしない
- 対立仮説: elo0=0、elo1=10。速度の換算（ADR-0248、314×ln(NPSの比)）では+29前後を見込むので、
  +10以上を見込む変更として宣言する
- 機能検証は `--no-verify` で飛ばす。ノード数が全局面で一致することは、上の結果で確かめてある

### 事前登録した解釈

| 結果 | 解釈と扱い |
|---|---|
| H1 | NPSの差が対局でも出た。指示の目標を満たしたとして、結果をこの節に追記する |
| H0 | 換算の見込みが外れた。速さと棋力の関係を測り直す材料として記録する。探索木は同じなので、コードは戻さない |
| 見送り | ADR-0217の規則で、延長か見送りかを決める |

## SPRTの結果（2026-10-31）

事前登録した条件で、H1を採択した。NPSの差が対局でも出たので、指示の目標を満たした。

| 項目 | 値 |
|---|---|
| 対局数 | 988（494ペア） |
| W-D-L | +525 =50 -413 |
| Elo [95%CI] | **+39.6 [+18.5,+60.9]** |
| LLR | +3.01 |
| 判定 | **H1**（elo0=0 elo1=10） |

切れ負けは0局だった。速度の換算の見込み（+29前後）は信頼区間に入っている。
SPRTは上振れしたところで止まりやすいので、点推定の+39.6は換算の検証に使わない。

## Consequences

- 置換表の先読みのキーは `key_after81` が求め、`do_move` のキーの足し引きと同じ式で書いてある。
  キーの作り方を変えるときは両方を直す。食い違っても先読みが外れるだけで、探索の結果は変わらない
- 王手の判定の本体は `gives_check_at` で、配列盤の手と81升の番号の両方の入口が呼ぶ。
  debugビルドでは、盤を歩く遅い版と突き合わせる
- 千日手の判定に、盤のキーの一致を前提としない規則を足すときは、走査の前の確かめを外す
- 残りの時間の多くは、置換表・eval hash・重みの表の読み込みを待つ時間である。命令を減らす変更より、
  読み込みを早く出す変更と、読み込みを減らす変更のほうが効く
