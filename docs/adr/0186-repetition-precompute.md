# 0186: 千日手判定をdo_move時の前計算にする

- Status: proposed
- Date: 2026-08-26
- 関連ADR: [0026](0026-repetition.md), [0089](0089-improvement-criteria.md), [0153](0153-superior-repetition-root-gate.md), [0155](0155-reference-walkthrough.md), [0163](0163-sprt-hypothesis-choice.md)

## Context

現行の千日手判定（[ADR-0026](0026-repetition.md)）は、探索の各ノードで
履歴を後ろへ線形走査する。走査に手数の上限がなく、`plies_from_null` の
許す範囲すべてを見る。1エントリごとにStateInfoをまたいで飛び飛びに
読むので、200手級の対局では毎ノード約20KBのストライド走査になる。
floodgateの300+10は200手級が珍しくなく、対局が長引くほど全ノードが
重くなる。**性能バグである**。

[ADR-0155](0155-reference-walkthrough.md)の群4がこの箇所を監査済みで、
性能のほかに2つの意味論の課題が記録されている。

1. 相互連続王手の千日手で、現行は手番側の勝ち扱い（危険側）になっている
2. 参照実装は走査を16手で打ち切る。参照コメントに「初手まで遡ると
   R40弱くなる」とあり、遠い一致まで千日手・優等劣等を拾うと探索が
   歪むという測定痕がある

群4は参照整列としては閉じたが（0155の「線を閉じた判断」）、この項目
だけは性能バグの解消として単独で残した。ROADMAPの候補から着手する。

## 選択肢と比較

### 案A: 現行の走査に16手キャップだけ足す

走査コストは定数に収まるが、毎ノードの走査自体は残る。意味論の課題
（LOSE優先）も別途直すことになる。

### 案B: do_move時の前計算へ置き換える（採用）

`do_move` で直前の一致だけを探して距離と種別をStateInfoへ記録し、
探索中の判定はO(1)の読み出しにする。走査は1手につき1回・最大16手で、
探索ノード数よりずっと少ない `do_move` 回数に比例する。意味論も
このタイミングでまとめて直す。

## Decision

**案Bを採る**。設計は次のとおり。

### 前計算

`do_move` のたびに、4手前から2手刻みで最大16手（`plies_from_null` で
さらに制限）を遡り、最初の一致をStateInfoへ記録する。

- `repetition: i16` — 一致までの距離。0は一致なし。負値は「その一致が
  連続王手（Win/Lose）または優等・劣等である」ことの符号に使う
- `repetition_type: Repetition` — 一致の種別（Draw・Win・Lose・
  Superior・Inferior）
- `repetition_times: u8` — 同一局面の出現回数。一致先の値+1を引き継ぎ、
  3（4回目の出現）で強制成立を表す

判定側（`repetition_state(ply)`）は記録を読むだけになる。rootを跨ぐ
優等・劣等を判定しない制限（[ADR-0153](0153-superior-repetition-root-gate.md)）は、
記録した距離とplyの比較で行う。

### 意味論の修正（同じPRで行う）

- 相互連続王手はLOSE優先にする。自分も王手を続けていたら自分の負けと
  判定する（安全側）。現行の手番側勝ち扱いは、詰みのない循環で誤って
  勝ちを主張しうる
- 走査は16手で打ち切る。距離16超の一致は千日手として扱わない。
  4回目の強制成立は `repetition_times` の引き継ぎで拾えるので、
  ルール上の千日手（同一局面4回）を取りこぼさない

### 検証

1. 機能検証は循環局面で行う。verifyの4局面は序盤でほぼ千日手が出ない
   （[ADR-0174](0174-mate1ply-knight-promotion.md)の教訓）。連続王手・
   優等劣等・4回目成立を含む局面列のユニットテストと、長手数局面での
   探索比較を用意する
2. NPSは長手数の局面で測る。開始4局面では走査が短く、差が出ない
3. SPRTは既定条件（elo0=0、elo1=5）。性能と意味論の両面から棋力向上を
   主張する変更である（[ADR-0163](0163-sprt-hypothesis-choice.md)）

**撤退ライン**。H0なら、意味論の修正だけを切り出して非劣性で入れ直すか
検討する。速度の利得は長手数でしか出ないため、10+0.1の対局（平均手数が
短い）ではそもそも測りにくい可能性をADRへ記録して判断する。

## Consequences

- StateInfoが3フィールド増える。do_moveのコストは最大16手の走査ぶん
  増える。かわりに毎ノードの走査が消え、差し引きは大きく軽くなる
- ADR-0026の「1回一致で即Draw」の設計を置き換える。ADR-0026と0153の
  該当記述はこのADRが上書きする（0155群4の記述を引き継ぐ）
- 千日手の意味論が変わるので、定跡生成・selfplayの裁定
  （`repetition_state_all`）にも同じ前計算が効く
