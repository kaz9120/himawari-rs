# 0126: 教師データの詰みスコアをどう扱うか

- Status: accepted（2026-08-01オーナー判断。現行の素通しを維持する）
- Date: 2026-08-01
- 関連ADR: [0040](0040-training-infra-v2.md), [0042](0042-training-log-registry.md), [0043](0043-pyo3-bridge.md), [0066](0066-halfkp-factorizer.md)

## Context

教師信号は評価値と勝敗の混合で作る（[ADR-0040](0040-training-infra-v2.md)）。

```
target = λ · sigmoid(score / 600) + (1 − λ) · result      （λ = 0.7）
```

`data/train/train_1900M.psv` の先頭200万局面で `score` の分布を測った。

| 閾値 | 割合 |
|---|---|
| \|score\| ≥ 1000 | 41.59% |
| \|score\| ≥ 3000 | 14.38% |
| \|score\| ≥ 5000 | 9.82% |
| \|score\| ≥ 20000 | 9.81% |
| \|score\| ≥ 29000 | 8.37% |

**5000から20000の間がほぼ空である**（9.82% → 9.81%）。9.8%は実質すべて詰みスコア
（±29000以上）で、残りは5000未満に収まる。分布が二極化している。

**`sigmoid(score / 600)` は |score| ≥ 4144 で飽和する**（0.001未満または0.999超）。
実測で9.86%の局面が該当した。この範囲では教師信号が0か1に張り付く。

実データで確かめた。`score = 31995` の局面で `target = 1.000000` になる。

**target が 1.0 のサンプルは、BCEで logit を無限大へ押し続ける**。モデルの出力は
量子化で ±31871 に収まる有限値なので、決して届かない。届かない目標に向かって
9.8%のサンプルが勾配を出し続ける。

なお教師データに引き分け（`game_result = 0`）は1件もない。他エンジンの生成物で、
持将棋や千日手を勝敗へ振っているとみられる。データセットの仕様として受け入れる
（2026-08-01オーナー判断）。自前でgensfenを持つときの論点として残す。

## 選択肢と比較

### 案A: 素通し（現行）

変更しない。詰み局面も「勝ち」として最大の教師信号を与える。終盤の局面を1つも
捨てない。ただし上に書いた飽和の問題が残る。

### 案B: 評価値を丸める

`score` を ±N へクランプしてから教師信号にする。「勝勢である」という情報は残り、
教師信号が0/1に張り付かない。詰みの手数の違いは表現できなくなるが、**詰みは探索が
見つけるもので、評価関数は形勢を表すもの**という分担には合う。

Nの候補は4000（sigmoidの飽和点）と2000。実データの `score = 31995` で、
clamp 4000 なら target 0.999110、clamp 2000 なら 0.975888 になる。

### 案C: 除外する

`score_limit` で落とす（実装済み、既定は無効）。9.8%の学習データを捨てる。
終盤の局面が減るので、入玉や詰むや詰まざるやの局面で弱くなるおそれがある。

## Decision

**測ったうえで、現行の素通しを維持する**。

5条件を3億局面で測った。valid lossは低いほどよい。

| 条件 | 設定 | valid loss | 現行との差 |
|---|---|---|---|
| B | clamp 4000 | **0.49840** | −0.00006 |
| A | 素通し（現行） | 0.49846 | — |
| D | clamp 2000 | 0.50085 | +0.00239 |
| C | 除外 5000 | 0.50463 | +0.00617 |
| E | clamp 1000 | 0.51897 | +0.02051 |

**除外は明確に悪い**。9.8%のデータを捨てる損失が、飽和を避ける利得を大きく上回った。

**クランプは飽和点（4000）が最良で、そこから強めると急激に悪化する**。理屈と一致する。
`sigmoid` は |score| ≥ 4144 で飽和するので、そこより上を丸めても情報を失わない。4000より
下を丸めると、実際に区別できていた評価値を潰す。1000では「+1000も+30000も同じ」になり、
中盤の優劣が消える。

**それでも現行を維持する**。最良のclamp 4000でも差は0.00006で、採用の根拠にならない。
参考として、factorizerの導入（[ADR-0066](0066-halfkp-factorizer.md)）は0.00051の改善で
採択された。その1/8である。1回の測定では、この差が本物か測定ノイズかも判別できない。

**「理論的に正しいが効果が測れない変更」は入れない**。入れれば教師信号の作り方が1つ
分岐し、以後すべての学習でその分岐を考えることになる。得られるものが測定限界以下なら、
複雑さのほうが確実に残る（2026-08-01オーナー判断）。

### 測り方

**validには変換を適用しない**。教師信号の作り方を変えると物差しが変わり、条件間で
valid lossを比べられなくなる。現行の `train.py` は `score_limit` をtrainとvalidの
両方へ渡していたので、trainだけに効くよう分離した。

学習データは3億局面（`train_1900M.psv` の先頭）を使う。本番の19.9億では1条件2.5時間
かかるが、3億なら20分で済む。**傾向を見るのに本番規模は要らない**。

学習条件は現行ネット（`halfkp_1900M_fact`）と揃える。
`--batch-loader --dense-ft --factorized`、batch 16384、peak_lr 0.001、
λ 0.7 である。差が条件だけから出るようにする。

### valid lossで足りるか

**足りない可能性がある**。validを素通しにする以上、詰み局面の target は0/1のままで、
そこを外すモデルはvalid lossで不利になる。クランプで学習したモデルは詰み局面で極端な出力を出さない。そのため
**valid lossが悪化しても棋力の上がることがありうる**。

3条件の差が小さければ、valid lossでは決まらない。そのときはSPRTへ回す。
[ROADMAPの候補](../ROADMAP.md#候補)にある「教師との指し手一致率の計測」も、lossとは
別の健全性指標として使える。

## Consequences

- 教師信号の作り方は変えない。9.8%の局面で target が0か1に張り付く状態は残る。
  **理論的な懸念は実在するが、3億局面では棋力に届く差にならなかった**
- `--score-clamp` と `--score-limit` の実装は残す。既定はどちらも無効で、コードパスは
  1行の分岐にすぎない。**本ADRの実験を再現できる状態を保つためである**。ただし
  「いつか使う見込み」で残しているわけではない。本番規模（19.9億局面）で測り直す
  意味があるかは分かっていない。データ量が増えると差が開くとも縮むとも言えない。
  **次にこのADRを読んだ人が「測り直す価値がない」と判断したら、実装ごと消してよい**
- `train.py` の train/valid 分離は残す。教師信号の作り方を変える実験すべてに要る。
  分離していないと、条件を変えるたびに物差しも変わって比較にならない
- valid lossが棋力の代理指標として弱いことが、また確認できた。
  [ADR-0045](0045-remove-effect-tower.md)の利き塔は valid loss が0.005低いのに棋力が
  70〜100 Elo劣り、[ADR-0067](0067-ft-dimension-512.md)のFT512は valid loss が最良なのに
  NPSで負けた。**今回は逆に、valid lossの差が小さすぎて棋力を推し量れなかった**。
  この指標で決められる範囲は狭い
