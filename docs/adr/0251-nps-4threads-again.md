# 0251: 探索木を変えずに4スレッドのNPSをさらに上げる

- Status: accepted（4スレッドで+5.11%〜+6.53%、1スレッドで+6.59%。目標の10%は未達。SPRTは+13.2 Elo でH1）
- Date: 2026-10-31
- 関連ADR: [0074](0074-feature-verification.md), [0241](0241-mailbox-board-research.md), [0250](0250-nps-4threads.md)

## Context

オーナーの指示（2026-10-30）は、[ADR-0250](0250-nps-4threads.md)の改善を入れたmainの4スレッドのNPSを測り、
探索木を変えずにさらに10%上げることである。成否はSPRTで判断する。対象は既定の構成 `1024x16x32e64` と
現行の評価関数 `pool1_2ep_f2_reorder` に限る。

mainの4スレッドは約684万NPSで、1スレッドの約171万のほぼ4倍だった。並列の損失は無いので、
1スレッドあたりの処理を速くする方針をADR-0250から引き継いだ。

### 測り方

NPSのベンチは2本を交互に回しても±1%ほど揺れ、1%前後の差を見分けられなかった。そこで候補の選別には
`/usr/bin/time -l` が出す退役命令数とサイクル数を使った。1スレッド、組み込み4局面、計1,000万ノードで、
1ノードあたりの値に直す。命令数は実行ごとに変わらず、サイクルの揺れも1%ほどに収まる。

mainは1ノードあたり9,132命令・2,416サイクル（IPC 3.78）だった。命令の数で速さが決まっているので、
命令を減らす変更を探した。部品ごとの命令数はその部品を同じ引数で2回呼ぶ版を作り、増えた分で見積もった。
結果は同じなので探索木は変わらない。

| 部品 | 1ノードあたりの命令 |
|---|---|
| FTの差分更新（活性化込み） | 約1,000 |
| 第1層以降（非ゼロ探索、第1層、第2層、出力） | 973 |
| 指し手生成 | 811（うち静かな手248） |
| 進めると戻す | 635 |
| 利きの段の差分 | 544 |
| 静かな手の採点 | 534 |
| SEE | 309 |
| 1手詰め | 207 |
| 子の先読みのキー | 178 |
| 王手判定 | 139 |

ノードの77%は通常探索で、静止探索は23%だった。評価は1ノードあたり0.43回、第1層の非ゼロの4列チャンクは
評価1回あたり96個（288個中）だった。

## 選択肢と比較

候補ごとに入れて測り、効いたものだけを残した。条件はADR-0250と同じで、固定深さのノード数が全局面で一致することと、
交互に測って差が出ることである。

### 採ったもの

| 変更 | 命令/ノード | サイクル |
|---|---|---|
| FTの最後の段で、accを書くのと同時に対の積の活性を連結ベクトルへ書く | −225 | −3% |
| 第2層は、ゼロで埋めた列を読まずに16列だけ積和する | −53 | 誤差の範囲 |
| 静かな手の採点で、表の面をノードごとに引き、添字の検査を手ごとに1回にする | −310 | −1.2% |
| 第2層を4行ずつペア加算で畳み、バイアス・シフト・clipをベクトルで当てる。第1層の出口も同じにする | −325 | −2.2% |
| 非ゼロ探索のビット数を表で引く | −53 | 誤差の範囲 |
| 静かな手の採点のループから関数呼び出しを出す。王手の升は表で受け取り、王手のSEEは後でまとめる | −65 | −1.5% |

各行は1つ前の版との差である。

#### 活性化を差分更新に畳む

評価する段のaccは親のaccに差分を当てて作る。その段で前半と後半のチャンクを同じ周で作れば、
レジスタに残っているうちに対の積を書ける。書いたaccを読み直す4KBのパスが消える。
最後の段を差分で作る評価は全体の85%で、残り（玉が動いた直後など）は従来どおり読み直す。

#### 第2層の畳み方

これまでの第2層は8行を束ねて積和し、出力1つごとに水平加算とスカラーのclipを払っていた。1行の積和を1本のベクトルに溜め、
4行ぶんをペア加算で畳むと、4出力の和が1本に並ぶ。飽和縮小で負を0にし、u8への縮小のあと127で抑えれば、
clipもベクトルのまま済む。

#### 静かな手の採点

ループの中に関数呼び出し（王手の升の取得と、王手になる手のSEE）があると、値がスタックへ退避され、
手の列の長さも毎回メモリへ書き戻される。王手の升は駒種ごとの表を1回で受け取り、SEEは王手になる手だけを
ループの後で当てる。SEEは局面を変えない判定なので、呼ぶ順を変えても結果は同じである。

### 効かなかったもの

| 変更 | 結果 |
|---|---|
| キャッシュからの全計算で、数ライン先の重みを先読みさせる | −0.26% |
| 同上で、行の参照を先に固定長の配列として引く | 命令−43、サイクル+1〜4% |
| 玉が動いた手を進めた時点で、全計算の行を先読みさせる | 命令+108、サイクル+1.5% |
| 静かな手のソートを、点数と位置を詰めた語の不安定ソートにする | 誤差の範囲 |
| 同上を、取り出すときに1手ずつ選ぶ遅延ソートと分岐なしの分割にする | 誤差の範囲 |
| 同上を、分岐のない順位の数え上げにする | 命令+78、サイクルは誤差の範囲 |
| 活性化の飽和をNEONの縮小命令で書く（関数に切り出す形） | 命令+500 |
| FTの差分更新と活性化を、すべてNEONの組み込み関数で書く | 命令+100〜150 |
| 非ゼロ探索を、FTの活性化を書くカーネルの中で行う | 命令+94、サイクル+3〜4% |
| 非ゼロ探索のマスクを `tst` と `uzp1` で作る | 命令は同じ（LLVMが同じ形にしていた） |
| 第1層のループを2チャンクずつ回す | 命令−19、サイクルは誤差の範囲 |
| 第1層のうち利きの部分を、非ゼロを探さずに密に積和する | 誤差の範囲 |
| 利きの段の重みを、先手と後手の行が隣り合う表に並べ替える | 命令−81、サイクル+1.3% |
| 駒打ちの手を、8升ずつ表で位置を引いてまとめて積む | 誤差の範囲 |
| 取る手を行き先の側から引き、元の生成順へ並べ直す | 誤差の範囲 |
| 指し手の取り出しで、手を順に返すだけの段を呼び出し側へインライン化する | 命令−37、サイクルは誤差の範囲 |
| eval hashを2^21〜2^25にする（既定2^23） | −0.9〜+0.1%（4スレッド） |

全計算の遅さは重みの行の読み込み待ちと見て先読みを2通り試したが、どちらも効かなかった。
ソートも分岐の外れが主と見て3通り試したが、効かなかった。どちらの仮説も外れたと読む。
命令を減らしてもサイクルが減らない変更は、表が大きくなるか、ループの中の状態が増えたものだった。

## Decision

採ったものをすべて入れる。種別は棋力に影響しない変更（`fix`）で、マージの条件はCIが緑であることである。
棋力への効果は、ADR-0250と同じくマージの後にSPRTで確かめる。

### 合格の条件

- Eloの判定: マージの後にSPRTで測る。条件は別の節で事前登録する
- Elo以外の条件: 固定深さのノード数・評価値・最善手が、mainと全局面で一致すること。
  4スレッドのNPSがmainより10%以上高いこと

## 結果（2026-10-31）

固定深さ13・18・22の組み込み4局面と、深さ16の別の6局面で、ノード数・評価値・最善手がmainと一致した。

NPSは1手500万ノード×組み込み4局面、置換表は既定で、mainと交互に測った。

| スレッド | 周 | main | 候補 | 比 |
|---|---|---|---|---|
| 4 | 7 | 6,759,350 | 7,104,987 | +5.11% |
| 4 | 5 | 6,842,786 | 7,289,606 | +6.53% |
| 1 | 3 | 1,707,817 | 1,820,435 | +6.59% |

7周の計測はload averageが3.3〜4.0の中で行い、候補の1周目だけが674万と低かった。
命令数は1ノードあたり9,132から8,240へ9.8%減り、サイクルは2,416から2,270前後へ6%減った。

**10%の目標には届かなかった**。Elo以外の条件のうち、ノード数の一致は満たし、NPSの条件は満たしていない。
探索木は変わらず、NPSは上がっているので、変更は入れる。

ログは `data/logs/bench-adr0251-nps4.log` にある。

## SPRTの事前登録（2026-10-31）

探索木は変わらないので、棋力の差はNPSの差だけから来る。マージの後に、その差が対局で出るかを確かめる。

### 仮説

**NPSが1スレッドで+6.59%上がったので、10+0.1の対局でmainの直前版より強い**。

### 条件

- 比較: baseは#984の直前のmain（b12299c）、candは#984のマージ後のmain（bd8c60c）。間にあるのはこの変更だけである
- 持ち時間と並列: 既定（10+0.1、Threads=1）。ADR-0250と同じく、探索木が同じで1スレッドでも差があるので、4スレッドの条件にしない
- 対立仮説: elo0=0、elo1=10。速度の換算（ADR-0248、314×ln(NPSの比)）では+20前後を見込むので、+10以上を見込む変更として宣言する
- 機能検証は `--no-verify` で飛ばす。ノード数が全局面で一致することは、上の結果で確かめてある

### 事前登録した解釈

| 結果 | 解釈と扱い |
|---|---|
| H1 | NPSの差が対局でも出た。結果をこの節に追記する |
| H0 | 換算の見込みが外れた。速さと棋力の関係を測り直す材料として記録する。探索木は同じなので、コードは戻さない |
| 見送り | ADR-0217の規則で、延長か見送りかを決める |

## SPRTの結果（2026-10-31）

| 項目 | 値 |
|---|---|
| 対局数 | 4488（2244ペア） |
| W-D-L | +2204 =251 -2033 |
| Elo [95%CI] | **+13.2 [+3.3,+23.2]** |
| LLR | +3.20 |
| 判定 | **H1**（elo0=0 elo1=10） |

事前登録のH1にあたり、NPSの差は対局でも出た。切れ負けは13局（0.3%）で、対局の環境は正常だった。
換算の見込み（+20前後）は信頼区間に入っている。

## Consequences

- 静かな手の採点は王手のボーナスをループの後で当てる。採点の式を変えるときは、2つのループの両方を見る
- 配列盤の `check_squares_all` を足した。coreの探索の構成（`core-search`）では駒種ごとに引き直す
- FTの最後の段を作る `ft_apply_out` は、評価のときだけ使う。親の段を作るときは従来の `ft_apply` を使う
- 残りの差はどの部品にも1〜3%ずつ散っている。命令数のほかに、表の大きさとループの状態の数を見ないと、
  命令を減らしてもサイクルは減らない
