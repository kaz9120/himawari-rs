# 0133: 利き予測でFTを自己教師あり事前学習する

- Status: proposed
- Date: 2026-08-03
- 関連ADR: [0034](0034-nnue-architecture.md), [0045](0045-remove-effect-tower.md), [0066](0066-feature-factorizer.md), [0127](0127-net-shape-bench.md), [0129](0129-auxiliary-heads.md), [0130](0130-freeze-ft.md), [0131](0131-frozen-ft-light-head.md), [0132](0132-ft-distillation.md)

## Context

**ボトルネックは一貫して上流にある。** 後段を32x32から16へ削ってもvalid lossは0.0006しか
動かず（[ADR-0131](0131-frozen-ft-light-head.md)）、線形1層でも0.001に収まる
（[ADR-0127](0127-net-shape-bench.md)）。ヘッドの容量は効いていない。FTを太らせる道は
速度で潰れ、蒸留は教師が生徒より0.0007しか良くないところで頭打ちになった
（[ADR-0132](0132-ft-distillation.md)）。

### FTはCBOWと同じ構造をしている

FTの正体は次の形である。

```
出力 = clamp(Σ w[特徴i] + bias, 0, 1)
```

疎特徴の埋め込みを和で集約し、非線形性はclamp 1回だけ。**word2vecのCBOWと同じ
bag-of-embeddingsである。**

したがって、FTが豊かな表現を持たない理由を構造に求めることはできない。word2vecの構造も
線形のエンコーダと線形のデコーダをsoftmaxで挟んだだけで、成功は**的の情報量**と
**大きな共有デコーダ**から来ている。FTに欠けているのはその2つで、的はスカラー1つ、
デコーダは積和17,440回しかない（2026-08-03オーナーとの整理）。

### 利きは、FTが原理的に持っていない情報である

[ADR-0045](0045-remove-effect-tower.md)は利きを入力特徴に足そうとして、NPS 0.6倍で
落ちた。**差分計算可能性と引き換えに、非加法的な特徴を手放したのがNNUEである。**
手書き評価関数の時代（習甦の入力層は各升の利き数だった）に使えていた情報が、
いまは使えていない。

利きには、事前学習の的として望ましい性質がそろっている。

- **探索が要らない。** 指し手生成器で厳密に計算できる。ラベルが無料同然になる
- **局面をいくらでも作れる。** 関係が決定的で局面分布に依存しないので、乱れた局面でも
  正しい的が得られる
- **加法では解けない。** 遮りが絡む

## 生徒のFTに何ができて、何ができないか

設計はこの1点に縛られるので、先に整理する。

**pseudo-利き（遮りを無視した利き）は厳密に加法である。** 升sの利き数は
「駒pがsを攻めるか」の和で、各項は駒種と升だけで決まる。FTの1次元にそのまま入り、
線形ヘッドが読める。81×2次元で厳密に解ける。

**だから的にする意味がない。** 加法で書けるなら、ヘッド側も十分な基底があれば線形に
復元できる。FTに置いても情報が増えない。

**実利き（遮りあり）は違う。** 飛車がe1からe5を攻めるのは、e2〜e4が空のときだけである。
これは論理積で、和では書けない。

ここで効くのがclampである。**飛車の特徴に大きな正の重み、遮り候補の升に大きな負の重みを
置いてバイアスを調整すれば、clampが閾値ゲートとして働く。** 遮りは1ユニットで表現できる。

**足りないのは表現力ではなく個数である。** (飛び駒の位置 × 標的升)の組み合わせを網羅するには
数千のユニットが要り、256次元には入らない。**完全復元は原理的に不可能である。**

**したがって頭打ちは「起きたら」ではなく「必ず起きる」。測るのはその位置である。**

## 選択肢と比較

### 案A: マスク予測（BERT風）

駒を隠して残りから当てる。**word2vecの目的関数をそのまま移した形**で、構造の対応は
いちばん素直である。

学べるのは共起、つまり陣形の構造になる。価値の意味からは遠い。**ベースラインとして
温存する。**

### 案B: afterstate予測（1手先）

局面と指し手から次局面の表現を予測する。FTが線形なので、**差分更新の規則を学ぶだけで
自明に解けてしまう。** 採らない。

k手先やPV末端を的にする版は筋が良いが、教師の生成に探索が要る。将来の拡張として温存する。

### 案C: 時間的対照学習

同一対局の近傍局面を近づける。信号が弱く、崩壊対策の実装が重い。採らない。

### 案D: 利き予測（本案）

盤面から厳密計算できるが、推論時には計算コストが高くて入力にできない情報を的にする。

## Decision

案Dを採る。**利き予測でFTを事前学習し、評価値学習の初期値にする。**

**決め手は、NNUEの構造的な弱点と的が正確に噛み合っていることである。** 利きを入力に
できないから[ADR-0045](0045-remove-effect-tower.md)は失敗した。**入力にできないなら、
出力として当てさせればよい。** 推論時のコストはゼロのままである。

加えて、予測タスク自体が表現の質の測定（probing）を兼ねる。前節のとおり完全復元は
できないので、**どこで頭打ちになるかがFTの容量の測定値になる。**

### 二段階に分ける

```
[第1段階: 事前学習（探索フリー）]
  局面（棋譜＋撹乱） → 利きラベルを即時計算
    → FT + 利きヘッドを学習 → ヘッドは捨てる

[第2段階: fine-tune]
  FTを初期値に採用 → 既存の評価値教師データで通常の学習
    → 基準（乱数初期値）と比べる
```

第2段階の口はすでにある。`--init-net`（[ADR-0130](0130-freeze-ft.md)）で初期値に読み、
`--freeze-ft` で段階的解凍もできる。

### 的はT3（長短を分離）。ただし両方を的に入れる

3つの案を検討した。

| 案 | 中身 | 判断 |
|---|---|---|
| T1 | 81升×2陣営の利き数回帰 | 長短が混ざる |
| T2 | 同、利き有無の二値 | **遮りの信号が最も希釈される。** 遮られた升も別の駒が利いていることが多く、二値では答えが変わらない |
| **T3** | **短い利きと長い利きを分離** | **採用** |

**短い利き（歩桂銀金玉、および飛角香の隣接）は遮りが原理的に起こらない。** 完全に加法で、
学習しても新しいものは得られない。**非加法な情報は飛角香の遠隔利きにしか存在しない。**

だからといって短い利きを的から落とすと、**FTがそれを表現する理由がなくなる。** 後段が
読むのはaccumulatorだけなので、FTが持たなかった情報は復元できない。習甦の入力層は
各升の利き数そのものだった。落とすと利き数の大部分が消える。

**分離は落とすためではなく、測るためである。**

| 出力群 | 役割 |
|---|---|
| 短い利き（81×2） | 加法で解けるのでほぼ100%出るはず。**健全性チェック** |
| 長い利き（81×2） | 非加法。**容量の壁を測る本体** |
| 和 | 利き数そのもの。表現として保持される |

重み付けは当面いらない。短い利きは早く収束するので、勾配は自然に長い利きへ寄る。

竜と馬は両方を持つ。**「長い」を『飛角香の筋のうち隣接升より先』と定義**すれば、
竜馬も同じ規則で分解できる。

### ヘッドの形は決め打たず、比較軸にする

[ADR-0129](0129-auxiliary-heads.md)は「ヘッドを深くするとタスクをヘッド自身が解いてしまう」
として線形1層を採った。**利き予測でも同じ懸念がある。** 2〜3層のMLPは遮りの論理積を
自分で計算できてしまい、FTが覚える理由がなくなる。

一方で、**SimCLRは非線形のprojection headのほうが良い表現になると報告している。**
ヘッドが事前学習タスク固有の計算を吸収し、エンコーダ側が汎用のまま残るためである。
この論法がFTに効きにくい理由はある（エンコーダが1層しかなく、「汎用を保ったままヘッドが
特化する」余地がない）が、否定はできない。

**議論で決めず、1条件として測る。** 3億局面で1条件20分なので安い。

- 線形1層ヘッド
- 2層MLPヘッド

probingは両方とも線形で行うので、比較は公平になる。

**なお代用可能性（「歩で足りるが歩がないので香で代用」）を狙うなら線形が要る。**
word2vecで似た語が近づく機構は**共有された線形デコーダ**であり、非線形にすると
離れたベクトルでも同じ出力へ写せてしまい、近づく理由が消える。

利き予測はこの代用可能性を和の水準で作る。**香が2升先で遮られていれば、その実利きの
寄与は歩と同一になる。** 同じ利きマップを要求されるので、accumulatorが近づく。
（FTの表の行そのものは文脈に依存できないので、代用可能性が成立しうるのは和の水準だけ
である。後段が読むのは和なので、それで足りる。）

### 判定はprobingを主にし、対局は最後だけ

[ADR-0132](0132-ft-distillation.md)で、**リーグ戦の解像度が直接対決で±55 Elo**だと
分かった。的の設計やヘッドの形を対局で比べるのは割に合わない。

φを凍結して線形ヘッドだけを載せ、検証精度で比べる（[ADR-0130](0130-freeze-ft.md)の
FT固定学習がそのまま使える。1条件10〜20分）。

| probingのタスク | 何を見るか |
|---|---|
| 利き有無（長短別） | 事前学習が効いているか。容量の壁の位置 |
| 評価値回帰 | 評価に転用できる表現か |
| 勝敗（WDL） | 同上、別の軸 |

比較の3点は、乱数初期値のφ（下限）、**現行ネットから抜いたFT（上限側の参照点）**、
本案のφである。上限側は今日測った。[ADR-0131](0131-frozen-ft-light-head.md)の
`frz-32x32` が−0.7 Elo で、**FTを差し替えて後段を学習し直す操作は棋力中立である。**

採否は最終的にSPRTで決める（[ADR-0028](0028-pruning-extensions.md)）。

### 局面の供給

実戦棋譜を基礎に、次を行う。

- 序盤の重複除去。同一局面の出現回数に上限を設ける
- 進行度で層化サンプリングし、序中終盤を概ね均等にする
- **ランダム手による撹乱局面を混ぜる（初期値30%）。** 推論時にFTが呼ばれるのは探索木内の
  乱れた局面である

優劣・手番による除外はしない。劣勢局面にも固有の共起構造がある。

**構造タスクなので、撹乱の比率は上げても害が小さい。** 利きの関係は決定的で局面分布に
依存しないためである。価値タスクではこうはいかない。

### 実装は1点だけ足りない

仕様書は「フェーズ1で1〜2週」としていたが、**この repository では大半が揃っている。**

| 要素 | 現状 |
|---|---|
| 学習時だけのヘッドを足して書き出し時に捨てる経路 | **ある**（[ADR-0132](0132-ft-distillation.md)） |
| FT凍結・段階的解凍 | **ある**（`--freeze-ft`、[ADR-0130](0130-freeze-ft.md)） |
| FTを初期値に採用 | **ある**（`--init-net`） |
| linear probing | **ある**（FT固定学習がそのまま。1条件10〜20分） |
| 3億局面の学習時間 | 20分（mps） |
| **利きラベルの計算** | **ない。これだけが新規** |

`extract_batch` のRust抽出パスに、実利きを長短に分けて返す関数を1つ足す。指し手生成器は
すでにある。

## Consequences

- 学習時間が増える。利きヘッドの順伝播・逆伝播と、ラベル計算が乗る
- ハイパーパラメータが増える（λ_effect）。[ADR-0132](0132-ft-distillation.md)の教訓どおり、
  **λは値ではなく `λ × 利き損失 ÷ value損失` の割合で決める**
- **推論側は変わらない。** ヘッドは書き出し時に捨てる。効かなければ学習側の分岐を消すだけ
- 破滅的忘却への手当ては、効かなかったときにだけ入れる。FTの学習率を下げる、段階的解凍、
  fine-tune中も利き損失を小さく併走させる、の順で試す。**併走は安い。** 評価値教師の局面にも
  利きラベルはその場で計算できる
- **撤退ライン。** probingで乱数初期値に勝てない的の設計は捨てる。fine-tuneで序盤の収束だけ
  速く最終lossが並ぶなら、事前学習単独をやめて併走へ移る
- **頭打ちの位置が分かれば、次の判断材料になる。** 256次元で長い利きをどこまで表現できるかは、
  FTを太らせる投資の期待値を直接見積もる材料である
- 的の拡張は利き単独の結果を見てから積む。**合法手集合**（2187次元のmulti-label）が次の候補で、
  遮りに加えてピンと王手放置が絡むため非加法性が強い。玉の安全度へ部分的に届く。
  ただし**「誰が利いているか」まで分解する的は採らない。** 機能が同じ駒に別の答えを要求する
  ことになり、代用可能性を壊す
