# 0258: 1手の上限maximumを配分の3倍から4倍へ広げる

- Status: rejected（既定条件のSPRTでH0、−3.0 [−9.0, +3.0]。3倍を据え置く）
- Date: 2026-11-04
- 関連ADR: [0021](0021-time-management.md), [0253](0253-short-tc-floors.md), [0257](0257-cut-settled-iteration.md)

## Context

[ADR-0257](0257-cut-settled-iteration.md)は、予算を超えた反復を打ち切って総消費を8.7%減らし、
既定条件のSPRTで −6.2 [−13.8, +1.3] だった。読みかけの反復には、浮いた時間を後の手へ回すより
大きな価値があるのかもしれない。

上限 `maximum` の倍率3は [ADR-0021](0021-time-management.md) から据え置いた値で、ADR-0253の後の
配分では測っていない。floodgateの棋譜4局の160手を順に読むと（20+1、1スレッド）、15.0%の手がこの上限まで使っていた。

## 選択肢と比較

### 案A: 3倍のまま据え置く

変更はない。上限で止まる手の読みかけは残る。

### 案B: 4倍にする（採用）

上限で止まる手だけが長く読む。予算の係数は変えないので、ほかの手は同じ時刻に止まる。

## Decision

案Bを採る。持ち時間が尽きない範囲で、最善手が揺れた手と評価が下がった手により長く使う。
切れ負けの持ち時間では、従来どおり残り分数で倍率を抑える。

時間管理の中だけの変更なので、固定ノードと固定深さの探索は変わらない。

### 合格の条件

- Eloの判定: 既定条件のSPRT（10+0.1、elo0=0、elo1=5）
- Elo以外の条件: 切れ負けが1%以下
- 採否: 両方を満たしたときだけ入れる

固定深さのノード数は一致する見込みなので、`--no-verify` で起動して別に確かめる。

### 事前登録

- 仮説: 上限で止まっていた手を長く読むと、後の手の時間が減る損を上回って強くなる
- 動かす変数: 倍率だけ。評価関数と開始局面集はSPRTの既定で固定する
- H1なら入れる
- H0なら棄却し、3倍を据え置く。5倍以上や2倍は試さない
- 判定が出ないまま10,000ペアに届いたら、ADR-0217の追記に従い点推定で決める
