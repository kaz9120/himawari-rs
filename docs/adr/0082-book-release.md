# 0082: 定跡をGitHub Releaseで配布し、生成条件を成果物に残す

- Status: proposed
- Date: 2026-07-28
- 関連ADR: [0060](0060-opening-book-policy.md)（配布方針の射程を明確にする）, [0063](0063-book-loader-and-mini-book.md), [0080](0080-net-release.md), [0081](0081-portability.md)

## Context

[ADR-0063](0063-book-loader-and-mini-book.md)で定跡の生成と読み込みを
実装した。現在 `data/book/mini.db`（133局面・15KB）がローカルにあるが、
`data/` はgitignoreのためこのマシンにしか存在しない。開発機を移すと失われる。

管理を決めるにあたり、3つの事情がある。

第1に、生成が非決定的である。[ADR-0063](0063-book-loader-and-mini-book.md)が
「Lazy SMPはスレッド間の探索順序が実行ごとに変わるため、同じコマンドでも
定跡の内容が変わりうる」と記している。実際、深さ24の初期局面で単スレッドは
2g2f（評価18）、8スレッドは6i7h（評価17）を選んだ。教師データのように
「取り直せば同じものが得られる」性質ではない。成果物そのものを保存する
必要がある。

第2に、評価関数に依存する。現在の `mini.db` は `halfkp_370M` で生成した
ものである（`data/book/gen.log` の1行目に記録がある）。現行の最強ネットは
`halfkp_1900M_fact` で、対370Mで+243.8 Elo強い。定跡が2世代前の判断で
作られている。

第3に、[ADR-0060](0060-opening-book-policy.md)の「定跡ファイルは配布物に
含めない」の射程が曖昧である。同ADRを読むと、理由はやねうら王やAperyの
定跡を借用した場合のライセンス懸念であり、自前生成した定跡には当てはまらない。

生成コストも無視できない。133局面で4485秒（75分）を要した。

## 選択肢と比較

### 案A: GitHub Releaseで独立に配布する

[ADR-0080](0080-net-release.md)がネットに対して採った方式を、定跡にも適用する。
タグは `book-v<N>`。

非決定的な成果物を保存する目的に合う。定跡は今後掘り下げて大きくなる前提
（[IDEAS.md](../IDEAS.md)の「定跡の掘り下げ・ランダム化」）なので、
サイズが増えても同じ仕組みで扱える。

### 案B: リポジトリに含める

現在15KBのテキストで、Gitの管理下に置ける大きさである。差分も追える。

ただし掘り下げれば数MB規模になる。バイナリに近い自動生成物を履歴へ
積むことになり、あとから外すのは面倒である。最初から外に置くほうがよい。

### 案C: 生成スクリプトで再現する

教師データ（[ADR-0081](0081-portability.md)）と同じ扱いにする。

生成が非決定的なため成立しない。同じコマンドで違う定跡ができる。
`--threads 1` なら決定的になるが、75分がさらに延びる。

## Decision

案Aを採る。

### タグとアセット

タグは `book-v<N>`。`N` は1から始まる単調増加の整数。ネットの
`net-v<N>` と同じ体系で、エンジン本体の `v0.7.x` とは別系統である。

`scripts/release-book.sh` で、定跡を生成したマシンから直接作る。
`--latest=false` を付ける（[ADR-0080](0080-net-release.md)と同じ理由）。

### 生成条件を成果物に残す

`book gen` のログに生成条件を残すよう改める。現在は `EvalFile` の
学習来歴しか出ておらず、`--ply` `--width` `--depth` `--threads` が
記録されない。これらは定跡の性質を決める値であり、後から追えないと
再生成の判断ができない。

リリースノートには次を載せる。

- 生成に使ったネット（`net-v<N>` との対応を含む）
- `ply` / `width` / `depth` / `threads`
- 局面数と所要時間
- 生成日

定跡はネットに依存するため、`net-v<N>` との対応を明記する。ネットを
更新したら定跡も作り直す判断ができるようにする。

### ADR-0060の射程を明確にする

[ADR-0060](0060-opening-book-policy.md)の「定跡ファイルは配布物に含めない」は、
**借用データについての決定**として読む。他エンジンが配布する定跡を
本体の配布物へ混ぜない、という意味である。

自前生成した定跡はこの制限を受けない。独立したリリースとして配布する。
db形式互換を保つのは他ソフトの定跡を使うためではなく、フォーマットを
自前で決める必要がないためである（2026-07-28オーナー確認）。

### 現行ネットで作り直してから最初のリリースを作る

現在の `mini.db` は `halfkp_370M` 製で、2世代前の判断が入っている。
これをそのまま `book-v1` にする意味は薄い。`halfkp_1900M_fact`
（`net-v1`）で再生成したものを `book-v1` とする。

生成は75分かかる。SPRTと同時に走らせると双方の測定が乱れるため、
単独で回す。

## Consequences

定跡がマシン間で受け渡せるようになる。移行先では
`gh release download book-v<N> -D data/book/` で取得できる。

`book gen` のログが増える。生成条件が残るため、「この定跡はどのネットの
どの設定で作ったか」を後から追える。ネット更新時に作り直すかの判断材料になる。

[ADR-0060](0060-opening-book-policy.md)の解釈が確定する。他ソフトの定跡を
使う予定はないため、ライセンスの検討は不要になった。db形式互換は
フォーマット設計を省くための選択として残る。

定跡のリリースは手動操作になる。ネットと同じく、生成した人が忘れれば
配布されない。CIで強制する手段はない（成果物がローカルにしかない）。

ネットを更新するたびに定跡を作り直すかの判断が生じる。作り直しは75分
かかり、規模を広げればさらに延びる。判断の基準は実戦での効果を見てから
決める。現時点では実戦投入すらしていない（ROADMAP.mdの残作業）。
