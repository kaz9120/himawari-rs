# 0215: 公開dlshogiの探索なし評価値で教師を付け直し、E4の1億で効きを測る

- Status: proposed
- Date: 2026-09-18
- 関連ADR: [0136](0136-quiet-teacher-positions.md), [0185](0185-sibling-ranking-loss.md), [0192](0192-tanuki2024-teacher.md), [0199](0199-roadmap-inventory.md), [0205](0205-relabel-loop.md), [0210](0210-teacher-mix-control.md), [0212](0212-tanuki-bench-mix.md), [0213](0213-freeze-structure-focus.md)

## Context

[ADR-0213](0213-freeze-structure-focus.md)で構造を凍結し、学習側に集中すると
決めた。効いてきたのはラベルの質（教師の置き換え、+43.2）と目的関数で、
次の手は「より真理に近いラベル」である。オーナーの提起（2026-09-18）は、
公開されているDL系のモデルで教師を付け直す蒸留だった。

### 先例: 探索なしのDL評価値で+34、ただしスケールで−41まで振れる

tanukiチーム（nodchip）が2024年末から同じ型の実験を数字つきで公開している。
tanukiの80億局面（自己対局、depth 9・5万ノード）の評価値だけをDL系の
推論1回（探索なし）で付け直し、halfkp_512x2-8-96をゼロから学習する。

| 付け直しの教師 | 結果（対tanuki基準） | 出典 |
|---|---|---|
| DL水匠（dlsuisho-15b-20220426）、λ=1.0 | FV_SCALEで−41.4〜+33.9（16で−41.4、28で+33.9） | [2025-01-31](https://nodchip.hatenablog.com/entry/2025/01/31/000000) |
| AobaZero（resnet30x384） | −48.0〜−100.0 | [2025-03-04](https://nodchip.hatenablog.com/entry/2025/03/04/000000) |
| DL水匠のpolicyで局面を生成し、2モデルで付ける | −191.0 | [2025-09-21](https://nodchip.hatenablog.com/entry/2025/09/21/000000) |

やねうら王の[2025年の振り返り](https://yaneuraou.yaneu.com/2025/12/29/shogi-ai-2025/)も、
水匠10がRyfamateのモデルで「1手も読まずに評価をつけた」教師から学習して
優勝したと書いている。探索は要らない。

読み取れることは3つある。

1. **値のスケールが主変数である**。DLの評価値はNNUEの探索値より膨らみ、
   探索の枝刈りのマージンとの相性が変わる。同じラベルでスケールだけ変えて
   −41から+34まで動いた
2. **教師の強さがそのまま出る**。AobaZeroは完全公開だが、ラベラーとしては
   tanukiのdepth 9に負ける
3. **局面の分布を変えると壊れる**。policyのサンプリングで生成した局面は
   lossが良くなって−191だった。局面の厳選は、ラベルの質を確かめた後に
   統制を置いて測る

### 使えるモデル

| モデル | 入手 | ライセンス |
|---|---|---|
| dlshogi 第2回電竜戦エキシビジョン版（15ブロック、2021-08） | 公開 | 「モデル学習用の棋譜生成」を[明示的に許可](https://tadaoyamaoka.hatenablog.com/entry/2021/08/17/000710)。定跡生成・大会での使用・追加学習・再配布・営利は禁止 |
| ふかうら王モデル2025Q2-20b、Ryfamate TSEC4 | やねうら王の支援者向け頒布 | 本文がログインの先で、蒸留の可否は未確認 |
| AobaZero resnet30x384 | 完全公開 | 自由。ただし上の先例で弱い |

dlshogiの現役世代は非公開で、生態系では支援者向けの頒布に移っている。
**公開の2021版で始める**。ライセンスが明文で安全なことと、nodchipが+34を
出したDL水匠15b（2022-04）と同じ世代・同じ規模なので、参照点があること
が理由である。既存局面へのラベル付けは許可の文言「棋譜生成」そのものでは
ないが、学習用の教師を作る用途として許可の範囲と読む。

### 本エンジンでの参照点

[ADR-0205](0205-relabel-loop.md)のE4が同じ型の実験である。tanuki 2024の
生データ14ファイル（109,976,497局面）のラベルを本エンジンのdepth 9へ
付け替え、ゼロから学習して直接対局した。結果は+12.2 [−9.0, +33.4]で、
「本エンジンのラベルはtanukiと同等」だった。統制のデータ
（`e4_ctrl_train_q1.psv`、静止化済み）と兄弟群とネットが残っている。
**局面と前処理を1ビットも変えず、ラベルだけを差し替えられる**。

## 仮説

**同じ1億局面で、ラベルをtanukiのdepth 9からdlshogi 2021版の推論1回の
評価値へ替えてゼロから学習すると、スケールを合わせれば強くなる**。

## 測定の設計

### 動かす変数

ラベルだけを動かす。スケールは副変数として3水準を振り、いちばん良い
水準で判定する。1水準で測ると効果を見逃す（先例の−41と+34）。

DLのvalueは勝率pで出る。学習器の評価値→勝率の変換は
`sigmoid(cp / 600)` なので、`cp = S × logit(p)` で評価値へ戻す。S=600が
無変換に当たる。Sを小さくすることは、推論側の `FV_SCALE`（16）を大きく
することと、λの評価値部分では等価である。エンジンを作り直さずに
学習3本で振れる。

| 群 | ラベル | S | 相当するFV_SCALE |
|---|---|---|---|
| 統制 `e4_ctrl` | tanuki depth 9（既存） | − | 16 |
| `e4_dl600` | dlshogi、推論1回 | 600 | 16 |
| `e4_dl430` | 同上 | 430 | 22 |
| `e4_dl340` | 同上 | 340 | 28 |

先例の最良（FV_SCALE 28）を上端に置く。

### 固定するもの

- 局面と前処理。`e4_ctrl_train_q1.psv`（静止化済み、シャッフル済み）の
  局面をそのまま使い、scoreだけを書き換える。勝敗・手数・教師手は残す
- **静止化した局面へ付ける**。探索なしのvalueは非静止の局面で当てにならず、
  ネットが見るのも静止化後の局面である。統制のラベルは静止化前の探索値
  なので順番が違うが、探索値は静止化後の葉の値に当たるので土俵は揃う
- 検証集合も同じラベラーで付け直す（`e4_ctrl_valid_q1.psv` → 各群）。
  最良チェックポイントの選択の土俵を学習データに揃える
  （[ADR-0136](0136-quiet-teacher-positions.md)）
- 兄弟群は `e4_ctrl.rankpsv` を4群で共通にする
- 学習はE4と同じ。ゼロから1エポック、batch 16384、peak_lr 1e-3、λ0.7、
  seed 0。λは先例の1.0と違うが、変数を増やさない。効いたら1.0を次に足す
- 対局は[ADR-0212](0212-tanuki-bench-mix.md)と同じ条件。ビルドは両側
  `data/bin/adr0200-himawari`、10+0.1、hash 64、並列8、裁定2000,8、
  最大400手、各1,000ペア。統制との3本

### 読み方の事前登録

各群の対統制のEloを、1,000ペアの幅±20で読む。「効いた」は点推定+15以上で、
95%区間の下端が0を超えることとする。

| 結果 | 読み | 次の一手 |
|---|---|---|
| いずれかの群が効いた | 探索なしのDL評価値は、tanukiのdepth 9より真理に近い | 80億の付け直しを設計する次のADR。費用の見積もり（下）、λ=1.0、20%混合対置き換え（[ADR-0212](0212-tanuki-bench-mix.md)の結果を見て）を変数にする |
| 3群とも±15以内 | 2021版はtanukiのdepth 9と同等。ラベルの質は教師の強さで決まる | 現役世代のモデル（支援者向け頒布）の入手と利用条件の確認へ。オーナー判断 |
| 3群とも負 | スケール以外の原因がある | 静止化前の局面へ付ける順番を1つだけ変えて測り直す。それでも負なら閉じる |

Sの3水準の中で単調でない結果が出ても、水準を足さない。最良の1点で判定する。

## 実行

### 0段目: 推論速度を測る（AWSなし）

dlshogiの入力特徴はcshogiで作れ、モデルはONNXで配布されている。手元の
Mac（MPSまたはCoreML）で1,000局面/秒以上が出れば、1億局面は一晩で
付けられる。足りなければg5（A10G、約$1/時間）を数時間借りる。1万局面/秒
なら1億は3時間で、費用は$10未満である。80億へ外挿すると$150〜250になる
（[ADR-0199](0199-roadmap-inventory.md)は「AWSは一旦見送る」だったが、
オーナーがこの用途では許可した。2026-09-18）。

### 道具

`hmwr data relabel <出力名> --in <入力名> --labeler dlshogi --model <path>
--scale S` を足す。[ADR-0205](0205-relabel-loop.md)の `psv relabel`（本エンジンの
探索で付け直す）と同じ動詞で、裏側だけ違う。psvをcshogiで復元し、
バッチ推論で勝率を取り、`S × logit(p)` をscoreへ書く。mateの扱いは
±30000の飽和で揃える。

スケールの3水準は推論を1回で済ませる。S=600で付けた出力を
`--labeler rescale` で `S / 600` 倍に縮めれば、`S × logit(p)` と同じ値になる
（飽和の±8289も比率で縮む）。specは `experiments/adr0215-dl-relabel-pilot.toml`
で、推論1回（約11時間）、縮め2本、学習3本（約3時間）、対局3本（約6時間）の順に
走る。

## 測定

### 0段目: 推論速度と符号の確認（2026-09-18）

手元のMacで測った。cshogiは最新版が新しいclangで通らず、`square.hpp` の
列挙子の初期化を整数へキャストして入れた（Issue #556）。

| 経路 | 速度 | 値 |
|---|---|---|
| CPU（onnxruntime） | 174局面/秒 | 基準 |
| CoreML、既定のNeuralNetwork形式 | 3,047局面/秒 | fp16。勝率が0.005ずれる |
| **CoreML、MLProgram形式** | **2,590局面/秒** | fp32。CPUと1e-6で一致 |

MLProgram形式を使う。1億局面は約11時間で、一晩に収まる。AWSは要らない。

E4の検証集合2万局面で、tanukiのdepth 9のscoreと比べた。

| 指標 | 値 |
|---|---|
| 符号の一致率（\|tanuki\| > 300の11,421局面） | 97.7% |
| 相関（mateを除く） | 0.724 |
| 勝敗との符号の一致率 | tanuki 0.757、dlshogi 0.747 |
| scoreの平均 | tanuki +235、dlshogi −131 |
| 平均\|score\|（mate込み） | 3,270 → 2,044 |

符号の向きは合っている。勝敗との一致はtanukiがわずかに上で、2021版の
推論1回がtanukiのdepth 9を大きく上回る材料はここにはない。平均が+235から
−131へ動くのは、静止化後の局面（取り合いの直後で、手番側が待つ側）の
評価の癖が2つのラベラーで違うためと見ている。対局で判定する。

## Consequences

- 効いた場合、80億の付け直しが次の投資になる。推論は$250以内、学習は
  現行と同じ50時間で、費用の主因は学習側のままである
- 支援者向けの現役モデルは、2021版の結果を見てから検討する。頒布の利用
  条件に蒸留が含まれるかの確認と、支援の可否はオーナーの判断になる
- 局面の厳選（自分の探索が訪れる局面、不一致で選ぶ、盲点の型）は、
  ラベルの質が確かめられた後に、同数のランダム抽出を統制に置いて測る。
  先例の−191が、統制なしで分布を動かす危険を示している
- `hmwr data relabel` が増え、ラベラーを差し替えられる形になる。AobaZeroや
  別のNNUE（AobaNNUE）を「別系列の教師」として混ぜる実験にも使える
