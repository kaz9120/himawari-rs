# 0198: 将棋の進行度の指標を、評価の系統誤差で選ぶ

- Status: accepted（測定で出力バケットを閉じた。下の「Decision」）
- Date: 2026-09-03
- 関連ADR: [0067](0067-ft-dimension-512.md), [0116](0116-g7-timeman.md), [0137](0137-output-buckets.md), [0158](0158-mirror-factorizer.md), [0194](0194-dead-dim-measurement.md)

## Context

[ADR-0137](0137-output-buckets.md)は出力層を局面のフェーズで分岐する機構を
残しつつ、分岐の指標を決め直すと判断した。盤上の駒数（案A）は範囲が実質
20〜40枚で、均等に割れても意味のある境界にならない。手数（案B）は同一局面が
到達経路で違うクラスへ落ちるので、置換表と相性が悪い。

指標が要るのは出力バケットだけではない。時間管理の配分
（[ADR-0116](0116-g7-timeman.md)）やcontemptの条件づけも、序盤・中盤・終盤を
機械で測れないと始まらない。ROADMAPはこれを「次に着手する」に据えた。

チェスの先行研究（[Checkmating One, by Using Many](https://arxiv.org/abs/2401.16852)）は
Lichessの分割で+122 Eloを得ている。分割は駒数だけでなく、backrankのスパース性と
駒の交錯度を組み合わせる。将棋へ写す論点はADR-0137の「指標を決め直す」に
ある。混合度はそのまま使え、backrankは自陣の密度へ写せ、駒数は成駒の枚数や
大駒の位置へ置き換える余地がある。

**指標の候補を頭で選ばず、測って選ぶ**。同じ局面集合を候補ごとに分類し、
クラス間で評価の系統誤差が違うかを見る。違いが出ない指標でネットを分けても、
パラメータが薄まるだけになる（[ADR-0134](0134-head-capacity.md)の一様な拡大が
効かなかった理由と同じ）。

## 仮説

**良い進行度の指標ほど、クラスごとに現行ネットの評価の偏りと尺度が違う**。
差の大きい指標ほど、出力の分岐で回収できる誤差を多く持つ。

## 測定の設計

起動前に固定する4点（CLAUDE.md「実験の規律」）。

### 動かす変数

指標（局面を数値へ写す関数）だけを動かす。10本の候補を同じ手順で測る。

| 指標 | 定義 | 由来 |
|---|---|---|
| `board` | 盤上の駒数（玉を含む） | ADR-0137の案A |
| `ply` | 手数 | ADR-0137の案B。チェスでは効かないと報告されている |
| `mixed` | 2×2の窓64個のうち、先手と後手の駒が両方ある窓の数 | Lichessの混合度 |
| `contact` | 相手の駒に利かれている駒の数（両者合計、玉を含む） | 開戦の度合い |
| `advanced` | 敵陣（相手側の3段）にいる駒の数（両者合計、玉を除く） | 進出の度合い |
| `promoted` | 盤上の成駒の数（両者合計） | 駒数を成駒へ置き換える案 |
| `majors` | 飛角4枚のうち、成っているか敵陣にいる数 | 大駒の位置 |
| `camp` | 自陣（自分側の3段）にいる自分の駒の数の、両者の小さいほう | backrankのスパース性 |
| `king_adv` | 玉の段（自陣の1段目を0）の、両者の大きいほう | 入玉度 |
| `king_zone` | 玉の周囲8マスへの相手の利きの数の合計の、両者の大きいほう | 詰むや詰まざるや |

どれも局面から直接計算でき、探索木の中の任意の局面で定義できる。`ply` は
その条件を満たさないが、チェスの報告を本エンジンで確かめる対照として置く。

### 固定するもの

- 局面集合。`valid_tanuki_q1.psv` の20万局面を主台にする。現行ネットの教師
  （tanuki- 2024、[ADR-0192](0192-tanuki2024-teacher.md)）と同じ系列で、
  学習には使っていない。副台に `valid_385M_q1.psv`（hao系列）を置き、
  順位が台で変わらないかを見る
- ネット。現行の評価関数（`hmwr/config.py` の `EVAL_FILE`）の静的評価を使う。
  教師局面は静止化済み（[ADR-0136](0136-quiet-teacher-positions.md)）なので、
  qsearchを挟まなくても釣り合う
- 目標値。学習と同じ勝率空間で、`sigmoid(score/600)` と勝敗を0.7:0.3で
  混ぜた値にする（`training/train.py` の `--lambda` の既定）。バケットの
  ヘッドが学習で合わせに行くのはこの目標なので、系統誤差もこれに対して測る
- クラス数。指標ごとに四分位で4クラスへ切る。値が離散で四分位に乗らない
  指標は、四分位にいちばん近い値の境界で切り、クラスの大きさを併記する
- 補正の形。クラスごとにロジットのアフィン変換 `a·eval/600 + b` を
  当てはめる。2パラメータ×4クラスで、出力段の分岐が最低限できる補正になる

### 読み方の事前登録

指標の点数は次の差で決める。

```
ΔL(指標) = L(クラス別アフィン) − L(全体アフィン)
```

`L` は勝率空間のBCE損失（学習と同じ）で、全体アフィンは1クラスで同じ補正を
当てたものである。ΔLが負に大きいほど、その指標の分類が評価の系統誤差を
説明している。ノイズの床は、乱数で4クラスへ分けた分割を20回当てて
その最良値とする。

1. ΔLが乱数分割の最良値の10倍を超えて負なら、その指標は進行度に依存する
   系統誤差を持つと読む。超える指標が2本以上あれば、それらを組み合わせた
   3クラスの規則を次のADRで設計し、出力バケット（ADR-0137）を再開する
2. 超えるのが `board` だけなら、案Aを退けた判断を撤回してADR-0137へ戻る。
   オーナーの指摘と測定が食い違うことになるので、その旨を記録する
3. どの指標も床を超えなければ、出力段のアフィン分岐では進行度の誤差を
   回収できないと読む。L2からの分岐が要るかは別の測定（隠れ活性ごとの
   線形補正）が要るので、本ADRの範囲では線を閉じる
4. `ply` が床を超えても採らない。到達経路で値が変わり探索で使えないため
   である。他の指標が `ply` と同程度に効くかを見る対照に使う

ΔLの絶対値は学習の検証損失と比べない。固定したネットに対する決定的な量で、
初期値の系列で0.00136動く学習損失（[ADR-0158](0158-mirror-factorizer.md)）
とは別物である。

副次的に、クラスごとの平均残差（ネット−目標、勝率と評価値の両方）と
RMSEを出す。偏りの向きが解釈の材料になる。詰みスコア（±30000近傍）は
勝率空間では端に張り付くので除外せず、評価値の残差だけ|score|3000以下に
絞る。

## 道具

`psv phase` が局面ごとの指標と静的評価をTSVへ書き、`hmwr net phase` が
クラス別の集計を出す。指標の計算はRust側（`crates/tools/src/bin/psv.rs`）、
アフィンの当てはめと表はPython側（`hmwr/tools/phase.py`）が持つ。

```
hmwr net phase data/train/valid_tanuki_q1.psv
```

### 追加測定の事前登録（出力段の線形ヘッド、第1測定の後に書いた）

第1測定（アフィン2パラメータ）は、主台で `camp` だけが床の10倍を超えた。
事前登録は「2本以上」と「0本」しか読み方を決めておらず、**1本だけ超える
場合を書いていなかった**。しかも副台では `camp` が7.3倍へ落ち、順位が
入れ替わる。この結果だけで閉じるか進めるかを決めるのは、登録の穴を
後付けで埋めることになる。

代わりに、ADR-0137が提案した機構そのものの容量で測り直す。提案は
「最終段だけを分岐する」で、L2（32次元）から出力への線形ヘッド33個を
バケットごとに持つ形である。アフィン2パラメータはその部分集合にすぎない。
**この容量で床を超えなければ、提案の機構は現行ネットの誤差を回収できない**。

- 学習器のモデル（`training/model.py`）で同じ局面のL2活性 `h`（32次元）を
  取り、クラスごとに33パラメータの線形ヘッドをBCEに当てはめる。基準は
  全体で1本のヘッドを当て直した損失で、差をΔL2とする
- 床は第1測定と同じ乱数分割20回の最良値。ただし当てはめのパラメータが
  2から33へ増えるので、床の値も変わる。比較は床比で行う
- 読み方は第1測定と同じ10倍の基準を使う。2本以上なら3クラスの規則へ進み、
  1本ならその指標を主台と副台の両方に通してから採否を決める。0本なら
  出力バケットの線を閉じる。「1本だけ」の扱いをここで決めておく
- 主台と副台の両方で測る。順位の安定も見る

## 測定

### 第1測定: アフィン2パラメータ（2026-09-03）

主台 `valid_tanuki_q1.psv`、20万局面、λ=0.7。補正なしのBCEは0.49520で、
全体アフィン（a=1.007、b=−0.041）で0.49505になる。現行ネットは全体では
よく較正されている。乱数分割20回の最良値は−0.069（×1e-4）だった。

| 指標 | ΔL（×1e-4） | 床比 | 副台のΔL | 副台の床比 |
|---|---|---|---|---|
| `camp` | −0.793 | 11.6 | −0.767 | 7.3 |
| `advanced` | −0.653 | 9.5 | −0.692 | 6.6 |
| `contact` | −0.584 | 8.5 | −0.959 | 9.2 |
| `majors` | −0.581 | 8.5 | −0.353 | 3.4 |
| `mixed` | −0.546 | 8.0 | −1.016 | 9.7 |
| `promoted` | −0.472 | 6.9 | −0.227 | 2.2 |
| `king_zone` | −0.414 | 6.0 | −1.556 | 14.9 |
| `king_adv` | −0.288 | 4.2 | −0.805 | 7.7 |
| `ply` | −0.276 | 4.0 | −0.774 | 7.4 |
| `board` | −0.212 | 3.1 | −0.327 | 3.1 |

副台 `valid_385M_q1.psv`（hao系列）は床が−0.104で、全体アフィンの
a=1.190と尺度のずれが大きい。教師が違うので当然で、副台は順位の
確認にだけ使う。

読めることは3つある。

1. **どの指標も、出力のアフィン補正で回収できる系統誤差は1e-4規模しか
   ない**。学習損失の乱数ぶれ（0.00136、[ADR-0158](0158-mirror-factorizer.md)）
   より1桁小さい
2. **`board` は両台で最下位（床比3.1）である**。駒数が弱いというオーナー
   指摘は測定と一致する。`ply` も主台で下から2番目で、チェスの報告と
   一致する
3. 上位は盤面の形の指標で占められるが、順位は台で入れ替わる。両台で
   上位5本に入るのは `contact` と `mixed` だけである

評価値の偏り（ネット−教師、手番視点）はどの指標でも終盤側で大きい
（`camp` の薄い側で+93cp、厚い側で+14cp）。勝率の偏りは+0.6〜0.9%で
ほぼ平らなので、これは終盤で評価値の絶対値が大きいことの反映で、
較正のずれではない。

### 第2測定: L2活性の線形ヘッド（2026-09-03）

同じ局面・同じネットで、学習器のモデルからL2活性（32次元）を取り、
クラスごとに33パラメータの線形ヘッドを当てた。モデルの出力とTSVの
静的評価の相関は1.0000で、並びは揃っている。全体で1本を当て直した
損失は主台0.49474、副台0.48619になる。

乱数分割20回の最良値は主台−0.751、副台−1.113（×1e-4）だった。第1測定の
床（−0.069）の10倍以上で、**132パラメータを20万局面に当てる当てはめ
ノイズだけでこの量が出る**。

| 指標 | 主台ΔL2（×1e-4） | 床比 | 副台ΔL2 | 床比 |
|---|---|---|---|---|
| `promoted` | −2.021 | 2.7 | −2.417 | 2.2 |
| `king_adv` | −1.844 | 2.5 | −2.449 | 2.2 |
| `board` | −1.809 | 2.4 | −2.263 | 2.0 |
| `ply` | −1.761 | 2.3 | −2.327 | 2.1 |
| `advanced` | −1.651 | 2.2 | −2.039 | 1.8 |
| `camp` | −1.531 | 2.0 | −1.940 | 1.7 |
| `majors` | −1.441 | 1.9 | −2.013 | 1.8 |
| `mixed` | −1.323 | 1.8 | −2.064 | 1.9 |
| `contact` | −1.157 | 1.5 | −2.072 | 1.9 |
| `king_zone` | −1.111 | 1.5 | −2.045 | 1.8 |

**どの指標も床比3倍に届かず、10倍の基準には遠い**。指標間の差も、
第1測定で最下位だった `board` が主台の3位に上がるほど不安定であり、
当てはめノイズの中で順位が入れ替わっている。床の平均（−0.609）を
引いた実質の利得は−1e-4規模で、第1測定のΔLと同じ量になる。

## Decision

**出力段を進行度で分岐する線（[ADR-0137](0137-output-buckets.md)）を
閉じる**。同ADRはrejectedにする。

理由は測定にある。ADR-0137の提案は最終段だけの分岐で、その容量
（L2からの線形ヘッド33パラメータ×バケット数）でクラスごとに当て直しても、
現行ネットの誤差は当てはめノイズの3倍以下しか減らない。10本の候補の
どれで分けても同じで、指標の選び方の問題ではない。**現行ネットの後段は、
どの進行度でも同じ写像で足りる程度に較正されている**。

事前登録の読み方3（0本なら閉じる）に従う。第1測定で `camp` だけが
床を超えた点は、登録に「1本だけ」の扱いがなく、機構そのものの容量で
測り直す追加測定を事前登録して解いた。追加測定は0本で、第1測定の
1本は当てはめの偶然と読む。

進行度の指標そのものは、消費者を失ったので選定を保留する。この測定が
言えるのは「評価の系統誤差では指標を選べない」ことまでで、時間管理や
contemptの条件づけに使えるかは別の物差し（配分の利得）で測るしかない。
時間管理側で必要になったとき、その用途の測定を設計する。

言えないこともある。この測定は学習済みのネットを固定して後段だけを
当て直した。チェスの+122 Eloはフェーズごとに別のネットを丸ごと学習して
いる。FTから分ける案は本ADRの範囲外で、着手するなら速度の代償
（換算率3.12 Elo/1%）と学習資源の見積もりから別のADRで始める。

## Consequences

- ADR-0137はrejectedになり、学習器・推論・ファイル形式の3か所の改造を
  避けられる。ROADMAPの「次に着手する」は次の案へ移す
- 進行度の指標10本の計算は `psv phase` に残る。時間管理や盲点ベンチの
  分類で局面の属性が要るとき、そのまま使える
- 「固定したネットの後段を当て直して機構の容量を測る」型は、ヘッドの
  構造を変える案の足切りに使い回せる。学習を回す前に、現行ネットの
  L2活性でその容量が誤差を減らすかを見る。`hmwr net phase` の
  `--weights` がその測定を持つ
