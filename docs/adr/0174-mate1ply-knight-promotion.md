# 0174: mate_1plyへ桂の成り王手を列挙する

- Status: rejected
- Date: 2026-08-17
- 関連ADR: [0029](0029-mate-search.md), [0074](0074-feature-verification.md), [0093](0093-mate1ply-in-search.md), [0109](0109-reference-parity.md), [0115](0115-g6-qsearch.md), [0139](0139-mate1ply-in-search-retry.md), [0163](0163-sprt-hypothesis-choice.md), [0173](0173-knight-non-promotion-movegen.md)

## Context

[ADR-0173](0173-knight-non-promotion-movegen.md)の調査で `mate_1ply` の見逃しを
駒種別に測ったところ、**桂の成り王手を100%見逃していた**ことが分かった。

`crates/engine/src/mate.rs` は桂だけ移動先を `knight_to`（桂で王手になるマス）に
固定している。`move_mates` の移動先（298行）と `check_cand` の的（70-74行）の
両方で同じ限定がかかる。

```rust
let targets = attacks::attacks(pc, from, occ)
    & if pt == PieceType::KNIGHT { knight_to } else { near };
```

**桂の王手マスは玉に隣接しない**。筋±1・段2の位置だからである。一方、成桂は
金の動きなので隣接からしか王手にならない。したがって桂の成り王手は、候補の
列挙に一度も現れない。他の駒は移動先が `near`（玉の隣接8マス）なので、
成りの王手も同じループで拾える。**桂だけが例外になっていた**。

実戦局面を全合法手で1手展開した6,211,930局面での実測である。

| 桂の王手の種類 | 詰め手の数 | 認識率 |
|---|---|---|
| 桂打ち | 6,490 | 100% |
| 桂の跳ね（不成の王手） | 447 | 100% |
| 成桂（すでに成っている駒）の移動 | 3,808 | 100% |
| **桂を動かして成る王手** | **5,266** | **0%** |

局面単位では、詰め手が桂だけの局面4,423件のうち697件を見逃していた
（15.76%）。桂を含まない局面の見逃しは1.43%で、**11倍の開きがある**。

## 参照実装の扱い

やねうら王は明示的に扱っている。`mate1ply_without_effect.cpp:1547` は桂の
移動先を限定せずに取り、王手にならなければ `goto PRO_KNIGHT` で成りの判定へ
落とす。`CHECK_CAND_BB` の構築側（145-153行）にも `// 成って王手(金)になる移動元`
として桂の移動元を足すコードがある。

```cpp
case PIECE_TYPE_CHECK_KNIGHT:
    tmp = knightEffect(~c, sq);
    while (tmp) { to = tmp.pop(); bb |= knightEffect(~c, to); }
    // 成って王手(金)になる移動元
    tmp = goldEffect(~c, sq) & enemyBB;
    while (tmp) { to = tmp.pop(); bb |= knightEffect(~c, to); }
```

**`mate_1ply` に関する参照実装との乖離は、この1点だけである**。遠隔からの移動王手と遠打ちも見逃している。そちらは原典も同じ範囲しか
列挙していない（該当コードは `#if 0` で切られ、「離し角・飛車での詰み、
そんなに出てこないので調べるコストに見合っていない」と理由が残っている）。

## 選択肢と比較

### 案A: 桂の的を `knight_to | near` へ広げる

`move_mates` と `check_cand` の2か所で桂の的を広げる。数行で済み、参照実装と
一致する。玉の近傍への不成は王手にならないが、除くのは `is_mate_move` に
任せる（判定は既にある）。

### 案B: 成りだけを別ループで扱う

原典の `goto PRO_KNIGHT` に構造を寄せる。無駄な検証を減らせるが、コードが
分岐で膨らむ。本実装は「王手になるかの事前判定をせず検証側に任せる」設計
（`move_mates` のコメント）なので、案Aのほうが揃う。

## Decision

**案Aを採る**。参照実装との唯一の乖離であり、変更が小さいためである。

### 測定（2026-08-17）

実戦局面を1手展開した6,211,930局面での前後比較である。偽陽性は前後とも0件。

| 指標 | 修正前 | 修正後 |
|---|---|---|
| 見逃し | 2,897（1.76%） | **2,200（1.34%）** |
| 桂の詰め手を含む局面の見逃し | 15.76% | **0.00%** |
| 詰め手が桂だけの局面の見逃し | 15.76% | **0.00%** |
| 桂を含まない局面の見逃し | 1.43% | 1.43% |

**見逃しの24.1%が消えた**。削減件数697は、事前に見積もった「桂の成りを列挙
すれば救える件数」と1件の狂いもなく一致する。

実戦局面そのもの（展開なし、67,468局面）では1.05%→0.84%で、詰みあり475件の
うち見逃しが5件から4件へ減るにとどまる。**効果が大きいのは探索木に近い分布のほうで
ある**。

コストは候補手の増加である。1局面あたりの `is_mate_move` の呼び出しが
1.115から1.157へ増える（**+3.8%**）。[ADR-0115](0115-g6-qsearch.md)の内訳
（1回27.2ns＝列挙8.4＋検証11.5＋駒打ち4.2）から、qsearch経由のNPS影響は
0.84%×0.038で測定限界以下と見込む。実測は機能検証で行う。

### 機能検証（2026-08-17。[ADR-0074](0074-feature-verification.md)）

**`verify` の既定4局面では、全局面でノード数が一致した**。基準どおりに読めば
「探索に影響していない、SPRTにかけても中立」になる。

| 局面 | 変更前 | 変更後 | 変化 |
|---|---|---|---|
| 1 | 22,759 | 22,759 | +0% |
| 2 | 84,567 | 84,567 | +0% |
| 3 | 63,856 | 63,856 | +0% |
| 4 | 37,349 | 37,349 | +0% |

**しかしこれは局面の選び方の問題である**。`verify` の局面は初期局面と
`openings/start_sfens_ply24.txt` の先頭3行で、**4つとも序盤**である。桂の成りで
詰む形は終盤にしか現れない。**この機能をこの局面集では検証できない**。

floodgateの長手数の棋譜24局から終盤48局面（終局の40手前と20手前）を取り、
深さ15で測り直した。

| 指標 | 値 |
|---|---|
| 局面数 | 48 |
| ノード数が変わった局面 | **26（54%）** |
| 変化の幅 | −48.5% 〜 +78.0% |

探索に影響していることを確認した。変化は両方向に出る。詰みを早く確定して
部分木を刈る局面（−48.5%）と、候補が増えて検証が走る局面（+78.0%）がある。

**`verify` の局面集が序盤に偏っている点は、本ADRの範囲を超える運用の問題
である**。終盤に効く機能を測るたびに専用の局面集を作るのは手戻りが大きい。
ROADMAPの候補へ「verifyへ終盤局面を足す」を残す。

### SPRTの条件（着手時に確定。[ADR-0163](0163-sprt-hypothesis-choice.md)）

**非劣性（elo0=−5、elo1=0）で測る**。根拠は3つある。

1. 参照実装との乖離を埋める変更であり、[ADR-0163](0163-sprt-hypothesis-choice.md)の
   分類では「参照追従で害がなければ入れたい」に当たる
2. `mate_1ply` の呼び出し元はqsearchのstand-pat判定1か所だけである
   （`search.rs:2894`）。通常探索への組み込みは[ADR-0093](0093-mate1ply-in-search.md)と
   [ADR-0139](0139-mate1ply-in-search-retry.md)で2度棄却している
3. [ADR-0139](0139-mate1ply-in-search-retry.md)の実測が「詰みがあるノードの86%が
   詰みでない値を返すが、そのほぼ全部がfail-highで親は正しく捨てている」と
   記録している。**見逃しを減らしても棋力へ届く経路は細い**

[ADR-0173](0173-knight-non-promotion-movegen.md)を既定条件で測ったのとは扱いを
変える。あちらは探索が手を生成しないバグで、実戦の敗着11局という直接の証拠が
あった。本ADRにはそれがない。

## SPRT結果（2026-08-18）

**取り込まない。24,546局（12,273ペア）で −1.7 [−6.0, +2.5]、LLR +0.81**。
W-D-Lは +11692 =1039 -11815 である。判定へ達する前に、マシンリソースを
これ以上使う価値がないというオーナーの判断で打ち切った。

条件は着手時に決めた非劣性（elo0=−5、elo1=0）のまま変えていない。

**局数を積むほど点推定が下がった**。

| 時点 | 局数 | Elo [95%CI] | LLR |
|---|---|---|---|
| 途中 | 12,534 | +1.5 [−4.5, +7.4] | +1.75 |
| 最終 | 24,546 | **−1.7** [−6.0, +2.5] | +0.81 |

標本が増えるほど真値へ寄るので、+1.5 は上振れだったと読む。CIの下限 −6.0 は
非劣性の閾値 elo0=−5 を割っており、**「害がない」と言い切れる状態ではない**。

[ADR-0153](0153-superior-repetition-root-gate.md)は判定に至らないまま採択した
先例だが、状況が違う。あちらは4,134局で **+4.0** [−5.7, +13.8] と走行を通じて
正側で推移し、実対局での害が6局分実証されていた。本ADRはその6倍の局数を積んで
負側に落ち、実戦の敗着との紐付けもない。

## 棄却の判断

**見逃しが24.1%減ること自体は621万局面で実測済みであり、偽陽性もゼロである**。
関数としては正しくなっている。それでも取り込まない理由は3つある。

1. 24,546局は十分な標本で、点推定が負側である
2. [ADR-0139](0139-mate1ply-in-search-retry.md)の実測と整合する。「詰みがある
   ノードの86%が詰みでない値を返すが、そのほぼ全部がfail-highで親は正しく
   捨てている」——見逃しを減らしても棋力へ届く経路は細い、という予想どおりだった
3. 候補手が+3.8%増えるコストは実在し、それに見合う得が出ていない

**「正しくなること」と「強くなること」は別だった**。
[ADR-0173](0173-knight-non-promotion-movegen.md)が実戦の敗着11局に直結して
いたのとは決定的に違う。同じ「桂の不成・成りの取りこぼし」でも、探索が手を
生成しない欠陥（ADR-0173）と、1手詰め判定の見逃し（本ADR）では重みが違う。

### 再訪の条件

1. **df-pn（[ADR-0142](0142-dfpn-mate-search.md)）を作るとき**。`mate_1ply` は
   葉の判定に使われるので、質の差が効く可能性をもつ
2. **USIの `go mate` を実装するとき**。詰将棋として解かせるなら見逃しは直接の
   欠陥になる

どちらも「探索の枝を刈る道具」ではなく「詰みを読み切る道具」として使う場面で
ある。qsearchのstand-pat判定に使うかぎり、本ADRの結論は変わらない。

## Consequences

- **コードはmainへ入れない**。`mate_1ply` は桂の成り王手を見逃したままになる。
  参照実装との乖離もこの1点だけ残る
- **棄却の記録が次の判断材料になる**。「見逃し率の改善」を根拠に棋力向上を
  期待する提案は、今後この結果を引いて見積もりを下げる
- 測定に使った一時ツール（`mateaudit`）は残さない。手順はこのADRの数字と
  [ADR-0173](0173-knight-non-promotion-movegen.md)の記述で再現できる
- [ADR-0139](0139-mate1ply-in-search-retry.md)が挙げた再挑戦の条件の1つ
  「mate_1ply自体の見逃し率が下がったとき」に一部該当する。ただし下がった幅は
  1.76%→1.34%で、通常探索への組み込みを再訪する根拠には足りない
