# 0134: 後段の容量が壁かを、上向きに振って確かめる

- Status: proposed
- Date: 2026-08-04
- 関連ADR: [0034](0034-nnue-architecture.md), [0127](0127-net-shape-bench.md), [0130](0130-freeze-ft.md), [0131](0131-frozen-ft-light-head.md), [0132](0132-ft-distillation.md), [0133](0133-effect-pretraining.md)

## Context

[ADR-0133](0133-effect-pretraining.md)で、評価値ラベルを使わない事前学習が第2段階で−0.001の
改善を出した。ただし**表現学習としては成立していない**。表現学習の価値は表現が再利用される
ことにあり、FTごと学習し直して−0.001なら、それは初期化の工夫である（2026-08-03オーナー指摘）。

そして同じ指摘が、測定の解釈そのものを崩す。

### probingの数字が読めない

[ADR-0133](0133-effect-pretraining.md)のprobingは、FTを凍結して後段だけ学習し、
事前学習FT（0.59974）と現行FT（0.49549）を比べた。**表現の質の差だと解釈した。**

**しかし後段が小さすぎて特徴から評価値を引ききれていないなら、この差は表現の差ではない。**
両方が同じ天井に頭を打っている可能性がある。後段の容量が分からないと、probingを解釈できない。

同じ疑いが別の観測にもかかる。[ADR-0133](0133-effect-pretraining.md)では、利きの当てやすさが
3倍違う2つのFT（linearとmlp）が、probingでも第2段階でもほぼ同じ値になった。**両方が後段の
天井に当たっているなら、当然そうなる。**

### 上向きに測ったことが一度もなかった

手元の証拠はすべて下向きだった。

| 出典 | 測ったこと | 結果 |
|---|---|---|
| [ADR-0127](0127-net-shape-bench.md) | FT固定で後段12通り（L1=32/16/8、L2=32/16/8/なし） | **すべて現行より小さい** |
| [ADR-0131](0131-frozen-ft-light-head.md) | 32x32 → 16（2層） | loss +0.0006 |
| [ADR-0127](0127-net-shape-bench.md) | 256x64x32・256x32x64 | −0.0002。**同時学習・3億で、幅も2倍まで** |

「後段の容量は効いていない」という主張は、**下向きの測定からの外挿だった。**
下向きが平らなことは上向きも平らである弱い証拠にはなるが、論理的には別の話である。

## 選択肢と比較

### 案A: FTを固定して後段だけ上へ振る

現行FTを凍結し、後段を大きくする。[ADR-0130](0130-freeze-ft.md)のFT固定学習が使えるので
1条件8〜10分で済む。

**しかし答えが違う。** 分かるのは「いまのFT出力から、大きい後段がどれだけ引き出せるか」で、
**大きい後段がFTを育てる余地を測れない。** 固定した時点でFTは変わらない。

### 案B: FTと後段を一緒に学習し、後段を上へ振る

同時学習で幅を振る。1条件20〜25分と案Aより高い。

**大きい後段がFTを別の形に育てる余地まで含めて測れる。** 求めているのはこちらである
（2026-08-04オーナー指摘）。

## Decision

案Bを採る。**同時学習で後段の幅を上へ振り、lossの天井を測る。**

**決め手は、案Aでは目的の出口へつながらないことである。** 期待している流れは
「大きい後段で良いFTを作る → FTを固定して32x32を載せる → 推論の速度を払わずに載せ替える」で、
1段目でFTが育たなければ成立しない。

3億局面、seed 0、条件は[ADR-0127](0127-net-shape-bench.md)と揃える。基準は同条件の
`256x32x32`（`a0`、valid loss 0.49874）。

| 構成 | 隠れ層の積和 | 基準比 |
|---|---|---|
| 256x32x32（基準） | 17,440 | 1.0 |
| 256x64x64 | 36,928 | 2.1 |
| 256x128x128 | 82,048 | 4.7 |
| 256x256x256 | 197,376 | 11.3 |
| 256x512x512 | 525,824 | 30.1 |

### 大きく下がったときの出口

後段が大きいままでは実戦に出せない。L1を厚くする費用は高く、256x64x32 で 0.909倍、
512x64x32 で 0.645倍になる（[ADR-0127](0127-net-shape-bench.md)）。

そこで**FTだけを取り出す。** 大きい後段で学習したネットからFTを取り、固定して32x32を
載せ直し、現行FTを固定して32x32を載せたもの（`train-256x32x32-s0`、0.49549）と比べる。
**同じ後段で比べるので、差はFTの質の差になる。**

[ADR-0131](0131-frozen-ft-light-head.md)で**FTを差し替えて後段を学習し直す操作は棋力中立**
（−0.7 Elo）だと測ってある。良いFTができれば、推論のコストを1ミリも払わずに載せ替えられる。

### 下がらなかったときに言えること

**壁は容量ではない**と確定する。FTを太らせる道は速度で潰れ（[ADR-0127](0127-net-shape-bench.md)）、
後段を太らせる道は精度で返らない、ということになる。残るのは特徴設計と教師信号の側で、
[ADR-0129](0129-auxiliary-heads.md)・[ADR-0133](0133-effect-pretraining.md)の系列に戻る。

**あわせて[ADR-0133](0133-effect-pretraining.md)のprobingが解釈できるようになる。**
後段が天井でないなら、事前学習FTの0.59974は表現の質そのものを表しており、現行FTとの差は
本物である。

## 結果（2026-08-04）

**後段の容量は壁ではなかった。積和を30倍にすると、むしろ基準より悪くなる。**

| 構成 | 積和（基準比） | valid loss | 基準との差 |
|---|---|---|---|
| 256x32x32（基準 `a0`） | 1.0 | 0.49874 | — |
| 256x64x64 | 2.1 | 0.49826 | −0.00048 |
| **256x128x128** | 4.7 | **0.49806** | **−0.00068** |
| 256x256x256 | 11.3 | 0.49828 | −0.00046 |
| 256x512x512 | 30.1 | 0.49916 | **+0.00042** |

きれいな逆U字で、頂点は `128x128` の付近にある。**最良でも−0.00068で、
[ADR-0127](0127-net-shape-bench.md)が定めた判別限界0.001に届かない。** 厳密には、
どの構成も基準と差があると言えない。

`512x512` が基準を下回るのは、量子化の制約（`clip_weights` が隠れ層の重みを±127/64へ丸める）が
広い層ほど強く効くこと、3億局面に対して過剰な容量であることのどちらかと見られる。追っていない。
**採る構成ではないので、棄却の記録として残す。**

### FTを凍結しても同じ。ただし事前学習FTだけ違った

同時学習はFTが後段に合わせて育つ条件なので、「凍結したFTから小さい後段が引ききれていない」
可能性が残る。[ADR-0133](0133-effect-pretraining.md)のprobingを解釈するにはここを塞ぐ必要が
あった。FTを凍結したまま後段を `128x128` へ広げて測り直した。

| FT（凍結） | 32x32 | 128x128 | 差 |
|---|---|---|---|
| 現行FT | 0.49549 | 0.49530 | −0.00019 |
| **事前学習FT**（[ADR-0133](0133-effect-pretraining.md)） | 0.59974 | **0.59482** | **−0.00492** |

**現行FTでは凍結しても後段は壁でない**（−0.00019）。同時学習の結論がそのまま成り立つ。

**事前学習FTだけは違った。** 効き目が26倍ある。**利きで作った表現は、小さい後段では
引き出しにくい形をしている。** 評価値で学習した表現が後段に読みやすく整っているのに対し、
利きで学習した表現はそうなっていない、と読める。

ただし縮まるのは現行FTとの差0.104のうち5%（0.005）で、残り0.099は表現そのものの差である。
[ADR-0133](0133-effect-pretraining.md)の結論は変わらない。

### 出口は開かなかった

[Decision](#大きく下がったときの出口)に置いた「大きい後段で良いFTを作り、FTを固定して32x32を
載せ替える」という筋は、**1段目が成立しないので進まない。** lossが下がっていない以上、
取り出す価値のあるFTができていない。

## Consequences

- 量子化の制約が残る。`clip_weights` が隠れ層の重みを ±127/64 に丸めるので、後段を大きく
  してもこの範囲でしか使えない。**上限の測定としては保守側に出る**
- 大きい後段は推論に出せない。出口はFTの取り出しに限られる
- 3億局面での測定である。19.9億で同じ形になるとは限らない
- **この測定は1度でよい。** 天井の位置が分かれば、以後の後段の設計はその中で決まる
