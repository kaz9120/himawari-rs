# 0034: NNUE特徴量とネットの構成

- Status: accepted
- Date: 2026-07-19
- 関連ADR: [0023](0023-eval-interface.md), [0009](0009-piece-encoding.md), [0035](0035-nnue-accumulator.md), [0036](0036-nnue-quantization-simd.md)

## Context

特徴量は、このプロジェクトが独自性を出す注力先と位置づける
（オーナー方針）。利きは評価の本質に近い情報だが、非局所的
（1手で数十マスの利きが変わる）でNNUEの差分更新と相性が悪く、
成功事例が乏しい。dlshogi系CNNで利き入力が機能するのは
毎回全計算するからで、「利きが弱い」のではなく「差分機構と
相性が悪い」だけである。この観察が設計の起点。

## 選択肢と比較

- 標準HalfKPのみ: 検証は楽だが独自性がない
- 利きをFT（差分部）に入れる: 差分更新のコストが爆発する。
  過去の失敗の主因
- 2系統の入力: 差分更新のFT（KP系）と、全計算の小さな利き入力を
  ネット内で連結する。差分と利きを同居させない。採用

## Decision

### 構成（1つのネット、出力は評価値1個）

```
KP特徴     → FT 256×2視点（差分更新）──┐
                                      ├─連結→ 32 → 32 → 1
玉近傍利き → 線形32（毎回全計算）  ──┘
```

活性化はClipped ReLU。出力はFV_SCALEで歩=90スケールに写像。

### FT側（差分更新）

- 特徴はHalfKP。BonaPiece番号はやねうら王互換の変換表を持つ
- 独自KP変種（玉近傍の情報量を増やす等）は学習パイプライン確立後に
  SPRT比較で検討する（このADRの改訂として扱う）

### 利き入力

- 特徴: 両玉の周囲5×5=25マスについて、自利き数・敵利き数を
  各0..3に飽和させたone-hot（マスあたり16クラス）。
  50マス×16 = 800次元、活性は常時50特徴
- evaluateのたびに全計算する。コストはattackers_to×50マスで、
  隠れ層の行列積より小さい。差分状態を一切持たないため、
  特徴定義の変更は全計算関数の差し替えだけで済み、
  P5での変種実験（長い利きのみ・ピン・脱出路など）が速い
- 玉移動時の全再計算はHalfKPのrefresh意味論と自然に一致する

### 互換性と検証

- 利き入力の重みをゼロにすると標準HalfKP 256×2-32-32-1と
  数学的に一致する。この性質を検証に使う: 公開ネットを
  FT側に読み込み、公開エンジンとのevaluate一致で
  推論スタック（差分・量子化・SIMD）を外部照合する
- 学習の初期化は乱数からと、公開ネットのFT側の流用＋利き入力ゼロ
  （ウォームスタート。ライセンス要確認）の両方を選べるようにする

## Consequences

- 層を深くせず、入力の情報を増やして表現力を上げる構成なので、
  探索速度への影響が小さい（オーナー方針の
  「ネットワークはシンプル、特徴量にこだわる」に一致）
- 利き入力はNPSを下げる。それを差し引いた棋力の損得はSPRTで判定する。
  負けた場合もFT側だけの標準構成に安全に戻れる
- 2系統の入力経路を持つぶん推論コードは複雑になる。
  差分更新=全計算、SIMD=スカラーの一致テスト（P4出口条件）は
  両系統それぞれに課す
