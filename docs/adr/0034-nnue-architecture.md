# 0034: NNUE特徴量とネットワーク構成

- Status: proposed
- Date: 2026-07-19
- 関連ADR: [0023](0023-eval-interface.md), [0009](0009-piece-encoding.md)

## Context

P4の中心課題は「推論部のバグと学習部のバグを切り分ける」こと
（ROADMAP）。自前学習（P5）の前に、既存の公開評価関数を
読み込んで推論だけを検証できれば、切り分けが成立する。
特徴量とネットワーク構成はファイル互換性と表裏一体なので、
まとめて決める。

## 選択肢と比較

### 特徴量

HalfKPは自玉位置×玉以外の盤上駒・持ち駒（BonaPiece）の
2視点特徴で、将棋NNUEの標準。Kristallweizen・orqha・水匠系など
公開評価関数が豊富にある。HalfKA系（玉を含む）やより大きい
特徴量は表現力で勝るが、互換で読める公開物が乏しく、
第一世代の検証戦略に合わない。独自特徴量はP5で学習が回って
比較基盤ができてから検討する。

### ネットワーク構成

HalfKP標準の 256×2-32-32-1（FT 256、隠れ2層32、Clipped ReLU）を
採用する。公開評価関数がこの構成であることが決め手。
FT拡大（512×2、1024×2）は学習パイプライン確立後の選択肢。

## Decision

- 特徴量: HalfKP。BonaPiece番号付けはやねうら王互換
  （盤上駒・持ち駒の通し番号、fe_end = 1548）とし、
  自前のPiece/PieceType（ADR-0009）からの変換表をcoreに置く
- ネットワーク: FT 256×2 → 32 → 32 → 1。活性化はClipped ReLU。
  出力はFV_SCALE除算で歩=90スケールの評価値に写像する
  （量子化の詳細はADR-0036）
- 視点は手番側・非手番側の2アキュムレータ連結（標準どおり）
- 検証: 公開評価関数を読み込み、公開エンジンと同一局面での
  evaluate値一致を確認する（推論部の正解基準）

## Consequences

- 第一世代の棋力上限は公開HalfKP評価関数の水準に律速されるが、
  推論部の正しさが先に確定する
- BonaPiece変換はP5の教師データ生成（PackedSfenValue互換）でも
  そのまま使える
- FT拡大や独自特徴量への移行は、P5で学習比較ができるように
  なってから別ADRで扱う
