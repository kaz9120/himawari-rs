# 0037: NNUE評価ファイルフォーマット

- Status: proposed
- Date: 2026-07-19
- 関連ADR: [0019](0019-usi-architecture.md), [0034](0034-nnue-architecture.md), [0036](0036-nnue-quantization-simd.md)

## Context

評価関数ファイルの形式は、公開評価関数の読み込み互換
（ADR-0034の検証戦略）に直結する。独自形式は自前学習（P5）が
回るまで必要にならない。

## Decision

- やねうら王のNNUE評価ファイル（nn.bin）互換の読み込みを
  実装する。ヘッダのバージョン・ハッシュ・アーキテクチャ文字列を
  検証し、不一致は読み込みエラーとして報告する
- 重み配置（FT→隠れ層の順、リトルエンディアン）も互換に従う
- USIオプション `EvalDir` / `EvalFile`（やねうら王互換の名前）を
  追加し、isreadyの初期化（ADR-0019）で読み込む。
  読み込み失敗時は駒割評価（ADR-0023）へフォールバックせず、
  エラーを出して起動を止める（気づかず弱いまま対局する事故を防ぐ）
- 書き出し（独自学習ネットの保存）もまず互換形式で行う。
  互換形式で表現できない拡張が必要になった時点で、
  独自形式を別ADRとして起草する（P5）
- 検証: 公開評価関数の読み込み→固定局面群のevaluate値を
  公開エンジンの出力と照合する回帰テストを持つ。
  ファイルはリポジトリに含めず、CIではヘッダ検証と
  ダミーネット（乱数重みを自前で書き出したもの）の
  roundtripテストのみ行う

## Consequences

- P5の学習器も互換形式で保存すれば、やねうら王側のツール群
  （検証・対局）がそのまま流用できる
- ヘッダのアーキテクチャ文字列に依存するため、FT拡大などの
  構成変更（ADR-0034の将来課題）をしたら互換が切れる。
  その時点で独自形式ADRを起草する
- 評価ファイルの配布・ライセンスはエンジン本体と別問題として
  扱う（リポジトリに同梱しない。ADR-0027の互角局面集と同じ整理）
