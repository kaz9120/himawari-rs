# 0037: NNUE評価ファイルフォーマット

- Status: accepted
- Date: 2026-07-19
- 関連ADR: [0019](0019-usi-architecture.md), [0034](0034-nnue-architecture.md), [0036](0036-nnue-quantization-simd.md)

## Context

2塔構成（ADR-0034）はやねうら王のnn.binでは表現できないため、
保存形式は独自になる。一方、公開評価関数の読み込みは
推論スタックの外部照合（検証フィクスチャ）として使うので、
互換ローダも別途必要。両者の位置づけを決める。

## Decision

### 独自形式（保存・通常運用）

- マジック・フォーマットバージョン・アーキテクチャ記述子
  （各塔の特徴量ID・次元・層構成）・学習来歴文字列・
  重みハッシュを持つヘッダ＋リトルエンディアンの重み列
- アーキテクチャ記述子の不一致は読み込みエラー。
  将来の構成変更はフォーマットバージョンで区別する
- USIオプション `EvalFile` で指定し、isreadyで読み込む。
  読み込み失敗時は駒割へフォールバックせず起動エラーにする
  （気づかず弱いまま対局する事故を防ぐ）

### 互換ローダ（検証フィクスチャ）

- やねうら王形式のHalfKPネットを「第1塔＋利き塔ゼロ」として
  読み込むローダを持つ。用途は推論一致検証と、学習の
  ウォームスタート初期化（ADR-0034）に限る
- 互換形式での書き出しはしない

### 検証

- 独自形式のroundtrip（乱数重みの書き出し→読み込み→一致）を
  CIで回す
- 互換ローダは公開評価関数＋固定局面群のevaluate値照合の
  回帰テストで検証する（ファイルはリポジトリに含めない。
  ローカル実行、CIではスキップ）

## Consequences

- 独自形式のため、やねうら王系ツール群との直接互換はない。
  必要になった場合は変換ツールをtoolsに書く（第1塔のみの
  ネットは相互変換可能）
- ヘッダの学習来歴と重みハッシュにより、SPRT結果と
  ネットワークの対応が追跡できる（ADR-0007のネットワーク
  識別子課題への部分回答）
- 評価ファイルの配布・ライセンスはエンジン本体と別問題として
  扱う（リポジトリに同梱しない）
