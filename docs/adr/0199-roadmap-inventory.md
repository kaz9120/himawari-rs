# 0199: ROADMAPを棚卸しし、注力を並列の実戦化とデータの質へ組み替える

- Status: accepted
- Date: 2026-09-03
- 関連ADR: [0134](0134-head-capacity.md), [0143](0143-spsa-tuning.md), [0151](0151-speedup-sweep.md), [0162](0162-parallel-group.md), [0188](0188-selfplay-rl-loop.md), [0192](0192-tanuki2024-teacher.md), [0198](0198-phase-indicator.md)

## Context

[ADR-0198](0198-phase-indicator.md)で出力バケットを閉じたところで、オーナーから
「本当にやるべきことはどこにあるのか、鉱脈を探りたい」と棚卸しの要望が出た
（2026-09-03）。ROADMAPは経緯を書かない決まりなので、根拠はここに残す。

## 実績の棚卸し

採択したEloをADR索引とCHANGELOGから領域で束ねた。

| 領域 | 採択の合計 | 8月後半の空振り | 読み |
|---|---|---|---|
| 探索の参照追従（G1〜G10、history・SEE・futility系） | 約+780 | なし | 一巡して閉じた |
| 速度（0151の12群、SoA SIMD、NNUEカーネル） | 約+270 | 4件連続 | 律速がメモリ待ちで頭打ち |
| 探索定数のSPSA | +32 | なし | 運用の域 |
| 評価関数の構造（対の積、i8量子化、L1半減） | 約+110 | 7件連続 | 掘り尽くした |
| 評価関数のデータ（29.9億、静止化、tanuki 78.6億、自己生成） | 約+95 | 1件 | まだ出る |
| 損失（ランキング） | +29 | 1件 | 上積みは閉じた |
| ルール・生成のバグ | +13 | なし | 定点観測で拾う |

**8月後半は、構造の線が7連敗、データの線が4戦4勝である**。構造の空振りは
どれも「ネットは新しい項を使うが対局に変換されない」で、同じ壁に当たり続けた。

### 実戦の負け方は健全

floodgateはレート3567、628勝590敗（2026-09-03）。回収済みの1001局のうち
負け457局を棋譜のsummary行から集計した。

| 項目 | 値 |
|---|---|
| 時間切れ | 0 |
| 反則負け | 1 |
| 60手以内の負け | 0 |
| 101手以降の負け | 446（98%） |
| 入玉宣言負け | 8 |
| 千日手 | 38（弱い相手も混じる） |

バグや運用で落としている分はなく、**上位との700 Eloの差は棋力そのもの**で
ある。宣言負け8局は教師の入玉の薄さ（1.65%、[ADR-0190](0190-selfplay-decided-thinning.md)）
に、千日手38局は既定のSPRT条件では見えない領域に対応する。

## 鉱脈の見立て

大きい順に3つある。

1. **複数スレッドの実戦化**。放流も選手権も複数スレッドなのに、SPRTは
   すべて1スレッドで回している。NPSは8スレッドで7.1倍と分かっているが
   （[ADR-0162](0162-parallel-group.md)）、**Eloが何倍になるかは一度も
   測っていない**。Lazy SMPは実装が雑だとNPSが伸びてもEloが伸びない典型で、
   historyの共有（Issue #430）とfalse sharing（0151群E）が未着手のまま
   残っている。放流機はSurface Pro 9（Pコア2＋Eコア8）で6スレッド、
   選手権はAWSの大きいインスタンスを予定しており、均質な多コアでの
   伸びが本番の棋力を決める
2. **教師データの質**。上位との差の本体はここだと見る。上位はより強い
   教師で何世代も回したデータで学習しており、構造は本エンジンと大差ない。
   データを変えた実験が全勝なのも符合する。ただし自前の再ラベルは本機で
   数か月級になるので、無料の実験台で「ラベルの質が効くか」を先に確かめる。
   入玉5億（MIT）は宣言負けへ直接効き、Kanade蒸留の1.1億は同じ局面で
   ラベルの質だけを変えた比較になる（ライセンス確認が要る）
3. **長い持ち時間での時間管理と千日手**。時間管理の参照追従は−107・−117・
   −54と大負けし非劣性で妥協した。10+0.1では床が配分を支配するので、
   300+10の挙動をSPRTが見ていない。効く保証はないが、実戦にだけ効く手が
   眠っている場所ではある

構造と損失の線は掘り終えた坑道と判断し、候補へ降ろす。残差ヘッドの足切り
（[ADR-0198](0198-phase-indicator.md)の型）は安いので待ち時間に限って行う。

## 計算資源の判断（2026-09-03オーナー）

- **AWSは一旦見送る**。試算は、SPRT1本がスポットで約$2・1.5時間、学習
  1エポックが$17〜55、月額で$30〜250だった。軽い使い方なら年6〜12万円で
  ミニPC1台分を下回るが、起動と同期の工事と運用の手間がつく
- **PCの新調を検討する**。x86の均質16コアが最も用途に合う
  （Ryzen AI Max+ 395のミニPCか、9950Xのデスクトップ）。放流もSPRTも
  本番と同じISAで回せることと、Lazy SMPを均質コアで測れることが理由になる。
  iGPUは学習の当てにしない
- **Cloudflare Workersは対象外**。実行中に `Date.now()` が進まない仕様で、
  時間制の対局が成立しない。Containersなら成立し、同時1,500 vCPUの上限で
  SPRT1本を数分・約$6で終えられる見込みがある。学習と生成には向かない。
  やるなら「standard-2を1つ立てて20局指させる」試作から
- 費用を抑え、計算資源に依存しない方法を優先する（オーナー方針）

## Decision

注力を2本へ組み替える。

1. **複数スレッドの実戦化**を最初に着手する。開発機（M4 Pro、Pコア10）で
   時間がかかっても測る（2026-09-03オーナー決定）。最初の測定は
   スレッド数ごとのElo曲線で、[ADR-0200](0200-thread-scaling.md)が持つ
2. **自己生成と継続学習のループを型にする**。入玉5億の混合を並行し、
   生成の深さ・太いネットの蒸留・生成局面の選び方で「新しい情報の出どころ」
   を確かめる（追記で組み替えた）

SPSAは運用へ降ろす。構造と損失は候補へ戻す。時間管理と千日手は本番の
実戦条件が決まってからの枠に置く。

## 追記（2026-09-03、同日のオーナー判断）

- **Kanadeの蒸留データは使わない**。有償の評価関数に由来し、ライセンスが
  不明瞭である。公開データはライセンスが明らかなものに限る
- **マシン資源は、学習データの作り方と継続学習のループの作り方が見えたら
  提供する**。注力2の成果物は棋力ではなく、再現できるレシピと資源の
  見積もりになる。いまの資源で小さく回し、ノウハウを先に確立する

## Consequences

- ROADMAPの注力・運用・次に着手する・候補を書き換える
- 放流機の設定はスレッド数6・Pコア2＋Eコア8である。最適なスレッド数は
  持続クロックでのNPSと、6を基準にした側別スレッド数の自己対局で決める。
  電源モードとメインスレッドのPコア配置は、それより効き目の大きい
  可能性を持つので先に確かめる
- 新しいPCが入ったら、x86のAVX2経路のベンチと放流の移設を最初に行う
