# 0105: ttPvの伝播を直しRFPの安全弁に使う案（発動率不足で棄却）

- Status: rejected
- Date: 2026-07-29
- 関連ADR: [0074](0074-feature-verification.md), [0076](0076-lmr-fixed-point-ttpv.md), [0096](0096-rfp-margin.md), [0022](0022-transposition-table.md), [0028](0028-pruning-extensions.md)

## Context

[ADR-0096](0096-rfp-margin.md)はRFPのマージンをやねうら王へ寄せて-139.4で
棄却された。その反省に「やねうら王の `76*depth` は `!ss->ttPv` という
安全弁と組で成立しており、本エンジンにttPvがないまま数値だけ寄せた」と
書いてある。[ROADMAPの候補](../ROADMAP.md#候補)にも「ttPvフラグの活用（RFPの前提）」が
残っていた。

置換表にPVフラグを持つこと自体は[ADR-0022](0022-transposition-table.md)で
決まっており、`TtData::pv` として実装済みである。

### 見つけた欠陥

保存している値がStockfishと違っていた。

```rust
// himawari（変更前）: 現在のノードのPV性をそのまま保存する
self.shared.tt.store(key, ..., bound, is_pv);
```

```cpp
// Stockfish: 一度立ったフラグが置換表に残り続ける
ss->ttPv = PvNode || (ttHit && ttData.is_pv);
tt.store(..., ss->ttPv, ...);
```

himawariのフラグは、同じ局面を非PVで読み直すたびに消える。「過去にPV上で
読まれた」という意味を持っていない。[ADR-0076](0076-lmr-fixed-point-ttpv.md)が
LMRのttPv項で-43.8を出した理由はこれで説明がつく。参照していた材料が、
移植元とは別のものだった。

## Decision

伝播を直したうえで、RFPに `!tt_pv` の安全弁を足す形を実装し、発動率を
測った。**基準を下回ったため棄却する**。

[ADR-0074](0074-feature-verification.md)は「枝刈り・延長は発動率も測り、
0.1%を下回るならSPRTにかけない」と定めている。

### 測定

固定深さ13、40局面、1,810万ノード。

| 指標 | 件数 | 割合 |
|---|---|---|
| tt_pvを置換表から受け継いだノード | 83,037 | 全ノードの**0.46%** |
| RFPの他の条件を満たしたノード | 8,458,631 | 全ノードの46.7% |
| うち `!tt_pv` で止めた数 | 3,227 | RFP候補の**0.04%**、全ノードの**0.018%** |

0.018%は基準の0.1%を大きく下回る。SPRTにかけない。

### なぜ効かないか

**本エンジンのRFPは葉に近すぎる**。`RFP_MAX_DEPTH` は6で、Stockfishの
`depth < 14` の半分以下である。深さ6以下のノードは木の大半を占める一方、
PV上に載っていた経験を持つものはほとんどない。安全弁を置いても閉じる
機会が来ない。

フラグ自体の希少さも効いている。PVは木の中で1本の細い経路なので、
そこに載ったことのあるノードは全体の0.46%しかない。

### ADR-0096の反省を訂正する

[ADR-0096](0096-rfp-margin.md)は「ttPvという安全弁がないまま数値だけ
寄せた」ことを敗因の1つに挙げた。**この読みは誤りだった**。安全弁を
入れても、本エンジンのRFPの深さ範囲では0.04%しか閉じない。マージンを
緩めたときの刈りすぎは、ttPvの有無とは別の原因による。

やねうら王の `76*depth` を成立させているのは、ttPvよりも深さ範囲
（14未満）とimproving項の組み合わせのほうである。ADR-0096を再訪する
なら、そちらを先に見る。

## Consequences

- 棄却する。ttPvの伝播も入れない。読む側がなければ配管だけが残る
  （[ADR-0028](0028-pruning-extensions.md)の「配管は最初の機能と一緒に
  入れる」）
- [ADR-0076](0076-lmr-fixed-point-ttpv.md)のLMRのttPv項が-43.8だった
  理由の説明は残る。フラグの意味が移植元と違っていた。ただし正しい
  フラグでも真になるのは0.46%なので、再挑戦の期待値は小さい
- [ROADMAPの候補](../ROADMAP.md#候補)の「ttPvフラグの活用」2件を落とす。フラグが
  未読なのは事実だが、読んでも働く場面がない
- [ADR-0096](0096-rfp-margin.md)の反省を訂正した。RFPを再訪するときの
  着眼は深さ範囲とimproving項に移る
- 測定に要した時間は30分で、SPRTの1000局より安い。
  [ADR-0103](0103-root-score-gap.md)と同じ進め方である
