# 0229: ROADMAPを引き直し、注力を「焦点が見える評価関数」にする

- Status: accepted
- Date: 2026-10-16
- 関連ADR: [0207](0207-roadmap-focus-eval.md), [0213](0213-freeze-structure-focus.md), [0228](0228-grow-labeled-pool.md), [0148](0148-effect-table.md), [0221](0221-public-site.md), [0030](0030-nyugyoku-declaration.md)

## Context

開発を始めて3か月（2026-07-17〜）で、floodgateの2週間レートは4,000の手前まで来た。
オーナーとの議論（2026-10-16）で、これまでのADRを一度脇に置き、白紙から
ロードマップを引き直すことにした。ROADMAPは経緯を書かない決まりなので、根拠はここに残す。

### 3か月の振り返り

8月は参照実装への追従と高速化で伸び、9月は構造の案が空振り続きで停滞した。
10月はdlshogiによる教師の付け直しが当たった（[ADR-0222](0222-promote-dl20.md)の+74.8）。
ただ、付け直しの後に続いた改善は+25.7、+22.8、+5.9と細っている。
量を足すだけの回は、4.2億を足して+5.9だった（[ADR-0228](0228-grow-labeled-pool.md)）。

強さの出どころは借り物が多い。探索は参照実装への追従で、10月の伸びはdlshogiの
ラベルである。選手権のアピール文書で「独自」と書ける取り組みは、まだない。

### オーナーが求めるもの

議論で、ゴールは強さだけではないと確かめた。

- 選手権のアピール文書に書ける、独自のアイデアが欲しい
- 将棋AIの開発を、クリエイター的な活動にしたい。開発の様子や実戦の状況を見せ、
  解説もしたい。棋力向上に役立つAIを通じて、将棋界の発展に寄与したい
- 強さの面では、評価関数を頑張るほかない。探索で上位との差（推定500）は埋まらない

### 過去の参加チームの調査

選手権の第20〜36回のアピール文書を要約した（`research/wcsc_appeals/`）。
今回の判断に効いたのは次の取り組みである。

| チーム（回） | 取り組み | 本ADRでの使いどころ |
|---|---|---|
| Miacis（30） | 評価値を51分割の分布で出し、分布の広さを難しさの目印にする | 難しさを出す出力 |
| Gokaku（35） | 升ごとの予測勝率を出すvalue head | 焦点を見せる出力 |
| 元気もりもりニンニクパワー・ねね将棋（36） | 局面の性質を多軸で持ち、評価を切り替える | 焦点を表す入力 |

| 技巧（26・27）・山田将棋（21〜36） | 配列盤やbyteboardで利き数を持ち、差分で更新する | 利きの基盤 |
| 水匠（35・36） | 事実はエンジンが確定し、LLMは日本語にするだけの解説 | 解説への出口 |
| 習甦（32） | 宣言法に沿った入玉の報酬を学習に足す | 入玉の点数 |

## 選択肢と比較

### 案A: データの母集団を増やし続ける

ADR-0228の路線を続ける。効きは細っており、ディスクとAWSの壁が先に来る。
独自性にもつながらない。

### 案B: 探索と時間管理を掘る

探索で上位との差は埋まらない（オーナー判断）。時間管理はマシンの性能で覆る。

### 案C: 評価関数に、焦点と難しさを出させる

評価関数が「どこが焦点か」「どれだけ難しいか」を自分で出せるようにする。
強さ（時間の配分・入力の改善）、独自性（NNUEで分布や升ごとの値を出す例は、
調査の範囲では見当たらない）、クリエイター活動（可視化と解説）の3つに同時に効く。
ADR-0213の構造の凍結を解く必要がある。

## Decision

**案Cを採り、ROADMAPの注力を「焦点が見える評価関数」の1本にする**。
決め手は、3つのゴールに同時に効く案がこれだけだったことである。

### 注力の段階

| 段階 | 中身 | 合格の条件 |
|---|---|---|
| 1. 基盤 | 盤面操作の内訳をプロファイルで測る。利きを差分で持つ試作を作る（[ADR-0148](0148-effect-table.md)の部品の接続か、byteboardの併用） | NPSの代償と、それで安くなる処理を数字で示す |
| 2. 出力を増やす | 勝率の分布と、升ごとの勝率をNNUEで出す。まず小規模学習で試す | 強さを落とさない（非劣性）。可視化に使える |
| 3. 入力を増やす | 利き数の入力と、進行度で後段を切り替える方式を試す | SPRTで強くなる |
| 4. 使う | 分布の広さで思考時間を配る。公開ページで焦点を見せ、解説につなげる | 強さは対局で、見せ方はオーナーの判断で決める |

段階ごとにADRを起こす。盤面の持ち方は、Bitboardをやめる案も含めて段階1の
測定で決める。盤面操作が探索時間の大きな割合を占めるなら、配列へ寄せる案を本気で
検討する。小さければ併用にとどめる。

### 並行する改善

注力とは別に、入玉を点数で教える改善だけを進める。宣言法の点数や「宣言までの残り」を、
学習の目標か入力に持たせる。2028年からの24点法への変更にも備える。やり方は
着手時にADRで決める。

ほかの改善（詰みの見落としを教師で直す、自動定跡、複数の候補の先読み）は
候補に置き、優先度は低い。開発機を取り合うときは注力を優先する。

### 止めるもの

ADR-0228の母集団を増やす回は止める。保留していた3件（#716・#718・#720）は
閉じる。いまの母集団（`pool1`、21.5億局面）で注力の方向が決まったら、復活させる。
specとADRの記録は残す。

### 凍結を解く

ADR-0213の構造の凍結を解き、supersededにする。凍結を理由に取り下げた案
（[ADR-0140](0140-king-line-features.md)・[ADR-0147](0147-effect-bucket-features.md)など）は
rejectedのまま残し、段階3で要るものは新しいADRで起こし直す。

### 用語

方針の中心を指す語は、ROADMAPの「注力」に揃える。注力と別に進めるものは
「並行する改善」と呼ぶ。

## Consequences

- ROADMAPの注力・次に着手する・候補を書き換える。時間管理の候補は段階4へ吸収する
- ADR-0213をsupersededにし、ADR-0228のStatusの注記を「2回目以降は本ADRで止めた」に直す
- ADR-0148は保留から再開に変わる。Statusはproposedのままで、段階1のADRが引き継ぐ
- 開発機の空き時間は、母集団の付け直しではなく注力の小規模学習に回る
- アピール文書の締切は例年3月末ごろである。目安は、段階2までの成果を2027年3月の
  時点で見せられる形へ仕上げることである
- 見直しのトリガーは2つある。段階2で、分布や升ごとの出力が強さを落とさずに出せない
  と分かったとき。放流機のレートが1か月動かないとき
