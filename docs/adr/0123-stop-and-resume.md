# 0123: 長時間走る処理は停止と再開ができること

- Status: proposed
- Date: 2026-08-01
- 関連ADR: [0087](0087-sprt-resume.md), [0121](0121-book-scale-up.md), [0122](0122-tooling-language-split.md)

## Context

このリポジトリの主な処理は長い。SPRTは数時間、定跡生成は十数時間、学習は数日かかる。
その間マシンは占有される。**別の作業へCPUを回したくなったとき、安全に止められないと
成果がまるごと消える。**

2026-08-01に実際に起きた。定跡生成を `--save-every 100` で走らせ、24局面まで進んだ
時点で条件を変えるため止めた。1度も書き出されておらず、24局面ぶん（16分）を失った。
書き出し間隔が中断時の損失そのものだと分かっていなかった。

現状を棚卸しすると、3つの長時間処理で揃っていない。

| 処理 | 途中保存 | 再開 | 停止 |
|---|---|---|---|
| `selfplay`（SPRT） | jsonlへ1局ずつ | `--resume`（[ADR-0087](0087-sprt-resume.md)） | `pkill` のみ |
| `book gen` | `--save-every` 局面ごと | 出力を読み直す（[ADR-0121](0121-book-scale-up.md)） | `pkill` のみ |
| `train` | `.best`（量子化した推論用ネット） | **なし** | `pkill` のみ（全部失う） |

再開はSPRTと定跡にある。**止め方は3つとも `pkill` しかない。** 途中で殺すので、
最後の保存から先が消える。

## 選択肢と比較

### 案A: シグナルを捕まえる

`SIGINT` / `SIGTERM` を受けたらフラグを立て、切りのよいところで保存して終了する。
Ctrl-Cで止まるのが自然で、`pkill` でも効く。ただしRustの標準ライブラリにシグナル
ハンドラの登録手段がなく、`libc` か `signal-hook` への依存が要る。

**バックグラウンドで走らせている処理にCtrl-Cは送れない。** `nohup ... &` で起動した
ものを止めるには、どのみちPIDを調べて `kill` する必要がある。「自然さ」の利点が
この用途では効かない。

### 案B: 停止ファイルを見る

`<出力>.stop` の有無を、切りのよいところで確認する。あれば保存して終了する。
`touch data/book/main.db.stop` で止まる。依存が要らない。PIDを調べなくてよい。

止まるまで最大1単位（定跡なら1局面、SPRTなら1局）待つ。即座には止まらない。

### 案C: 何もせず `pkill` のまま、保存間隔を詰める

実装が要らない。ただし損失をゼロにはできず、間隔を詰めるほど書き出しのコストが増える。

## Decision

案Bを採る。

**決め手は、止めたい対象がバックグラウンドで走っていることである。** 定跡生成もSPRTも
`nohup ... &` で起動して放置する。Ctrl-Cが届かない以上、案Aの利点は薄い。依存を足さずに
同じ結果が得られる。

案Cを採らないのは、損失をゼロにできないからである。保存間隔は書き出しコストとの
折り合いで決まるので、詰めるにも限度がある。**間隔で損失を減らすのと、停止時に
必ず保存するのは別の手当てで、両方要る。**

### 停止の作法

3つの長時間処理で揃える。

| 項目 | 決め |
|---|---|
| 停止ファイル | `<主な出力>.stop`。`--stop-file` で変えられる |
| 確認する場所 | 1単位の処理に入る前（定跡は1局面、SPRTは1局） |
| 停止時の動作 | そこまでを保存して終了コード0で終わる |
| 後始末 | 終了時に停止ファイルを消す。次回起動で即終了しないため |
| 表示 | 停止ファイルを見つけたら、そう言ってから止まる。黙って終わらない |

### 保存間隔の決め方

**書き出し間隔は「失ってよい時間」から決める。** 局面数やステップ数で指定していても、
効いているのは時間である。定跡生成は1局面5〜40秒と幅があり、同じ25局面でも2分から
17分まで変わる。

既定値は小さめに置く。試しに走らせたときに何時間も戻らないより、細かすぎて呼び直す
ほうがよい。

### `train` の再開は本ADRでは決めない

`train` は再開の口がない。`.best` は量子化した推論用ネットで、学習を続けるための
f32の重みと最適化器の状態を持たない。中断すると全部失う。3つの中でいちばん長く走る
処理がいちばん弱い。

ただし実装は保存形式の設計を伴い、停止ファイルを足すだけでは済まない。
[ROADMAPの候補](../ROADMAP.md#候補)にある「学習チェックポイント」で別に扱う。
**本ADRは停止の作法だけを決め、`train` には停止ファイルを入れない。** 保存できない
処理に停止の口だけ用意しても、失うものは変わらない。

### 実測

定跡生成は、375局面まで書き出した状態で376局面目を探索中に停止ファイルを置いた。
376局面すべてが残り、同じコマンドで再開して400局面まで続いた。**`pkill` なら
1局面ぶんを失っていた。**

SPRTは、走行中の対局を最後まで指してから止まった。8ペア16局が記録され、停止ファイルは
消えている。

## Consequences

- 定跡生成とSPRTを、成果を失わずに止められるようになる。マシンを別の作業へ回す判断が
  しやすくなる。今日のように「測りたいから定跡を止める」が気軽にできる
- 止まるまで最大1単位待つ。定跡なら1局面（深さ28で5〜40秒）、SPRTなら1局。即座に
  止めたいときは従来どおり `pkill` する。その場合の損失は最後の保存までで、
  停止ファイルを使ったときより大きい
- 停止ファイルの消し忘れで、次回が即終了する事故がありうる。終了時に消す実装にするが、
  `pkill` で殺されたときは残る。起動時に消すのではなく、見つけたら「前回の停止ファイルが
  残っている」と言って消してから続ける
- `train` は手当てされないまま残る。3つのうちいちばん長い処理が弱いという状態は変わらない
