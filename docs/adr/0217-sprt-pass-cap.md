# 0217: SPRTの既定に10,000ペアの上限を置き、判定に至らない走行を見送りにする

- Status: accepted
- Date: 2026-09-20
- 関連ADR: [0028](0028-pruning-extensions.md), [0087](0087-sprt-resume.md), [0160](0160-revisit-rejected-under-better-eval.md), [0163](0163-sprt-hypothesis-choice.md), [0175](0175-sprt-until-decision.md), [0209](0209-workflow-layers.md), [0211](0211-check-extension-see.md)

## Context

[ADR-0175](0175-sprt-until-decision.md)は「判定が出るまで走らせる」と決め、
上限（60,000ペア）を収束の判定基準ではなく暴走を止める安全弁に降格した。
[ADR-0163](0163-sprt-hypothesis-choice.md)の追記は、H1のときだけ採択する
ゲート用途に限って `--max-pairs` の打ち切りを許した。

[ADR-0211](0211-check-extension-see.md)のSPRTは、23,483ペア（46,966局）を
走っても判定に至らなかった。+2.7 [−0.3, +5.7]、LLR +0.44で、真のEloが
中点（+2.5）の近くを漂う型である。オーナー判断で打ち切った（2026-09-20）。

実験キュー（[ADR-0209](0209-workflow-layers.md)）は直列なので、1本の
SPRTの長さがそのまま後続すべての遅れになる。この走行は後ろに4本の
実験（ADR-0212・0214・0215・0216、合計約2日半）を待たせていた。

### 判定済みの走行は8,061ペアまでで決着している

`data/sprt/*.result` の判定済み17本（H1・H0）を集計した。

| 統計 | 局数 | ペア数 |
|---|---|---|
| 中央値 | 約2,600 | 約1,300 |
| 75%点 | 約5,800 | 約2,900 |
| 最大 | 16,122（[ADR-0176](0176-lance-non-promotion-rank.md)の非劣性） | 8,061 |

判定に至る走行は1万ペアの手前で決まっている。それを超えて漂う走行は、
真のEloが中点の近くにあり、その対立仮説では答えが出ない。

### CIを足切りに使うのは効かない

「95%区間の上限がelo1（+5）を下回ったら見送り」の規則は、ADR-0211では
23,483ペアでも上限が+5.7で止まらなかった。1万ペアの時点の区間幅は
±4.5前後で、中点の変更を弾くには足りない。実用になるのはペア数の上限である。

## 選択肢と比較

### 案A: 既定に10,000ペアの上限を置く（採用）

判定に至らなければ「見送り」として結果ファイルへ書き、mainへ入れない。
判定済みの過去17本はすべてこの中で決着している。8並列の10+0.1で約490ペア/時
なので、約20時間になる。

### 案B: 8,000ペア

最長の非劣性（8,061ペア）を切るぎりぎりで余裕がない。

### 案C: 現状維持（60,000ペア）

中点の変更に4〜5日払う。キューの後続が止まる費用に見合わない。

## Decision

**既定の走行に10,000ペアの上限を置く**（オーナー判断、2026-09-20）。
判定に至らなければ「見送り」とし、途中経過を結果ファイルへ書く。

統計の性質はこうなる。SPRTのα・βは境界まで走ったときの保証で、上限で
打ち切る運用ではH1を採択しないので誤採択率αは増えない。増えるのはβ、
真に+5ある変更を見送る率である。ただし上限で切られる走行は真のEloが
中点の近くにあるものなので、見送っても失う棋力は小さい。
[ADR-0163](0163-sprt-hypothesis-choice.md)の追記が言っていたことを既定に広げる。

見送りはrejectedとは別の状態である。棄却は「H0で負けた」、見送りは
「この仮説では答えが出なかった」で、後者は[ADR-0160](0160-revisit-rejected-under-better-eval.md)の
型（群にして測り直す）に回せる。

対立仮説は効きの見込みで選ぶ。判定までの局数はおおむねelo1の2乗に反比例
するので、教師の置き換えのように+10以上を見込む変更は、着手時にelo1=10と
宣言すれば4分の1の局数で決まる。「着手時に決めて走行後に変えない」の
規律は変えない。

上限は「この変更に何日払うか」の宣言でもある。ADRには、既定を変えるときだけ
理由を書く。

### 実装

- `hmwr/config.py` の `SPRT_MAX_PAIRS` を10,000にする。`SPRT_HARD_MAX_PAIRS` は
  廃止する。`--max-pairs` と `--set SPRT_MAX_PAIRS=` で走行ごとに変えられる
- 上限に達して判定に至らなければ、`hmwr match run` が途中経過を
  `decision=見送り` で結果ファイルへ書き、終了コード2で返す。`.result` が
  あるので、キューは「完了」として書き戻し、`hmwr sprt show` の一覧でも
  見送りと分かる
- トレーラは `SPRT: +2.7 [-0.3,+5.7] 20000games 見送り` の形になる。
  mainへ入れないので、CHANGELOGには載らない

## Consequences

- 中点の変更に払う時間が4〜5日から約20時間になる。キューの回転が上がる
- 真に+5ある変更のうち、収束の遅いものを見送る。見送りはADRに記録し、
  後で群にして測り直せる
- 非劣性（elo0=−5、elo1=0）も同じ上限に従う。過去の最長は8,061ペアで、
  上限の中に収まっていた
- CLAUDE.mdの「SPRTゲート」とrunning-sprtスキルを、この決定に合わせる。
  [ADR-0175](0175-sprt-until-decision.md)の「安全弁」の記述は、本ADRが
  上書きする
