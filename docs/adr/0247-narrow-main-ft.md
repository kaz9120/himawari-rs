# 0247: 利きを入れたまま主のFTの幅を256・128へ絞り、ノード数固定の対局で質を測る

- Status: proposed
- Date: 2026-10-25
- 関連ADR: [0245](0245-input-variants-screening.md), [0237](0237-effect-count-inputs.md), [0159](0159-ft-width-1024.md), [0171](0171-ft-pairwise-product.md)

## Context

ADR-0245では、HalfKP（kp）の主のFTを幅1024に固定したまま、利きの入力の表し方を並べている。
kpにF2を足したA0は、kpだけの `eff_ctrl` に対して+185.6だった。玉×升×利き（ke）を足しても伸びない
（A10）。習甦形式でkpと同じFTに混ぜても、途中の値は `eff_ctrl` と変わらない（A12、650ペアで−0.3）。

オーナーから、主のFTの幅は小さくてよいのではという問いが出た（2026-10-25）。利きがこれだけ効くなら、
kpの幅を256や128へ絞っても、十分に強いのではないかという問いである。kpを外して利きだけで組むB1は、
この問いの幅0の端に当たる。ただしB1は側のFTの幅や持ち駒も変えるので、幅だけを見るには別に測る。

FTを絞ると差分の更新と後段の第1層が軽くなる。ADR-0159では、ノード数固定でFT1024がFT256より
+58.1 Elo強く、NPSは29.09%落ちた。ただし教師の量とレシピがいまと違うので、そのまま引けない。

## 選択肢と比較

### 案W1: 利きありの幅だけを測る

`256x16x32e64` と `128x16x32e64` の2本。A0より落ちるかは読める。幅を絞ったことによる損失を、
利きがどれだけ埋めているかは読めない。

### 案W2: 利きなしの統制も一緒に測る

W1に `256x16x32` と `128x16x32` を足して4本にする。幅1024の組（`eff_ctrl` とA0）と合わせ、
幅3通り×利きの有無の表ができる。幅ごとの利きの効き（利きありのQ−利きなしのQ）を比べられるので、
「主が細いほど利きが効くか」を読める。利きなしの2本は側の入力を作らないので、1本3時間前後で済む。

## Decision

W2を採る。測る費用は2本ぶん増えるが、利きの効きが幅で変わるかは、この先に主の幅を決める判断の
中心になる。

| 案 | 主のFT | 利き | 構成名 |
|---|---|---|---|
| D1 | 256 | F2（e64） | `256x16x32e64` |
| D2 | 256 | なし | `256x16x32` |
| D3 | 128 | F2（e64） | `128x16x32e64` |
| D4 | 128 | なし | `128x16x32` |

幅1024の組は測定済みの値を使う。利きなしは `eff_ctrl`（Q=0、定義）、利きありはA0（Q=+185.6）である。

### 仮説

**利きを入れていれば、主のFTを256まで絞っても、ノード数固定の対局での質はA0と区別できない**。

### 動かす変数

主のFTの幅だけを動かす。利きの有無は、幅ごとの利きの効きを読むための統制として組にする。

### 固定するもの

ADR-0245の「固定するもの」と同じにする。データ `sel_dedup_100M`、学習のレシピ（1周、batch 16384、
peak_lr 1e-3、λ0.7、seed 0、FTクリップ1.0、兄弟群 `rank_tanuki_210M`、検証 `valid_tanuki_dl430_q1`）、
後段16→32→1、`eff_ctrl` との1手30万ノード固定・1,000ペアの対局である。

暗黙に動く変数を点検した。

- 後段の入力の幅。主のFTを絞ると連結ベクトルも狭くなり、第1層の重みが減る。幅を絞ることに含まれる違いとして扱う
- データの量。パラメータが減るので、1億局面はFT1024より相対的に足りる側へ動く。幅に連動する違いとして扱い、
  データ量は揃えたままにする
- 乱数の系列。表の大きさが違うので、初期化で乱数を消費する順序がずれる。ADR-0245と同じく数Elo規模で、
  区別できる差より小さい

### 解釈の事前登録

質Qは `eff_ctrl` → 案のEloである。1本の95%信頼区間は±16前後なので、Qどうしの差の線を±25に置く。
幅ごとの利きの効きG（利きありのQ−利きなしのQ）は2本の差を幅1024のG（+185.6）と比べるので、
3本ぶんの誤差が乗る。線を±30に置く。

| 対象 | 結果 | 読み |
|---|---|---|
| D1・D3 | QがA0の+185.6から±25の内 | 主をその幅まで絞っても、利きがあれば質は落ちない。主を絞る方向を本命の候補にする |
| D1・D3 | Qが+25より上で、A0より25以上低い | 質は落ちるが、kpだけの幅1024よりは強い |
| D1・D3 | Qが±25の内 | 利きで、主を絞った損失をちょうど埋める |
| D1・D3 | Qが−25以下 | 利きでも、主を絞った損失は埋まらない |
| D2・D4 | Q | 幅を絞った損失そのもの。ADR-0159の−58.1（FT256、別条件）と比べる |
| G256・G128 | Gが+185.6より30以上大きい | 主が細いほど利きが効く。kpと利きは同じ情報を取り合っている |
| G256・G128 | Gが+185.6から±30の内 | 利きの効きは主の幅によらない。kpと利きは別の情報を持つ |
| G256・G128 | Gが+185.6より30以上小さい | 主が細いと利きも効きにくい。利きはkpと組んで効いている |

D1かD3がA0の±25の内に入ったら、その構成のNPSを `1024x16x32e64` と比べて測る。ノード数固定の質が
同じなら、速いほうが持ち時間の対局で強い。

### 順番

利きありのD1・D3を先に走らせ、ADR-0246のC1を挟んで、統制のD2・D4を後に置く（ADR-0245の「作戦の組み直し」、2026-10-25）。
幅を決める判断にはD1・D3で足り、D2・D4は利きの効きが幅で変わるかを読む材料になる。
B1（主の幅0）は保留にし、D3で質が保てたら積む。

### 合格の条件

この段は棋力の主張をしないので、SPRTは行わない。コードは変えない。4つの構成で
`cargo test -p himawari-engine --release` が通ることを、起票の前に確かめた（2026-10-25）。

#### 読み

D1のQは+126.6で、A0の+185.6より59.0低い。事前登録の「D1・D3、Qが+25より上で、A0より25以上低い」の
行に当たる。主を256へ絞ると質は落ちるが、kpだけの幅1024（`eff_ctrl`）よりは強い。仮説（256まで絞っても
A0と区別できない）は、D1では支持されなかった。

G256は、D2がまだ走っていないので読めない。D2の結果が出たら、+126.6からD2のQを引いて読む。

この行に次の一手の登録はない。NPSの測定は、A0の±25の内に入った構成だけが対象なので、D1では行わない。
「順番」のとおり、次はD3を走らせる。Statusはproposedのまま残す。D1〜D4がそろうまで変えない。

## Consequences

- 主の幅と利きの関係を表で持てる。B1（幅0）の結果と合わせて、kpをどこまで細くできるかを決める材料になる
- 利きありの構成は側の入力を毎回作り直すので、NPSは幅を絞った分ほどは上がらない。質が保てた場合の
  NPSの測定は別に行う
- 4本で学習と対局に14時間前後かかる
- 1億局面では幅の広いネットほど学習が足りないので、D1・D3は本番の規模より有利に出る。
  A0の±25の内に入っても、規模を上げた1本で確かめてから主の幅を決める
