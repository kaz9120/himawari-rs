## Context

探索改善キャンペーンの第7弾。現在のNMPはリダクションが
`R = 3 + depth/4`の固定式で（`search.rs:22-25`）、静的評価が
betaをどれだけ超えているかを考慮しない。評価が大差の局面では
より深く削っても安全で、SF系はevalマージン依存の動的Rを使う。

また、null moveカットは手番を放棄しても良い局面を前提と
するため、ツークツワンク的な局面で誤る。将棋は持ち駒により
パスに近い手がほぼ常にあり誤りは稀だが、入玉形・完全に
手詰まりの受け局面では起こりうる。深いノードに限り検証探索で
裏を取る。

## 選択肢と比較

### 案A: 動的R + 深ノード限定の検証探索

- `R = 3 + depth/4 + min(3, (static_eval - beta) / 200)`
- depth >= 12のnullカット時のみ、null無効で`depth - R`の
  通常探索を同窓で行い、それもbeta以上のときだけカット

### 案B: 動的Rのみ（検証なし）

実装最小。将棋のzugzwang稀少性に賭ける形。ただし入玉絡みの
終盤で読み抜けが混ざると、宣言勝ち周りの取りこぼしを
デバッグしにくい。

### 案C: SF完全形（nmpMinPlyによるサブツリー全体のNMP禁止）

検証探索のサブツリーでNMPを無効化する追加状態が要る。
初回導入では過剰。案Aの検証探索は1段のみで簡潔に済ませる。

## Decision

案Aを採用する。1アイデア1ADRの単位として「NMPの信頼度を
評価差と検証で調整する」一括変更と捉える（IDEAS.mdでも1行）。

### 実装スケッチ（search.rs）

- リダクション式を変更:
  `let r = NMP_BASE_REDUCTION + depth / 4 + margin_term;`
  `margin_term = ((static_eval - beta) / 200).clamp(0, 3) as u32`
  （static_evalは補正後。ADR-0046の値をそのまま使う）
- 検証探索: nullカット（`v >= beta`）かつ`depth >= 12`のとき、
  同一plyで通常探索`search(depth - r, beta - 1, beta)`を実行
  （null moveせず、そのままの局面で。ADR-0050の除外手つき
  探索と同様、do_moveしない再帰）。検証中の再NMPは
  「直前がnull move」ガード（既存のprev==NULL条件があれば
  流用、なければ検証中フラグをplyスタックで渡す）で防ぐ
- 検証がbeta未満ならカットせず通常のムーブループへ進む
- 詰みスコアの扱い・fail-softの返し方は既存NMPを踏襲

初期定数（チューニングしない）: マージン単位200、
margin_term上限3、検証の発動depth 12。SF系の実績値。

### 検証

SPRTはADR-0028の既定条件。両エンジンに
`--option "EvalFile=data/halfkp_180M.hmwr.best"`。

## Consequences

- 大差局面の探索が浅くなり、優勢時の指し手が速く決まる。
  互角局面への影響は小さい（margin_term=0）
- 検証探索はdepth>=12限定なのでコストはごく小さいが、
  入玉形の読み抜けに対する保険になる
- 見直しトリガー: 案CのnmpMinPly方式は、検証探索の
  すり抜け（検証自体が別plyのNMPで刈られる）が疑われる
  局面が見つかったら検討する
