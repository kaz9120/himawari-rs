# 0253: 時間管理の定数を短い持ち時間へ合わせて縮める

- Status: proposed
- Date: 2026-11-03
- 関連ADR: [0021](0021-time-management.md), [0116](0116-g7-timeman.md), [0163](0163-sprt-hypothesis-choice.md)

## Context

時間管理の3つの定数は、floodgateのような秒単位の持ち時間を前提にしている。
最小思考時間2000ms、NetworkDelay2の取り置き1120ms、秒単位の切り上げである。

10+0.1では、これらが配分を支配する。開始局面から1局を指すと次のようになる（現行のmain）。

| 手 | 消費[ms] | 指す前の残り[ms] | 深さ |
|---|---|---|---|
| 1 | 2880 | 10000 | 29 |
| 3 | 1880 | 7220 | 30 |
| 7 | 1880 | 3660 | 27 |
| 9 | 760 | 1880 | 25 |
| 10以降 | 100 | 約1220 | 13〜19 |

**最初の5手で持ち時間の9割を使い、残りの約1.2秒は最後まで使わない**。
勝敗を決める中終盤の全手が100msになる。

[ADR-0116](0116-g7-timeman.md)はこの問題を測定条件の限界と捉え、そのSPRTに限って
`MinimumThinkingTime=1 RoundUpToFullSecond=false` を指定した。この指定は既定の
起動条件に入らなかったので、現在のSPRTは上の配分で走っている。

指定を戻すだけでは、短い持ち時間で指す実機の問題が残る。

## 選択肢と比較

### 案A: SPRTの条件へオプションを戻す

エンジンは変わらない。実機で短い持ち時間を指すと同じ問題が起きる。

### 案B: 既定のオプション値を下げる

floodgateの安全余白まで一緒に減る。300+10の切れ負け（Issue #545）が怖い。

### 案C: 定数を1手の配分と残り時間で頭打ちにする（採用）

持ち時間が短いときだけ縮む。floodgateの300+10では常に定数のままで動く。

## Decision

案Cを採る。`avail` を1手の配分（`残り/残り想定手数 + 秒読み + 加算`）として、
秒読みなしの持ち時間で次のように頭打ちにする。

| 定数 | 頭打ち |
|---|---|
| 最小思考時間 | `avail / 5` |
| NetworkDelay | `avail / 4` |
| NetworkDelay2 | `max(残り / 8, 50ms)` |
| 秒単位の切り上げ | `avail < 5000ms` なら行わない |

floodgateの300+10は `avail` も残りも常に10秒以上なので、4つとも変わらない。
秒読みは毎手使い切る方式で、秒単位の時計を前提にするので触らない。

### 合格の条件

- Eloの判定: 既定条件のSPRT。+10以上を見込むので elo1=10 と宣言する。根拠は
  オプションだけを変えた同じバイナリの予備対局で18勝1分3敗だったこと
- Elo以外の条件: 切れ負けが1%以下。300+10で4定数が変わらないことを単体テストで保つ
- 採否: 両方を満たしたときだけ入れる

固定ノードの探索は時間管理を通らないので、探索木は変わらない。機能検証は飛ばす。

### 事前登録

- H1で切れ負けが1%以下なら入れる。以後のSPRTは全手に時間を配った条件で走る
- H0なら、中盤の配分が足りない可能性を疑い、`avail` の分母を見直す
- 切れ負けが1%を超えたら、`RESERVE_MIN_MS` を上げて測り直す

## Consequences

- 以後のSPRTの深さが中終盤で深くなる。過去のSPRTのEloとは条件が異なる
- 1局の所要時間は変わらない見込み。持ち時間の総量が同じだからである
- 秒未満の持ち時間を実際のネットワーク越しに指すと、取り置きが遅延より小さくなる
  場面がある。残り9秒未満の切れ負けに限られ、従来も残り1.2秒未満では余白がなかった
