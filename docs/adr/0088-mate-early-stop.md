# 0088: 勝ちの詰みを見つけたら反復深化を打ち切る

- Status: proposed
- Date: 2026-07-28
- 関連ADR: [0021](0021-time-management.md), [0059](0059-easy-move-scaling.md), [0086](0086-search-observability.md)

## Context

反復深化の終了条件は3つしかない。`stop` フラグ、時間切れ、ノード数上限で
ある。探索結果は見ていない。

```rust
if self.stopped() || self.tm.over_total(scale) {
    break;
}
if self.limits.nodes > 0 && self.nodes >= self.limits.nodes {
    break;
}
```

このため、詰みを見つけても時間いっぱい読み続ける。オーナーが実戦の
`info` を見て「終盤で深さ127まで回っている」と気づいた（2026-07-28）。
`MAX_PLY - 1` まで行き、その間ずっと結論は同じ詰みスコアである。

無駄なのは時間である。floodgateの負け11局はすべて長手数で、終盤10手の
消費が7〜9秒まで落ちていた（RESULTS.md）。詰みを読み切った局面で数秒を
捨てるのは、この負け筋を直接悪化させる。

## 選択肢と比較

### 案A: 勝ちの詰みを見つけたら打ち切る

反復深化ループの末尾で、そのイテレーションのスコアが勝ちの詰み圏なら
`break` する。

反復深化なので、より短い詰みがあれば浅い周で見つかっている。深さ d の
周で `mate_in(n)` を得たとき n ≤ d であり、`mate_in(m)`（m < n）が
存在するなら深さ m の周で見つかっていたはずである。したがって手数を
損なわない。

詰まされる側（`mated_in`）は打ち切らない。深く読めば、より長く粘る手が
見つかる可能性がある。相手が間違える余地を残すのは実戦的な利益になる。

MultiPV>1（検討モード）では打ち切らない。全ラインを見せる用途だからで
ある。

### 案B: 詰みが複数回のイテレーションで安定してから打ち切る

1周だけでは置換表の汚染で誤った詰みを見る可能性がある、という懸念への
対処。2周連続で同じ詰みスコアを得てから止める。

本エンジンの詰みスコアは `mate_in` / `mated_in` をply補正付きでTTへ
出し入れしており（ADR-0024）、詰みの誤検出は既知の問題になっていない。
安定を待つ分だけ時間を捨てる。まず案Aで入れ、誤検出が観測されたら
案Bへ移る。

### 案C: 打ち切らない

現状維持。深く読み続けても最善手は変わらないので、棋力への直接の害は
ないという立場。

害は時間である。切れ負けのfloodgateでは、終盤で数秒を捨てるたびに
その後の局面で読む時間が減る。

## Decision

案Aを採る。

```rust
// 勝ちの詰みを見つけたら打ち切る。詰まされる側は続ける
if self.multi_pv == 1 && last_score >= VALUE_MATE_IN_MAX_PLY {
    break;
}
```

置く場所は反復深化ループの末尾、時間切れ判定の直前とする。その周の
`info` は出し切ってから止めるため、GUIから見て報告が欠けることはない。

`last_score` はMultiPVの1本目のスコアで、`multi_pv == 1` の条件と
合わせて「対局時の最善手のスコア」を指す。

## 機能検証（2026-07-28）

1手詰めの局面（`4k4/9/9/5N3/9/9/9/9/4K4 b G 1`）を `go movetime 3000` で
読ませ、最後のinfo行を比べた。

| | 深さ | seldepth | ノード数 | 最善手 |
|---|---|---|---|---|
| 変更前 | 127 | 127 | 10,853 | G*5b |
| 変更後 | 1 | 2 | 143 | G*5b |

深さ127まで回り、同じ結論を126回出し直していた。打ち切りにより探索量が
1/76になる。最善手とスコア（mate 1）は変わらない。

`scripts/verify-feature.sh` の4局面は詰みのない中盤局面で、ノード数は
変わらない（打ち切り条件に入らない）。この変更が効くのは詰みを読み切った
局面に限られ、通常の探索には影響しない。

### 棋力には寄与しない

SPRTにはかけない。この変更は勝率を動かさないと考えるためである
（2026-07-28オーナー判断）。

詰みを読み切った局面は、すでに勝ちが確定している。そこから浮いた時間が
回る先は、詰み手順の中の局面だけである。その各局面でも同じ詰みを読み切って
即指しするため、時間を必要としない。「勝負を分ける局面へ時間が回る」
という経路がない。

当初はSPRTで測る前提で起草した。詰み局面の時間節約が終盤全体の持ち時間に
効くと考えたためだが、節約した時間の行き先を追うと勝負のついた局面に
しか届かない。[CLAUDE.md](../../CLAUDE.md)の判断（バイナリが変わるか、
棋力が変わるか）では「その他」に当たる。

残る利益は挙動の正しさである。同じ結論を126回出し直すのは無駄で、
`info` の見え方も実態と合わない。時間切れ負けの理論上のリスクも減る。

## Consequences

詰みを読み切った局面で時間を使わなくなる。

ponderには影響しない。相手番の思考は `infinite` 相当で走り、詰みを
見つけても `ponderhit` / `stop` を待つ設計（ADR-0033）は変えていない。
`iterate` を抜けても、bestmoveの出力は上位が制御する。

詰み局面での `depth` の伸びが止まるため、`info` の見え方が変わる。
深さ127まで並んでいたものが、詰み手数付近で止まる。

`scripts/verify-feature.sh` の検証局面に詰み局面が入っていないことが
分かった。今回は手で1手詰めを測った。詰み絡みの変更を今後も測るなら、
検証局面へ詰み局面を足す価値がある（[ADR-0074](0074-feature-verification.md)）。
