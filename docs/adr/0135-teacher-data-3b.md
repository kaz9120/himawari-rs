# 0135: 教師データを29.9億局面へ広げる

- Status: proposed
- Date: 2026-08-04
- 関連ADR: [0028](0028-pruning-extensions.md), [0065](0065-large-scale-dataloader.md), [0127](0127-net-shape-bench.md), [0131](0131-frozen-ft-light-head.md), [0134](0134-head-capacity.md), [0136](0136-quiet-teacher-positions.md), [0140](0140-king-line-features.md), [0144](0144-selfplay-teacher-loop.md)

## Context

**データ量が、いまも唯一効いている手段である**（ROADMAP「FTの表現学習を確立する」）。
容量を増やす3方向（FT拡大・後段拡大・利き教師）は2026-08-04までにすべて塞がった。
一方でhao_depth9には未取得の第3グループが残っている。

| グループ | 状態 | 規模 |
|---|---|---|
| start_time=1695340981 / 1695606850 | 取得済み | 254ファイル・77GB・約19.9億局面 |
| start_time=1695872823 | **未取得** | 127ファイル・約39GB・約10億局面 |

現行ネット（valid loss 0.49513）は19.9億で学習した。29.9億へ広げる操作は、
学習器・アーキテクチャ・レシピを一切変えずに実行できる。

懸念は逓減である。ROADMAPの制約節は「容量律速のうちは伸びが逓減する」と
書いている。ただし[ADR-0134](0134-head-capacity.md)の測定で、後段の容量は
上下どちらへ振っても0.001未満しか動かないと分かった。**いまの律速が容量なら
データ増は効かず、データなら効く。** どちらかはこの学習1回で判別できる。

## 選択肢と比較

### 案A: 第3グループを取得し、29.9億で学習し直す

追加コストはダウンロード39GBと学習1回。レシピは実績値
（epochs=1、batch=16384、peak_lr=1e-3、cosine decay、λ=0.7）をそのまま使う。

### 案B: 別系統のデータセットを混ぜる

分布の偏りは緩和できるが、ライセンス確認と品質検証が要る。
同一系統の増量で効くかをまず見るべきで、順序が後になる。

### 案C: 現状維持で他の軸に投資する

データ増が効くかどうかの判別材料を放棄する。学習1回（数時間）で
得られる情報に対して、節約が小さすぎる。

## Decision

案Aを採る。手順は4段になる。

1. 第3グループ127ファイルを取得する。[DATASETS.md](../DATASETS.md)の
   curl例はstart_time=1695340981の24ファイル分なので、start_timeを
   1695872823へ、thread_indexを000..126へ書き換えて回す
2. `psv shuffle` で全体を混ぜ、`train_2990M.psv` を作る。検証集合は
   現行のvalid_385M.psv（thread_index=023）を据え置き、lossの
   比較可能性を保つ
3. 実績レシピで学習し、valid lossを現行（0.49513）と比べる
4. lossが下がったらSPRT既定条件（[ADR-0028](0028-pruning-extensions.md)）にかける

**Elo見込みの根拠は、データ量の寄与の実績である。** 局面数を1.8億から
19.9億へ11倍にしたとき、valid lossは0.51727から0.49513へ0.0221下がった。
log-linear仮定で1.5倍の外挿は−0.004前後になり、判別限界0.001
（[ADR-0127](0127-net-shape-bench.md)）の4倍にあたる。学習系の再実行で
取り込める点も確認済みである（FT差し替えは棋力中立、
[ADR-0131](0131-frozen-ft-light-head.md)）。

**撤退ライン。** valid lossの改善が判別限界0.001
（[ADR-0127](0127-net-shape-bench.md)）を下回ったらSPRTへ進まず、
「データも律速でない」ことの測定として記録する。その場合、残る手段は
特徴設計（[ADR-0140](0140-king-line-features.md)）と教師信号の変更
（[ADR-0136](0136-quiet-teacher-positions.md)）に絞られる。

## Consequences

- ストレージが39GB（生データ）+ 加工分だけ増える
- 学習1回の時間が1.5倍になる。以後の再学習もこのデータが基準になる
- 効いた場合、hao_depth9は使い切りになる。次の増量は自前生成
  （[ADR-0144](0144-selfplay-teacher-loop.md)）しかない
- 効かなかった場合も、容量とデータのどちらが律速かという
  長く曖昧だった問いに答えが出る
