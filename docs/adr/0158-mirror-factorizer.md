# 0158: 学習時だけ左右ミラーの仮想特徴を併用する

- Status: rejected
- Date: 2026-08-12
- 関連ADR: [0034](0034-nnue-architecture.md), [0066](0066-halfkp-factorizer.md), [0135](0135-teacher-data-3b.md), [0157](0157-king-mirror-buckets.md)

## Context

[ADR-0157](0157-king-mirror-buckets.md)で、現行ネットが左右対称性を獲得して
いないことを実測した。実戦局面（ply24、3万件）で局面と左右反転像の評価が
平均91ずれる一方、評価値そのものの規模は50しかない。**序盤では信号より
ノイズのほうが大きい。**

ただし玉位置を45バケットへ畳む案は棄却した。負けた理由は2つある。

- **NPSが1.53%落ちた。** 差分計算のたびにミラーの判定が乗る
- **自由度を失った。** 左右で違う戦型の区別ができなくなる。ノード数を
  揃えても−5.6 [−22.6, +11.3]で、勝ちに転じなかった

**対称性を獲得していない事実は残っている。** 畳まずにこれを使う道が
[ADR-0066](0066-halfkp-factorizer.md)のfactorizerにある（2026-08-12
オーナー提案。KPPの時代から使われてきた手である）。

## 選択肢と比較

### 案A: 何もしない

対称性は学習で近似させ続ける。上の1.0歩は残る。

### 案B: 左右ミラーの仮想特徴を並列に引く

[ADR-0066](0066-halfkp-factorizer.md)の仕組みをそのまま拡張する。学習時だけ、
左右を正規化した特徴を第3の因子として引く。

```
z = ft(idx) + ft_p(idx % FE_END) + ft_m(mirror(idx)) + bias
```

因子が3層になり、共有の粒度が階層をなす。

| 因子 | 次元 | 何を共有するか |
|---|---|---|
| `ft`（実特徴） | 125,388 | 共有しない（玉位置と駒の組ごと） |
| `ft_m`（ミラー、本ADR） | 69,660 | 左右対称な位置どうし |
| `ft_p`（駒単独、ADR-0066） | 1,548 | 玉位置をまたいだ駒の価値 |

- **推論は1ビットも変わらない。** 書き出し時に畳み込む（`folded_ft_weight`）。
  特徴数は125,388のままで、[ADR-0157](0157-king-mirror-buckets.md)が落とした
  NPSの1.53%は生じない
- **自由度が残る。** 対称な成分は `ft_m` が共有し、左右で違う戦型は `ft` 側
  が持てる。畳む案は非対称な情報を捨てていたが、因子なら事前分布として
  効かせるだけで済む
- **実効サンプルが増えるのは共有される成分だけ**である。玉が5筋の局面は
  自分自身へ写るので、45バケットのうち9は共有相手を持たない

畳み込みは3項の和になる。

```
W_final[k * FE_END + p] = W_real[k * FE_END + p] + W_mirror[mirror(k, p)] + W_virtual[p]
```

### 案C: 学習時のミラーデータ拡張

教師データに左右反転した局面を足す。[ADR-0157](0157-king-mirror-buckets.md)で
取り下げた案である。**案Bとは別物なので、ここで区別しておく。**

- データ拡張は損失側にサンプルを足すだけで、パラメータの共有は起きない。
  対称性は勾配の平均を通して間接的に入る
- 案Bはパラメータを構造的に共有する。対称成分と非対称成分が分離され、
  どちらもデータから決まる

**案Bのほうが強い。** 加えてデータ拡張は学習時間が倍になるが、案Bは因子を
1本引くだけなので増分が小さい。

## Decision

**案Bを採ったが、測定で覆って棄却した**（下の「測定」）。以下は着手時の判断である。

**案Bを採る。**

決め手は推論が変わらないことである。[ADR-0157](0157-king-mirror-buckets.md)は
「lossは良いが棋力が動かない」で終わったが、あのとき棋力を押し下げていた
要素（NPS −1.53%、自由度の喪失）は案Bでは生じない。**効かなければ何も
起きず、効けばそのまま乗る**構造になる。

[ADR-0066](0066-halfkp-factorizer.md)の因子は+28.1 Eloを出しており、機構
自体には実績がある。

### 実装

写像は「視点変換済みの玉位置と、その視点でのBonaPiece」に対して定義する。

1. 玉の筋が6〜9なら、玉と盤上駒の升をまとめて左右反転する
2. 玉バケットは5筋 × 9段 = 45。手駒は升を持たないので変わらない

変更は3か所になる。

| 場所 | 中身 |
|---|---|
| `core/bonapiece.rs` | 写像 `mirror_factor_index` と、その表を作る関数 |
| `py/lib.rs` | 表を学習側へ渡す |
| `training/model.py` | `ft_m` を足し、`transform` と `folded_ft_weight` を3項にする |

**Rustの推論側は触らない。** 写像は学習の因子を作るためだけに使う。
表は125,388要素のu32で、Python側では `long` のテンソル（1MB）になる。

### 検証

1. 書き出したネットが因子なしのときとファイル形式・次元で一致すること
2. 3億局面で学習し、`--factorized` 単独と比べる（valid loss）
3. **3億ネット同士の直接対局。lossの結果にかかわらず必ず行う**

**lossで足切りしない**（2026-08-12オーナー指摘）。下の測定で分かったとおり、
初期値のばらつきだけでvalid lossは0.00136動く。**0.001〜0.002規模の差では
判断できないので、lossが横ばいでも悪くても対局する。**

[ADR-0157](0157-king-mirror-buckets.md)には「lossは必要条件であって十分条件
ではない」と書いたが、ばらつきの規模が分かった今は**必要条件ですらない**が
正確である。lossが動かなくても棋力が動く可能性は残る。

判断は対局で決める。NPSは構造上変わらないので、確認だけして物差しには
使わない。

## 測定（2026-08-12）

### 1本目は不具合で無効になった

3億局面の1本目はvalid lossが0.00136**悪化**した。因子はゼロから始めるので、
最悪でも同等になるはずである。チェックポイントを開くと `ft_m` の重みが
全てゼロのままだった。原因は2つある。

**1. 最適化器への登録漏れ。** `train.py` の `ft_params` に `ft_m` を足して
いなかった。勾配は計算されるが更新されない。

**2. 乱数の消費順序。** `nn.EmbeddingBag` のコンストラクタも
`nn.init.uniform_` も同じ生成器を使う。`ft_m` を `_init_weights` より前で
作ると、**以降の層の初期値がすべてずれる。**

### 初期値だけが違う2本で、valid lossは0.00136動く

1本目は事実上「因子なしと同じモデルを、違う初期値で学習した」ものになって
いた（`ft_m` がゼロなら出力は因子なしと一致する）。**その差が0.00136ある。**

| 何が違うか | valid lossの差 |
|---|---|
| 初期値の系列だけ（本ADRの1本目） | **0.00136** |
| 参考: データを19.9億→29.9億（[ADR-0135](0135-teacher-data-3b.md)） | 0.00202（+24.8 Elo） |

**0.001規模のloss差は、初期値のばらつきと区別がつかない。** 今後、モデルの
構造を変える比較では、乱数の消費順序を揃えるか、種を変えて複数本引く必要が
ある。本ADRでは `ft_m` の生成を `_init_weights` の後ろへ移し、**因子の有無で
他の層の初期値が1ビットも変わらないこと**をテストで確かめてから測り直した。

### [ADR-0157](0157-king-mirror-buckets.md)の解釈を訂正する

同じ罠を[ADR-0157](0157-king-mirror-buckets.md)も踏んでいる。あちらは
`FT_IN` が125,388から69,660へ変わるので、`nn.EmbeddingBag` の乱数消費量が
変わり、**以降の層の初期値がすべて違っていた。**

したがって、あそこで得た「valid lossが0.00112良い」は**初期値のばらつきと
同じ規模で、改善と断定できない。** ただし棄却の結論は変わらない。対局は
時間制で−16.0 [−30.8, −1.2]、ノード数固定でも−5.6と測っており、そちらは
初期値の影響を受けない直接の比較である。

**訂正されるのは「lossは良いのに棋力が動かない」という読みのほうである。**
正しくは「**lossの差自体が誤差だった可能性が高く、棋力も動かなかった**」に
なる。lossを単独の足切りにしない運用の根拠としては、むしろ強くなった。

### 2本目: 因子は学習されたが、lossは悪化した

不具合を直して測り直した。今度は `ft_m` に重みが乗っている
（平均\|w\|=0.04156で、実特徴の0.04460と同規模）。初期値は因子の有無で
1ビットも変わらないので、**差は純粋に因子の効果である。**

| | ミラー因子 | `--factorized` のみ | 差 |
|---|---|---|---|
| 最終valid loss | 0.49762 | 0.49536 | **+0.00226** |
| 学習時間 | 4,844秒 | 3,082秒 | +57% |

**9地点すべてで悪化し、ばらつき（0.00136）より大きい。** 因子はゼロから
始まるので、最適化が理想的なら最悪でも同等になるはずである。悪化した以上、
因子の追加が学習そのものを歪めている。

原因は3つ考えられる。どれも未検証である。

- **実効的な学習率が上がる。** 3つの経路が同じ勾配を受け、和が出力に効く。
  同じlrでも1特徴あたりの更新量は増える。`ft_p` は1,548次元で影響が薄いが、
  `ft_m` は69,660次元と実特徴に近い規模なので効き方が違う
- **FTクリップとの干渉。** `clip_ft_weights` は畳み込み後に制約を掛け、
  超過分を実特徴から引く（[ADR-0138](0138-ft-i8-quantization.md)）。
  `ft_m` が育つほど実特徴が削られる
- **共有が強すぎる。** 対称成分を因子が引き受けることで、実特徴が
  非対称な情報を学ぶ余地を狭めている

### 対局でも負けた

lossの結果にかかわらず対局する方針に従って測った。**推論側は1行も変えて
いないので、同一バイナリで評価関数だけを差し替えた比較になる。**
[ADR-0157](0157-king-mirror-buckets.md)と違い速度差は混ざらない。

| 項目 | 値 |
|---|---|
| 条件 | `--tc 10+0.1 --concurrency 8 --adjudicate 2000,8`、elo0=0、elo1=5 |
| 対局数 | 836（418ペア） |
| W-D-L | +340 =19 -477 |
| Elo [95%CI] | **−57.5 [−81.0, −34.4]** |
| LLR | −2.23（H0側へ進行中、打ち切り） |

**lossの悪化（+0.00226）と方向が一致した。** 信頼区間はゼロから大きく離れて
いる。

## なぜ棄却するか

因子を足すと学習が壊れる。**理屈の上では起きないはずの現象である**
（`ft_m` をゼロに保てば因子なしと同一なので、最適化が理想的なら最悪でも
同等になる）。原因として最も疑わしいのはFTクリップとの干渉である。

```python
folded = ft + ft_m[table] + ft_p          # 畳み込み後
ft.weight.sub_(folded - folded.clamp(-1, 1))   # 超過分を「実特徴からだけ」引く
```

**因子は制約を受けず、実特徴だけが削られる。** これが毎ステップ走る。実測でも
`ft_m` の最大\|w\|が1.2263、`ft` が1.5959と、どちらも制約値1.0を超える一方で
`folded` は1.0に張り付いていた。**大きな値どうしが打ち消し合って和が収まって
いる**状態で、数値的に不健全である。`ft_p` は1,548次元で影響が出なかったが、
`ft_m` は69,660次元と実特徴に近い規模なので歪みが顕在化したと見ている。

**ただしこれ以上は追わない**（2026-08-12オーナー判断）。KPPの時代のミラーは
量子化制約下の学習ではなく、仕組みが違う。学習パイプライン全体の見直しも、
FT幅の拡大を優先して見送る。書き出し・量子化の経路は健全であることを
確認済みで（f32の0.49536に対しi8は0.49576、差0.00040）、他に壊れている
兆候は見つからなかった。

## Consequences

- 学習の1ステップに因子1本ぶんの引きと勾配が増える。`ft_p` と同じ規模なので
  所要は数%の増加にとどまる見込み
- 書き出したネットは従来と同じ形式で、既存のバイナリがそのまま読める。
  比較は同じ教師データからの学習同士で行う
- **mainへは入れない。** 実装はブランチ `feat-adr0158-mirror-factor` に残す
- [ADR-0157](0157-king-mirror-buckets.md)と合わせて、**左右対称性を入れる道は
  2方向とも塞がった。** 畳んでも（−16.0）因子にしても（−57.5）棋力は下がる。
  現行ネットが対称性を獲得していないことは事実だが、**それを直しても棋力は
  上がらない**
- 因子の追加が学習を歪める件は未解決のまま残す。**FTクリップ
  （[ADR-0138](0138-ft-i8-quantization.md)）と仮想特徴は相性が悪い**という
  仮説だけを記録しておく。将来ほかの因子を足すときに同じ罠を踏みうる
- **valid lossを足切りに使う運用をやめる。** 初期値のばらつきが0.00136ある
  以上、この規模の差を見ても何も分からない。lossは学習が壊れていないことの
  確認に使い、**採否は対局で決める。** 0.005を超える差（ばらつきの3倍以上）
  が出たときだけ、lossは方向の示唆として読める
- モデルの構造を変える比較では、**乱数の消費順序を揃える**。層を1つ足す
  だけで以降の初期値が全部ずれる。揃えられない場合は種を変えて複数本引き、
  ばらつきの幅を出してから比べる
