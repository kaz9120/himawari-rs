# 0160: 評価の精度が上がった前提で、棄却した参照追従を測り直す

- Status: proposed
- Date: 2026-08-13
- 関連ADR: [0075](0075-razoring-margin.md), [0096](0096-rfp-margin.md), [0109](0109-reference-parity.md), [0141](0141-singular-rate-calibration.md), [0143](0143-spsa-tuning.md), [0155](0155-reference-walkthrough.md), [0159](0159-ft-width-1024.md)

## Context

[ADR-0159](0159-ft-width-1024.md)でFT幅1024のネットを作った。教師29.9億で
学習し、現行ネットに対して**ノード数固定で+70.6 Elo [+49.2, +92.5]**
（H1採択）である。評価関数としての実力は明確に上がった。

ところが時間制では負ける。速度が0.709倍に落ちるためで、10+0.1で−21.0、
60+0.6でも同水準にとどまる。**評価関数単体では採択に届かない。**

そこで問いが変わる。**精度の高い評価関数を活かして、ほかに何をすれば
強くなるのか**（2026-08-13オーナー提起）。

### 評価の精度は「枝刈りを強める権利」を生む

futility・razoring・RFPはいずれも「静的評価とalpha/betaの距離」を
マージンで測る。**マージンの適正値は評価誤差の大きさで決まる。** 誤差が
小さくなれば、狭めても取りこぼさない。singular extensionも同じで、
延長の率が高いのは「TTの手が本当に良いか確信が持てない」ことの裏返しに
なる。

**本エンジンはこの権利をまだ行使していない。**

### 棄却した案は、ほとんどが参照追従だった

過去に棄却したADRを2つの軸で分けた。

| ADR | 内容 | 出自 | 評価精度への依存 |
|---|---|---|---|
| [0141](0141-singular-rate-calibration.md) | singular率を参照の設計点へ較正 | 参照追従 | **直撃** |
| [0096](0096-rfp-margin.md) | RFPのマージンと深さ上限 | 参照追従 | **直撃** |
| [0075](0075-razoring-margin.md) | razoringのマージンを2次式に | 参照追従 | **直撃** |
| [0105](0105-ttpv-propagation.md) | ttPvの伝播をRFPの安全弁に | 参照追従 | あり |
| [0084](0084-lmr-cutnode.md) | LMRにcutNode項 | 参照追従 | あり |
| [0155](0155-reference-walkthrough.md)群1〜3 | 参照への構造整列 | 参照追従 | 薄い |
| [0093](0093-mate1ply-in-search.md) | 1手詰めを探索へ組み込む | 参照追従 | なし |
| [0058](0058-iteration-start-cutoff.md) | 反復深化の次イテレーション抑止 | 参照追従 | なし（時間管理） |
| [0048](0048-capture-history.md)・[0097](0097-capture-history.md) | capture history | 独自 | なし（手順序） |
| [0055](0055-lmr-terms.md) | LMRの条件項 | 独自 | あり |
| [0056](0056-tt-prefetch.md) | TTのprefetch | 独自 | なし（速度） |

**独自の案は3件だけで、残りはすべて参照実装とのギャップである。**

### 3件が同じ形で棄却されている

上の表で「参照追従 × 評価精度に直撃」が重なるのは3件で、**どれも同じ結末**を
たどった。参照の値へ寄せると弱くなり、本エンジンの保守的な値が残った。

- [ADR-0141](0141-singular-rate-calibration.md): 率を参照の設計点（10〜20%）へ
  下げる較正だけで**−81.2 Elo**。「本エンジンでは高い率が効いている」
- [ADR-0096](0096-rfp-margin.md): 参照の式（`76×depth − 152×improving`、
  depth < 15）へ揃える案を棄却
- [ADR-0075](0075-razoring-margin.md): 参照の式へ揃える案を機能検証で棄却。
  **前提の誤りも記録されている。** 本エンジンの300は参照の808〜3256より
  10.9倍「保守的」なのではなく、10.9倍「緩い」設定だった

[ADR-0155](0155-reference-walkthrough.md)は、この繰り返しを一般化して
こう結論している。

> 参照の構造と定数は**参照の評価関数と生態系**で最適化されており、自前ネットの
> 本エンジンには独自の平衡がある。

**評価関数を差し替えれば、その平衡は動く。**

## 選択肢と比較

### 案A: 探索パラメータを直接調整する

マージンを一律にスケールする、あるいは[ADR-0143](0143-spsa-tuning.md)のSPSAで
自動探索する。網羅的だが、SPSAは設計だけで未実装（ランナーがない）。探索空間も
広く、当たりの方向が分からないまま回すことになる。

### 案B: 棄却した参照追従を測り直す

**過去の投資を回収する。** 実装は当時のADRとコミットに残っており、定数を戻す
だけで再現できるものが多い。何より**仮説が具体的**である。「参照の値は参照の
評価関数に最適化されている。評価が近づけば参照の値が効く」という筋が、3件の
棄却すべてを一本で説明する。

外れたときも収穫がある。「評価を良くしても参照の平衡には寄らない」なら、
本エンジンの探索は評価関数と独立に最適化されていることになり、
[ADR-0155](0155-reference-walkthrough.md)の結論がさらに強くなる。

### 案C: 何もしない

FT1024を寝かせる。ノード数固定の+70.6は測定済みなので、将来の速度改善で
採算が合ったときに再訪する。ただし**その速度改善の当てがない。**

## Decision

**案Bを採る**（2026-08-13オーナー判断。「パラメータ調整を頑張るというよりも、
こういった棄却案を拾い上げるイメージ」）。

### 測定の設計

**ベースもFT1024にする。**

| | ベース | 候補 |
|---|---|---|
| 評価関数 | `ft1024_2990M_q1` | `ft1024_2990M_q1` |
| 探索 | 現行 | 棄却案を戻したもの |

**速度が共通なので、純粋に「評価が良くなったとき、その案が効くか」だけが
出る。** FT256との比較を混ぜると速度の代償（−103.2 Elo相当）が入り、読めなく
なる。

### 順序

1. **[ADR-0141](0141-singular-rate-calibration.md)（singular率の較正）。**
   −81.2という最大の負け幅は、裏を返せば**最も評価精度に依存している証拠**で
   ある。反転すれば効果も大きい。仮説が正しいかどうかがいちばん鮮明に出る
2. **[ADR-0096](0096-rfp-margin.md)（RFPのマージン）。** RFPは静的評価とbetaを
   直接比べるので、精度が直撃する
3. **[ADR-0075](0075-razoring-margin.md)（razoringのマージン）。** 同上

各案とも機能検証（ノード数が変わることの確認、[ADR-0074](0074-feature-verification.md)）を
先に行い、既定条件のSPRTで測る。

### 採否の考え方

**この3件は単体では棋力向上の候補にならない。** FT1024を採るかどうかと束に
なっている。順序はこうなる。

1. 本ADRの3件をFT1024上で測り、効くものを拾う
2. 拾った探索の変更を載せた状態で、**FT1024が現行構成に勝てるか**を測り直す
3. 勝てば[ADR-0159](0159-ft-width-1024.md)とまとめて採択する

## Consequences

- 3件とも効かなければ、**評価関数の精度と探索の平衡は独立**という結論になる。
  [ADR-0155](0155-reference-walkthrough.md)の「本エンジンには独自の平衡がある」が
  評価関数を跨いで成り立つことになり、参照追従の線は完全に閉じる
- 効いた場合、**評価関数を差し替えるたびに探索を追従させる必要が出る。**
  そのときは[ADR-0143](0143-spsa-tuning.md)のSPSAを実装して自動化する価値が
  生まれる。本ADRはその前段の粗い探索にあたる
- FT1024のネット（`ft1024_2990M_q1`、128.4MB）と、FT256との比較用バイナリは
  残す。[ADR-0159](0159-ft-width-1024.md)の測定を再現できる状態を保つ
- 本ADRで拾えなかった棄却案（[0105](0105-ttpv-propagation.md)・
  [0084](0084-lmr-cutnode.md)・[0055](0055-lmr-terms.md)）は第2群として残す。
  第1群の結果を見てから優先度を決める
