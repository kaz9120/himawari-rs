# 0145: 前世代のネットから継続学習で積む

- Status: proposed
- Date: 2026-08-08
- 関連ADR: [0130](0130-freeze-ft.md), [0135](0135-teacher-data-3b.md), [0136](0136-quiet-teacher-positions.md), [0138](0138-ft-i8-quantization.md), [0144](0144-selfplay-teacher-loop.md)

## Context

教師データの供給が尽きた。hao_depth9は使い切りで、次の増量は自前生成
（[ADR-0144](0144-selfplay-teacher-loop.md)）しかない。

**自前生成の運用は、1回に作れる量が限られる。** 生成は探索を回すので、
29.9億を一度に作り直すのは現実的でない。少しずつ作って積み上げる形に
なる。そこで問いが立つ。**前世代のネットから追加学習して強くできるか。**
できるなら、生成した分だけ段階的に良くできる。毎回29.9億で学習し直す
必要があるなら、自前生成の運用そのものが重くなる。

道具は揃っている。`train.py --init-net` は既存の `.hmwr` を初期値に読む
（[ADR-0130](0130-freeze-ft.md)で追加）。

## 選択肢と比較

### 案A: 量子化済みの `.hmwr` から始める

改修が要らない。ただし読むのは量子化を経た重みなので、f32の状態は
戻らない。世代を重ねるほど丸め誤差が乗る。

### 案B: f32のチェックポイントから重みだけ読む

`training/checkpoints/` の `.pt` には f32 の重みがある。既存の `--resume`
はstep・optimizer state・schedulerまで復元するので、そのままでは使えない。
**「同じ学習の中断再開」と「新しいデータで続ける」は別物である。**
重みだけ読む経路を足す必要がある。

### 案C: 毎回全データで学習し直す

正確だが、29.9億で8.5時間かかる。生成した分を足すたびにこれを払う。

## Decision

**案Aで効果の有無を先に測る。** 改修なしで測れるので、効くと分かってから
案Bを作るほうが安い。

## 工程1の実測（2026-08-08）

**824万局面の追加では、量子化を通した後に改善がほぼ残らない。**

`start_time=1695340981` の `thread_index=023` は検証用に取り分けてあり、
学習に一度も使っていない。先頭20万局面が `valid_385M.psv` で、残り
8,237,990局面が未見である。これを静止化し（置換率37.53%）、
`halfkp_2990M_q1` から追加学習した。503ステップ、1条件85秒で終わる。

| 条件 | valid loss（f32） | valid loss（量子化後） | ベースとの差 |
|---|---|---|---|
| ベース `halfkp_2990M_q1` | — | 0.49116 | — |
| `--peak-lr 1e-5` | 0.49093 | **0.49116** | 0 |
| `--peak-lr 1e-4` | 0.49087 | 0.49108 | −0.00008 |
| `--peak-lr 3e-4` | 0.49132 | 0.49151 | +0.00035 |

**lr 1e-5 の改善は量子化の丸め幅に埋もれた。** f32では0.00023下がって
いるのに、`.hmwr` へ書き出して読み直すとベースと同じ値になる。重みの
変化が i8/i16 の解像度より小さい。[ADR-0138](0138-ft-i8-quantization.md)で
FT重みをi8にした分、この床は上がっている。

lr 3e-4 は悪化した。前世代の表現が壊れる。**使える幅は 1e-5 から 1e-4 の
あいだにある。**

### 必要な規模は1回あたり約1億局面である

[ADR-0136](0136-quiet-teacher-positions.md)が得た換算を当てる。valid loss
0.00279 の差が +13.9 Elo だったので、0.00008 は **+0.4 Elo 相当**である。
SPRTの解像度（既定条件で±10 Elo前後）には遠く届かない。

SPRTのelo1（+5 Elo）を超えるには valid loss で約0.001 の改善が要る。824万で
0.00008 なら、**1回あたり約1億局面**が目安になる。29.9億に対して3.3%である。

**継続学習の効率そのものは悪くない。** [ADR-0135](0135-teacher-data-3b.md)は
19.9億から29.9億への50%増で0.00202を得た。単純に局面あたりへ均すと、824万の
追加で期待できるのは0.00002程度になる。実測の0.00008はその4倍で、少ない
データを既存の表現へ足すほうが効率が良いことを示す。**問題は効率ではなく
規模である。**

### 測っていないこと

**この検証集合は独立でない。** `valid_385M.psv` と追加データは同じ023
ファイルから来ており、同じ対局の別局面が混ざっている見込みが高い。lrの
大小を比べる用途では全条件が同じ影響を受けるので使えるが、絶対値は
信用できない。

SPRTは回していない。+0.4 Elo相当を既定条件で測っても判定に至らないため
である。**測れない大きさだと分かったことが、この工程の結果である。**

## Consequences

- **自前生成（[ADR-0144](0144-selfplay-teacher-loop.md)）の1回あたりの
  目標量は1億局面になる。** これを下回る単位で積んでも、量子化を通した
  後に残らない
- 案B（f32チェックポイントから重みだけ読む）は、規模の目処が立ってから
  作る。1億局面を回すなら量子化の丸めは相対的に小さくなるが、世代を
  重ねる運用では効いてくる
- lrは 1e-5 から 1e-4 のあいだで探す。3e-4 は前世代の表現を壊す
- **量子化の解像度が改善の下限を決める。** 学習側の小さな改善は、
  書き出しの丸めで消える。f32で測った差をそのまま棋力の見込みへ
  換算してはいけない
