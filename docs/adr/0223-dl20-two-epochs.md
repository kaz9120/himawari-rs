# 0223: dlshogiラベルの20億を2周し、1周のネットとSPRTで比べる

- Status: accepted（2周が1周に+25.7 Elo。並べ替えを当ててnet-v13として配布）
- Date: 2026-10-04
- 関連ADR: [0214](0214-epochs-bench.md), [0217](0217-sprt-pass-cap.md), [0218](0218-main-two-epochs.md), [0219](0219-relabel-2b-in-place.md), [0222](0222-promote-dl20.md)

## Context

[ADR-0222](0222-promote-dl20.md)で、dlshogiのラベルの20億を1周学習した
`dl20_7860M` が現行になった。ラベルを付け直した局面は20億しかなく、残りの
58.5億の付け直しはAWSの準備を待っている（2026-10-04）。それまでの間、
手元の20億から棋力を引き出す手を打つ。

3億局面の小規模学習では、同じデータの2周が1周より+32.2 [+17.7, +46.9]
強かった（[ADR-0214](0214-epochs-bench.md)）。新規の3億を足すと+70.4で、
繰り返しは新規データに劣る。ただ、今は新規データが無い。選択肢は
「2周するか、しないか」である。

[ADR-0218](0218-main-two-epochs.md)は同じ問いを、tanukiのラベルの78.5億で
測る設計だった。`train_7860M_q1` の先頭20億がdlshogiのラベルへ書き換わった
ので、その設計のままでは2種のラベルが混ざる。前提が崩れたので、本ADRで
置き換える。

2周の効きは規模で薄まる見込みがある。3億の+32.2には、cosineの減衰が2倍の
長さになった追加の最適化の効きも含まれる。20億×1周は122,071ステップで、
3億より最適化が進んでいる。どれだけ残るかは測るまで分からない。

## 仮説

**dlshogiのラベルの20億を2周したネットは、1周のネットより強い**。

## 測定の設計

### 動かす変数

エポック数だけを1から2にする。cosineの減衰は2周分の長さになる
（`total_steps = epochs × steps_per_epoch`）。2周目は1周目と別の順で回る。

### 固定するもの

- データは `dl20_7860M` と同じ。`train_7860M_q1` の先頭20億
  （`--positions 2000000000`）、兄弟群 `rank_tanuki_210M`、
  検証 `valid_tanuki_dl430_q1`
- レシピも同じ。batch 16384、peak_lr 1e-3、λ0.7、seed 0、FTクリップ1.0。
  ゼロから学習する
- 比較は1周の `dl20_7860M` 対2周の `dl20_2ep`。同一ビルドのネット差し替え
  （`hmwr sprt net`）で、どちらも並べ替えを施さない
- SPRTは既定（elo0=0、elo1=5、10+0.1）。規模で薄まる見込みがあり、+10以上を
  見込む根拠がない。上限は10,000ペア（[ADR-0217](0217-sprt-pass-cap.md)）

### 解釈の事前登録

| 判定 | 読み | 次の一手 |
|---|---|---|
| H1 | 20億でも繰り返しが効く | 2周のネットを並べ替え、現行 `dl20_7860M` と比べて切り替える。付け直しを増やした後の本学習も2周を標準にする |
| H0 | 繰り返しは20億の規模で消え、害になる | 打ち切る。20億は1周のまま。棋力は付け直しの追加と局面の選び方から取る |
| 見送り（10,000ペアで判定に至らず） | 効きは±2.5の中で、学習25時間に見合わない | H0と同じく打ち切る |

## 実行

specは `experiments/adr0223-dl20-two-epochs.toml` で、学習1本とSPRT1本である。
学習は約25時間を見込む（1周の12.4時間の倍）。落ちたら同じコマンドで
エポック内の位置から続く。

## 測定（2026-10-05）

| 項目 | 値 |
|---|---|
| baseline → candidate | dl20_7860M → dl20_2ep（どちらも並べ替えなし） |
| 対局数 | 2,998（1,499ペア） |
| W-D-L | +1559 =101 -1338 |
| Elo [95%CI] | **+25.7 [+13.4, +38.0]** |
| LLR | +2.95 |
| 判定 | H1（elo0=0 elo1=5） |

終局理由は裁定2,843・千日手100・詰み51・宣言3・最大手数1だった。

| ネット | ステップ | 最終の検証損失 | 所要 |
|---|---|---|---|
| dl20_7860M（1周） | 122,071 | 0.45135 | 12.4時間 |
| dl20_2ep（2周） | 244,142 | 0.44994 | 約25時間 |

### 読み

事前登録の表のH1に当たる。20億の規模でも、同じデータの繰り返しが効いた。
3億の+32.2（[ADR-0214](0214-epochs-bench.md)）に近い大きさが残っている。
cosineの減衰が2倍の長さになった効きと、繰り返しそのものの効きは分けていない。

### 次の一手

- `dl20_2ep` に並べ替え（[ADR-0195](0195-reorder-on-late-positions.md)）を当て、
  `dl20_2ep_reorder.hmwr` を現行の評価関数にする。net-v13として配る。並べ替えは
  評価値を変えないことを `hmwr net reorder --apply` が確かめた（第1層の削減31.5%）
- 付け直しを増やした後の本学習も、2周を標準にする
- 3周目が効くかは、別のADRで測る。3億の測定台では2周までしか測っていない
