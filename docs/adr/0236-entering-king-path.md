# 0236: 玉の前進の余地を利きで測る指標を作り、探索と学習のどちらで使うかを測定で決める

- Status: proposed
- Date: 2026-10-17
- 関連ADR: [0229](0229-roadmap-visible-focus.md), [0030](0030-nyugyoku-declaration.md), [0198](0198-phase-indicator.md), [0191](0191-blindspot-benchmark.md), [0206](0206-entering-king-mix.md), [0228](0228-grow-labeled-pool.md), [0232](0232-effect-table-prototype.md)

## Context

[ADR-0229](0229-roadmap-visible-focus.md)は、注力と並行する改善を1つだけ置いた。
「入玉を点数で教える」で、宣言法の点数や宣言までの残りを学習の目標か入力に持たせる。
2028年からの24点法への変更にも備える。やり方は着手時にADRで決めることになっている。

本ADRはその材料を作る。入玉を教えるには、まず「この局面は入玉へ向かえるか」を
数で表す必要がある。今あるのは2つで、どちらも前進の余地を見ていない。

- 宣言の成否（`can_declare_win`、`crates/core/src/position.rs:805`）。成立したかどうかの2値で、
  手前の局面には何も言わない。探索は各ノードでこれを引く（`crates/engine/src/search.rs:939`）
- 玉の段（`king_adv`、`crates/tools/src/bin/psv.rs:1284-1286`）。玉が何段進んだかだけを見る。
  前に相手の利きが詰まっていても同じ値になる

利きの表（[ADR-0232](0232-effect-table-prototype.md)）があれば、玉が相手の利きの無い升だけを通って
敵陣へ届く最短の手数を、盤の上で数えられる。これを「入玉の距離」と呼ぶ。

### これまでに分かっていること

- 入玉の局面は教師に薄い（[ADR-0190](0190-selfplay-decided-thinning.md)の被覆測定で1.7%）。
  入玉5億を足した母集団 `pool1` で、現行に+5.9だった（[ADR-0228](0228-grow-labeled-pool.md)）
- floodgateの崩壊局面に入玉はほとんど無い。盲点ベンチの候補は521件のうち4件だった
  （[ADR-0191](0191-blindspot-benchmark.md)）。実戦で入玉が負けの原因になっている証拠は出ていない
- 進行度の指標の測定（[ADR-0198](0198-phase-indicator.md)）では、`king_adv` で切っても
  評価の系統誤差は当てはめノイズの数倍しか減らなかった

## 選択肢と比較

指標の使い道は3つある。どれも入口は同じ指標なので、先に指標が効く場所を測る。

### 案A: 探索で使う

入玉の距離が短い局面で、玉を前へ進める手の枝刈りを控える。あるいは入玉の距離が
縮む手を並べ替えで前に出す。表があれば安い。
ただ、実戦で入玉が問題になっている証拠が無い。対局の効きは、入玉が起きる対局の割合に比例して薄まる。

### 案B: 評価関数の入力に足す

入玉の距離を入力の特徴にする。段階3（利き数の入力）と同じ枠で扱える。
入力の追加は速度の代償が大きく（[ADR-0147](0147-effect-bucket-features.md)が整理した壁）、
単独で起こす価値があるかは、評価の誤差が入玉の距離で説明できるかで決まる。

### 案C: 学習の目標・重みに使う

教師局面ごとに入玉の距離と宣言の点数の不足を計算し、補助の目標か局面の重みに使う。
計算は学習の前処理で済み、探索の速度に響かない。表も要らない。
ADR-0229の「宣言までの残り」をそのまま形にできる。

## Decision

**指標を作り、評価の誤差を指標で切って測ってから、案B・案Cのどちらへ進むかを決める**。
案Aは今のところ起こさない。実戦で入玉が問題になっている証拠が無く、対局で効きが見えにくいからである。

決め手は、案B・案Cの成否が同じ1つの事実に懸かっていることである。
現行の評価関数が入玉の局面で外れ、その外れが入玉の距離で説明できるか。
説明できなければ、入力に足しても目標に足しても、教えるものが無い。

### 指標の定義

`psv phase` の指標の列（`psv.rs:1220-1231`）に2本を足す。

| 指標 | 定義 |
|---|---|
| `entry_dist` | 手番側の玉が、相手の利きの無い升と空き升（自分の駒がいない升）だけを通って敵陣3段に入る最短の手数。相手の応手は考えない。届かなければ9、すでに敵陣なら0 |
| `decl_short` | 手番側の宣言の点数の不足（27点法、先手28・後手27）。敵陣の駒10枚の条件の不足も1枚1点で足す。成立していれば0 |

`entry_dist` は81升の上の幅優先探索で、相手の利きの有無を升ごとに1回ずつ引く。前処理なので
`attackers_to` で求める。24点法への変更は `decl_short` の閾値だけで吸収できる。

### 測定の設計（実験の規律の4点）

1. 仮説: **現行の評価関数の系統誤差は、`entry_dist` で切ると `king_adv` で切るより大きく減る**
2. 動かす変数: クラス分けに使う指標だけ（`entry_dist`・`decl_short`・既存の `king_adv`）
3. 固定するもの: 評価関数（`hmwr/config.py` の `EVAL_FILE`）、測定集合、λ=0.7、クラス数4。
   補正の容量（出力のアフィン2パラメータ）と、乱数分割20回のノイズフロアの取り方も固定する。
   ADR-0198の第1測定と同じ手順にする
4. 事前登録: 下の表

測定集合は2つにする。

- 主: `data/train/valid_tanuki_dl430_q1.psv`（学習に使っていない20万局面、dlshogiのラベル）
- 副: `data/train/pool1.psv` の先頭100万局面。入玉の局面が約2割混ざる。
  学習に使った局面なので、順位の確認だけに使う

主の集合は入玉の局面が少ない。`entry_dist` が3以下の局面が2,000件に満たなければ、
主の結果は判断に使わず、副の順位だけを参考にする。そのときは、学習に使っていない入玉の局面の
検証集合を作るところから始める（下の表の3行目）。

| 結果 | 読み方 | 次の一手 |
|---|---|---|
| `entry_dist` のΔLが、主の集合でノイズフロアの3倍以上、かつ `king_adv` の1.5倍以上 | 評価は入玉の距離で外れている | 案C（学習の目標・重み）を小規模学習のADRで起こす。入力に足す案Bは、段階3の利き数の入力の設計へ材料として渡す |
| どちらかを満たさない | 入玉の距離は、評価の外れを説明しない | 案B・案Cは起こさない。ADR-0229の並行する改善は、宣言の点数（`decl_short`）を勝敗ラベルの補正に使う案へ絞り直す |
| 主の集合の入玉の局面が2,000件未満 | 測定集合が足りない | 入玉5億の生データから、`pool1` に入っていない局面でdlshogiのラベルを付けた検証集合を作る。作り方は `hmwr data` の付け直しと台帳（ADR-0228）で決まる |

`decl_short` は同じ表で並べて記録し、採否には使わない。宣言の点数は24点法への備えとして
どの案でも要る。効きの大小を問わず、実装へ残す。

### 計測の手順

指標の追加は `psv phase` の変更で、探索を変えない。ブランチ `chore-adr0236-entry-dist` で入れる。

```
hmwr queue pause
hmwr diag phase data/train/valid_tanuki_dl430_q1.psv
hmwr diag phase data/train/pool1.psv --limit 1000000
hmwr queue resume
```

TSVは `data/profile/phase-<名前>.tsv` に残る。表は本ADRの追記へ貼る。

### 合格の条件

本ADRはSPRTにかけない。測定のADRで、上の表のどの行に落ちたかで次のADRが決まる。
次のADRの対立仮説は、そのADRの着手時に決める。学習の変更なら既定（elo0=0、elo1=5）を基本にする。
小規模学習で+10以上を見込める根拠が出たら、elo1=10を選ぶ。

## 前提条件: ADR-0232が合格しない場合

本ADRは表に依存しない。指標は学習の前処理で `attackers_to` から求める。探索の速度にも響かない。

表が要るのは案A（探索で使う）だけである。案Aを起こすのは、実戦で入玉が負けの原因になっている
証拠が出たときに限る。そのときADR-0232の結果を見て、表引きか都度計算かを決める。

## Consequences

- `psv phase` の指標が12本になる。ADR-0198の10本と同じ道具で測れる
- 入玉の距離は「相手の応手を考えない」近似である。大駒の利きで道が開閉する局面では外れる。
  外れ方は、上の測定で `entry_dist` が誤差を説明できるかに含まれる
- 宣言の点数の計算は `can_declare_win` と同じ規則を使う。24点法のモードを足すとき
  （索引のバックログ「宣言勝ちの24点法対応」）、`decl_short` も同じ切り替えに乗せる
- 見直しのトリガーは、floodgateで入玉の絡む負けが出たときである。そのとき案Aを起こす
