# 0225: 付け直し済みの20億から重複を除き、2周で学習して現行と比べる

- Status: accepted（重複除去した20億の2周が現行に+22.8 Elo。切り替えは対話セッションが行う）
- Date: 2026-10-06
- 関連ADR: [0214](0214-epochs-bench.md), [0217](0217-sprt-pass-cap.md), [0219](0219-relabel-2b-in-place.md), [0223](0223-dl20-two-epochs.md), [0224](0224-selection-bench.md)

## Context

[ADR-0224](0224-selection-bench.md)で、付け直し済みの20億から1億を選ぶとき、
重複の除去が統制に+27.3 [+12.8, +42.0]で勝った。異なる局面が7.67%増えただけに
しては大きい。

現行の評価関数は、同じ20億を2周した `dl20_2ep` である（[ADR-0223](0223-dl20-two-epochs.md)）。
20億の重複率は1億より高い。先頭1億で7.67%、先頭5億で10.53%で、20億では13%前後と
見込む。1億で効いた介入を、現行の学習データそのものへ当てる。

## 仮説

**付け直し済みの20億から重複を除き、2周で学習したネットは、現行 `dl20_2ep` より強い**。

## 測定の設計

### 動かす変数

学習データから重複を除くかどうかだけを動かす。重複除去は `train_7860M_q1` の
先頭20億（dlshogiのラベルの区間）だけを読み、盤面が初めて現れた局面を入力の順に残す。

ステップ数は連動して減る。重複を除くと局面数が約13%減り、同じ2周でもステップが
その分減る。付け直し済みの局面は20億しかないので、局面数は揃えられない。
本ADRは「実際に使うレシピどうし」の比較として読む。重複除去の側が少ないステップで
勝てば、控えめな側の結論になる。負けたときは、重複の効きとステップ数の減少を
分けられない。

### 固定するもの

- 学習のレシピは `dl20_2ep` と同じ。2周、batch 16384、peak_lr 1e-3、λ0.7、seed 0、
  FTクリップ1.0。兄弟群 `rank_tanuki_210M`、検証 `valid_tanuki_dl430_q1`。ゼロから学習する
- 比較は `dl20_2ep` 対 `dl20u_2ep`。同一ビルドのネット差し替え（`hmwr sprt net`）で、
  どちらも並べ替えを施さない
- SPRTは既定（elo0=0、elo1=5、10+0.1）。1億の+27.3が20億でどれだけ残るかは
  分からないので、+10以上を見込む根拠にしない。上限は10,000ペア
  （[ADR-0217](0217-sprt-pass-cap.md)）

### 解釈の事前登録

| 判定 | 読み | 次の一手 |
|---|---|---|
| H1 | 重複除去は20億の2周でも効く | 並べ替えを当てて現行と切り替える。以後の学習データは重複除去を標準にする |
| H0 | 20億では、ステップ数の減少が重複除去の効きを上回るか、効きが規模で消える | 切り替えない。付け直しの入力の重複除去は、費用を削る目的でADR-0224のとおり続ける |
| 見送り（10,000ペアで判定に至らず） | 効きは±2.5の中にある | H0と同じ扱い |

## 測定（2026-10-06〜07）

手順は予定どおり走った。再開は起きず、SPRTは3,478局でH1に達した。
見込みから2点ずれた。重複除去は20億のうち1,709,817,583局面を残し、
除いた割合は14.5%だった（見込みは13%前後）。学習の所要は28.4時間で、
見込みの約22時間より長い。ステップは208,718で、`dl20_2ep` の244,142
（[ADR-0223](0223-dl20-two-epochs.md)）より少ない。表は `hmwr exp report` の
出力である。

### 読み

判定はH1で、事前登録の「H1」の行に当たる。重複除去は20億の2周でも効く。
重複除去の側はステップが約15%少なく、少ないステップで勝った。測定の設計で
書いたとおり、控えめな側の結論になる。

### 次の一手

事前登録の行のとおりにする。

- `dl20u_2ep` に並べ替え（[ADR-0195](0195-reorder-on-late-positions.md)）を当て、
  現行の評価関数と切り替える
- 以後の学習データは重複除去を標準にする

## Decision

**仮説を採る**。付け直し済みの20億から重複を除いて2周したネットは、現行
`dl20_2ep` に+22.8 [+11.5, +34.2]で勝った。採用の操作（並べ替えと評価関数の
切り替え）は対話セッションが行う。

## 実行

specは `experiments/adr0225-dedup-20b.toml` である。重複除去（約70GBの書き出し）、
学習（2周で約22時間）、SPRT1本を順に走らせる。重複除去のハッシュ表は、20億を読むと
30〜38GBのメモリを使う見込みである（1億の実測は最大2.4GB）。重複を除いたpsvは、
以後の学習の土台として残す。

## 昇格（2026-10-07）

`dl20u_2ep` に並べ替えを当てた（第1層の削減31.0%）。`hmwr net reorder --apply` が、
固定深さのノード数・評価値・最善手が前後で一致することを確かめた。
`dl20u_2ep_reorder.hmwr` をnet-v14として配り、`hmwr/config.py` の `EVAL_FILE` と
配布物のPGOのネットを切り替えた。
