# 0089: 探索改善の選定基準を3軸で置く

- Status: accepted
- Date: 2026-07-28
- 関連ADR: [0074](0074-feature-verification.md), [0084](0084-lmr-cutnode.md), [0028](0028-pruning-extensions.md)

## Context

次に何を実装するかの選び方が言語化されていなかった。実際には
[ROADMAPの候補](../ROADMAP.md#候補)の候補表から「やねうら王との機能差分が大きいもの」
「他の案の土台になるもの」を選んでいた。

この選び方は[ADR-0084](0084-lmr-cutnode.md)で失敗した。LMRのcutNode項を
「リダクションを強める唯一の大項で、他の弱める項の前提になる」という
構造的な理由で選んだが、**それ単独で強くなる仮説を持っていなかった**。
912局を使って -1.1 Eloの中立だった。

機能差分は「やってないこと」のリストであって、「効くこと」のリストでは
ない。移植元で効いているのは、その周りの機能がすべて揃った状態での話で
ある。

オーナーが2026-07-28に、棋力への寄与を考えるための仮説を3つ示した。
これを選定の軸として採用する。

## Decision

候補は次の3軸のどれに乗るかで評価する。どの軸にも乗らない候補は、
棋力向上として着手しない（機能の作り込みとしては別に扱う）。

### 軸1: 速度

同じ探索木を読むなら、速いほうが強い。

**この軸の価値は副作用がないことにある**。探索木が変わらないので、
読み抜けも評価の歪みも増えない。純粋な上積みになる。測定も対局を
使わずNPSで直接できる。現状は約1.2M nps（M4、1スレッド、NNUE込み、
初期局面）。

期待値は対数で効く。速度2倍でおよそ +50〜70 Elo というのがチェス・将棋を
通じた経験則で、10%なら +7〜10 Elo になる。一発は大きくないが、
副作用なしの +10 Elo は十分に価値がある。

避けるのは、1%を追う作業に時間を溶かすことである（2026-07-28オーナー
判断）。プロファイルは取る。突出した箇所が見つかれば直す。局所的な
最適化もいずれ必要になる。優先順位の問題であって、否定ではない。

FT重みのi8量子化はこの軸に**入らない**。重みの精度が落ちれば評価値が
変わり、探索木も変わる。速度と評価精度のトレードオフであり、NPSの利得と
評価精度の損の両方を測る必要がある。軸1の「副作用なし」には当たらない。

該当する候補: 差分計算・データ構造・メモリアクセスの改善など、探索の
出力が1ビットも変わらないもの。プロファイルで突出した箇所の個別対処。

### 軸2: ノード効率

同じPVに到達するなら、ノード数の少ないほうが深く読める。

枝刈りとオーダリングがここに入る。「同じPVを作れるか」が条件で、
PVが変わる枝刈りは軸2ではなく賭けになる（下の危険度を参照）。

該当する候補: lmrDepth基準の枝刈り、SEEベースの枝刈り、
オーダリングの改善、historyの精度向上。

### 軸3: 終盤の正確さ

互角の探索でも、詰む詰まないを正確に判断するほうが強い。

終盤は評価関数の精度が落ちる領域で、探索で補う必要がある。詰みの
判定は評価関数を介さず勝敗が確定する。

該当する候補: df-pn詰み探索、mate1plyの探索組み込み、
入玉宣言まわりの精度。

### 枝刈りの危険度

軸2の候補は、危険度でグラデーションを持つ。危険とは「本来読むべき手を
読まずに捨てる確率」である。安全な順に並べる。

| 危険度 | 内容 | 本エンジンの実装状況 |
|---|---|---|
| なし（等価） | 置換表カット（同深さ以上）、mate distance pruning、千日手判定 | 実装済み |
| 低 | SEEベースの枝刈り（駒損が静的に確定する手を捨てる） | **未実装**（quiet SEE・capture SEEの2件） |
| 低 | 静止探索のfutility（取る駒の価値を足しても届かない） | 実装済み（ADR-0077） |
| 中 | LMR（削って外れたら読み直す） | 実装済み。再探索条件は `d < new_depth` のみ |
| 中 | razoring（qsearchへ降格、拾い直しがある） | 実装済み（ADR-0057） |
| 高 | RFP・futility（静的評価だけで捨てる） | 実装済み |
| 高 | LMP（手数で機械的に捨てる） | 実装済み |
| 高 | NMP（zugzwangで誤る） | 実装済み |
| 高 | ProbCut（浅い探索で高深度を代替） | 実装済み（ADR-0051, 0078） |

**危険度の低い枝刈りをすべて実装しきってはいない**。SEEベースの2件が
残っている。SEEは静的に正確で、駒損が確定する手を捨てるのは読み抜けの
リスクが小さい。危険度の高い枝刈りを増やす前に、こちらを先に埋める。

危険度が高い枝刈りは、マージンや条件で危険度を調整できる。同じ機能でも
設定次第で位置が変わる。

## Consequences

候補を選ぶとき、ADRのContextに「どの軸に乗るか」と「単独で効く仮説」を
書く。書けない候補は着手しない。[ADR-0084](0084-lmr-cutnode.md)は
「他の項の前提になる」としか書けておらず、この基準なら着手前に止まった。

移植元で効いている、という理由だけでは足りない。移植元は周辺機能が
揃った状態でそれを測っている。単独で入れたときに効く経路を、本エンジンの
実装に即して説明できる必要がある。

軸1（速度）の候補はSPRTの前にNPSで判定できる。対局を使わずに絞り込める
ため、探索リソースの使い方として効率がよい。探索木が変わらないことを
機能検証（[ADR-0074](0074-feature-verification.md)）で確かめれば、
ノード数の完全一致が副作用のなさの証明になる。

[ROADMAPの候補](../ROADMAP.md#候補)の候補表は節ごとに分かれているが、軸との対応は
この文書を正とする。表を軸で並べ替えることはしない。1つの候補が複数の軸に
またがることがあるためである（例: eval hashは軸1と軸2の両方）。
