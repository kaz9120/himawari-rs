# 0108: ライセンスをMITからGPLv3へ変更する

- Status: accepted
- Date: 2026-07-30
- 関連ADR: [0074](0074-feature-verification.md), [0109](0109-reference-parity.md)

## Context

探索部を参照実装（やねうら王）へ本格的に追従させる方針を決めた
（[ADR-0109](0109-reference-parity.md)）。その実行を、現行のライセンスが
制約している。

本リポジトリはMIT、やねうら王とStockfishはGPLv3である。MITのまま
GPLv3の実装を取り込むことはできない。そのため今までは
[ADR-0074](0074-feature-verification.md)の運用で、係数と技法を仕様として
抽出し、独立に書き直してきた。

この回り道には2つの損がある。第1に、忠実さが落ちる。条件式の順序や
細部の扱いは、仕様の要約からは復元できない。移植したつもりで別物が
できる。第2に、遅い。5,940行の探索部に対して本エンジンの探索部は
1,432行で、この差を仕様の言い換えで埋めるのは現実的でない。

そもそも仕様として抽出する運用自体が、線引きの曖昧な領域にある。
定数と条件式をそのまま借りている以上、参照実装の表現に依存している
可能性は残る。曖昧さを抱えたまま移植の規模を上げるのは筋が悪い。

オーナーが2026-07-30に、ライセンスをGPLv3へ揃える案を示した。
Stockfishを起点にコンピュータ将棋の主要な実装がGPLv3で連なっており、
文化として揃えるのも一手だという判断である。

前提条件は揃っている。コミット443件のうち442件が単独の著作権者に
よるもので、残る1件はrelease-pleaseの自動更新である。依存クレートは
pyo3・numpy・rayon・criterionの4つで、いずれもMITまたはApache-2.0の
ためGPLv3と互換性がある。

## 選択肢と比較

### 案A: MITのまま、仕様として抽出する運用を続ける

現状の[ADR-0074](0074-feature-verification.md)の運用を維持する。

利点は、成果物を誰でも制約なく再利用できることである。欠点は上に
書いた2つの損をそのまま抱えることで、追従の規模を上げるほど大きく
なる。線引きの曖昧さも残る。

### 案B: GPL-3.0-or-laterへ変更する

参照実装と同じライセンスへ揃える。逐語的な移植ができるようになり、
仕様へ言い換える工程が消える。

欠点は不可逆であることと、MITとしての再利用ができなくなることである。

### 案C: デュアルライセンス（MIT OR GPL-3.0）

利用者が選べる形にする。ただしGPLv3のコードを取り込んだ時点でMIT側の
選択肢が成立しなくなる。追従を進める前提と両立しないため、検討の
対象にならない。

## Decision

案Bを採る。識別子は `GPL-3.0-or-later` とする。

決め手は、追従の忠実さを制約する要因がライセンスだけだという点にある。
参照実装の探索部との差は構造の水準にあり（[ADR-0109](0109-reference-parity.md)）、
仕様の要約を経由して埋めるには量も精度も足りない。ライセンスを揃えれば
この制約は消える。

「MITのほうが再利用されやすい」という反論は成り立つ。ただし本
プロジェクトの目標は2027年5月の選手権参加であり
（[ADR-0068](0068-sprt-driven-versioning.md)）、ライブラリとして
再利用されることではない。コンピュータ将棋の流通ではGPLv3が標準で、
揃えるほうがむしろ使いやすい。

### 適用範囲

リポジトリ内のすべてのソースを対象とする。Rustの5クレート、
`training/` のPyTorch学習器、`scripts/` のシェルスクリプトを含む。

`data/` の中身と配布物は対象外とする。学習済みネットと定跡はプログラムの
出力物であり、GPLはプログラムの出力へ及ばない。GitHub Releaseでの配布
条件（[ADR-0080](0080-net-release.md)・[ADR-0082](0082-book-release.md)）は
この決定では変更しない。ネットと定跡のライセンス表記は別途決める。

### 適用時期

この変更をマージしたコミット以降に適用する。既存のタグ（v0.13.7まで）は
MITのまま残る。過去のリリースは遡って変更できないし、その
必要もない。

### 帰属の表記

参照実装から移植したファイルと関数には、由来を書く。書くのは
「どのプロジェクトの、どのファイルに対応するか」である。GPLv3は
派生であることの明示を求めており、追従の記録としても役に立つ。

READMEに謝辞の節を設け、やねうら王とStockfishへの依存を明記する。

### Cargo.tomlの扱い

`Cargo.toml` の `license` フィールドを変更する。[CLAUDE.md](../../CLAUDE.md)は
`Cargo.toml` を触らないと定めているが、これはrelease-pleaseが管理する
`version` フィールドを指す規約である（[ADR-0071](0071-release-please.md)）。
`license` は管理対象外のため、この変更は規約と衝突しない。

## Consequences

参照実装のコードをそのまま持ち込めるようになる。[ADR-0109](0109-reference-parity.md)の
追従は、仕様の抽出ではなく移植として進められる。

**この決定は実質的に不可逆である**。GPLv3のコードを一度取り込めば、
以後MITへ戻すには取り込んだ部分をすべて捨てるしかない。ライセンスを
戻すトリガーは設けない。

MITとしての再利用を期待していた利用者には不利益が生じる。ただし現時点で
本リポジトリを依存に取っている外部プロジェクトは把握していない。

派生物を作る側には、ソースの開示義務が生じる。コンピュータ将棋では
やねうら王の派生が同じ条件で流通しており、実務上の障害にはならない。

`crates/py` はpyo3のextension-moduleで、Pythonから読み込まれる。この
モジュールを使う学習コードもGPLv3の対象になるが、いずれも自作のため
支障はない。

選手権への参加に制約は生じない。ライブラリの使用申告は必要だが、
これはライセンスの種類によらない義務である。
