# 0155: 参照実装との精緻ウォークスルーで見つけた乖離を群で修正する

- Status: rejected（群1〜3は−6.7で棄却。群4は性能改善として単独の候補へ。群5・6は行わない。下の「線を閉じた判断」）
- Date: 2026-08-11
- 関連ADR: [0026](0026-repetition.md), [0054](0054-qsearch-tt.md), [0074](0074-feature-verification.md), [0109](0109-reference-parity.md), [0125](0125-search-decomposition.md), [0153](0153-superior-repetition-root-gate.md)

## Context

ADR-0153（優等局面のroot跨ぎ）で「参照実装との無自覚な意味論の乖離」が
実害つきで見つかったのを受け、同種のバグを探す精緻ウォークスルーを行った
（2026-08-11オーナー指示）。参照はやねうら王2026-08-05 master。

体制は領域別の監査ワーカー5体である（探索本体・TT／枝刈り・history／
局面ルール／qsearch・評価配線／定数全数照合）。報告は相互に裏付けを取り、
監督が単独ソースの指摘2件をコードで直接確認した。

**名前付き定数・式は220項目超すべて一致していた**。ADR-0109の「参照の値を
そのまま使う」は守られている。乖離は「参照の分岐が丸ごと欠けている」型に
集中し、いずれもADRに記録がない（＝無自覚な欠落）。

## 見つかった乖離と修正群

群ごとに1PR・機能検証（ノード数が**変わる**ことの確認）・1SPRT。
番号は着手順（見込みの大きい順）。

### 群1: depth 0の入口（最重要・最ホット）

`search()` は `depth == 0` の判定が遅く、qsearchへ落ちる前にノード計数・
千日手判定・mate distance pruning・TT probe/カットを実行する。参照は
関数冒頭・全処理より前でqsearchへ渡す。3つの実害がある。

1. **history汚染**。TTカット時の更新bonusが `min(130×0−71, 1043) = −71` の
   負値になり、βカットを起こした手にマイナスを配る。depth 1の全子ノードが
   通る経路である
2. ノードの二重計上（search側とqsearch側で `nodes += 1`）。NPS・
   `go nodes`・引き分け値の揺らぎ位相がずれる
3. mate distance pruningがqsearchの窓を参照より狭める

修正: `depth == 0` の分岐を関数冒頭（計数より前）へ移す。

### 群2: TTの追従

| 欠落 | 参照の挙動 |
|---|---|
| TTカットの深さ条件が対称 | `ttValue > beta` のときは `ttDepth >= depth+1` を要求（fail high側に1段厳しく） |
| ノード種別の一致条件がない | `cutNode == (ttValue >= beta) \|\| depth > 5`。浅いノードで向きの合わないカットを拒む |
| TTミス時に静的評価を書かない | `DEPTH_UNSEARCHED`・手なしで書く。再訪時の `tt_hit` が立ち、RFP係数・1手詰め頻度・pawn history更新の前提になる |
| 詰みノード（合法手0）で何も書かない | `depth+6` で書き、fail-lowボーナスとttPv継承も行う |
| TT storeの同一キー上書き | 見送り時も指し手だけは更新する。`2*pv` の項。不等号が1ずれ |
| TT storeが空きスロットで走査打ち切り | クラスタ全走査でキー一致を先に探す。現状は浅い書き込みが深い記録を影で消せる |

### 群3: ムーブループの終端

| 欠落 | 参照の挙動 |
|---|---|
| fail high時のbestValue減衰 | `(bestValue*depth + beta) / (depth+1)`。TT store・correction historyもこの調整後の値を使う。qsearch側の同種の寄せは移植済みで、通常探索側だけ欠けた非対称 |
| 同値の手の確率的昇格 | `value == bestValue` かつ葉近傍かつ `nodes & 14 == 0` で入れ替える |

### 群4: 千日手の前計算追従（ADR-0026の置き換え）

ADR-0153が直したのは優等・劣等のroot跨ぎだけで、参照は通常のDraw・
連続王手Win/Loseも同じゲート（`repetition < ply`、例外は4回目の強制成立）に
通す。**1回の一致はルール上の引き分けではない**（ADR-0153の記述の訂正）。
さらに走査に16手キャップがなく（参照コメント「初手まで遡るとR40弱くなる」）、
200手級の対局では毎ノード約20KBのストライド走査になる性能バグを兼ねる。
相互連続王手でのWin/Lose優先順も参照と逆（手番側勝ち扱い＝危険側）。

修正: 参照のdo_move前計算方式（`repetition`・`repetition_times`・負値による
強制成立の表現・16手キャップ・種別変化時のDRAW降格・LOSE優先）へ追従する。

### 群5: rootの統合（構造、要測定）

`search_root` が独立関数で、rootでhistory・correction history・TT storeを
一切更新せず、root LMRもない（参照はrootで後続手を深く読む）。参照と同じく
`search` へ統合するのが本筋だが、変更が大きいので群1〜4の後に単独で扱う。

### 群6: 小物（1群にまとめて中立確認）

- `MaxMovesToDraw` の境界が1手早い
- `ply >= MAX_PLY` で引き分け値でなく生評価を返す（Stockfish側の分岐を
  写していた）
- `do_null_move` が `game_ply` を進める（参照は進めない）
- `pseudo_legal` にNormal生成の不成制限がない
- `sel_depth` が非PVも数える（表示のみ）

### 記録済み・対象外

- SEEのpin無視（ADR-0025。再訪候補として残す）
- singular多段延長（ADR-0114で棄却済み）
- qsearchのMultiPV分岐（ADR-0077）
- VALUE_SUPERIORのスケール差（ADR-0026。参照は評価値の上限=優等値で、
  本エンジンには28000〜31871の帯がある。実測レンジ確認のみTODO）
- SEEの最安駒順で馬・飛が参照と逆（本エンジンのほうが価値順に忠実。
  追従しない）

## 測定の記録と判断（2026-08-11〜12）

| 走行 | 対象 | 結果 |
|---|---|---|
| 1 | 群1単独 | 3542局 −3.7 [−14.9, +7.4]、LLR −0.97、停止基準で打ち切り |
| 2 | 群1+2+3の束 | 3030局 −6.7 [−18.7, +5.4]、LLR −1.21（H0側）、打ち切り |
| 3 | 群1の最小形（depth 0のTTカットで負のbonusを配らない、それだけ） | 6000局 −1.8 [−10.5, +6.9]、LLR −1.08、上限3000ペアで判定に至らず |

**最小形も棄却し、群1〜3の線を閉じる（2026-08-12）**。純粋な自傷に見える
−71のmalusですら、止めて利得が測れなかった。解釈: depth 0のTTカットで
罰される手は既にhistory上位にあり、−71は葉近傍の小さなノイズとして
実質無害だった。3走とも点推定が負側なのは偶然としても、正の証拠は
どこにもない。この探索は現在の平衡が最適である。

**群1〜3の整列は見送る（オーナー相談のうえ2026-08-12判断）**。「参照に
あるから正しい」は棋力の根拠にならない、が数字の言うことである。参照の
構造と定数は**参照の評価関数と生態系**で最適化されており、自前ネットの
本エンジンには独自の平衡がある。同じ結論は[ADR-0141](0141-singular-rate-calibration.md)
（singular率を参照の設計点へ較正して−81.2 Elo）で既に出ていた。乖離は
「無自覚なバグ」から「測定済みの意図的な乖離」へ変わったので、監査の
目的は達成している。

例外として、**束から自傷部分だけを最小形で切り出して測る**。depth 0の
TTカットで負のbonus（−71）をβカットの手へ配る更新だけを止める変更で、
これは参照でも本エンジンでも正当化できない純粋な自己傷害である。
入口の移動もTT整列も伴わない。結果はこの表へ追記する。

群4（千日手の前計算）は性能面の実測（16手キャップ）から入る価値が残る。
群5（root統合）・群6（小物）は、群1〜3の結果を踏まえ優先度を下げる。

## 測定の規律（ADR-0153の教訓）

- 各群とも機能検証でノード数が変わることを先に確認する
- SPRTは既定条件から始め、**1500ペア経過してLLRが±1.0の内側なら打ち切って
  判断へ進む**（漂う走行に半日使わない）。群1〜3は全ノード級の頻度なので
  既定条件で判定が出る見込み
- 判定に至らない場合の扱い（非劣性へ落とす・fix型で入れる・棄却）は
  各群のPRで根拠を添えて決め、このADRへ追記する

## Consequences

- 定数レベルの追従は完全と確認できた。残っていたのは構造の欠落で、
  今回の6群で参照との既知の乖離は「意図的なもの＋root統合」だけになる
- 群1のhistory汚染は参照にない自傷の修正なので、Eloの上積みがいちばん
  期待できる
- 群4はADR-0026の設計（1回一致で即Draw）を置き換える。ADR-0026と0153の
  該当記述はこのADRが上書きする

## 線を閉じた判断（2026-08-22）

参照実装への整列としては、このADRを閉じる。理由は2つある。

1. 群1〜3が3030局で−6.7となり、構造の整列に利得がないと分かった。
   参照の設計点へ寄せて弱くなった例は[ADR-0141](0141-singular-rate-calibration.md)
   （−81.2）に続いて2件目で、本エンジンには独自の平衡がある
2. SPSA（[ADR-0143](0143-spsa-tuning.md)）で探索定数を自前の評価関数へ
   再適合させ始めた（第1群26項目のうち24項目が動き、検収中）。定数レベル
   でも参照から離れていくので、以後の「参照と同じにする」は根拠にならない

群4（千日手判定のdo_move前計算化）だけは、参照整列ではなく性能バグの
解消として価値が残る。ROADMAPの候補へ単独の案として移した。群5・群6は
行わない。
