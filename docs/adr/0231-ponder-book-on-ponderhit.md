# 0231: ponder中は定跡を引かずに探索し、ponderhitで定跡を引く

- Status: accepted
- Date: 2026-10-17
- 関連ADR: [0119](0119-g10-book.md), [0117](0117-g8-ponder.md), [0063](0063-book-loader-and-mini-book.md), [0033](0033-ponder.md)

## Context

ponderする局面が定跡にあると、エンジンは `book hit` を出すだけで探索しなかった
（Issue #747、オーナー指摘）。`go` はponderかどうかに関係なく先に定跡を引き、
ヒットしたらbestmoveをUSI層に保留して、stopかponderhitを待っていた。

この挙動は[ADR-0119](0119-g10-book.md)（G10）で参照実装へ揃えて入れた。
参照実装の `search()` はponderでも定跡を通る（S:1115-1117）。

困るのは定跡区間の相手番である。ponder中に探索しないので、置換表もhistoryも
温まらない。定跡を抜けた最初の手は、相手番の思考を丸ごと失った状態で読み始める。
ponder中に探索しておけば、定跡を抜けた直後の置換表が温まる。

## 選択肢と比較

### 案A: 現状維持（ponder中も定跡を引く）

参照実装と同じ。定跡区間の相手番では何もしない。

### 案B: ponder中は探索し、ponderhitで定跡を引く

`go ponder` では定跡を引かずに探索し、ponderした局面を控える。ponderhitで
その局面を定跡で引く。ヒットしたら探索の結論を捨てて、定跡のbestmoveを出す。
ヒットしなければ従来どおり探索を続ける。ponderが外れたとき（stopのあと次のgo）も
従来どおりで、次のgoで定跡を引き直す。

## Decision

案Bを採る。

ponderhitのあとはどちらの方式でも定跡の手を指す。**指し手は変わらない**。
変わるのは定跡を抜けた直後の置換表とhistoryの温まり方だけで、副作用は無い。
このためオーナーの判断（2026-10-17）で、SPRTで測らずに入れる。測るなら
`--ponder-both` に定跡を付けた非劣性の検定になるが、指し手が同じである以上、
検定で得る情報が乏しい。

### 実装

USI層は `go ponder` の局面を控え、ponderhitで定跡を引く。ヒットしたら
`ThreadPool::abandon_ponder` を呼んでから定跡のbestmoveを出す。

`abandon_ponder` はponderの状態を `Abandoned` にし、stopを立て、探索の終了を
`wait_idle` で待つ。メインスレッドは `Abandoned` を見たら `conclude` を呼ばず、
bestmoveを出さない。終了を待ってから定跡の手を出すので、**1回のgoに対して
bestmoveは1本だけになる**。二重のbestmoveや、前の探索の結論が後から出る事故
（Issue #545の類型）を防ぐ。

捨てた探索では、goをまたぐ記憶（`MainMemory`）を探索前の値へ戻す。指したのは
定跡の手なので、この探索は時間管理が参照する「前回のgo」に当たらない。
戻しておけば、次のgoの時間配分は従来と同じ入力から決まる。

`go infinite` で定跡にヒットしたときは、従来どおり探索せずにbestmoveを保留する。

### 確かめたこと

`crates/usi/tests/ponder_book.rs` で、USIの対話を実際のバイナリへ流して固定した。
入力を一度に流してquitまで待つので、判定はマシンの速度に依存しない。

| 対話 | 確かめた出力 |
|---|---|
| 定跡にある局面で `go` | 探索せず定跡の手を1本 |
| 定跡にある局面で `go ponder` → `ponderhit` | 探索のinfoが出たうえで、定跡の手を1本 |
| 定跡にある局面で `go ponder` → `stop` | 定跡を引かず、探索の結論を1本 |
| 定跡にない局面で `go ponder` → `ponderhit` | 探索の結論を1本 |

ponderなしの `go` の探索は変わらない。`hmwr verify` で固定深さのノード数が
変更前後で全局面一致することを確かめた。

## Consequences

定跡区間の相手番でも探索するようになる。定跡を抜けた最初の手は、温まった
置換表から読み始める。

`BookIgnoreRate` と `BookRandomize` の乱数を引く時点が、go ponderからponderhitへ
ずれる。ponderが外れた回は定跡を引かないので、乱数を1回ぶん消費しなくなり、
以後に引かれる値の並びも変わる。既定値なら影響しない。`BookIgnoreRate` の既定は0で
乱数を引いても定跡を外さず、`BookRandomize` の既定はfalseで候補の先頭を採る。

ponder中の探索に計算資源を使う。定跡区間でも相手番に探索スレッドが動く。
対局機を他の処理と共有するときは、定跡区間でも相手番に負荷がかかる。

参照実装とは乖離する。定跡区間で読まないことに、本エンジンで成り立つ理由は
見当たらない。指し手が変わらないので、乖離の損は生じない。
