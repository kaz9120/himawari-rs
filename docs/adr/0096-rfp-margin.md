# 0096: reverse futilityのマージンと深さ上限を見直す

- Status: rejected
- Date: 2026-07-29
- 関連ADR: [0075](0075-razoring-margin.md), [0089](0089-improvement-criteria.md), [0028](0028-pruning-extensions.md), [0074](0074-feature-verification.md)

## Context

[ADR-0075](0075-razoring-margin.md)でrazoringのマージンを見直したとき、
4種の枝刈りについて本エンジンとやねうら王を並べた表を作った。そこで
**RFPだけが本エンジンの方が刈りにくい側にある**と分かっている。

| 枝刈り | 条件 | 本エンジン | やねうら王 | 刈りにくいのは |
|---|---|---|---|---|
| razoring | `static_eval < alpha - M` | 300 | 502+306d² | 本エンジン |
| RFP | `static_eval - M >= beta` | 120d | 76d（improving項で減る） | **やねうら王** |

razoringは向きを取り違えて棄却した（[ADR-0075](0075-razoring-margin.md)）。
RFPは表の時点で「次はここを見る」と書いてあった。

現状は次のとおりである。

```rust
const RFP_MAX_DEPTH: u32 = 6;
const RFP_MARGIN: Value = 120;
// static_eval - 120 * depth >= beta なら static_eval を返す
```

やねうら王は `76 * depth`、深さ上限は `depth < 15`、improvingのときは
マージンをさらに引く。返り値も静的評価そのままではなくβ寄りに寄せる。

[ADR-0089](0089-improvement-criteria.md)の軸2（ノード効率）に乗る。
単独で効く仮説は「本エンジンだけが刈りにくい設定になっており、他エンジンと
同じ水準へ寄せればノードが減る」である。実測の裏づけがある点が
[ADR-0084](0084-lmr-cutnode.md)（構造的な理由だけで着手して失敗）と違う。

## Decision

4点をまとめて変える。RFPの再設計として1つのSPRTで測る。

```
margin = 76 * depth - 152 * improving
depth <= 14（やねうら王の depth < 15）
static_eval - margin >= beta なら beta + (static_eval - beta) / 3 を返す
```

1. **マージンを 120 → 76**。depthあたりの額を下げ、刈りやすくする
2. **深さ上限を 6 → 14**。適用範囲を広げる
3. **improving項（-152）**。2手前より静的評価が上がっているなら読み抜けの
   危険が小さいと見て、さらに刈りやすくする。係数はやねうら王の
   improvingDeductionが `futilityMult * 2` である形に合わせ、76×2とした
4. **返り値を `beta + (static_eval - beta) / 3` へ**。`(2*beta + static_eval)/3`
   と等価である。静的評価をそのまま返すと、刈った枝の値を過大に見積もって
   上位ノードへ伝える

出典はやねうら王で、評価値は歩=90スケールで一致するため絶対値のまま
用いる（[ADR-0074](0074-feature-verification.md)）。

1項ずつ測らないのは[ADR-0084](0084-lmr-cutnode.md)の教訓による。マージンと
深さ上限と返り値は互いに釣り合う組で、片方だけ動かすと釣り合いが崩れる。

## 機能検証（2026-07-29）

`scripts/verify-feature.sh` で固定深さ13のノード数を比べた。

| 局面 | 変更前 | 変更後 | 変化 | 評価値 | 最善手 |
|---|---|---|---|---|---|
| 1 | 251,563 | 100,083 | **-60%** | 65 → 70 | 同じ |
| 2 | 189,125 | 55,910 | **-70%** | -92 → -165 | 同じ |
| 3 | 1,059,556 | 306,673 | **-71%** | 726 → 809 | 同じ |
| 4 | 211,527 | 69,916 | **-67%** | -95 → -145 | 同じ |

**4局面すべてで60%以上減り、最善手は変わらない。** ADR-0075の診断どおり、
本エンジンのRFPは刈りにくすぎた。

評価値の振れは大きい（局面2で-92→-165）。RFPは静的評価だけで枝を捨てる
危険度の高い枝刈りで、返り値もβ寄りに寄せるため、fail-softの値が粗くなる。
最善手が4局面とも変わらない点を根拠に、SPRTへ進む。

## SPRT結果（2026-07-29、打ち切り）

42局（21ペア）で **-139.4 Elo [-250.8, -50.3]**、LLR -0.38。開始直後から
大きく負け続けたため打ち切った。

## Decision（改訂）

**案を棄却する。** 前提が誤っていた。

### 比較の前提が成立していなかった

[ADR-0075](0075-razoring-margin.md)の表は、マージンの数値だけを並べて
「本エンジンだけが刈りにくい側にある」と読んだ。**条件を揃えていない。**

やねうら王のRFPには `!ss->ttPv`（過去にPVだったノードでは刈らない）が
付く。本エンジンはttPvをTTに保存しているが探索で読んでいない
（[ROADMAPの候補](../ROADMAP.md#候補)）。安全弁がない状態で、安全弁を前提にした
マージンへ寄せたことになる。

マージンの数値は、それを支える条件と組でしか意味を持たない。数値だけを
比べて「緩い・きつい」を判断してはいけない。

### 4項の分解（固定深さ11、mainを基準）

どの項が効いたかを個別に測った。

| 項 | 局面1 | 局面2 | 局面3 | 局面4 | 最善手 |
|---|---|---|---|---|---|
| マージン 120→76 | -47% | -16% | -78% | -34% | **2局面で変化** |
| 深さ上限 6→14 | +0% | -0% | -60% | -0% | 変化なし |
| improving項 -152 | -48% | -39% | -55% | -9% | **2局面で変化** |
| 返り値のβ寄せ | +12% | +2% | -66% | +14% | 変化なし |

**深さ上限の拡大はほぼ無害だった。** マージンが120のままなら、深さ7〜11で
`static_eval - 120*depth >= beta` はほとんど成立しない。適用範囲を広げても
発動しないためである。

**マージンとimproving項が刈りすぎている。** どちらも大きく削るうえ、
最善手を変えている。危険度「高」の枝刈り
（[ADR-0089](0089-improvement-criteria.md)）を緩めた結果、読み抜けが
起きている。

**返り値のβ寄せは最善手を変えない。** ノード数はむしろ増える。fail-softの
値が下がり、上位ノードで刈りにくくなるためである。値の精度は上がるので、
単独なら安全側の変更である。

## Consequences

RFPは現状（`120 * depth`、`depth <= 6`、返り値は静的評価）のままとする。

得られた知見は2つある。

1. **他エンジンとの数値比較は、条件を揃えないと意味がない。**
   [ADR-0075](0075-razoring-margin.md)の比較表は、この観点で作り直す
   必要がある。マージンの列だけでなく、それを支える条件（ttPv・cutNode・
   statScoreの有無）を併記する
2. **機能検証で最善手が変わる項は、読み抜けを疑う。** 今回は4項まとめた
   状態で「最善手は4局面とも同じ」だったが、分解すると2項で変わっていた。
   まとめて測ると個々の危険が隠れる

[ADR-0084](0084-lmr-cutnode.md)の「1項ずつではなく群として測る」と、
今回の「まとめると個々の危険が隠れる」は緊張関係にある。使い分けは、
**項が互いに釣り合う設計なら群で、独立に効くなら分けて**測る。RFPの4項は
釣り合う組だと考えたが、実際には独立に刈る量を増やす項の集まりだった。

返り値のβ寄せだけは単独で入れる余地がある。最善手を変えず、値の精度を
上げる。[ROADMAPの候補](../ROADMAP.md#候補)へ候補として残す。

## Consequences

ノード数が大幅に減る。同じ持ち時間でより深く読める。

読み抜けのリスクは上がる。RFPは[ADR-0089](0089-improvement-criteria.md)の
危険度分類で「高」に属し、静的評価だけで枝を捨てる。60〜70%も刈る量が
増えるため、H0だった場合はマージンを76と120の中間へ戻す方向で1調整=1SPRTを
行う。

深さ上限を14へ広げたことで、深いノードでもRFPが働く。correction history
（[ADR-0085](0085-correction-history-multi.md)）で静的評価の精度が上がって
いることが前提になる。両者は補完しあう。
