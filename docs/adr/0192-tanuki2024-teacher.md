# 0192: 教師データをtanuki- 2024の78.6億局面へ置き換える

- Status: accepted（既定SPRTで+43.2のH1。下の「測定」）
- Date: 2026-08-29
- 関連ADR: [0135](0135-teacher-data-3b.md), [0136](0136-quiet-teacher-positions.md), [0185](0185-sibling-ranking-loss.md), [0190](0190-selfplay-decided-thinning.md)

## Context

教師の増量はhao_depth9を使い切って止まっていた（[ADR-0135](0135-teacher-data-3b.md)）。
[nodchip/tanuki-.nnue-pytorch-2024-07-30.1](https://huggingface.co/datasets/nodchip/tanuki-.nnue-pytorch-2024-07-30.1)
はMITライセンスの生psvで、実測998ファイル・292.9GiB＝約78.6億局面ある。
生成は同名の2024年の評価関数によるdepth 9で、haoの生成元
（WCSC33のHao、2023年）より1年新しい同チームの系列になる。
AobaZeroの分布調査に出る「野田さんの80億」と同一物で、評価値の全域に
厚みを持つ形はオーナーが良形と判断している。

3億の測定台で教師の出どころだけを比べるA/B案もあったが、**オーナー判断で
省略し、全面移行を決めた**（2026-08-29、「80億の方が絶対に優秀なので
そちらを使いましょう」）。ラベル品質が未検証のまま移行するリスクは
この判断に含まれる。最終の検収は対局（既定SPRT）が担い、haoは
HuggingFaceに残るので、負けたら戻せる。

移行には利点が3つある。局面数が2.6倍になる。教師が単一の生成系に
揃い、エンジン間の評価値スケール差の混合問題が消える。ローカルの
hao系ファイルを最終的に置き換えるので、ディスクも単純になる。

## Decision

hao 29.9億の学習資産（現行ネットの初期値）はそのままに、次の本学習から
教師をtanuki 2024へ置き換える。

### 前処理パイプライン（空き356GBに収める）

| 段 | 操作 | ピーク時の占有 |
|---|---|---|
| 1 | 全998ファイルを取得（`hmwr data fetch --dataset tanuki2024`） | 生293GiB |
| 2 | 消費型の全体シャッフル。読み終えた入力から順に消す | 約293GiB＋端数 |
| 3 | シャッフル出力の先頭からランキング群を導出（約2億群・24GB、[ADR-0185](0185-sibling-ranking-loss.md)の本学習と同じ規模） | ＋24GB |
| 4 | 分割出力を1本ずつ静止化し、済んだ入力を消す | 約293GiB＋分割1本 |

段2と4に `psv shuffle` の入力消費と分割出力の拡張が要る（本ADRと同じ
ブランチで実装する）。検証集合は特定の1ファイルを学習から除いて
切り出す（haoの`valid_385M`と同じ流儀）。hao由来のvalidはテレメトリに
残す（[ADR-0150](0150-rootstrap-evaluation.md)の格下げを踏襲）。

### 学習と検収

- レシピは現行採択構成（対の積＋ランキング損失＋静止化）を変えず、
  データだけを置き換える。ゼロから1エポックの本学習で、45.3時間だった
  29.9億の実績から約5日を見込む
- 検収は既定SPRT。基準は現行ネット `rl_g1b_reorder` で、H1なら昇格する
- 読み方も先に固定する。H1なら移行成立。H0なら「量2.6倍でも
  ラベル品質の差を埋められない」が結論になり、haoへ戻して
  混合設計かラベル検証へ落とす

### 待ち時間と資源の割り当て

取得はネットワークだけ使うので常時流せる。静止化（約19時間）と学習は
CPU・GPUを使うので、走行中のSPRTと重ねない。

## 実行の記録

### 前処理の事故と復旧（2026-08-30）

初回の静止化は誤った条件で走った。チェーンのスクリプトが `psv quiet` を
直接呼び、`--max-plies` の指定を落としたため、既定の16手で静止化された
（採択構成は[ADR-0136](0136-quiet-teacher-positions.md)の1手）。part000〜
004の生データは消費済みで、誤設定の出力212GBだけが残った。

復旧はパイプラインの決定論に頼る。生データを再取得し、同じseedで
シャッフルすればバイト単位で同じ分割が再現される（先頭から導出した
ランキング群もそのまま有効）。再発防止として `psv quiet` の既定を
1手へ揃え、恒久策はチェーンのhmwrコマンド化（issue #412）に置く。

再走の静止化は `--jobs 6` の並列版で行う。並列出力はjobs固定で決定論
だが、TTを全レコードで引き継ぐ逐次とは0.063%のレコードで異なる
（2M局面の実測）。どの置換も正当なqsearch葉であり、教師の意味は
変わらない。hao（逐次で静止化）との厳密な同条件性はこの点だけ緩む。

## 測定（2026-09-02、既定SPRT）

| 項目 | 値 |
|---|---|
| 学習 | 78.54億×1エポック、479,372ステップ、50.6時間（等価高速化後の学習器、48kサンプル/秒） |
| 比較 | `rl_g1b_reorder` 対 `pairrank_7860M_q1_reorder`（同一ビルドのネット差し替え） |
| 対局数 | 1,682（841ペア） |
| W-D-L | +918 =54 -710 |
| Elo [95%CI] | **+43.2 [+26.9, +59.6]** |
| LLR | +3.00（**H1採択**） |

**移行成立**。841ペアの即決着で、効果量は教師分布の静止化（+35.8）を
超える。単一教師系の78.6億は、haoの29.9億に焼き込まれた資産の上からでも
大きく積み増した。

付随の観測を2つ記録する。盲点ベンチマーク（[ADR-0191](0191-blindspot-benchmark.md)）の
乖離は平均0.110で移行前の0.109から劣化なし。教師を総入れ替えしても
分布外の精度は保たれた。一方、ゼロ率0.95以上の活性次元は198から288へ
増えており、死んだ活性の問題（ROADMAP候補）は教師を変えても残る。

静止化後のtanuki教師の勝率分布は、互角圏に山を持つhao型だった
（40〜60%帯が38.8%、スパイク質量15.6%）。生の自己対局が持つ端の
突出は、静止化と勝率分布の変換でほぐれる。

## Consequences

- `data/raw/tanuki2024/` と加工後の約293GiBが常駐する。空きの余裕は
  約60GBに縮む。手狭になったらhao系ローカルファイル（111GB）を消す。
  再取得で戻せるので破壊的ではない
- 入玉データ（19.5GiB、取得済み）の混合は本移行の後に別途測る。
  単一教師系の利点を最初の測定で崩さないためである
- 学習損失は過去の系列と比較できなくなる（validの土俵が変わる）。
  採否は対局で決める方針（[ADR-0158](0158-mirror-factorizer.md)）の
  ままなので運用は変わらない
