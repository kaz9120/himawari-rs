# 0044: P7特徴量実験（玉ライン特徴・利き塔有無の比較）

- Status: accepted（2026-07-21オーナー承認）
- Date: 2026-07-21
- 関連ADR: [0034](0034-nnue-architecture.md), [0040](0040-training-infra-v2.md)

## Context

現在のNNUEは HalfKP（125K次元）+ 利き塔（800次元）の2塔構成
（ADR-0034）。利き塔は玉周辺5×5の利き数をone-hotで符号化し、
駒間相互作用（遮り・利きの重なり）を捉える。NPS低下は約40%。

P7では、利き塔のコスト対効果と代替特徴の可能性を検証する。

HalfKPは（玉位置, 駒種, 駒位置）の関数なので、単一駒に関する
情報は全て表現できる。HalfKPに含まれない情報は**複数駒の
相互作用**、たとえば「飛車と玉の間に遮り駒があるか」「ピン
されているか」「玉の逃げ道が塞がれているか」。

利き塔はこの相互作用を利き数として捉えるが、全計算が必要で
差分更新できない。差分計算可能で、かつ駒間相互作用を捉える
新特徴を設計する。

## Decision

3条件の比較実験を行い、P7の構造を決定する。

### 条件1: 純粋HalfKP（ベースライン）

利き塔を除去し、HalfKP 256×2 = 512次元のみで構成する。
隠れ層の入力は512次元に縮小（現在544）。

目的: 利き塔が何Elo分の価値を持つかを測る。NPS改善量も計測。

### 条件2: HalfKP + 玉ライン特徴（新提案）

利き塔の代わりに、各玉からの8方向の最近接駒情報を入れる。

設計: 手番視点の各玉（自玉・敵玉）について、8方向（上下左右
＋斜め4方向）のレイを走査し、最初に見つかった駒を特徴化する。

特徴インデックス:
```
index = king_id × 8 × N_PIECE_ENC
      + direction × N_PIECE_ENC
      + encode(is_friendly, piece_type, distance_bucket)
```

- king_id: 0=自玉, 1=敵玉
- direction: 8方向（手番視点で正規化）
- piece_encoding: 味方/相手(2) × 駒種(14) × 距離区分(4: 1, 2, 3-4, 5-8)
  + 空(駒なし=盤端到達) = 113
- 合計: 2 × 8 × 113 = 1,808次元

盤端到達（遮る駒なし）は「玉の逃げ道が開いている」「ラインが
空いている」という情報を符号化する。

この特徴が捉える情報:
- **ピン**: 玉方向の最近接駒が味方→その裏に敵飛角がいるか
  （直接は見えないが、学習で間接的に捉える）
- **飛車先の脅威**: 敵飛車が玉と同一筋にいて遮りが少ない
- **玉の開放度**: 盤端到達する方向が多い=逃げ道が広い
- **歩の盾**: 玉の前方に味方歩がいる=囲いが堅い

差分計算: 駒がsq_Aからsq_Bに移動したとき、各玉について
sq_A・sq_Bが属する方向（最大2方向×2玉=4方向）のレイだけを
再走査する。平均O(1)、最悪O(盤の辺長=9)。利き塔の全計算
（全駒の利きを再計算）より大幅に安い。

### 条件3: HalfKP + 利き塔（現行）

既存構成のまま。条件1・2との比較基準。

### 実験手順

1. 3条件それぞれで86Mデータ×1エポック（best step選択）を学習
2. best valid lossを比較
3. 条件1 vs 条件3のSPRTで利き塔の価値を計測
4. 条件2 vs 条件1のSPRTで玉ライン特徴の効果を計測
5. 条件2 vs 条件3のSPRTで代替の可否を判定

NPS計測: 条件1と条件2の推論NPSを計測し、コストを定量化する。
条件2の差分計算実装はP7の後半で行う（初回は全計算で棋力を
先に評価し、差分化は効果が確認されてから）。

### 実装

- 条件1: model.pyのef関連を除去するだけ
- 条件2: PyO3ブリッジに玉ライン特徴抽出を追加。Rustで
  レイ走査と特徴インデックス計算を実装
- 条件3: 変更なし（既存コード）

推論側（Rustエンジン）の変更は、条件2の効果が確認されてから
行う。学習実験はPyTorch側だけで完結する。

## Consequences

- 3条件の比較でP7の構造判断に必要なデータが揃う
- 利き塔の価値が定量化され、存廃の判断ができる
- 玉ライン特徴が利き塔以上のEloを出せば、差分計算化の
  投資が正当化される
- 玉ライン特徴は将来の差分計算実装（ADRバックログのA）と
  自然に接続する
- 実験は学習器側（Python+PyO3）のみで完結し、推論側の
  変更は効果確認後に行う
