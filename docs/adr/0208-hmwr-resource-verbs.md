# 0208: hmwrのコマンドを手順の固定から資源への操作へ切り直す

- Status: accepted（段取り1〜5を実装。league runとdata genはIssue #502・#509に残る）
- Date: 2026-09-17
- 関連ADR: [0149](0149-experiment-runner.md), [0175](0175-sprt-until-decision.md), [0180](0180-hmwr-cli-in-python.md), [0181](0181-agent-surface.md), [0128](0128-round-robin-league.md), [0168](0168-ft-dim-reorder.md), [0192](0192-tanuki2024-teacher.md)

## Context

CLAUDE.mdは「入口は `hmwr` コマンドである」と定めている
（[ADR-0180](0180-hmwr-cli-in-python.md)）。実験に関しては、そうなって
いなかった。

`data/logs/` に残る使い捨てのチェーンスクリプト13本（ADR-0200〜0206の
実験）が呼んだコマンドを数えた（2026-09-17）。

| 呼び先 | 回数 |
|---|---|
| `psv`（head 12、quiet 11、shuffle 7、rank 5、ほか7） | 42 |
| `selfplay` | 11 |
| `gensfen` | 3 |
| `makenet`・Pythonのヒアドキュメント | 2 |
| `hmwr`（`net train` 6、`sprt net` 1、`net reorder` 1、`net actdump` 1） | 9 |

**68回のうち `hmwr` を通ったのは9回（13%）である**。直接叩いた結果、既定値が
ずれた。`selfplay` の `--max-moves` はADR-0201のチェーンが320、ADR-0206の
チェーンが400だった。[ADR-0192](0192-tanuki2024-teacher.md)のmax-plies事故と
同じ型である。

原因はコマンドの切り方にある。`hmwr` はADRのたびに「その時の手順」を
1コマンドへ固めて増えてきた。

- 実験で毎回使う部品が載っていない。`hmwr data` は `fetch` と `quiet` の
  2つで、shuffle・head・rank・混合がない。固定ペア数の対局もない
- 1本のADRでしか使わなかった診断が正規のサブコマンドになっている。
  `hmwr net` の9個のうち3個（`rank`・`dead`・`phase`）が該当する
- 対局の入口が4つに割れている。`sprt run`・`sprt net`・`league run`・
  `selfplay` の直接実行である。`sprt net` はSPRTの判定で止まる。固定ペア数を
  指し切る指定・開始局面集・時間オッズを受けないので、チェーンの対局は
  11回すべてが `selfplay` を直接叩いた
- 対象の指し方が揃っていない。`sprt run` は名前を取り、`data quiet` と
  `net train --data` はパスを取り、`league run` は出力先のパスを取る

手順は次の実験で少し変わる。固めたコマンドは合わなくなり、部品を直接叩く。
土台（名前の検証とログの置き場の `paths.py`、dry-runと終了コードの
`proc.py`）は健全で、直すのはコマンド体系である。

オーナーからも「アドホックなコマンドが増えていそうで心配」と指摘があった
（2026-09-17）。実験をキューで無人実行する計画があり、その前提は実験が
`hmwr` のコマンドだけで書けることである。コマンド体系を直さずにキューを載せると、
アドホックさごと固めてしまう。

## 選択肢と比較

### 案A: 足りないコマンドをその都度足す

`hmwr match` や `hmwr data mix` を、要るときが来たら足す。着手は軽い。
しかし増え方の規則がないので、同じ理由でまた手順が固まる。診断の
サブコマンドも増え続ける。

### 案B: 資源と操作の表でコマンド体系を決め、部品は薄くラップする

サブコマンドを「少数の資源に対する操作」に限る。`hmwr` が足す価値を4つに
絞り、部品の実体はRust側のツールに残す。ラップするコストが小さければ、直接叩く
理由が減る。

### 案C: hmwrをやめ、Rustのツールを直接使う規約にする

層が1つ減る。しかし名前からパスを決める仕事、ADRで決めた既定値、ログの
置き場、切り離しと完了マーカーは、どのツールにも共通で要る。ツールごとに持たせると
ADR-0180で消した重複が戻る。

## Decision

**案Bを採る**。決め手は、直接叩かれた原因が「ラップするコストと、固めた手順の
寿命の短さ」にあったことである。案Aは原因に触れず、案Cは共通の仕事の
置き場を失う。

### hmwrが足す価値は4つ

1. **名前からパスを決める**。教師は `data/train/<名前>.psv`、ネットは
   `data/nets/<名前>.hmwr`、対局は `data/sprt/<名前>.jsonl` に決まる。
   引数は名前で受け、パスは受けない（リポジトリの外にある参照エンジンの
   ような例外だけパスを許す）
2. **ADRで決めた既定値を持つ**。既定を変えたら理由がADRにある状態を保つ
   （[ADR-0149](0149-experiment-runner.md)）
3. **ログの置き場を決める**（`data/logs/<領域>-<名前>.log`）
4. **完了マーカーと再開を持つ**。出力が揃っていれば何もせず終わる。途中なら
   続きから走る。SPRTの `.result`（[ADR-0175](0175-sprt-until-decision.md)）の
   考え方を全コマンドへ広げる

この4つを足さないコマンドは `hmwr` に置かない。

### 資源と操作

| 資源 | 操作 | 備考 |
|---|---|---|
| `data`（教師psv） | fetch・shuffle・split・mix・quiet・rank・gen | splitは学習用と検証用の切り出し。genは `gensfen` |
| `net` | train・shapes・eval・reorder・actdump・release | |
| `match`（対局） | run・show・wait | 下に書く |
| `build` | pair・pgo・engine | いまのまま |
| `book`・`kifu` | いまのまま | |
| `spsa` | いまのまま | |
| `diag` | 単発の診断 | 下に書く |
| `verify`・`bench`・`env`・`ci`・`doc`・`clean` | いまのまま | |

`data` の操作は `psv` のサブコマンドへの対応表から作る。1操作は表の1行で、
名前の解決・既定値・ログ・完了マーカーは共通の実装が足す。**部品を足すコストを
表の1行にすることが、直接叩かせないための要点である**。

### 対局は `match` の1本にする

`sprt run`・`sprt net`・`league run`・直接の `selfplay` は、どれも「2者以上を
対局させ、ある規則で止める」の変種である。

- 対局者は、ビルド・ネット・USIオプション・時間オッズの組で表す。`sprt run`
  はビルドが違う2者、`sprt net` はネットが違う2者になる
- 止める規則は `--stop sprt`（既定）か `--stop pairs:500` で選ぶ
- 開始局面集は `--openings` で選ぶ。既定は現行と同じにする
- `--max-moves`・`--hash`・`--adjudicate` の既定は `config.py` の1か所が持つ

`sprt run` が持つ「ペアの作成→機能検証→起動」の段取りは、`build pair`・
`verify`・`match run` の列として残す。running-sprtスキルの手順は変えず、
呼び先だけ変える。`sprt` は `match` の別名として当面残し、移行が済んだら消す。

### 単発の診断は `diag` へ隔離する

`net rank`・`net dead`・`net phase` は `hmwr diag <名前>` へ移す。`diag` は
安定したインターフェースとして扱わない。引数の互換は保たず、使ったADRが完了して90日
たったら消してよい。消したものはgitの履歴とADRから掘り起こせる。
`net reorder` と `net actdump` は学習の標準手順に入っているので、`net` に残す
（[ADR-0168](0168-ft-dim-reorder.md)）。

**診断を足すときは `diag` に置き、2本目のADRで使われたら昇格を検討する**。

### 守らせる仕組み

期待ではなく設定で守らせる（[ADR-0181](0181-agent-surface.md)）。

- PreToolUseのhookで、`target/release/` の `psv`・`selfplay`・`gensfen` の
  直接実行を止める。止めたときは「`hmwr` 経由で実行する。足りない操作は
  対応表へ足すIssueを切る」と返す
- `--help` にない操作の直接実行が要るなら、それがIssueになる
- **hookを有効にするのは、部品をひととおりラップしてからにする**。先に止めると
  作業が詰まり、抜け道が作られる

### 移行の段取り

各段はCIが緑の「その他」のPRで入れる。等価性は、旧コマンドと新コマンドの
`--dry-run` の出力（実際に走るコマンド列）が一致することで示す。

1. `data` の対応表と共通の実装を作り、shuffle・split・mix・rankを足す
   （Issue #412・#458を吸収する）
2. `match run` を作り、`sprt run`・`sprt net`・`league run` を載せ替える
3. 診断を `diag` へ移す
4. 検証として、ADR-0206のチェーンを `hmwr` のコマンド列だけで書き直す。
   書けない操作が残ったら1へ戻る
5. hookを有効にし、CLAUDE.mdとhimawari-cliスキルを更新する

## Consequences

- 実験が `hmwr` のコマンド列で書けるようになる。実験キューの前提が整う
- コマンドの名前が変わる。running-sprtスキルとhimawari-cliスキル、
  CLAUDE.mdの「日常操作」を同じPRで直す。`sprt` の別名を残す間は、
  既存の手順が壊れない
- 既定値が `config.py` の1か所に集まり、チェーンごとのずれが消える。
  過去の対局との比較では、`--max-moves` のような条件の違いに注意が要る
- 対応表でラップするので、`psv` に引数を足したら表にも足す手間が残る。表と
  `psv --help` の食い違いはテストで検出する
- 見直しのトリガーは、移行後のチェーンや実験のspecに `hmwr` 以外の
  コマンドが再び現れたときである。そのときはコマンド体系の切り方を疑う

## 段取り1の実装（2026-09-17）

`data` の操作を `hmwr/dataops.py` の対応表から作った。入ったのはshuffle・
split・mix・quiet・rankの5つである。等価性は小さな実データで確かめた。
5つとも、`psv` を直接実行した出力とバイト一致した。`rank --jobs 4` の結合は
逐次の出力とも一致した。

決めたことが4つある。

- 完了マーカーは `<出力>.done` に置き、走らせたコマンドを控える。出力は `.part` へ
  書いてから改名するので、出力があれば最後まで書けている。同じ条件の
  再実行は何もせず成功で終わる。同じ名前で条件が違うと止まる。完了マーカーのない
  古い出力も止める。黙って古い出力を使う事故と、黙って上書きする事故の
  両方を防ぐためである
- 静止化の並列数の既定を8にした。並列の出力はjobs固定で決定論になり、
  逐次とは一致しない。チェーンが静止化を呼んだ11回は、すべて8だった。旧 `data quiet` は
  並列数を渡さず、`psv` の既定の1で走っていた
- `data quiet` の引数をパスから名前へ変えた。旧形式の `<入力> <出力>` は
  受けない。別名は残さない。使う場所がhimawari-cliスキルの1行だけだった
  ためである
- `gen` は外した。`gensfen` は出力へ追記するので、同じseedで再開すると同じ
  対局を重複して生成する。再開時のseedの扱いを決めてから足す（Issue #509）。
  自己生成の方向は打ち切っており、急がない

表と `psv` の食い違いはテストが見る。表の各オプションが `psv.rs` の
サブコマンドの節に現れることを検査する。

## 段取り2の実装（2026-09-18）

`hmwr match run` を作り、`sprt run` と `sprt net` を載せ替えた。対局の実体
（結果が出るまで回す・棋譜からの再開・結果ファイル）は `match.py` に移り、
`sprt.py` に残るのは対局者の組み立てと、ペア作成・機能検証の段取りだけで
ある。等価性は `--dry-run` の出力をorigin/mainの `hmwr` と比べて確かめた。
差は `--hash 64 --max-moves 320` の明示だけで、`selfplay` の既定と同じ値なので
対局は変わらない。既存の `sprt` のテストは無修正で通る。

決めたことが3つある。

- 止める規則は `--stop sprt` と `--stop pairs:N` の2つにした。指し切った
  実行は結果ファイルに `decision=指し切り` を書き、終了コード0で終わる。
  完了を結果ファイルの有無で決める考え方（[ADR-0175](0175-sprt-until-decision.md)）は
  そのまま使える
- 対局の条件を `data/sprt/<名前>.cond` に控え、再開のたびに比べる。再開は
  棋譜の有無だけで決まるので、名前が既存の実行とぶつかると、条件の違う対局が
  黙って続きに積まれる。dry-runで `yane-t8` の棋譜へ別条件で再開しかけて
  気づいた。ペア数の上限は条件に数えない。続きを積むときに変わるためである。
  記録のない古い棋譜は `--adopt` を付けたときだけ引き継ぐ
- `league run` は載せ替えていない。3者以上の総当たりで、Rust側のツールも別で
  ある。`match` の下へ移す作業はIssue #502に残す

`sprt` の別名を消すのは、running-sprtスキルとCLAUDE.mdを書き換える段取り5で行う。

## 段取り3の実装（2026-09-18）

`net rank`・`net dead`・`net phase` を `hmwr diag` へ移した。引数と動作は
変えていない。`--dry-run` の出力は、3つとも移す前と一致した。旧名の別名は
残さない。過去のADRに残る `hmwr net rank` などの記述は、当時の記録として
そのままにする。

## 段取り4と5の実装（2026-09-18）

ADR-0206のチェーンを `hmwr` のコマンド列へ書き直した。15行になり、
`tests/test_experiment_chain.py` が全行のdry-runを検査する。書き直しで
足りないと分かった操作は4つあり、同じPRで足した。

- `net train` が教師・検証集合・兄弟群を名前で受ける（`--rank` を新設）
- `data rm`。学習が済んだ混合データを消す。完了マーカーのある出力だけを消すので、
  消しても完了マーカーに残るコマンドで作り直せる。由来の記録がないファイルには
  触らない
- `data openings`。教師データから手数の条件で開始局面集を作る。ADR-0206の
  `entering_king_ply40.txt` をバイト単位で再現できた
- `data stats`。読むだけの確認も直接実行の理由になるのでラップした

hookを有効にした（`.claude/hooks/no_direct_tools.py`）。**止めるのは `hmwr` に
同じ操作があるものだけにした**。`selfplay` と、`psv` のhead・shuffle・quiet・
rank・statsである。`psv` のrelabel・thin・phase・dumpと `gensfen` は通す。
ラップし終える前に止めると抜け道が作られる、というDecisionの条件に沿う。`hmwr` で
ラップしたら、hookの一覧へ足す。コマンドの位置にある実行だけを見るので、
`ls` や `grep` の引数に出るパスは止めない。

残りは2つである。`league run` の載せ替え（Issue #502）と `data gen`
（Issue #509）で、どちらも次に使う実験が出たときに着手する。`sprt` の別名は、
running-sprtスキルの手順を書き換えるまで残す。
