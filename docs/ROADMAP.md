# ロードマップ

着手を決めるときに読む文書。4つの節で構成する。**現在地**は正の場所への
ポインタ、**注力**はいま張っている賭け、**運用**は回り続ける手順、
**候補**は網羅を担う待ち行列である。注力は絞り、思いつきの置き場は候補が持つ。

なぜそうしたかは[ADR索引](adr/README.md)、何が入ったかは
[CHANGELOG.md](../CHANGELOG.md)にある。この文書に過去の経緯・変わり続ける
数値・やらないと決めたことは書かない（棄却の記録はADRが持つ）。
着手を決めた案はADRを起こし、候補から消す。

### 制約

- hao_depth9は381ファイル・約30.0億局面すべてを取得済み。教師の増量の
  残り手は、別系統の公開データ（候補表の学習に取得候補を調査済み）と
  自前生成（[ADR-0144](adr/0144-selfplay-teacher-loop.md)）の2つになる
- 学習の所要が規模で効く。RAM 48GBに対し29.9億のpsvは111GBあり、
  ページキャッシュに載らない。処理速度は19.9億の222k局面/秒から96k局面/秒へ落ちる
- 持将棋のルールが2028年の選手権から27点法→24点法へ変わる見込み
  （2026-07-20オーナー共有）。影響するのは宣言勝ちの判定
  （[ADR-0030](adr/0030-nyugyoku-declaration.md)）、自前生成の勝敗ラベル、
  selfplayの入玉局面裁定の3か所である
- x86_64でのperft・ベンチ再計測は環境入手待ちで持ち越している

## 注力

いま張っている賭けは2本である。参照実装への追従は一巡して閉じ、SPSAで
定数まで自前化を始めたので、以後は独自の平衡を前提に進む。

### 1. 探索定数を自前の評価関数へ適合させる（SPSA）

追従で入れた探索定数は参照実装の値で、参照の評価関数に対して最適化された
ものである。本エンジンの評価関数は自前学習の別物なので、構造的なずれが残る
（singular率が設計点の4.4倍。[ADR-0114](adr/0114-g5-singular.md)）。
SPSAの一括チューニングでこのずれを回収する（[ADR-0143](adr/0143-spsa-tuning.md)）。

第1群（26項目）は**+32.0 Elo [+17.9, +46.2] のH1で採択した**。ずれは実在し、
回収できる。300+10の抜き取りも通過済みである（+63.2、過適合なし）。
残る作業は、SEE駒価値の配線判断と第2群の対象決めになる。再走は毎世代
ではなく機を見て行う（大きな構造変更の後や選手権前。2026-08-26
オーナー判断。実験の時間を優先する）。詳細と定数の動きは
[ADR-0143](adr/0143-spsa-tuning.md)の測定節にある。

### 2. 評価関数を構造と損失で強くする

自前学習の評価関数が本エンジンの独自資産で、参照実装が持たない領域である。
どこへ投資するかは、効き方の実測で決める。

- **構造の利得はデータ量で薄まらない**。FT出力の対の積は3億の測定台で
  +78.4、29.9億の本学習でも+65.4だった（[ADR-0171](adr/0171-ft-pairwise-product.md)）。
  教師分布の改善（静止化）が+35.8から+13.9へ薄まったのと対照的で
  （[ADR-0136](adr/0136-quiet-teacher-positions.md)）、表現できる関数の形が
  広がる変更はデータを増やしても価値が残る
- **検証損失は採否の物差しにならない**（[ADR-0158](adr/0158-mirror-factorizer.md)・
  [ADR-0172](adr/0172-multihot-input.md)）。lossが誤差の範囲でも対局は
  52 Elo負けることがある。採否は対局で決める
- **入力側の表を小さくする線は閉じた**。ミラー45が−16.0、マルチホットが
  −52.2で、入力の行数は素直に効いている（[ADR-0157](adr/0157-king-mirror-buckets.md)・
  [ADR-0172](adr/0172-multihot-input.md)）
- **速度の換算率は1%あたり3.12 Elo（10+0.1）である**（[ADR-0171](adr/0171-ft-pairwise-product.md)までの実測）。
  速度改善の期待値はこれで着手前に見積もる。ただし命令数やメモリ往復を
  削っても速度に結びつかない例が4件あり（[ADR-0164](adr/0164-bona-piece-bitset.md)・
  [ADR-0166](adr/0166-movepick-frame.md)・[ADR-0167](adr/0167-nnue-kernel-instructions.md)・
  [ADR-0169](adr/0169-clip-nnz-fusion.md)）、NNUE推論はメモリ待ちが律速で
  ある。命令を削る型の速度候補はこの教訓で足切りする

**掛け算の線は一巡した**。次数を上げる案（[ADR-0183](adr/0183-stacked-pairwise-product.md)）と
範囲を広げる案（[ADR-0184](adr/0184-cross-view-product.md)）を続けて測った。
どちらも「ネットは新しい項を使うが対局の利得に変換されない」で棄却した。視点内1段の対（0171の形）がこの機構では最適に近い。
構造の残りの手は活性の枠を変えないものになる。深さ方向は残差付きヘッド
（候補表）、条件分岐は出力バケット（[ADR-0137](adr/0137-output-buckets.md)）。
学習側は幅の3割が死んでいる問題の回収が残る（候補表の「死んだ活性の次元」。
枠の半減が−9になった0184の注意書きを見よ）。

損失の側は、回帰からランキングへの拡張が**+28.9 Eloで採択された**
（[ADR-0185](adr/0185-sibling-ranking-loss.md)）。教師のmoveフィールドが
持つ兄弟局面の順序制約を、qsearchの葉へヒンジで課す。この線の続きは
負例の数と選び方、α・δの配合で、同ADRの後続実験の節にある。副産物として
死んだ次元が75→39へ減った。

さらに先には、多ヘッド出力（WDL・進行度・安定度）を時間管理・枝刈りへ
供給する結合の線を置いている（[ADR-0120](adr/0120-after-parity.md)）。
学習器・ネット・探索の3つが揃って初めて測れる長工程なので、構造と損失の
線が一巡してから着手する。

## 運用

回り続ける手順。着手の対象ではなく、止まっていたら再開する。

- **実戦の定点観測**（[ADR-0152](adr/0152-floodgate-cycle.md)）。floodgateの
  棋譜を回収し、評価値系列から問題を掘り、定跡を足す。桂の3段目不成の
  生成漏れ（+11.2 Elo、[ADR-0173](adr/0173-knight-non-promotion-movegen.md)）は
  この観測が見つけた。CSAに残る評価値系列は、再解析より安い診断材料になる。
  次に見るのは定跡の追加（`book seed`）と、まだ回していない大悪手の全量解析
- **測定の手順はスキルが持つ**。SPRTはrunning-sprt、ビルド・計測・SPSAは
  himawari-cliを使う

## 候補

未着手の案を1案1行で置く。**やってみたい案だけを書く**。思いついただけの
汎用ノブや、単独で効く仮説を書けない案は載せない（2026-08-22オーナー方針。
消した案はgitの履歴から掘り起こせる）。着手を決めたらADRを起こして
ここから消す。完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記は、SPRT=対局ゲート、loss=検証損失、NPS=速度計測とする。
表の並び順は優先度を表さない。

単発の候補は[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・
ノード効率・終盤の正確さ）で選ぶ。どの軸に乗るかと、単独で効く仮説を
書けない候補は着手しない。過去にSPRTで棄却した案のうちP3期（駒割評価）の
測定は条件が違い、singular extensionがP3の−16.0からP8で+12.6へ反転した
先例がある。NNUE後の再測定には意味がある。

| 案 | 狙い・メモ | 検証 |
