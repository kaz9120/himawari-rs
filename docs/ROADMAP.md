# ロードマップ

着手を決めるときに読む文書。5つの節で構成する。**現在地**は正の場所への
ポインタ、**注力**はいま張っている賭け、**運用**は回り続ける手順、
**次に着手する**はセッションの入口、**候補**は網羅を担う待ち行列である。
注力は絞り、思いつきの置き場は候補が持つ。

なぜそうしたかは[ADR索引](adr/README.md)、何が入ったかは
[CHANGELOG.md](../CHANGELOG.md)にある。この文書に過去の経緯・変わり続ける
数値・やらないと決めたことは書かない（棄却の記録はADRが持つ）。
着手を決めた案はADRを起こし、候補から消す。

### 制約

- 計算資源は手元の開発機（M4 Pro、RAM 48GB）で、PCの新調はしない。AWSは
  当たったレシピの最終実行と選手権のリハーサルに限る
  （[ADR-0207](adr/0207-roadmap-focus-eval.md)）
- 教師はtanuki- 2024の78.6億局面である（[ADR-0192](adr/0192-tanuki2024-teacher.md)）。
  計算を積んで教師を作る線は閉じている。自己生成の継続学習は1回+15で
  頭打ちになり（[ADR-0201](adr/0201-loop-recipe.md)）、教師80億の付け直しは
  開発機で69日かかる（[ADR-0205](adr/0205-relabel-loop.md)）
- 学習の所要が規模で効く。78.6億のpsvは293GBあり、ページキャッシュに
  載らない。等価高速化後の実測は48kサンプル/秒で、1エポック50時間かかる。
  実験は3億局面の測定台（学習3時間＋対局2時間）で回す
- 持将棋のルールが2028年の選手権から27点法→24点法へ変わる見込み
  （2026-07-20オーナー共有）。影響するのは宣言勝ちの判定
  （[ADR-0030](adr/0030-nyugyoku-declaration.md)）、自前生成の勝敗ラベル、
  selfplayの入玉局面裁定の3か所である
- x86_64でのperft・ベンチ再計測は持ち越している。選手権のリハーサルで
  AWSを使うときに測る

## 注力

いま張っている賭けは1本である（[ADR-0207](adr/0207-roadmap-focus-eval.md)の
棚卸しで絞った）。

### 評価関数の学習と構造

上位との差は棋力そのもので、その本体は評価関数にあると見る。探索は参照
実装への追従が一巡し、8スレッドの並列効率も参照と同等に達した
（[ADR-0202](adr/0202-smp-loss-diagnosis.md)）。探索で発明的な発見を狙うのは
難しい。探索と時間管理の案は候補に置き、後で戻る。

掘り方の材料は実績にある。評価関数の構造は8月後半に7件続けて空振りし、
どれも「ネットは新しい項を使うが、対局に変換されない」という同じ壁に
当たった。当たったのは学習の側で、教師の置き換え
（[ADR-0192](adr/0192-tanuki2024-teacher.md)、+43.2）、ランキング損失
（[ADR-0185](adr/0185-sibling-ranking-loss.md)、+28.9）、静止化
（[ADR-0136](adr/0136-quiet-teacher-positions.md)、+20.3）がある。
**何をどの順で掘るかはオーナーと議論して決める**。決まるまで、候補の
評価関数・学習の表が待ち行列になる。

学習の測定で守ることは変わらない。検証損失は採否の物差しにならず
（[ADR-0158](adr/0158-mirror-factorizer.md)・[ADR-0172](adr/0172-multihot-input.md)）、
採否は対局で決める。

## 運用

回り続ける手順。着手の対象ではなく、止まっていたら再開する。

- **実戦の定点観測**（[ADR-0152](adr/0152-floodgate-cycle.md)）。floodgateの
  棋譜を回収し、評価値系列から問題を掘り、定跡を足す。桂の3段目不成の
  生成漏れ（+11.2 Elo、[ADR-0173](adr/0173-knight-non-promotion-movegen.md)）は
  この観測が見つけた。CSAに残る評価値系列は、再解析より安い診断材料になる。
  次に見るのは定跡の追加（`book seed`）と、崩壊局面の盲点ベンチマーク化
  （[ADR-0191](adr/0191-blindspot-benchmark.md)、大悪手の全量解析の後継）
- **探索定数のSPSA**（[ADR-0143](adr/0143-spsa-tuning.md)、第1群+32.0）。
  再走は毎世代ではなく機を見て行う（大きな構造変更の後や選手権前）。
  残る作業はSEE駒価値の配線判断と第2群の対象決め
- **実験キュー**（[ADR-0209](adr/0209-workflow-layers.md)）。specとADRをmainへ
  入れてIssueフォーム「実験」で積むと、開発機のlaunchdが古い順に1件ずつ
  走らせる。手順は `hmwr` のコマンド列で書く
  （[ADR-0208](adr/0208-hmwr-resource-verbs.md)）。止まっていたら
  `hmwr queue status` と `data/logs/queue-launchd.log` を見る
- **測定の手順はスキルが持つ**。SPRTはrunning-sprt、ビルド・計測・SPSAは
  himawari-cliを使う
- **細かい改善のIssueサイクル**。小さな気になりを `micro` ラベルの
  Issueへ即時に切り、実験の待ち時間に消化する。手順は
  micro-improvementsスキルが持つ
- **成果物の掃除**（[ADR-0189](adr/0189-artifact-retention.md)）。月1回を
  目安に `hmwr clean --apply` を回す。保持は30日で、現行の評価関数の系列と
  結果の要約は残る

## 次に着手する

**教師系列の混合の統制実験**（[ADR-0210](adr/0210-teacher-mix-control.md)）。
[ADR-0206](adr/0206-entering-king-mix.md)で3億の測定台に入玉データを20%
混ぜると、通常局面で+37.3だった。事前登録にない結果で、説明が3つ混ざって
いる。量の20%増、教師の系列の違い、入玉という性質である。haoを足す群と
tanukiを足す群の2本を統制群にして分ける。読み方はADR-0210に事前登録して
ある。効いたのが量でなければ、次はtanukiの測定台を作り、本学習へ移るかを測る。

並行して、開発プロセスの見直し（[ADR-0209](adr/0209-workflow-layers.md)）の
残りを進める。結果の記録の無人化（Issue #506）、GitHub Actionsの文書検査と
レートの定点記録（Issue #507）、Claude Code Routines（Issue #508）である。

## 候補

未着手の案を1案1行で置く。**やってみたい案だけを書く**。思いついただけの
汎用ノブや、単独で効く仮説を書けない案は載せない（2026-08-22オーナー方針。
消した案はgitの履歴から掘り起こせる）。着手を決めたらADRを起こして
ここから消す。完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記は、SPRT=対局ゲート、loss=検証損失、NPS=速度計測とする。
表の並び順は優先度を表さない。

単発の候補は[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・
ノード効率・終盤の正確さ）で選ぶ。どの軸に乗るかと、単独で効く仮説を
書けない候補は着手しない。過去にSPRTで棄却した案のうちP3期（駒割評価）の
測定は条件が違い、singular extensionがP3の−16.0からP8で+12.6へ反転した
先例がある。NNUE後の再測定には意味がある。

### 評価関数

| 案 | 狙い・メモ | 検証 |
|---|---|---|
| 残差付きヘッド深化 | 現行ヘッドは512→16→32→1と極小で、深さを振ったことがない。skip接続を付ければ深さは安全に振れるので、16→16の2〜3段で後段の容量が壁かを確かめる（[ADR-0134](adr/0134-head-capacity.md)の問いを残差で解禁する形）。速度の代償は換算率3.12 Elo/1%で見積もってから測る | loss+SPRT |
| 二段評価 | 全ノードはNNUEのまま、PVノードやrootだけ桁で重いネットに再評価させる。評価回数の大半は非PVの葉近傍なので、重い側の呼び出しを千分の一に抑えられれば予算に入る。TT・評価キャッシュとの整合と探索側の改造が要り、上の2案より不確実性が一段高い。氷彗は128-15-64の小ネット併用を試して弱くなり不採用と報告している（第6回電竜戦の感想戦、詳細不明）。着手時は失敗の型を確かめてから | 要検討 |
| 死んだ活性の次元 | 並べ替えの測定で分かった副産物（[ADR-0168](adr/0168-ft-dim-reorder.md)・[ADR-0171](adr/0171-ft-pairwise-product.md)）。ランキング損失（[ADR-0185](adr/0185-sibling-ranking-loss.md)）が一部を回収した。診断は[ADR-0194](adr/0194-dead-dim-measurement.md)にあり、構造的な死も量子化も原因ではない。**積は片側がゼロなら結果もゼロなので、対の相手を道連れにする**。死んだ対の3分の2は片側の死が原因で、残りは片側ずつ発火するのに同時には立たない。手当てが違うので、どちらから取るかを決めてから着手する。枠の半減が−9になった[ADR-0184](adr/0184-cross-view-product.md)の注意書きどおり、ゼロ率の高い次元もまれに発火して効くので、刈る方向は慎重に | loss+SPRT |
