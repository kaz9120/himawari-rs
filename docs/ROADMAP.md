# ロードマップ

着手を決めるときに読む文書。5つの節で構成する。**現在地**は正の場所への
ポインタ、**注力**はいま張っている賭け、**運用**は回り続ける手順、
**次に着手する**はセッションの入口、**候補**は網羅を担う待ち行列である。
注力は絞り、思いつきの置き場は候補が持つ。

なぜそうしたかは[ADR索引](adr/README.md)、何が入ったかは
[CHANGELOG.md](../CHANGELOG.md)にある。この文書に過去の経緯・変わり続ける
数値・やらないと決めたことは書かない（棄却の記録はADRが持つ）。
着手を決めた案はADRを起こし、候補から消す。

## 注力

いま張っている賭けは2本である（[ADR-0199](adr/0199-roadmap-inventory.md)の
棚卸しで組み替えた）。参照実装への追従は一巡して閉じ、評価関数の構造は
掘り尽くし、8月後半に効いたのはデータの線だけだった。実戦の負け方には
バグも運用の穴もなく、上位との差は棋力そのものである。計算資源は増やさず、
費用を抑えて強くする方針を優先する（2026-09-03オーナー）。

### 1. 複数スレッドの実戦化

放流も選手権も複数スレッドで動くのに、SPRTはすべて1スレッドで回して
きた。NPSは8スレッドで7.1倍と分かっている（[ADR-0162](adr/0162-parallel-group.md)）が、
**Eloが時間の何倍に相当するかは一度も測っていない**。Lazy SMPは共有の
質でここが決まり、1スレッドで積んだ改善が本番で薄まっている可能性がある。

最初の測定はスレッド数ごとのElo曲線で、時間オッズの曲線と突き合わせて
並列効率を読む（[ADR-0200](adr/0200-thread-scaling.md)）。効率の値で次の手が
決まる。健全なら共有の細部をThreads=4のSPRTで1件ずつ測る（historyの共有
Issue #430、false sharing [ADR-0151](adr/0151-speedup-sweep.md)群E）。
損失が大きければ、置換表の競合かメインスレッド依存かを切り分ける。

放流機はSurface Pro 9（Pコア2＋Eコア8）で6スレッド、選手権はAWSの多コアを
予定している。均質な多コアでの伸びが本番の棋力を決めるので、新しいPCが
入ったらx86のAVX2経路のベンチと放流の移設を最初に行う。

### 2. 自己生成と継続学習のループを、資源を足す前に型にする

上位との差の本体はここだと見ている。上位はより強い教師で何世代も回した
データで学習しており、構造は本エンジンと大差ない。データを変えた実験は
4戦4勝で（29.9億、静止化、tanuki 78.6億、自己生成）、構造の7連敗と対照的
である。

**マシン資源は、学習データの作り方と継続学習で強くなるループの作り方が
見えたら提供する**（2026-09-03オーナー）。この線の成果物は棋力そのもの
ではなく、**再現できるレシピと、資源を何倍にすると何Elo出るかの見積もり**
である。いまの資源で小さく回し、ノウハウを先に確立する。

ループの現在地は[ADR-0188](adr/0188-selfplay-rl-loop.md)にある。1世代目は
既定SPRTで+13.9に届いたが、同じレシピ（depth 8の生成4,700万局面、
lr 1e-5）の2世代目は積み増しにならず、lrの中間にも山はなかった。
**現行の重みの近傍に、depth 8の自己生成が足せる情報は残っていない**。
次に確かめるのは「新しい情報をどこから持ってくるか」で、候補は3つある。

1. 生成の深さ。ノード上限付きでdepth 8より深く読ませ、同じ局面数で
   2世代目が積み増しになるかを見る。1世代の生成コストは深さに比例して
   増えるので、深さと利得の関係がそのまま資源の見積もりになる
2. 教師専用の太いネットで蒸留する（[ADR-0132](adr/0132-ft-distillation.md)の
   再起動）。推論の速度を払わずに教師の質だけを上げる
3. 生成局面の選び方（候補表「自己生成の生成条件の精査」）。対局内の相関、
   序盤の重複、開始局面の被覆を既存データから測る

外部の公開データは、ライセンスが明らかなものだけを使う。入玉5億
（候補表の同名の項、MIT）は宣言負け8局（[ADR-0199](adr/0199-roadmap-inventory.md)）へ
直接効くので、この線と並行して混ぜる。Kanadeの蒸留データは有償の
評価関数に由来しライセンスが不明瞭なので使わない（2026-09-03オーナー）。

学習の測定で守ることは変わらない。検証損失は採否の物差しにならず
（[ADR-0158](adr/0158-mirror-factorizer.md)・[ADR-0172](adr/0172-multihot-input.md)）、
採否は対局で決める。

## 運用

回り続ける手順。着手の対象ではなく、止まっていたら再開する。

- **実戦の定点観測**（[ADR-0152](adr/0152-floodgate-cycle.md)）。floodgateの
  棋譜を回収し、評価値系列から問題を掘り、定跡を足す。桂の3段目不成の
  生成漏れ（+11.2 Elo、[ADR-0173](adr/0173-knight-non-promotion-movegen.md)）は
  この観測が見つけた。CSAに残る評価値系列は、再解析より安い診断材料になる。
  次に見るのは定跡の追加（`book seed`）と、崩壊局面の盲点ベンチマーク化
  （[ADR-0191](adr/0191-blindspot-benchmark.md)、大悪手の全量解析の後継）
- **探索定数のSPSA**（[ADR-0143](adr/0143-spsa-tuning.md)、第1群+32.0）。
  再走は毎世代ではなく機を見て行う（大きな構造変更の後や選手権前）。
  残る作業はSEE駒価値の配線判断と第2群の対象決め
- **測定の手順はスキルが持つ**。SPRTはrunning-sprt、ビルド・計測・SPSAは
  himawari-cliを使う
- **細かい改善のIssueサイクル**。小さな気になりを `micro` ラベルの
  Issueへ即時に切り、実験の待ち時間に消化する。手順は
  micro-improvementsスキルが持つ。初日の実績はIssue 9件・PR 6本
  （静止化5.3倍、学習+22%、CI並列化）
- **成果物の掃除**（[ADR-0189](adr/0189-artifact-retention.md)）。月1回を
  目安に `hmwr clean --apply` を回す。保持は30日で、現行の評価関数の系列と
  結果の要約は残る

## 次に着手する

**スレッド数ごとのElo曲線を測る**（[ADR-0200](adr/0200-thread-scaling.md)）。
5条件×1000局を開発機で回しており、約1日かかる。結果の読み方は同ADRに
事前登録してある。並列効率が出たら、その値で注力1の次の手を選ぶ。

待ち時間に進めるものは3つある。入玉5億のダウンロードと前処理（注力2）。
放流機の最適スレッド数の測定手順（[ADR-0199](adr/0199-roadmap-inventory.md)のConsequences）。
残差付きヘッドの足切り（候補表）で、ADR-0198の型を凍結FTの土俵へ移し、
深さだけを振って[ADR-0134](adr/0134-head-capacity.md)の−0.00019を超えるかを見る。

## 候補

未着手の案を1案1行で置く。**やってみたい案だけを書く**。思いついただけの
汎用ノブや、単独で効く仮説を書けない案は載せない（2026-08-22オーナー方針。
消した案はgitの履歴から掘り起こせる）。着手を決めたらADRを起こして
ここから消す。完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記は、SPRT=対局ゲート、loss=検証損失、NPS=速度計測とする。
表の並び順は優先度を表さない。

単発の候補は[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・
ノード効率・終盤の正確さ）で選ぶ。どの軸に乗るかと、単独で効く仮説を
書けない候補は着手しない。過去にSPRTで棄却した案のうちP3期（駒割評価）の
測定は条件が違い、singular extensionがP3の−16.0からP8で+12.6へ反転した
先例がある。NNUE後の再測定には意味がある。

|---|---|---|
| 残差付きヘッド深化 | 現行ヘッドは512→16→32→1と極小で、深さを振ったことがない。skip接続を付ければ深さは安全に振れるので、16→16の2〜3段で後段の容量が壁かを確かめる（[ADR-0134](adr/0134-head-capacity.md)の問いを残差で解禁する形）。速度の代償は換算率3.12 Elo/1%で見積もってから測る | loss+SPRT |

| 死んだ活性の次元 | 並べ替えの測定で分かった副産物（[ADR-0168](adr/0168-ft-dim-reorder.md)・[ADR-0171](adr/0171-ft-pairwise-product.md)）。ランキング損失（[ADR-0185](adr/0185-sibling-ranking-loss.md)）が一部を回収した。診断は[ADR-0194](adr/0194-dead-dim-measurement.md)にあり、構造的な死も量子化も原因ではない。**積は片側がゼロなら結果もゼロなので、対の相手を道連れにする**。死んだ対の3分の2は片側の死が原因で、残りは片側ずつ発火するのに同時には立たない。手当てが違うので、どちらから取るかを決めてから着手する。枠の半減が−9になった[ADR-0184](adr/0184-cross-view-product.md)の注意書きどおり、ゼロ率の高い次元もまれに発火して効くので、刈る方向は慎重に | loss+SPRT |
| 入玉局面の評価精度を測る | 教師データ（hao_depth9）は他エンジン由来で入玉が薄い（実測1.65%、ADR-0190）。薄さを補う公開データは見つけてある（学習表の「入玉教師データの混合」） | 実測 |
