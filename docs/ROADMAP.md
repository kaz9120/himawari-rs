## 次の方向

### 1. 参照実装との残りの乖離を閉じる

参照追従の線はほぼ閉じている。定数は220項目超が一致しており、構造の整列は
群1〜3が3030局で−6.7として棄却された（[ADR-0155](adr/0155-reference-walkthrough.md)）。
個別に棄却した5件をまとめ直す案も、5件ともADR-0109の群で導入済みと分かって
棄却した（[ADR-0160](adr/0160-revisit-rejected-under-better-eval.md)）。

並列まわりの3件も閉じた（[ADR-0162](adr/0162-parallel-group.md)）。historyの
スレッド共有・best thread voting・窓幅多様化を1群で測り、`Threads=4` の
6398局で非劣性のH1を得た（+7.9 [−0.2, +16.1]）。TTクラスタの手番分割は、
本エンジンが64bit全体を照合するため不要と判断して見送った。

残るのはADR-0155の群4である。千日手判定を参照のdo_move前計算方式へ
置き換える。現状は走査に16手キャップがなく、200手級の対局では毎ノード
約20KBのストライド走査になる。性能バグを兼ねるので速度側からも測れる。
群5（rootの統合）と群6（小物）は優先度を下げたままにする。

### 2. 評価関数の構造と学習で取る

FT1024は勝ち越しまで持っていき、現行構成になった。並べ替え
（[ADR-0168](adr/0168-ft-dim-reorder.md)、+13.19% NPS）とL1半減
（[ADR-0170](adr/0170-l1-half.md)、+13.4 Elo）が速度の代償を取り返した。
FT出力の対の積（[ADR-0171](adr/0171-ft-pairwise-product.md)、+65.4 Elo）は
駒対の相互作用を入れた。**利得の本体は評価の質で、構造の利得はデータ量で
薄まりにくい**。

この線から、計画に使える物差しが2つ残った。

- **速度の換算率は1%あたり3.12 Elo（10+0.1）である**。ADR-0159が得た3.5を
  実測で更新した。速度改善の期待値を着手前に見積もれる
- **命令数やメモリ往復を削っても速度に結びつかない例が4件ある**
  （[ADR-0164](adr/0164-bona-piece-bitset.md)・[ADR-0166](adr/0166-movepick-frame.md)・
  [ADR-0167](adr/0167-nnue-kernel-instructions.md)・[ADR-0169](adr/0169-clip-nnz-fusion.md)）。
  NNUE推論はメモリ待ちが律速で、命令を削る小細工は一巡した。挙動を変えない
  高速化で残るのは `Threads=4` で測る群E（[ADR-0151](adr/0151-speedup-sweep.md)）
  だけである

**入力側の表を小さくする線は閉じた**。ミラー45（行数44%削減）が−16.0、
マルチホット（1/73）が−52.2で、削る量と損の大きさが揃っている
（[ADR-0157](adr/0157-king-mirror-buckets.md)・[ADR-0172](adr/0172-multihot-input.md)）。
入力の行数は素直に効いており、速度に効いていたのは表の大きさではなく活性の
疎さだった。

次は2方向ある。どちらも教師データを増やさずに測れる。

- **損失関数の側**。ADR-0172は「lossが誤差の範囲なのに52 Elo負ける」を
  記録した。候補表の「兄弟局面のランキング損失」がこの線になる
- **構造の側**。積の掛け方はまだ視点の中で閉じている。候補表の
  「視点をまたぐ対の積」と「死んだ活性の次元」がこの線になる

### 3. 教師データを自前で作る

第1世代は−35.7 Eloで棄却した（[ADR-0144](adr/0144-selfplay-teacher-loop.md)）。
生成の仕組みは動き、5228万局面を3時間で作れる。足りないのは質である。
現行ネットは29.9億のhao_depth9で学習済みであり、そこへ自分のdepth 8探索を
教え直しても情報が増えない。教師signalと静的評価の乖離は338で、haoの353を
下回る。

残る手は4つある。探索を深くする、開始局面を定跡から取る、hao 29.9億との
混合再学習にする、外部データを探す。深さを上げるのが最初の候補だが、
depth 9ぶんの差をどの深さで埋められるかは分かっていない。

### 4. 評価関数と探索を結合する

多ヘッド出力（WDL・進行度・安定度）を学習し、時間管理・枝刈りの強度・
contemptへ供給する（[ADR-0120](adr/0120-after-parity.md)）。追従で探索は
参照実装と同じ構造になった。同等より先へ行くには別の軸が要る。評価関数を
自前で学習していることが本エンジンの独自資産で、参照実装が持たない領域である。

工程が長い。学習器・ネット・探索の3つが揃って初めて測れるので、
1群1SPRTのような短い周期にならない。

### 5. 実戦を定点観測する

floodgateの棋譜を定期回収し、分析と定跡追加を決定論の手順で回す
（[ADR-0152](adr/0152-floodgate-cycle.md)）。回収済みは569局（2026-08-17まで）で、
wdoor側に追いついている。

**この観測から探索のバグが1件見つかった**。負け267局のうち14局が「+1000以上
から投了級への崩壊」で、そのきっかけの手は11局が桂の跳ねだった。原因は桂の
3段目不成を通常探索が生成していなかったことで、+11.2 Eloの修正になった
（[ADR-0173](adr/0173-knight-non-promotion-movegen.md)）。**CSAに残る実戦の
評価値系列は、再解析より安い診断材料になる**。

次に見るのは定跡の追加（`book seed`）と、まだ回していない大悪手の全量解析である。

### 6. 探索定数をSPSAで回す

追従で入れた探索定数は、参照実装の値をそのまま使っている。評価関数は
自前学習の別物で、ずれの実例もある（singular率が設計点の4.4倍。
[ADR-0114](adr/0114-g5-singular.md)）。1定数1SPRTでは相互作用を拾えないので、
SPSAで一括チューニングする（[ADR-0143](adr/0143-spsa-tuning.md)）。

基盤を先に作る。対象の定数を `tune` featureのビルドだけUSIオプションへ出し、
`hmwr spsa` がθ±の対局を回して定数を動かす。リリースビルドは定数のまま
畳み込み、NPSに影響させない。検収はチューニングに使っていない既定条件の
SPRTで行う。1サイクル数万局を消費するので、SPRTと時期を分けて回す。

## 候補

未着手の案を1案1行で置く。着手を決めたらADRを起こしてここから消す。
完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記は、SPRT=対局ゲート、loss=検証損失、NPS=速度計測とする。
表の並び順は優先度を表さない。

単発の候補は[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・
ノード効率・終盤の正確さ）で選ぶ。どの軸に乗るかと、単独で効く仮説を
書けない候補は着手しない。参照実装に対応物がある候補はこの判断を使わず、
群単位で移す（[ADR-0109](adr/0109-reference-parity.md)）。

### 探索

過去にSPRTで棄却した案のうち、P3期（駒割評価）の測定は条件が違う。
singular extensionがP3の−16.0からP8で+12.6へ反転した先例があり、
NNUE後の再測定に意味がある。

単発の候補はいま空である。2026-08-20の棚卸しで、決着済みの2件
（[ADR-0174](adr/0174-mate1ply-knight-promotion.md)・
[ADR-0176](adr/0176-lance-non-promotion-rank.md)）と、続ける根拠を
失った2件を消した。mate_1plyの遠隔・遠打ちは、見逃し率の改善が棋力へ
届かない結果が2件続き、参照実装もコストを理由に列挙していない
（経緯はADR-0174）。`score_quiets` の命令削減は、メモリ待ちに隠れる
公算が高い（上の4件の教訓）。SEE駒価値の再調整は方向6（SPSA）の
第1群へ移した。

定数の適合は方向6が、参照との乖離の残りは方向1（群4）が持つ。
