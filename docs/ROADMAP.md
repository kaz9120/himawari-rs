# ロードマップと現在地

このプロジェクトの「やりたいこと・状況」はすべてこの文書で管理する。
GitHub Issuesは使わない。設計判断は [ADR索引](adr/README.md)、
未起草の設計論点はADR索引のバックログにある。
フェーズ管理は[ADR-0068](adr/0068-sprt-driven-versioning.md)で終え、
現在地・現行の最強構成・残作業の3節で運用する。
計測・検証の結果は 計測記録、改善アイデアは
[下の候補](#候補)、教師データの所在は [DATASETS.md](DATASETS.md) を参照。
更新タイミングは、フェーズの出入り・残作業の増減があったとき。

## 現行構成

| 項目 | 実体 |
|---|---|

FT512は評価精度で上回る（valid loss 0.49374）が、NPSが0.65倍に落ちる代償を
取り返せず不採択（[ADR-0067](adr/0067-ft-dimension-512.md)）。比較用に
`data/bin/himawari-ft512` と `data/nets/halfkp_1900M_ft512.hmwr.best` を残して

3186、負けはすべて相手3121以上・長手数で時間枯渇）。ここを越えるのが当面の
目標で、参加時のビルドを1.0.0とする（[ADR-0068](adr/0068-sprt-driven-versioning.md)）。

**何が入ったかは[CHANGELOG.md](../CHANGELOG.md)、なぜそうしたかは
[ADR索引](adr/README.md)にある。**

## 次の方向

**候補の一覧は[下の候補](#候補)にある。** ここには「今どこにいて、次にどちらへ
向かうか」だけを書く。着手を決めた案はADRを起こしてROADMAPの候補から消す。

### 1. floodgateで実戦を確認する

追従で+517.5を積んだ状態がレートでどこに現れるかを見る。2026-07-24〜25の初参戦は
30局でレート3186、実力の境界が3100〜3250にあった。

**追従で入れた機能のうち4つは既定条件のSPRTで測れていない。** 定跡のponder手
（`BookFile` の指定が要る）、best thread voting（`Threads=4`）、Lazy SMPの窓幅
多様化（同上）、時間管理の既定値（`MinimumThinkingTime=2000` は300+10向けで、
10+0.1では床が配分を支配する）である。floodgateは300+10なので、参照実装の既定値が
本来想定する条件に近い。**実戦が次の測定の場になる。**

### 2. 評価関数と探索を結合する

多ヘッド出力（WDL・進行度・安定度）を学習し、時間管理・枝刈りの強度・contemptへ
供給する（[ADR-0120](adr/0120-after-parity.md)）。

追従で探索は参照実装と同じ構造になった。**同等より先へ行くには別の軸が要る。**
本エンジンの独自資産は評価関数を自前で学習していることで、参照実装が持たない
領域である。あわせて[ADR-0089](adr/0089-improvement-criteria.md)の3軸へ第4の軸
「判断材料の質」を足す。

工程が長い。学習器・ネット・探索の3つが揃って初めて測れるので、1群1SPRTのような
短い周期にならない。

### 制約

- **持将棋のルールが2028年の選手権から27点法→24点法へ変わる見込み**
  （2026-07-20オーナー共有。詳細規定は公式発表を正とする）。影響するのは3か所で、
  宣言勝ちの判定（[ADR-0030](adr/0030-nyugyoku-declaration.md)は27点法/CSA実装）、
  自前gensfenの勝敗ラベル、selfplayの入玉局面裁定である。公開データセット
  （hao_depth9等）は27点法時代の生成物だが、入玉決着は少数なので教師あり学習への
  影響は無視できる
- 教師データの残り: hao_depth9のstart_time=1695872823（127ファイル、約10億局面）が
  未取得。29.9億まで増やせるが、容量律速のうちは伸びが逓減する
- 持ち越し: x86_64でのperft・ベンチ再計測（環境入手待ち）

## 候補

未着手の案を1案1行で置く。**着手を決めたらADRを起こしてここから消す。**
完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記: SPRT=対局ゲート、loss=検証損失、NPS=速度計測。
他の案を前提とする案は、メモ欄に依存先を書く。表の並び順は優先度を表さない。

単発の候補は[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・ノード効率・
終盤の正確さ）で選ぶ。どの軸に乗るかと、単独で効く仮説を書けない候補は着手しない。
**参照実装に対応物がある候補はこの判断を使わず、群単位で移す**
（[ADR-0109](adr/0109-reference-parity.md)）。
