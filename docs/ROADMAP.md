# ロードマップと現在地

このプロジェクトの「やりたいこと・状況」はすべてこの文書で管理する。
GitHub Issuesは使わない。設計判断は [ADR索引](adr/README.md)、
未起草の設計論点はADR索引のバックログにある。
フェーズ管理は[ADR-0068](adr/0068-sprt-driven-versioning.md)で終え、
現在地・現行の最強構成・残作業の3節で運用する。
計測・検証の結果は 計測記録、改善アイデアは
[下の候補](#候補)、教師データの所在は [DATASETS.md](DATASETS.md) を参照。
更新タイミングは、フェーズの出入り・残作業の増減があったとき。

## 現行構成

| 項目 | 実体 |
|---|---|
| エンジン | `target/release/himawari`（FT256ビルド） |
| 評価関数 | `data/nets/halfkp_1900M_fact.hmwr.best`（valid loss 0.49513） |
| 定跡 | `data/book/main.db`（540局面、深さ28、ply 13まで。[ADR-0121](adr/0121-book-scale-up.md)） |

FT512は評価精度で上回る（valid loss 0.49374）が、NPSの代償を取り返せず不採択
（[ADR-0067](adr/0067-ft-dimension-512.md)）。比較用に `data/bin/himawari-ft512` と
`data/nets/halfkp_1900M_ft512.hmwr.best` を残してある。

**2026-08-02に8構成を測り直したが、FTを太らせて現行を上回るものはなかった**
（[ADR-0127](adr/0127-net-shape-bench.md)）。FT512は−71.2 Eloで、ADR-0067の−72.8と
ほぼ同じ値になった。

**後段を256x16へ削る案は棄却した**（[ADR-0131](adr/0131-frozen-ft-light-head.md)）。
ADR-0127が足切りで得た+56.0 Elo は、19.9億局面で測り直すと−7.0になり、同じ3億のネットの
再測定でも−4.7だった。NPSの+9.8%は実測どおりだが、精度の損を上回らない。
ネットワークの次元は `HIMAWARI_ARCH=<FT>x<L1>[x<L2>[x<L3>]]` でビルド時に切り替える。

**FTを差し替えて後段を学習し直す操作は棋力中立である**（−0.7 Elo、
[ADR-0131](adr/0131-frozen-ft-light-head.md)）。良いFTを作れれば現行の構成へ載せて直接
比べられる。1回1時間で回る**測定台**になった。

**リーグ戦の推定は公称の区間より広くぶれる。** ±27.7と報告した推定が再測定と60 Elo
ずれた例がある。単独の数字で採否を決めない。最終ゲートはSPRT
（[ADR-0028](adr/0028-pruning-extensions.md)）。

実力の壁はfloodgateのレート3100〜3250にある（2026-07-24〜25の初参戦は30局で
3186、負けはすべて相手3121以上・長手数で時間枯渇）。ここを越えるのが当面の
目標で、参加時のビルドを1.0.0とする（[ADR-0068](adr/0068-sprt-driven-versioning.md)）。

参照実装（やねうら王）への追従は2026-08-01に一巡した。11群のうち10群が入り、
単純加算で+525.5 Elo（[ADR-0109](adr/0109-reference-parity.md)〜[0119](adr/0119-g10-book.md)）。
保留はsingularの多段延長と時間配分の分母の2件である。

追従の直後に、機能を足さない整理を一巡させた（2026-08-01）。探索本体の分割
（[ADR-0125](adr/0125-search-decomposition.md)）、開発スクリプトの3言語分割
（[ADR-0122](adr/0122-tooling-language-split.md)）、長時間処理の停止と再開
（[ADR-0123](adr/0123-stop-and-resume.md)）、挙動を変えない高速化で+2.71% NPS
（[ADR-0124](adr/0124-hot-path-allocs.md)）である。

**何が入ったかは[CHANGELOG.md](../CHANGELOG.md)、なぜそうしたかは
[ADR索引](adr/README.md)にある。**

## 次の方向

**候補の一覧は[下の候補](#候補)にある。** ここには「今どこにいて、次にどちらへ
向かうか」だけを書く。着手を決めた案はADRを起こしてROADMAPの候補から消す。

### 1. floodgateで実戦を確認する

追従で+525.5を積んだ状態がレートでどこに現れるかを見る。2026-07-24〜25の初参戦は
30局でレート3186、実力の境界が3100〜3250にあった。

**追従で入れた機能のうち4つは既定条件のSPRTで測れていない。** 定跡のponder手
（`BookFile` の指定が要る）、best thread voting（`Threads=4`）、Lazy SMPの窓幅
多様化（同上）、時間管理の既定値（`MinimumThinkingTime=2000` は300+10向けで、
10+0.1では床が配分を支配する）である。floodgateは300+10なので、参照実装の既定値が
本来想定する条件に近い。**実戦が次の測定の場になる。**

### 2. 挙動を変えない高速化を積む

[ADR-0124](adr/0124-hot-path-allocs.md)で3群を入れて+2.71% NPSを得た。残る候補は
`Shared` のfalse sharing、`MovePicker` の候補手バッファ、`partial_insertion_sort`、
`attackers_to` である。

**1件ずつでは測れない。** 個々の候補は0.2〜0.7%で、NPSの測定誤差（±1.5%）に埋もれる。
群でまとめて測る。false sharingは1スレッドでは効果がゼロなので、`Threads=4` 以上で
測る別枠になる。

NNUEのFT更新が25.2%でいちばん大きいが、そこを削る本命（FTのi8量子化）は評価値が
変わる。[ADR-0138](adr/0138-ft-i8-quantization.md)で扱い、SPRTで確かめる。

**FTを太らせる道はここを通る。** FT 256→512 で増える時間の3分の2はFT更新で、
差分更新（`apply_dirty`）だけで0.8%未満から7.8%へ跳ねる
（[ADR-0127](adr/0127-net-shape-bench.md)）。L1を削っても埋まらない。

**ノード数を揃えれば容量は効く。** FT768（L1半減）は1手30万ノード固定で+31.4 Elo になった
（[ADR-0127](adr/0127-net-shape-bench.md)、2400局）。ただしFT512は−19.6で効かない。
速度の代償は98 Eloあり、量子化で取り返せるのは+27程度なので、10+0.1では−40残る。
**300+10での再測定と組み合わせて判断する。**

### 3. FTの表現学習を確立する

**ボトルネックは一貫して上流にある。** 後段を32x32から16へ削ってもlossは0.0006しか動かず
（[ADR-0131](adr/0131-frozen-ft-light-head.md)）、上へ振っても最良で0.0007しか下がらない
（[ADR-0134](adr/0134-head-capacity.md)）。**上下どちらにも動かない。**

**FTはCBOWと同じ構造をしている。** 疎特徴の埋め込みを和で集約し、非線形性はclamp 1回だけ
である。word2vecが表現を獲得できたのは構造ではなく、的の情報量と大きな共有デコーダによる。
FTに欠けているのはその2つで、的はスカラー1つ、デコーダは積和17,440回しかない
（2026-08-03オーナーとの整理）。

**容量を増やす道は3方向とも塞がった**（2026-08-04）。

| 方向 | 結果 | 出典 |
|---|---|---|
| FTを太らせる | 速度で潰れる（−67〜−71 Elo） | [ADR-0127](adr/0127-net-shape-bench.md) |
| 後段を太らせる | 精度で返らない。最良で−0.00068、積和30倍では基準より悪化 | [ADR-0134](adr/0134-head-capacity.md) |
| 教師信号を太らせる（利き） | 初期値の工夫止まり（−0.001） | [ADR-0133](adr/0133-effect-pretraining.md) |

**データ量が、いまも唯一効いている手段である。** 残るのは特徴設計と、利き以外の教師信号になる。

道は2つある。どちらも推論のコストを増やさない。

- **利き予測**（[ADR-0133](adr/0133-effect-pretraining.md)）。**一巡した。** FTは短い利きを
  厳密に、長い利きを83%表現できる。ただし第2段階の改善は−0.001で、初期値の工夫の域を出ない。
  **利きの当てやすさと下流の効きが連動しない**ので、精度を上げる投資は返らない見込み
- **蒸留**（[ADR-0132](adr/0132-ft-distillation.md)）。**保留。** 機構は動くと確認できたが
  （λ=1〜3でFTが教師へ寄る）、手持ちの教師が生徒より0.0007しか良くなく、棋力差を測れない。
  教師が桁で良くなったときに再訪する

**道具は残った。** 局面生成器（`--generate`、4.0M局面/秒）は的を変えてそのまま使える。
使い捨てにすれば訓練損失がそのまま未見データの損失になり、過学習が構造的に起こらない。
学習時だけのヘッドを足して書き出し時に捨てる経路も、補助ヘッド・蒸留・利きで3度使った。

**対局の解像度は直接対決で±55 Elo である**（[ADR-0132](adr/0132-ft-distillation.md)、
1カード160局）。的の設計やヘッドの形は対局で比べず、FT固定のprobing（1条件10〜20分）で
絞る。採否はSPRTで決める。

### 4. 評価関数と探索を結合する

多ヘッド出力（WDL・進行度・安定度）を学習し、時間管理・枝刈りの強度・contemptへ
供給する（[ADR-0120](adr/0120-after-parity.md)）。

追従で探索は参照実装と同じ構造になった。**同等より先へ行くには別の軸が要る。**
本エンジンの独自資産は評価関数を自前で学習していることで、参照実装が持たない
領域である。あわせて[ADR-0089](adr/0089-improvement-criteria.md)の3軸へ第4の軸
「判断材料の質」を足す。

工程が長い。学習器・ネット・探索の3つが揃って初めて測れるので、1群1SPRTのような
短い周期にならない。

### 制約

- **持将棋のルールが2028年の選手権から27点法→24点法へ変わる見込み**
  （2026-07-20オーナー共有。詳細規定は公式発表を正とする）。影響するのは3か所で、
  宣言勝ちの判定（[ADR-0030](adr/0030-nyugyoku-declaration.md)は27点法/CSA実装）、
  自前gensfenの勝敗ラベル、selfplayの入玉局面裁定である。公開データセット
  （hao_depth9等）は27点法時代の生成物だが、入玉決着は少数なので教師あり学習への
  影響は無視できる
- 教師データの残り: hao_depth9のstart_time=1695872823（127ファイル、約10億局面）が
  未取得。29.9億まで増やせるが、容量律速のうちは伸びが逓減する。取得と再学習は
  [ADR-0135](adr/0135-teacher-data-3b.md)が扱う
- 持ち越し: x86_64でのperft・ベンチ再計測（環境入手待ち）

## 候補

未着手の案を1案1行で置く。**着手を決めたらADRを起こしてここから消す。**
完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記: SPRT=対局ゲート、loss=検証損失、NPS=速度計測。
他の案を前提とする案は、メモ欄に依存先を書く。表の並び順は優先度を表さない。

単発の候補は[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・ノード効率・
終盤の正確さ）で選ぶ。どの軸に乗るかと、単独で効く仮説を書けない候補は着手しない。
**参照実装に対応物がある候補はこの判断を使わず、群単位で移す**
（[ADR-0109](adr/0109-reference-parity.md)）。
