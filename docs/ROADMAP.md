# ロードマップ

着手を決めるときに読む文書。5つの節で構成する。**現在地**は一次情報の置き場を
示す。**注力**はいま力を入れている方向、**運用**は回り続ける手順である。
**次に着手する**はセッションの入口、**候補**は未着手の案の一覧である。
注力は絞り、思いつきの置き場は候補が持つ。

なぜそうしたかは[ADR索引](adr/README.md)、何が入ったかは
[CHANGELOG.md](../CHANGELOG.md)にある。この文書に過去の経緯・変わり続ける
数値・やらないと決めたことは書かない（棄却の記録はADRが持つ）。
着手を決めた案はADRを起こし、候補から消す。

## 注力

いま注力している方向は1本である（[ADR-0229](adr/0229-roadmap-visible-focus.md)で引き直した）。

### 焦点が見える評価関数

評価関数が「どこが焦点か」「どれだけ難しいか」を自分で出せるようにする。
強さ・独自性・見せる活動の3つに同時に効くので、これを選んだ。強さの面では、
上位との差は評価関数にあると見る。探索で発明的な発見を狙うのは難しい。
独自性の面では、選手権のアピール文書へ書ける取り組みを目指す。見せる面では、
公開ページの可視化と解説の材料にする。

段階は4つあり、段階ごとにADRを起こす。

1. **土台**。盤面操作が探索時間の何割かをプロファイルで測り、利きを差分で持つ
   試作を作る。部品は[ADR-0148](adr/0148-effect-table.md)の `EffectTable` にある。
   Bitboardをやめる案も含めて、測定で決める。参考は技巧（C++版のbyteboard）と
   山田将棋（駒背番号のビット）
2. **出力を増やす**。勝率の分布と升ごとの勝率をNNUEで出す。まず小規模学習で試し、
   強さを落とさないこと（非劣性）と、可視化に使えることを確かめる
3. **入力を増やす**。利き数の入力と、進行度で後段を切り替える方式を試す
4. **使う**。分布の広さで思考時間を配る。公開ページで焦点を見せ、解説につなげる

他チームの取り組みは `research/wcsc_appeals/` に要約してある。Miacisの分布出力、
Gokakuの升ごとの勝率、習甦の利き数の入力が出発点になる。

学習の測定で守ることは変わらない。検証損失は採否の指標にならず
（[ADR-0158](adr/0158-mirror-factorizer.md)・[ADR-0172](adr/0172-multihot-input.md)）、
採否は対局で決める。

## 運用

回り続ける手順。着手の対象ではなく、止まっていたら再開する。

- **実戦の定点観測**（[ADR-0152](adr/0152-floodgate-cycle.md)）。floodgateの
  棋譜を回収し、評価値系列から問題を掘り、定跡を足す。桂の3段目不成の
  生成漏れ（+11.2 Elo、[ADR-0173](adr/0173-knight-non-promotion-movegen.md)）は
  この観測が見つけた。CSAに残る評価値系列は、再解析より安い診断材料になる。
  次に見るのは定跡の追加（`book seed`）と、崩壊局面の盲点ベンチマーク化
  （[ADR-0191](adr/0191-blindspot-benchmark.md)、大悪手の全量解析の後継）
- **探索定数のSPSA**（[ADR-0143](adr/0143-spsa-tuning.md)、第1群+32.0）。
  再走は毎世代ではなく機を見て行う（大きな構造変更の後や選手権前）。
  残る作業はSEE駒価値を組み込むかの判断と第2群の対象決め
- **実験キュー**（[ADR-0209](adr/0209-workflow-layers.md)）。specとADRをmainへ
  入れて `hmwr exp queue` かIssueフォーム「実験」で積むと、開発機のlaunchdが古い順に1件ずつ
  走らせる。手順は `hmwr` のコマンド列で書く
  （[ADR-0208](adr/0208-hmwr-resource-verbs.md)）。止まっていたら
  `hmwr queue status` と `data/logs/queue-launchd.log` を見る
- **クラウドの定期実行**（[ADR-0209](adr/0209-workflow-layers.md)）。Claude Code
  Routinesが `micro` の消化（毎晩）と巡回（週次）を回す。手順と止め方は
  `.claude/routines/README.md` にある。GitHub Actionsは文書の整合検査を週次で回す
- **測定の手順はスキルが持つ**。SPRTはrunning-sprt、ビルド・計測・SPSAは
  himawari-cliを使う
- **細かい改善のIssueサイクル**。小さな気になる点を `micro` ラベルの
  Issueへ即時に切り、実験の待ち時間に消化する。手順は
  micro-improvementsスキルが持つ
- **成果物の掃除**（[ADR-0189](adr/0189-artifact-retention.md)）。月1回を
  目安に `hmwr clean --apply` を回す。保持は30日で、現行の評価関数の系列と
  結果の要約は残る

## 次に着手する

**注力の段階1から入る**。盤面操作の内訳は[ADR-0230](adr/0230-board-op-profile.md)で
測った。盤面の持ち方はその測定をもとにオーナーと決め、利きの差分の試作に進む。

**並行する改善は、入玉を点数で教えることだけを進める**。宣言法の点数や
「宣言までの残り」を、学習の目標か入力に持たせる。2028年からの24点法への変更にも
備える。やり方は着手時にADRで決める。開発機を取り合うときは注力を優先する。

外から見る役は、公開ページ（`himawari.y-kaz.com`、[ADR-0221](adr/0221-public-site.md)）が持つ。
このリポジトリは公開用データを書き出すところまでを持ち、表示はHidokoで作る。
段A（開発の記録）の形を決めて、Hidokoへ要件を渡すのが次の一手である。
放流機のUSIログも、同じR2で開発機へ運ぶ（2026-10-16オーナー判断）。バケットはオーナーが用意する。

開発環境の再設計（[ADR-0220](adr/0220-dev-environment-redesign.md)）は、状態の
出力仕様が入った。残りはコマンドの棚卸し（`sprt` を `match` へ統一）と、記録の
無人化の続きである。

## 候補

未着手の案を1案1行で置く。**やってみたい案だけを書く**。思いついただけの
汎用パラメータや、単独で効く仮説を書けない案は載せない（2026-08-22オーナー方針。
消した案はgitの履歴から掘り起こせる）。着手を決めたらADRを起こして
ここから消す。完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記は、SPRT=マージ判定の対局、loss=検証損失、NPS=速度計測とする。
表の並び順は優先度を表さない。

候補は、3つのゴール（強さ・独自性・見せる活動）のどれに効くかで選ぶ
（[ADR-0229](adr/0229-roadmap-visible-focus.md)）。強さに効く単発の候補は、
[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・ノード効率・終盤の正確さ）の
どれに効くかも示す。効く先を示せない候補と、単独で効く仮説を書けない候補には着手しない。過去にSPRTで棄却した案のうちP3期（駒割評価）の
測定は条件が違い、singular extensionがP3の−16.0からP8で+12.6へ反転した
先例がある。NNUE後の再測定には意味がある。

| 案 | 狙い・メモ | 検証 |

| 残差付きヘッド深化 | 現行ヘッドは512→16→32→1と極小で、深さを振ったことがない。skip接続を付ければ深さは安全に振れるので、16→16の2〜3段で後段の容量が壁かを確かめる（[ADR-0134](adr/0134-head-capacity.md)の問いを残差で解禁する形）。速度の代償は換算率3.12 Elo/1%で見積もってから測る | loss+SPRT |

| 死んだ活性の次元 | 並べ替えの測定で分かった副産物（[ADR-0168](adr/0168-ft-dim-reorder.md)・[ADR-0171](adr/0171-ft-pairwise-product.md)）。ランキング損失（[ADR-0185](adr/0185-sibling-ranking-loss.md)）が一部を解消した。診断は[ADR-0194](adr/0194-dead-dim-measurement.md)にあり、構造的な死も量子化も原因ではない。**積は片側がゼロなら結果もゼロなので、対の相手を道連れにする**。死んだ対の3分の2は片側の死が原因で、残りは両側とも発火はするが、同時には発火しない。手当てが違うので、どちらから取るかを決めてから着手する。視点内の次元数の半減が−9になった[ADR-0184](adr/0184-cross-view-product.md)の注意書きどおり、ゼロ率の高い次元もまれに発火して効くので、刈る方向は慎重に | loss+SPRT |
