# ロードマップ

着手を決めるときに読む文書。4つの節で構成する。**現在地**は正の場所への
ポインタ、**注力**はいま張っている賭け、**運用**は回り続ける手順、
**候補**は網羅を担う待ち行列である。注力は絞り、思いつきの置き場は候補が持つ。

なぜそうしたかは[ADR索引](adr/README.md)、何が入ったかは
[CHANGELOG.md](../CHANGELOG.md)にある。この文書に過去の経緯・変わり続ける
数値・やらないと決めたことは書かない（棄却の記録はADRが持つ）。
着手を決めた案はADRを起こし、候補から消す。

### 制約

- hao_depth9は381ファイル・約30.0億局面すべてを取得済み。教師の増量の
  残り手は、別系統の未取得の公開データ（ライセンス確認が要る）と自前生成
  （[ADR-0144](adr/0144-selfplay-teacher-loop.md)）の2つになる
- 学習の所要が規模で効く。RAM 48GBに対し29.9億のpsvは111GBあり、
  ページキャッシュに載らない。処理速度は19.9億の222k局面/秒から96k局面/秒へ落ちる
- 持将棋のルールが2028年の選手権から27点法→24点法へ変わる見込み
  （2026-07-20オーナー共有）。影響するのは宣言勝ちの判定
  （[ADR-0030](adr/0030-nyugyoku-declaration.md)）、自前生成の勝敗ラベル、
  selfplayの入玉局面裁定の3か所である
- x86_64でのperft・ベンチ再計測は環境入手待ちで持ち越している

## 注力

いま張っている賭けは2本である。参照実装への追従は一巡して閉じ、SPSAで
定数まで自前化を始めたので、以後は独自の平衡を前提に進む。

### 1. 探索定数を自前の評価関数へ適合させる（SPSA）

追従で入れた探索定数は参照実装の値で、参照の評価関数に対して最適化された
ものである。本エンジンの評価関数は自前学習の別物なので、構造的なずれが残る
（singular率が設計点の4.4倍。[ADR-0114](adr/0114-g5-singular.md)）。
SPSAの一括チューニングでこのずれを回収する（[ADR-0143](adr/0143-spsa-tuning.md)）。

第1群（26項目、15,000ペア）は完走し、24項目が動いた。RFP系がそろって
「もっと刈る」方向へ動いており、マージンが本エンジンの評価値分布に対して
保守的すぎたという仮説と整合する。焼き込んだ定数一式をSPRT既定条件で
検収中である。採択されれば「評価関数の世代更新→SPSA再走」が運用に加わり、
300+10側の抜き取り測定で時間条件への過適合を確かめる。

### 2. 評価関数を構造と損失で強くする

自前学習の評価関数が本エンジンの独自資産で、参照実装が持たない領域である。
どこへ投資するかは、効き方の実測で決める。

- **構造の利得はデータ量で薄まらない**。FT出力の対の積は3億の測定台で
  +78.4、29.9億の本学習でも+65.4だった（[ADR-0171](adr/0171-ft-pairwise-product.md)）。
  教師分布の改善（静止化）が+35.8から+13.9へ薄まったのと対照的で
  （[ADR-0136](adr/0136-quiet-teacher-positions.md)）、表現できる関数の形が
  広がる変更はデータを増やしても価値が残る
- **検証損失は採否の物差しにならない**（[ADR-0158](adr/0158-mirror-factorizer.md)・
  [ADR-0172](adr/0172-multihot-input.md)）。lossが誤差の範囲でも対局は
  52 Elo負けることがある。採否は対局で決める
- **入力側の表を小さくする線は閉じた**。ミラー45が−16.0、マルチホットが
  −52.2で、入力の行数は素直に効いている（[ADR-0157](adr/0157-king-mirror-buckets.md)・
  [ADR-0172](adr/0172-multihot-input.md)）
- **速度の換算率は1%あたり3.12 Elo（10+0.1）である**（[ADR-0171](adr/0171-ft-pairwise-product.md)までの実測）。
  速度改善の期待値はこれで着手前に見積もる。ただし命令数やメモリ往復を
  削っても速度に結びつかない例が4件あり（[ADR-0164](adr/0164-bona-piece-bitset.md)・
  [ADR-0166](adr/0166-movepick-frame.md)・[ADR-0167](adr/0167-nnue-kernel-instructions.md)・
  [ADR-0169](adr/0169-clip-nnz-fusion.md)）、NNUE推論はメモリ待ちが律速で
  ある。命令を削る型の速度候補はこの教訓で足切りする

この実測から、次の一手は**掛け算の場所**に置く。視点内の積で駒対が入った
ので、視点をまたぐ積で両玉と駒の関係（KKPP相当）を狙う（候補表）。並行して、
幅の3割が死んでいる問題を学習側で解ければ、速度と独立にノード効率が上がる
（候補表の「死んだ活性の次元」）。

損失の側は、回帰からランキングへの拡張が本命である。現行の損失は局面1つに
数値1つの回帰で、探索が実際に要求する「兄弟局面の順序」を見ていない
（候補表の「兄弟局面のランキング損失」）。

さらに先には、多ヘッド出力（WDL・進行度・安定度）を時間管理・枝刈りへ
供給する結合の線を置いている（[ADR-0120](adr/0120-after-parity.md)）。
学習器・ネット・探索の3つが揃って初めて測れる長工程なので、構造と損失の
線が一巡してから着手する。

## 運用

回り続ける手順。着手の対象ではなく、止まっていたら再開する。

- **実戦の定点観測**（[ADR-0152](adr/0152-floodgate-cycle.md)）。floodgateの
  棋譜を回収し、評価値系列から問題を掘り、定跡を足す。桂の3段目不成の
  生成漏れ（+11.2 Elo、[ADR-0173](adr/0173-knight-non-promotion-movegen.md)）は
  この観測が見つけた。CSAに残る評価値系列は、再解析より安い診断材料になる。
  次に見るのは定跡の追加（`book seed`）と、まだ回していない大悪手の全量解析
- **測定の手順はスキルが持つ**。SPRTはrunning-sprt、ビルド・計測・SPSAは
  himawari-cliを使う

## 候補

未着手の案を1案1行で置く。網羅性はこの節が担う。着手を決めたらADRを起こして
ここから消す。完了・棄却した案も残さない（経緯と結果はADRが持つ）。

検証手段の略記は、SPRT=対局ゲート、loss=検証損失、NPS=速度計測とする。
表の並び順は優先度を表さない。

単発の候補は[ADR-0089](adr/0089-improvement-criteria.md)の3軸（速度・
ノード効率・終盤の正確さ）で選ぶ。どの軸に乗るかと、単独で効く仮説を
書けない候補は着手しない。過去にSPRTで棄却した案のうちP3期（駒割評価）の
測定は条件が違い、singular extensionがP3の−16.0からP8で+12.6へ反転した
先例がある。NNUE後の再測定には意味がある。

### 評価関数

| 案 | 狙い・メモ | 検証 |
|---|---|---|
| 視点をまたぐ対の積 | [ADR-0171](adr/0171-ft-pairwise-product.md)の積は視点の中で閉じており、係数の対は（自玉, 駒）×（自玉, 駒）に限られる。自視点と相手視点の活性を掛ければ、（自玉, 駒）×（敵玉, 駒）の相互作用が同じ低ランク機構で入る。KKP・KKPPが別表で持っていた両玉と駒の関係である。accumulatorと差分計算は変わらず、3億の測定台の手順がそのまま使える。掛ける相手を視点内・視点間で半々にする折衷もある | loss+SPRT |
| 死んだ活性の次元 | 並べ替えの測定で分かった副産物（[ADR-0168](adr/0168-ft-dim-reorder.md)・[ADR-0171](adr/0171-ft-pairwise-product.md)）。現行構成では75次元（14.6%）が12,500サンプルすべてでゼロ、261次元（51%）がゼロ率0.95以上だった。**積は片側がゼロなら結果もゼロなので、対の相手を道連れにする**。正則化・初期化・lrの問題か、この教師データに対して幅が過剰かの切り分けが要る。有効次元を増やせれば、速度側の投資とは独立にノード効率が上がる。学習側と別に、常時ゼロの対を刈ってFT_OUTを縮める推論側の経路もある | loss+SPRT |
| PSQT直結パス（material head） | FTから評価へのskip。序盤の材料感を安定化する | loss+SPRT |
| 手番特徴の明示化 | HalfKPは手番を視点でしか持たない。tempo項を学習する | loss |
| 合法手集合の予測 | [ADR-0133](adr/0133-effect-pretraining.md)の次の的。遮りに加えてピンと王手放置が絡むので非加法性が強く、2187次元と的も大きい。局面生成器がそのまま使える。利きが−0.001止まりだった理由が「的が細い」なら、ここで差が出る | probing+SPRT |
| 入玉局面の評価精度を測る | 教師データ（hao_depth9）は他エンジン由来で入玉が薄い。ただし実戦で問題が出た証拠はまだない | 実測 |

### 学習

| 案 | 狙い・メモ | 検証 |
|---|---|---|
| 兄弟局面のランキング損失 | 現行の損失は局面1つに数値1つの回帰で、**探索が要求する兄弟局面の順序を見ていない**。教師の最善手mに対し、他の合法手m'について `value(P·m) ≤ value(P·m')` が成り立つ。1局面あたり80本前後の制約が、教師データを1バイトも増やさずに手に入る。Bonanza法の目的関数をNNUEの回帰へ戻す形になる。制約はqsearchの葉へ課すのが正しく、そこが計算の主コスト（負例2本で3億なら6億回、数時間）。[ADR-0129](adr/0129-auxiliary-heads.md)の指し手ヘッドは−300 Eloだったが、あれは指し手を当てる分類で、評価値に順序を課すのとは別物 | loss+SPRT |
| 左右ミラーのデータ拡張 | 将棋のルールは左右対称で、鏡映局面は同じ評価値を持つ。読み込み時に確率0.5で盤と手を鏡映すれば、教師データを1バイトも増やさず分布を対称化できる。重みを縛った[ADR-0157](adr/0157-king-mirror-buckets.md)（−16.0）・[ADR-0158](adr/0158-mirror-factorizer.md)（利得なし）と違い、データ側から対称性を教えるので表現力を落とさない。初期配置は左右非対称なので、序盤の分布が実戦から離れる懸念は残る | loss+SPRT |
| 自前生成の教師・第2世代 | 第1世代は−35.7 Eloで棄却した（[ADR-0144](adr/0144-selfplay-teacher-loop.md)）。生成の仕組みは動き、5228万局面を3時間で作れる。足りないのは質で、残る手は3つある。探索を深くする、開始局面を定跡から取る、hao 29.9億との混合再学習にする | SPRT |
| λのply依存化 | 序盤はresult重視、終盤はscore重視の混合比にする | loss+SPRT |
| 詰みスコアの扱い | ±30000近傍のclamp・除外・専用ターゲット。現状は8.5%を素通ししている | loss+SPRT |
| EMA重み平均（SWA） | 終盤の重み振動を平均化する。ほぼ無料で数Elo | SPRT |
| 教師との指し手一致率の計測 | PSVのmoveフィールドを使う。lossと別の健全性指標になる | 指標 |
| 複数データセット混合 | hao系＋水匠系など。分布の偏りを緩和する（ライセンス確認） | SPRT |
| 序中終盤のサンプリング重み | gamePly別の採択率を調整する | loss+SPRT |
| ハイパラのSPRT運用 | lr・λ・epochsを1変更=1SPRTで積む | SPRT |
